## 1. 目标与闭环定位

交付三类管理页（三者共享 RBAC 语义，均为 governed / 权限门控）：

1. **Users**：分页列表 + 增删改 + 改状态 + 改密码 + 分配角色。
2. **Roles**：分页列表 + 增删改 + 改状态 + 基于 permission catalog 的权限分配 + 菜单分配。
3. **Menus**：菜单树编辑器 + 增删改；`component` 必须在 `views/**` allowlist、拒绝已删旧路径。

后端已就绪（见 §3 契约），本 phase 为**纯前端 + allowlist 校验**；不阻塞任何主路径。

## 3. 契约与模块设计

### 3.1 后端（已完整，不改）

- **Users**：`GET/POST /users`、`GET/PUT/DELETE /users/{id}`、`PUT /users/{id}/status`、
  `PUT /users/{id}/password`、`PUT /users/{id}/roles`（`crates/quant-pivot-web/src/routes/users.rs`）。
- **Roles**：`GET/POST /roles`、`GET/PUT/DELETE /roles/{id}`、`PUT /roles/{id}/status`、
  `GET/PUT /roles/{id}/permissions`、`GET/PUT /roles/{id}/menus`（`roles.rs`）。
- **Menus**：`GET/POST /menus`、`GET /menus/accessible`、`PUT/DELETE /menus/{id}`（`menus.rs`）。
- **Permission catalog**：`GET /permissions/catalog` → `PermissionCatalogEntry[]`
  （`RESOURCE_OPERATIONS` in `enums/rbac.rs`）。
- 写入 Casbin policy 表后 handler 已 `state.casbin.reload()`（授权即时生效）。

DTO：`UserView`/`RoleView`/`RoleInfo`/`MenuInfo`/`MenuTreeNode`/`PermissionCatalogEntry`
（`ui/packages/types/src/rbac.ts` 已存在，补齐 `*Request` 类型）。

### 3.2 前端 — Users

- 分页表格（username、status、roles、created_at）+ 搜索。
- 行动作（权限门控）：编辑（`user:update`）、删除（`user:delete`）、改状态（`user:update`）、
  改密码（`user:update`）、分配角色（`user:assign`，多选 role checkbox 抽屉）。
- toolbar：新建用户（`user:create`）。
- 所有 mutation 走 governed modal（reason + acting-role）或直接 governed request（依后端是否
  要求 `X-Acting-Role`；users/roles CRUD 若非 `ActingRoleGoverned` 则普通 request + 权限码门控）。

### 3.3 前端 — Roles

- 分页表格（code、name、status、created_at）+ 搜索。
- 行动作：编辑、删除、改状态、**分配权限**、**分配菜单**。
- **权限分配抽屉**：`GET /permissions/catalog` → 按 resource 分组的 checkbox 树；
  `GET /roles/{id}/permissions` 回填选中；`PUT /roles/{id}/permissions` 提交
  （`role:assign`）。
- **菜单分配抽屉**：`GET /menus`（全树）→ tree checkbox；`GET /roles/{id}/menus` 回填；
  `PUT /roles/{id}/menus` 提交。

### 3.4 前端 — Menus（防漂移硬约束）

- 菜单树编辑器（directory / menu / button 三类节点）。
- **component allowlist 校验**：`shared/rbac/component-allowlist.ts` 由
  `import.meta.glob('../views/**/*.vue')` 派生合法 component 字符串集合（与
  `router/access.ts` 的 `pageMap` 同源）；menu 编辑表单的 `component` 字段用 Select（allowlist
  选项）而非自由文本，**拒绝**已删旧路径（opportunities/trades/risk/…）。
- 提交前二次校验：`component ∈ allowlist ∧ path` 合法；不满足则 fail-closed 报错，不提交。
- 节点类型联动：directory 无 component/permission；menu 必填 component + 可选 permission；
  button 必填 permission、无 component（复用 10.0 菜单树语义）。

### 3.5 权限矩阵（前端 access 门控）

| 动作 | 权限码 |
|---|---|
| users 列表 / roles 列表 / menus 列表 | `user:read` / `role:read` / `menu:read` |
| user create/update/delete/assign | `user:create/update/delete/assign` |
| role create/update/delete/assign | `role:create/update/delete/assign` |
| menu create/update/delete | `menu:create/update/delete` |
| permission catalog 查看 | `permission:read` |

## 5. 生产不变量与 UX 语义

1. **菜单不漂移**：menu 编辑器 component 必须在 `views/**` allowlist（与 `router/access.ts`
   `pageMap` 同源），拒绝旧路径；否则登录后动态路由不可达。
2. **授权即时生效**：后端 policy 写入后 `casbin.reload()`；前端 mutation 成功后刷新列表。
3. **改密不回显**：`password` 只入不出，`UserView` 永不含 `password_hash`。
4. **operation-log 是唯一通用审计入口**：admin 页不重复实现审计视图。

## 6. 验收测试

**Unit：** menu component allowlist validator（拒绝旧路径、接受现有 `views/**`）。

**Manual：** users CRUD + 分配角色；roles 权限/菜单分配后目标用户可见性即时变化；menus 编辑器
无法选择已删 component。

**门禁：** 前端 typecheck/build/unit/eslint 全绿；若触及后端 seed / RBAC 则后端全量门禁。

## 7. Blocker

- menu 编辑器可选 `views/trades/index` 等已删 component → **Blocker**。
- users/roles/menus 页仍为 `RoadmapPlaceholder` → **Blocker**。
- 权限/菜单分配未回填当前选中 → **Blocker**（会误清空）。
