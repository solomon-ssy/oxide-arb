## 0. 落地实现的关键决策（与初版计划的差异）

1. **Report 详情 = 全屏路由** `/quant/reports/:id`（镜像 market detail 的 `page_hidden` seed 模式），
   而非抽屉——避免"抽屉套抽屉"，支持深链/刷新/分享。
2. **Recommendation 详情 = 共享面板 + 双形态**：drawer（从报告详情行打开，携带 `reportStatus`）
   与全屏深链路由 `/quant/recommendations/:id`，二者复用同一
   [`recommendation-detail-panel.vue`](../../../../ui/apps/web-antdv-next/src/views/quant/recommendations/modules/recommendation-detail-panel.vue)。
3. **后端补齐 `runtime_mode` filter**：`QuantReportListQuery` 增 `runtime_mode`（DTO + repository SQL + web 测试），
   对齐 §3.1 的筛选维度。
4. **Menu seed**：`menus.rs` 新增两条 `page_hidden`（report-detail / recommendation-detail），`MENUS_SEED.version` 9→10；
   前端 `menu-seed-paths.test.ts` 同步。
5. **TS 契约修正**：`ReportDiffView`（`retained` + base/compare totals & eligibility）、`QuantEvidenceView`
   （补齐 feature_vector / model_run / market_selection / runtime_config / model_version / data_quality refs）
   与后端 `*View` 严格对齐；`QuantReportListQuery` 增 `runtime_mode?`。
6. **Enriched `QuantRecommendationView`（生产级加固）**：后端 `QuantRecommendationView` 增 `report_status`
   （父报告 lifecycle）与 `active_order_intent_id`（阻塞 intent 或 `null`），经 `RecommendationViewContext`
   在 core port 层 join 三个仓库（recommendation / report / order_intent）组装——删除 `From<RecommendationInfo>`
   直转，所有 outbound 走 assembly。前端 create-intent gate 不再依赖 drawer 传入的 `reportStatus`，
   而是消费权威 DTO 字段。
7. **Create-intent gate 与后端严格对齐**：新增 `@vben/types/execution-gate.ts` 纯函数
   （`isExecutionEligible` / `killSwitchAllowsNewEntry` / `isRiskEnvelopeActionable` /
   `isReportActionableForIntent` / `isRecommendationActionableForIntent`），镜像 Rust
   `ExecutionEligibility::is_eligible`、`KillSwitchState::allows_new_entry`、mode-gate 风险边界校验；
   gate 覆盖 permission / mode / kill-switch / eligibility(含 auto_execution + ineligibility_reasons) /
   risk-envelope / validity / report_status / recommendation_status / active_intent 全矩阵。
8. **Diff 方向语义修正**：diff 固定为 `baseline(旧) -> this report(当前)`——UI 调用
   `getReportDiff(baselineId, currentId)`，`added` = 当前报告新增、`removed` = 相对 baseline 移除；
   picker 默认预选“上一份 published”，分页拉全量 published，totals 区标注 baseline / this report。

## 1. 目标与闭环定位

交付报告平面四块 UI：

1. **Reports 列表与 latest**：筛选、表格、latest panel、run/revoke governed actions。
2. **Report detail 与 diff**：trigger、config refs、recommendations tab、structural diff tab。
3. **Recommendation detail drawer**：score、plans、factors、evidence、attribution 全量展示。
4. **从 Recommendation 创建 Intent**：eligibility gate + governed create + 409 fail-closed。

本子phase完成后，operator 可完整消费 Phase 04 报告产物；10.4 可从 recommendation 创建 intent。

## 3. 契约与模块设计

### 3.1 Reports 列表与 latest

**筛选：** status、report_kind、trigger_kind、runtime_mode、time range。

**表格列：**

report id、as_of、runtime mode、status、top_n、published count、capital base、suggested USD、empty reason、published/revoked/expired time。

**Latest panel：** 展示最新 published report summary + 快捷跳转 detail。

**Actions：**

| Action | API | Governed |
|---|---|---|
| Run report | `POST /api/quant/reports/run` | yes |
| Revoke | `POST /api/quant/reports/{id}/revoke` | yes |

**WS：** `quant.report` → list/latest reload + toast。

**Run 202 响应：** 展示 `request_id` / `trigger_key`，非同步等待 published。

### 3.2 Report detail 与 diff

**Detail drawer tabs：**

| Tab | 内容 |
|---|---|
| Overview | trigger、source delay、horizon、account snapshot ref、runtime config version、model version、market selection、summary JSON |
| Recommendations | ranked rows：rank、market、token、side、scores、eligibility |
| Diff | 输入 other report id → `GET .../diff/{other_id}` |

**交互：**

- recommendation row click → 打开 recommendation detail drawer
- diff 只展示后端 structural diff，不做前端猜测
- diff endpoint 失败不影响 detail 主信息

**Empty report UX：**

- 明确显示 `empty_reason` 和 `status_reason`
- 不隐藏 empty 状态

### 3.3 Recommendation detail drawer

**必须完整展示的字段组：**

| 组 | 字段 |
|---|---|
| Identity | recommendation_id、report_id、rank、market_id、event_id、token_id、outcome_side |
| Score | composite、risk_adjusted、confidence、expected_return_bps、downside_bps |
| Context | market_context、liquidity_score、data_quality_score、model_score_percentile |
| Plans | entry_plan、sizing_plan、exit_plan、risk_envelope |
| Factors | factor_breakdown |
| Evidence | signal_candidate_id、feature_vector_id、model_run_id、book_snapshot_ref、runtime_config_version_id、model_version_id、factor_definition_versions、data_quality_snapshot_ref |
| Attribution | outcome、realized_pnl_usd、MAE/MFE、entry/exit outcome、attribution JSON |

**Lazy load tabs：**

- Evidence：`GET /api/quant/recommendations/{id}/evidence`
- Attribution：`GET /api/quant/recommendations/{id}/attribution`
- 无权限或不存在 → 明确 empty state

**业务目标：** 推荐详情能独立解释"为什么买、怎么买、买多少、何时退出、风险边界是什么"。

### 3.4 从 Recommendation 创建 Intent

**启用条件（全部满足才 enable 按钮）：**

| 条件 | 检查 |
|---|---|
| Permission | `order_intent:create` |
| Runtime mode | 非 `report_only`（且已知） |
| Kill-switch | `state === closed`（`killSwitchAllowsNewEntry`） |
| Eligibility | `isExecutionEligible`（mode 在 `eligible_modes`；`auto_execution` 额外要求 `ineligibility_reasons` 为空） |
| Risk envelope | `max_position_usd > 0 && max_loss_usd > 0` |
| Validity window | `now ∈ [valid_from, valid_until]` |
| Report status | `report_status === published`（权威 DTO 字段） |
| Recommendation status | `published` 或 `intent_created`（`is_actionable_for_intent`） |
| Active intent | `active_order_intent_id === null`（无阻塞 intent） |

**交互：**

- governed modal：展示 entry order、sizing、risk envelope hash、expires_at
- `POST /api/quant/intents`
- 409 原因原样展示

**Disabled UX（`report_only`）：**

- 按钮 disabled + tooltip 解释：不是 dry-run，当前模式不允许创建 intent
- 不误导为"模拟执行"

**成功：** 跳转或打开 `/quant/intents` 对应详情。

## 5. 生产不变量与 UX 语义

1. **Report 是主产物：** 导航和 dashboard 均指向 reports 为 primary workflow。
2. **Immutable report：** UI 不提供 edit report；只有 revoke governed action。
3. **Attribution 不在通用 audit：** 证据在 recommendation drawer，不重复建 audit 页。
4. **Money 字段：** 全部 `string` 格式化展示，禁止 JS number 运算。

## 7. Blocker

- recommendation drawer 缺少 plans 或 risk_envelope 展示 → **Blocker**
- create intent 在 `report_only` 可点击 → **Blocker**
- 仍引用旧 opportunity type 展示 score → **Blocker**
- diff 前端自行计算而非 backend endpoint → **Blocker**

## 8. 延后 / 缺口（含后续 phase 前向设计）

- **Intent 深链 + 审批台**：本 phase create-intent 成功后跳转 `/quant/intents` 列表。
  **10.4** 补 `/quant/intents/:id` 深链路由（同 `page_hidden` 模式）+ 审批台
  （approve/reject/cancel/submit），并把 create-intent 成功后的跳转目标接到 intent 详情。
  见 [`10.4-execution-plane.md`](10.4-execution-plane.md) §3.1。
- **Attribution 只读闭环**：attribution 由盘后标注 worker（execution/settlement 结算后）写入 WORM 行，
  前端**恒只读**、无编辑；无归因时永远 empty state（展示 `label_available_at` 提示）。
  写路径不属前端；生产触发链在 **10.4** execution/settlement 平面闭合。
- **Evidence replay 打开**：evidence tab 目前展示 replay handle（signal candidate / feature vector /
  model run / book snapshot / …）并支持点击复制。"直接打开 feature vector / model run / book snapshot"
  的深跳交由 **10.5** research workbench（replay 工具）实现。
- **Diff 可视化深化**：本期为结构化 added/removed/retained 三表 + totals + eligibility 对比。
  rank-change 高亮、suggested_usd delta 图表等可视化增强延后（不阻塞主闭环）。
- **E2E**：Report latest/detail/recommendations/diff + create-intent（成功 / 409 fail-closed）
  的 Playwright 覆盖在 **10.6** 补齐，见 [`10.6-hardening.md`](10.6-hardening.md)。
