# 10.3 — RecommendationReport Plane

## 1. Workspace contract

`/trading/recommendations` 是 report 决策平面的唯一入口：

| Module | 语义 |
|---|---|
| `reports` | report run 与 report ledger |
| `queue` | report/recommendation 对象详情与审阅队列 |
| `funnel` | candidate → eligibility → ranking → TopN 谱系 |
| `diff` | 两个 report 的语义差异 |

Report detail 使用 `entity=report`；单条推荐使用 `entity=recommendation`；report run 使用 `entity=report-run`。不存在独立 resource route。

## 2. Report lifecycle

列表与详情展示 immutable input snapshot、policy/model revision、account truth、coverage、data quality、route readiness、publication delivery 与 lifecycle timeline。撤销状态必须在 banner、timeline、推荐表和 intent containment 上保持一致。

运行报告、重试 publication、retry run 与 revoke 都经过 governed action。WS 事件只使 report store revision 递增，列表随后读取 REST。

## 3. Recommendation evidence

每条 recommendation 至少关联：market identity、outcome side、probability/edge、size、route、entry condition、economic tier、model/factor/calibration/policy evidence。所有 decimal 值保持 string，显示层统一格式化。

从 recommendation 创建 intent 时，服务端再次执行 runtime mode、report status、entry condition 与 admission 验证；前端不能把旧 evidence 解释为仍可执行。

## 4. Funnel 与 diff

Funnel 由后端聚合提供 stage counts、market diagnostics 与 lineage；缺 stage 不是 0，而是明确 unavailable/partial。Diff 绑定两个 report id，对 policy/model/account/candidate/recommendation 变化做结构化展示，不做 JSON 文本 diff。

## 5. 测试闭环

真实 E2E 从 revoked report 读取 recommendations，进入 canonical queue detail，验证 lifecycle containment 与 recommendation evidence。视觉关键态覆盖 report detail、funnel 与 diff；console/pageerror/HTTP/Axe/overflow 均零容忍。
