# 10.4 — Execution Plane

## 1. 唯一业务链

```text
Recommendation
  → OrderIntent
  → Approval
  → Admission
  → Submission / ExecutionOrder
  → Fill
  → Position
  → Reconciliation
  → Settlement
```

Execution Flow Rail 只展示真实外键和 scoped query 得到的链路。Settlement 当前没有 intent 外键时必须明确标为 market-scoped，不得伪造一一归属。

## 2. Orders workspace

`/execution/orders` modules：

- `intents`：全部 intent ledger 与详情。
- `approvals`：同一 ledger 的 `approval_status=pending` 权威视图。
- `orders`：execution order ledger。
- `flow`：八阶段相关性、状态、duration、count 与 Object Inspector。

Intent approve/reject/cancel 和 submission 都由服务端 eligibility 决定并经过 governed action。被 report revoke containment 失效的 intent 不展示 approve/cancel/submit。

## 3. Portfolio workspace

`account` 读取真实 CLOB collateral 与 Data API positions；`positions` 是持久 position ledger；`exposure` 展示聚合风险；`equity` 展示权威 equity snapshots。四个 module 不再复用同一完整页面伪装成不同功能。

## 4. Post-Trade workspace

`reconciliation` 默认展示 unresolved queue，可切换 resolved/all。解决动作记录 governed receipt，并通过 WS hint 刷新权威列表。

`settlement` 展示 readiness 与 redeem ledger；`actions` 展示 governed action queue。Settlement write policy 默认 disabled，ManualOnly inventory 只给出人工退出语义；系统 redemption/canary/operator approval 必须由服务端 preflight 和 policy 双重允许。

## 5. 安全不变量

- `report_only` 不签名、不提交，但仍读取真实资金账户。
- 缺 credential、kill-switch 非 running、approval/admission 失败、sequence/persistence 异常都 fail closed。
- E2E deterministic adapter 不触发真实签名或真实下单。
- position、reconciliation、settlement detail 都使用 canonical `entity` + `id` deep link。
