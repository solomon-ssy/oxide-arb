# 10.4 — Execution Plane

> 父：[`README.md`](README.md) · 依赖：[`10.3-report-plane.md`](10.3-report-plane.md)
>
> 闭环定位：**Intent -> ledger 执行闭环**。完整闭合
> `OrderIntent -> ExecutionOrder -> Position -> Reconciliation -> SettlementRedeem` 前端观测与
> governed mutation 路径。

## 1. 目标与闭环定位

交付执行平面六块 UI + governed UX 标准：

1. **Intents 审批台**：queue + ledger + approve/reject/cancel/submit。
2. **Execution Orders**：venue submission 只读 ledger。
3. **Positions**：system lot ledger 只读。
4. **Reconciliations**：队列 + governed resolve。
5. **Settlement Redeems**：worker 输出只读。
6. **Governed Mutation UX 标准**：全站 mutation modal 规范。

本子phase完成后，operator 可追踪真实执行全链路；与 Phase 05 后端 execution API 对齐。

## 3. 契约与模块设计

### 3.1 Intents 审批台

**双视图：**

| 视图 | 用途 |
|---|---|
| Queue | pending approval、approved waiting submit、submitted、terminal 快捷过滤 |
| Ledger | 全量：status、approval_status、runtime_mode、recommendation_id、time range |

**10.3 handoff（本 phase 必须接上）：**

- 10.3 的 create-intent 成功后跳转 `/quant/intents` 列表（intent 详情深链尚未存在）。
  本 phase 需新增 **`/quant/intents/:id` 全屏详情路由**（同 `page_hidden` seed 模式，`menus.rs`
  + `menu-seed-paths.test.ts` 同步），并把 10.3
  [`use-create-intent-action.ts`](../../../../ui/apps/web-antdv-next/src/views/quant/recommendations/modules/use-create-intent-action.ts)
  成功后的 `router.push('/quant/intents')` 改为跳转到新建 intent 的详情。
- Attribution 只读闭环：本 phase execution/settlement 结算后触发盘后标注 worker 写入 WORM 归因行；
  10.3 recommendation drawer 的 attribution tab 即从"等待盘后归因"empty 转为展示实数据（前端无需改动）。

**Detail drawer / 全屏详情：**

entry_order、exit_policy、risk_envelope_hash、policy_id/hash、admission_trace_ref、status_reason、approval info、关联 execution orders 链接。

**Governed actions：**

| Action | Permission | Pre-submit checks |
|---|---|---|
| Create | `order_intent:create` | 通常从 recommendation drawer；页面内 recommendation_id driven |
| Approve | `order_intent:approve` | — |
| Reject | `order_intent:reject` | — |
| Cancel | `order_intent:cancel` | — |
| Submit | `order_intent:submit` | 展示 kill-switch / mode / account freshness |

**WS：** `quant.intent` → queue + detail refresh。

**Terminal intent：** 不展示非法动作（FSM-aware action bar）。

### 3.2 Execution Orders

**表格列：**

execution_order_id、intent_id、phase、market、token、side、type、price、shares、cost、venue_order_id、venue_status、state、submitted/filled/cancelled/error。

**Detail drawer：** venue payload refs、错误上下文、关联 intent 链接。

**只读：** 无 cancel/submit；执行动作回到 intent 页。

### 3.3 Positions

**表格列：**

position_plane、position_id、intent_id、market、token、state、shares、avg_price、cost_usd、realized_pnl_usd、opened/closed。

**Detail drawer：** lot lifecycle、相关 orders、attribution link。

**交叉链接：** market、intent、execution order 页面互跳。

**不复用**旧 risk positions；realized PnL 来自 position/attribution API。

### 3.4 Reconciliations

**队列筛选：** unresolved、state conflict、data mismatch、recovery required。

**Detail：** evidence chain、related order/position/intent、detected_at、suggested resolution。

**唯一 mutation：**

- `POST /api/quant/reconciliations/{id}/resolve`
- Permission：`reconciliation:resolve`
- Governed modal：reason、resolution、evidence note
- 成功后刷新 related order/recovery state

### 3.5 Settlement Redeems

**Batch table：** batch id、status、market count、lot count、submitted/confirmed/failed、created_at。

**Detail drawer：** lots、tx/venue refs、失败原因。

**只读 worker 输出** — 无前端 mutation。

### 3.6 Governed Mutation UX 标准（全站）

适用 mutation：

- report run/revoke（10.3）
- market subscribe/unsubscribe/block/unblock（10.2）
- intent create/approve/reject/cancel/submit（本 phase）
- reconciliation resolve（本 phase）
- runtime-config create/activate/rollback（10.5）
- system mode/kill-switch/halt/resume/emergency（10.2/10.5）

**Modal 要求：**

| 要素 | 规则 |
|---|---|
| Acting role | 必填，下拉或输入 |
| Reason | 必填 |
| 高风险确认 | halt/emergency/rollback 等需危险确认词 |
| Body | resource id、当前状态、目标状态、资金/执行影响摘要 |
| 错误 | 409/403/422 展示后端 detail，禁止通用 toast |

**实现：** 统一 `governed-action-modal.vue` + `use-governed-action.ts`，各页面只传 config。

## 5. 生产不变量与 UX 语义

1. **OrderIntent 是唯一执行入口：** UI 不提供 skip-intent 下单。
2. **semi_auto 必须审批：** approve 按钮 gated by `order_intent:approve`。
3. **Ledger 只读页无 mutation：** execution orders / positions / settlement redeems。
4. **Admission denial：** 若 backend 返回 admission rejected，detail 展示 trace ref，不 hide。
