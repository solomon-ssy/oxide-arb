> **Lifecycle contract**
> - `lifecycle_assumption`: 项目尚未正式生产上线，当前状态为 `pre_production_resettable`，系统自有基线统一为 `boot` / schema version `1`。
> - `schema_data_version_impact`: 本文中的历史版本号与递增路径不再具有实施效力；当前实现不迁移测试数据、旧结构或旧版本。
> - `pre_production_behavior`: 允许 clean-break、migration squash 与全新基础设施 bootstrap，但任何数据销毁仍需操作者单独授权。
> - `production_frozen_behavior`: 一旦完成不可逆 production seal，后续变更必须提供前向 migration、兼容性评估、回滚方案与数据验证。
> - `rollback_and_data_verification`: 封存前通过清空后的 fresh-install 验证；封存后不得回退到 boot reset。

## 0. 实施状态与决策记录（已落地）

本子phase已落地并通过质量门禁（前端 typecheck/build/unit/lint 全绿；后端
fmt/clippy/architecture/boundary/errors + models/repository/web/core 单测全绿）。落地过程中确认的关键设计决策：

| 决策 | 结论 | 理由 |
|---|---|---|
| Governed mutation 额外字段 | **扩展统一** `governed-action-modal` 支持 typed field schema（`shares/price/usd/text/select`，`decimal.js` 校验，值经 `ctx.fields` 透传） | 全站单一 modal 复用；approve override 与 reconciliation resolve 共用，避免两步弹窗。纯校验逻辑抽到 [`governed-field.ts`](../../../../ui/apps/web-antdv-next/src/shared/composables/governed-field.ts) 便于单测 |
| 详情形态 | **Intent = 全屏路由 + drawer**；execution-orders / positions / reconciliations / settlement-redeems = **drawer 详情 + URL query 过滤/`?open=<id>` 深链** | 不滥增 `page_hidden` 路由；跨页跳转靠 query（如 `execution-orders?order_intent_id=`），保持单一 detail 组件 |
| Approve override | **历史契约，已被 11.7 删除** | 当前使用 tagged `override_amount` + side-aware `override_price`，审批即 Arm，无 submit action |
| Settlement `lot_count` | **后端破坏式新增** `SettlementRedeemView.lot_count`（读端 `SettlementRedeemSummary` 聚合 + 分组 `COUNT`） | 每 batch 单一 market，"market count" 恒为 1；lot_count 让列表可解释批次规模，无需逐条打开详情 |
| Reconciliation `suggested_resolution` | **放弃** | 不硬造后端启发式建议（误导+风控敏感）；UI 用 evidence chain + `venue_filled_shares/avg_price/discrepancy_usd` + 关联实体让 operator 自判 |
| Intent FSM 合法性 | 集中于 [`intent-fsm.ts`](../../../../ui/packages/types/src/intent-fsm.ts) 纯谓词，byte 对齐后端 `intent_service`/`ensure_submittable` guard | terminal 不显示非法动作；`admission_pending` 为 dispatcher-owned 瞬态，无 operator 动作 |
| Submit 结果语义 | 200→execution order；409（admission deny，展示 `admission_trace_ref`）；503（deferred） | 全部经 governed modal `showApiError` 原样透传后端 detail，不吞 |

新增 `page_hidden` 路由：`/quant/intents/:id` → `quant/intents/detail/index`（`menus.rs` +
`menu-seed-paths.test.ts` 已同步）。10.3 create-intent 成功后跳转已改为该详情深链。

### 0.1 收尾优化决策记录（本轮）

在初版落地基础上，按生产级最佳实践补齐执行平面的治理、导航与实时闭环：

| 决策 | 结论 | 理由 |
|---|---|---|
| Submit 治理对标 create-intent | 新增纯函数 [`submit-intent-gate.ts`](../../../../ui/packages/types/src/submit-intent-gate.ts)（permission × 状态 × mode × kill-switch × recovery × expiry），detail 页 Submit 按钮 disabled + tooltip 解释首个阻塞原因；modal 内展示 live account `fetched_at` 新鲜度 | 与 10.3 create gate 同级；account 不做武断阈值 gate，凭证不可用时后端 fail-closed（503/409）透传 |
| Intent FSM submit 语义修正（破坏式） | `intent-fsm.ts` 移除 `intentActions.canSubmit`，改 `intentSubmitAllowed(status, mode)`：`semi_auto→approved`、`auto_execution→approved_by_policy`、`report_only` 恒 false | 修正原 mode 无关 `canSubmit` 与后端 `RuntimeModeCheck` 的语义偏差（实质 bug） |
| Intent 生命周期 WS（破坏式扩展） | `IntentEventKind` 增 `Submitted/AdmissionRejected/PartiallyFilled/Filled/Failed`；集中 [`IntentLifecyclePublisher`](../../../../crates/quant-pivot-core/src/execution/intent_lifecycle.rs) 在 intent_service / dispatcher / reconciliation 的 status 落库点统一发布 | 关闭「submit 后 ledger 无 WS 刷新」缺口，多 operator 场景实时收敛；repo 不发 WS（事务提交后由 core 服务发布） |
| Queue 分诊 + approval 过滤（破坏式扩展 query） | `OrderIntentListQuery` 增 `statuses`（CSV 多状态）+ `approval_status`；queue 预设 pending / awaiting-submit（approved+approved_by_policy）/ in-flight / terminal | serde_urlencoded 无法解析重复 key，故 `statuses` 用 CSV + 自定义 deserializer；`statuses` present 时覆盖单 `status` |
| Position → Attribution 深链（破坏式 DTO） | `PositionView` 增 `recommendation_id`（读端 `PositionSummary` 聚合 + 批量 join）；position drawer 直链 `/quant/recommendations/:id?tab=attribution` | 免去 position → intent → recommendation 多跳；recommendation detail 支持 `?tab=` 深链预选 |
| 列表跨页导航 | 新增共享 `CellEntityRoute` vxe 渲染器，intents/execution-orders/positions/reconciliations 列表 ID 列可点直达；submit 成功深链 `execution-orders?open=<id>` | 列表即可追链，不必逐行开 drawer |
| 深链响应式 | 新增 [`use-route-query-sync.ts`](../../../../ui/apps/web-antdv-next/src/shared/composables/use-route-query-sync.ts) 的 `useQueryOpenDrawer`，`?open=` 用 `watch(immediate)` 驱动（替换 setup 快照 + onMounted） | 客户端路由复用组件实例时 `?open=` 变更也能重开 drawer |
| Intent 全屏详情错误态 | discriminated `LoadState`（loading/ready/not_found/error）：404 → Empty，其余 → Alert + 后端 detail + 重试 | 不再把网络/500 伪装成 not-found |

### 0.2 收尾优化第二轮（已落地）

| 决策 | 结论 | 理由 |
|---|---|---|
| 执行平面上下文入链 | 共享 [`execution-plane.ts`](../../../../ui/apps/web-antdv-next/src/shared/routes/execution-plane.ts)；submit modal recovery 行、`GovernedDetailRow.routeTo`、EO error drawer、position closed/settled drawer 深链 reconciliation / settlement 队列 | 闭环叙事不再依赖侧栏菜单偶然发现 |

| 列表列与深链补齐 | EO：`token_id`/`venue_status` + `execution_order_id` `CellEntityRoute`；Position：`position_plane`/`token_id` + `position_id` 深链；Settlement：batch `?open=` + lot `position_id` 深链 | 列表扫视与跨页追链一致 |


交付执行平面六块 UI + governed UX 标准：

1. **Intents 审批台**：queue + ledger + approve/reject/cancel/submit。
2. **Execution Orders**：venue submission 只读 ledger。
3. **Positions**：system lot ledger 只读。
4. **Reconciliations**：队列 + governed resolve。
5. **Settlement Redeems**：worker 输出只读。
6. **Governed Mutation UX 标准**：全站 mutation modal 规范。

本子phase完成后，operator 可追踪真实执行全链路；与 Phase 05 后端 execution API 对齐。

## 3. 契约与模块设计

### 3.1 Intents 审批台

**双视图：**

| 视图 | 用途 |
|---|---|
| Queue | pending approval、approved waiting submit、submitted、terminal 快捷过滤 |
| Ledger | 全量：status、approval_status、runtime_mode、recommendation_id、time range |

**10.3 handoff（本 phase 必须接上）：**

- 10.3 的 create-intent 成功后跳转 `/quant/intents` 列表（intent 详情深链尚未存在）。
  本 phase 需新增 **`/quant/intents/:id` 全屏详情路由**（同 `page_hidden` seed 模式，`menus.rs`
  + `menu-seed-paths.test.ts` 同步），并把 10.3
  [`use-create-intent-action.ts`](../../../../ui/apps/web-antdv-next/src/views/quant/recommendations/modules/use-create-intent-action.ts)
  成功后的 `router.push('/quant/intents')` 改为跳转到新建 intent 的详情。
- Attribution 只读闭环：本 phase execution/settlement 结算后触发盘后标注 worker 写入 WORM 归因行；
  10.3 recommendation drawer 的 attribution tab 即从"等待盘后归因"empty 转为展示实数据（前端无需改动）。

**Detail drawer / 全屏详情：**

entry_order、exit_policy、risk_envelope_hash、policy_id/hash、admission_trace_ref、status_reason、approval info、关联 execution orders 链接。

**Governed actions：**

| Action | Permission | Pre-submit checks |
|---|---|---|
| Create | `order_intent:create` | 通常从 recommendation drawer；页面内 recommendation_id driven |
| Approve | `order_intent:approve` | — |
| Reject | `order_intent:reject` | — |
| Cancel | `order_intent:cancel` | — |
| Submit | `order_intent:submit` | 展示 kill-switch / mode / account freshness |

**WS：** `quant.intent` → queue + detail refresh。

**Terminal intent：** 不展示非法动作（FSM-aware action bar）。

### 3.2 Execution Orders

**表格列：**

execution_order_id、intent_id、phase、market、token、side、type、price、shares、cost、venue_order_id、venue_status、state、submitted/filled/cancelled/error。

**Detail drawer：** venue payload refs、错误上下文、关联 intent 链接。

**只读：** 无 cancel/submit；执行动作回到 intent 页。

### 3.3 Positions

**表格列：**

position_plane、position_id、intent_id、market、token、state、shares、avg_price、cost_usd、realized_pnl_usd、opened/closed。

**Detail drawer：** lot lifecycle、相关 orders、attribution link。

**交叉链接：** market、intent、execution order 页面互跳。

**不复用**旧 risk positions；realized PnL 来自 position/attribution API。

### 3.4 Reconciliations

**队列筛选：** unresolved、state conflict、data mismatch、recovery required。

**Detail：** evidence chain、related order/position/intent、detected_at、suggested resolution。

**唯一 mutation：**

- `POST /api/quant/reconciliations/{id}/resolve`
- Permission：`reconciliation:resolve`
- Governed modal：reason、resolution、evidence note
- 成功后刷新 related order/recovery state

### 3.5 Settlement Redeems

**Batch table：** batch id、status、market count、lot count、submitted/confirmed/failed、created_at。

**Detail drawer：** lots、tx/venue refs、失败原因。

**只读 worker 输出** — 无前端 mutation。

### 3.6 Governed Mutation UX 标准（全站）

适用 mutation：

- report run/revoke（10.3）
- market subscribe/unsubscribe/block/unblock（10.2）
- intent create/approve/reject/cancel/submit（本 phase）
- reconciliation resolve（本 phase）
- runtime-config create/activate/rollback（10.5）
- system mode/kill-switch/halt/resume/emergency（10.2/10.5）

**Modal 要求：**

| 要素 | 规则 |
|---|---|
| Acting role | 必填，下拉或输入 |
| Reason | 必填 |
| 高风险确认 | halt/emergency/rollback 等需危险确认词 |
| Body | resource id、当前状态、目标状态、资金/执行影响摘要 |
| 错误 | 409/403/422 展示后端 detail，禁止通用 toast |

**实现：** 统一 `governed-action-modal.vue` + `use-governed-action.ts`，各页面只传 config。

## 5. 生产不变量与 UX 语义

1. **OrderIntent 是唯一执行入口：** UI 不提供 skip-intent 下单。
2. **semi_auto 必须审批：** approve 按钮 gated by `order_intent:approve`。
3. **Ledger 只读页无 mutation：** execution orders / positions / settlement redeems。
4. **Admission denial：** 若 backend 返回 admission rejected，detail 展示 trace ref，不 hide。

## 8. 延后 / 缺口

- **Intent 生命周期 WS 已补齐**：`quant.intent` 现覆盖 submit / admission_rejected /
  partially_filled / filled / failed（见 §0.1），execution-orders / positions / reconciliations
  ledger 经 `orderIntentStore.revision` 实时刷新。
- **Reconciliation / Settlement 专用 WS 通道仍延后**：队列/账本除 `quant.intent` 联动外，
  resolve 成功后走 REST refresh-on-action。专用 `quant.reconciliation` / `quant.settlement`
  通道与 recovery 面板的完整设计**移交 10.5**（见
  [`10.5-research-and-governance.md`](10.5-research-and-governance.md) §3.5 / §8.3）。
- **Exit monitor 实时 UI 不做**：backend exit worker 观测走 system recovery 只读（10.5）。
- **Attribution 编辑不做**：只读 link；盘后归因 worker 已在后端落地，10.3 attribution tab 自动展示实数据。
- **Reconciliation `suggested_resolution` 放弃**：不引入后端启发式建议（见 §0 决策记录）。
- **Settlement venue/on-chain 证据**：`SettlementRedeemInfo` 内部 index-set / balance evidence
  当前不进 HTTP view；如需前端展示，另起后端 view 扩展并回填 10.0 契约。
