# 10.2 — Navigation, Dashboard, Activity & Market Intelligence

## 1. 五域导航

主导航只表达用户任务：Command、Trading、Execution、Research、System。工作区内部以 tabs 表达 module，不把每张事实表提升为菜单项。Command Palette 使用与后端菜单同源的 workspace/module catalog，支持键盘检索和 canonical deep link。

移动端保留 390×844 的完整任务路径；tabs 可滚动，Object Inspector 使用 Drawer，命令与 Activity 入口保持 44px 触达面积。

## 2. Dashboard Command Center

`GET /api/dashboard/overview?window={24h|7d|30d}` 返回单次权威聚合。页面展示：

- runtime mode、kill-switch、数据/研究 readiness 与 primary action authority；
- account、report、execution、runtime activity 的高密度 KPI；
- recommendation orbit、execution lifecycle、exposure/equity 与 attention inbox；
- subsystem failure 的 section-level partial state，不以旧快照掩盖失败。

切换 window 会取消旧请求并以 generation guard 防止慢响应覆盖新状态。WebSocket 只触发协调刷新，不直接覆写 Dashboard DTO。

## 3. Activity Center

Header Drawer 与 `/runtime/activity` 共用 permission-filtered、keyset-paginated API。领域为 research、report、execution、reconciliation、settlement；状态为 running、pending、attention、failed、succeeded、cancelled、skipped。

可用动作来自后端 `available_actions`。取消/重试/解决动作全部经过 governed modal；成功后先使本地 revision 失效，再由 REST 快照确认。Research feedback 重连使用 durable revision cursor。

## 4. Market Intelligence

Modules：

- `overview`：market catalog、状态/category/subscription、block/unblock 治理动作。
- `live`：指定 market 的 metadata、book、microstructure、price/spread/depth/imbalance 与 order book。
- `structure`：neg-risk、trade tape 与 participant concentration 的结构证据。

Market detail 使用 `?module=live&entity=market&id=<market-id>`。Book 可作为唯一跨页热点 payload 缓存；catalog 和 microstructure 仍以 REST 为权威。

## 5. Readiness 与可访问性

Dashboard、Activity 与 Workspace 根节点只在权威数据可用后发布 `data-ui-ready=true`。图表在 ECharts `finished` 后发布 `data-echarts-ready=true`。发布截图前还必须满足 HTTP drain、字体就绪、无 skeleton/spinner/toast、Axe serious/critical 为 0 和无页面级横向 overflow。
