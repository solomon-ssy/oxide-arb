## 1. 目标与闭环定位

交付四类页面 + 导航基础设施：

1. **后端 menu seed 与 locale 同步**：第 10.0 菜单树落地；每个 component 有真实 Vue 文件。
2. **Dashboard → Command Center**：Header 三灯（运行态 + 模式 + 熔断）、WS、latest report、data quality chart、live account、execution pipeline、health、recovery。
3. **Markets 页面**：检索、订阅生命周期、YES/NO book drawer、block/unblock、market-scoped WS。
4. **Account 页面**：live account、venue positions、exposure、equity snapshots、drawdown。

本子phase完成后，operator 登录即有可用首屏；10.3 report 和 10.4 execution 可引用 dashboard 上下文。

## 3. 契约与模块设计

### 3.1 Dashboard（Command Center）

**卡片布局：**

| 卡片 | 数据源 | 跳转 |
|---|---|---|
| Header 运行态灯 | WS `system.status` → `systemStore` | — |
| Header 模式灯 | `systemStore` + governed `POST /system/quant-mode` | Preflight drawer |
| Header 熔断灯 | `systemStore` + governed `POST /system/kill-switch` | — |
| WS status | `store/ws.ts` | — |
| Current report | `GET /api/quant/reports/current?profile_id&kind`；11.8 后按 scope 查询 | `/quant/reports` |
| Data quality | `GET /api/quant/data-quality` | — |
| Live account / equity | `GET /api/quant/account/live`、`equity-snapshots/latest` | `/quant/account` |
| Pending intents / pipeline | `GET /api/quant/intents` 等 | `/quant/intents` 等 |
| Subsystem health | `GET /api/system/health` | — |
| Execution recovery | `GET /api/system/execution-recovery` | — |
| System alerts | WS `system.alert` + REST fallback | — |

**Governed actions（header 状态灯 + dashboard）：**

| Action | Permission | Modal fields |
|---|---|---|
| Run Report | `quant_report:enqueue` | reason, top_n, knowledge_lag_secs |
| Switch Mode | `system:switch_mode` | from/to mode, reason, impact text; preflight drawer on success |
| Halt / Resume / Emergency | `system:halt` / `resume` / `emergency` | reason, confirmation word |

**WS 刷新：**

- `system.status` → refresh mode/kill-switch cards
- `quant.report` → refresh latest report card
- `quant.intent` → refresh pending intents count

### 3.2 Markets 页面

**列表筛选：** keyword、status、category、event_id、subscribed。

**表格列：** question、status、category、YES/NO token、best bid/ask、depth、updated_at、subscribed、resolved。

**Drawer：**

- market identity + metadata
- YES/NO book tabs
- book version / timestamp / last WS update

**Governed actions：**

| Action | Permission | Notes |
|---|---|---|
| Subscribe / Unsubscribe | `market:update` | governed modal |
| Block / Unblock | `market:update` | unblock 必须选择 restore status |

**Market-scoped WS：**

```typescript
// 打开 drawer 时
marketStore.subscribeBook(marketId); // refcount++
// 关闭 drawer 时
marketStore.unsubscribeBook(marketId); // refcount--
// reconnect 后 restore all active subscriptions
```

- `market.book_update` → `marketStore.setBook` → drawer 刷新
- `market.resolved` → list row 标记 resolved

### 3.3 Account 页面

**Sections：**

1. **Live account：** collateral、cash、positions source、credential status、checked_at
2. **Venue positions table：** token、market、shares、avg price、cost、mark value

## 5. 生产不变量与 UX 语义

1. **Credential-gated sizing 文案：** Dashboard/System 必须说明 `report_only` 使用真实 venue account，非 simulation。
2. **Private key / funder 缺失：** 后端报告失败时，dashboard latest report card 显示 fail-closed 原因。
3. **Data quality 仅 snapshot：** 不做趋势图（API gap）。
4. **Governed modal 标准：** acting role + reason；高风险动作危险确认词（与 10.4 §3.6 一致）。
