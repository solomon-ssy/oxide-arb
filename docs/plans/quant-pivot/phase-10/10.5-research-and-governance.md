## 1. 目标与闭环定位

交付四类工作台：

1. **Research Workbench**：operator-driven dataset plan/build、model train、backtest、polling；ID-driven governance。
2. **Runtime Config**：schema-driven form + JSON editor + version activate/rollback。
3. **System Page**：quant mode、kill-switch、deploy config、health、execution recovery。
4. **Operation Log & Admin**：保留 users/roles/menus；menus 防止旧 component path。

本子phase与 10.3/10.4 **可并行**（依赖 10.1 地基 + 10.2 menu seed），不阻塞 report/execution 主路径。

## 3. 契约与模块设计

### 3.1 Research Workbench

**设计原则：** 无 list endpoint → 无 catalog UI。每个操作 operator 根据 ID 追踪。

**Workflow sections：**

| Section | API | 行为 |
|---|---|---|
| Dataset plan | `POST /api/research/training-datasets/plan` | 输入 time window、market filters、feature/factor config；展示 dry plan |
| Dataset build | `POST .../build` | 从 plan 发起 build → dataset id |
| Dataset polling | `GET .../training-datasets/{id}` | 状态轮询 |
| Model train | `POST /api/research/models/train` | dataset id + model spec + reason（governed） |
| Model get | `GET /api/research/models/{id}` | by-id 查询 |
| Backtest | `POST .../models/{id}/backtest` | model id + dataset/window |
| Backtest report | `GET /api/research/backtest-reports/{id}` | polling |
| Comparison | `GET /api/research/comparison-reports/{id}` | by-id only |
| Model/factor governance | publication POSTs | ID-driven publish/rollback/retire governed actions |

**WS：** `materialization.run_update` 仅作刷新提示；最终状态仍 REST polling。

**UX：**

- 长任务 pending 时禁用重复提交
- 输入框保存 last-used id（localStorage 可选，非 catalog）
- 无 model list / dataset list / comparison list 表格

### 3.2 Runtime Config

**内容：**

- schema-driven preference form（`GET /api/runtime-config/schema`）
- advanced JSON editor
- version catalog（`GET /api/runtime-config/versions`）
- activation/rollback lineage
- diff baseline 选择

**Governed actions：**

| Action | Permission |
|---|---|
| Create version | `runtime_config:create` |
| Activate | `runtime_config:activate` |
| Rollback | `runtime_config:rollback` |

**Schema renderer 必须正确处理：**

- `UiText`
- `enum_items`
- `when` conditional fields
- `sensitive` masking
- `money_critical` formatting/validation

**WS：** `config.activated` → refresh current view + toast。

**删除：** v2 compatibility parser、旧 config field 文案。

### 3.3 System Page

**内容：**

| Section | 数据源 |
|---|---|
| Quant mode | `GET/POST /api/system/quant-mode` |
| Kill switch | `GET/POST /api/system/kill-switch` |
| Deploy config | `GET /api/system/deploy-config` |
| Health | `GET /api/system/health` |
| Execution recovery | `GET /api/system/execution-recovery` |
| WS status | `store/ws.ts` |
| Active runtime config | runtime-config active version hint |

**Governed actions：** switch mode、set kill-switch、halt、resume、emergency — 统一 governed modal。

**Recovery：** 只读展示；若 backend 未提供 recovery mutation endpoint，**不在前端伪造**恢复按钮。

**关键文案：**

- `ReportOnly` 必须说明：不是 dry-run，报告 sizing 基于真实 venue account
- credential 缺失导致报告失败 → 明确 fail-closed 说明

### 3.4 Operation Log & Admin

**Operation log：** 唯一通用审计入口（保留现有页）。

**Users / roles：** 保留；权限来自新 RBAC catalog。

**Menus 编辑器：**

- 展示新 component path 与 permission catalog
- **防止**选择已删除 component path（opportunities/trades/…）
- validation：component 必须在 allowlist（10.0 菜单树）

**删除：** 旧 opportunity audit 页面；recommendation evidence 只在 recommendation drawer（10.3）。

## 5. 生产不变量与 UX 语义

1. **Research 不造假 catalog：** API gap 是设计约束，不是临时 TODO。
2. **Governance 与 execution 分离：** runtime-config mutation 不影响 intent 页面逻辑，但 WS 提示 operator。
3. **Admin 防止菜单漂移：** menus 编辑器 validation 与 10.0 seed 同源 allowlist。
4. **Publication 不单独进菜单：** workbench 内 ID-driven action，直到 backend list。
