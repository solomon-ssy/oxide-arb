## 1. 目标与闭环定位

交付三条闭环：

1. **Research Catalog**：datasets / models / backtests / factors 四个分页 catalog 页 +
   详情抽屉 + governed 动作（plan/build/train/backtest/publish/rollback/retire）+
   comparison 深链详情。后端补齐 `GET /research/*` list/detail 端点（不再造伪列表）。
2. **实时 WS 三通道**：`materialization.run_update`、`quant.reconciliation`、`quant.settlement`
   producer 全落地（WsChannel 8→10），前端 store/dispatch/permission/test 同步；WS 只 bump
   revision，列表始终 REST query。
3. **Recovery 收敛 Dashboard**：`ExecutionRecoveryCard` 升级为恢复驾驶舱（`next_steps`
   enum i18n、kill_switch 展示 + 内联 ack、阻塞行深链 reconciliations），**不新增 system 菜单页**。

本子 phase 与 10.3/10.4 并行，不阻塞 report/execution 主路径。

## 3. 契约与模块设计

### 3.1 Research Catalog（后端 read 平面）

单一只读端口 `ResearchCatalogPort`（镜像 `AccountReadPort`/`ExecutionReadPort`），
core 侧 `CoreResearchCatalogPort` 薄委托到 `ResearchBundle` 既有 repo；repo 层新增 `page*`
分页方法（复用 `paginate_mapped` + `PageRequest`）。

新增 HTTP（`/api/research/*`，`Accept-Api-Version: v1`，`Paginated<*View>`）：

| Method | Path | Permission | 视图 |
|---|---|---|---|
| GET | `/research/training-datasets` | `materialization:read` | `TrainingDatasetView` |
| GET | `/research/models` | `materialization:read` | `TrainedModelView` |
| GET | `/research/model-specs` | `materialization:read` | `QuantModelSpecView` |
| GET | `/research/backtest-reports` | `replay:read` | `BacktestReportView` |
| GET | `/research/comparison-reports` | `replay:read` | `ModelComparisonReportView` |
| GET | `/research/factors` + `/research/factors/{id}` | `factor_definition:read` | `FactorDefinitionView` |

`*ListQuery` DTO（`domain/api/*`）：dataset（model_spec_id/status/from/to）、model
（model_spec_id/publication_status/from/to）、model-spec（status）、backtest
（model_version_id/from/to）、comparison（candidate_model_version_id/from/to）、factor
（factor_family/scope/status），均 `#[serde(flatten)] page: PageRequest`。

RBAC：不新增权限码；`READ_RESOURCES` 补 `Replay`（回测/对比 catalog 只读对齐其它研究只读）。

### 3.2 Research Catalog（前端）

复用 execution-plane 的 vxe-grid + `useQueryOpenDrawer`（`?open=<id>` 深链）+
`watch(researchStore.revision)` 范式。

- **Datasets**：toolbar `Plan`（试算 planned_samples）+ `Build`（governed）；行→详情
  （status/coverage/hashes/parquet，非终态轮询）；仅 Ready 行→`Train` 深链
  `/research/models?train=<id>`。
- **Models**：toolbar `Train`（governed，spec/version 选择器）；行动作 `Backtest`/`Publish`/
  `Rollback`/`Retire`（governed，按 publication 状态门控）；行→详情（family-shaped metrics +
  lineage：dataset + 该版本回测列表）。
- **Backtests**：行→详情（rank_ic/hit_rate/coverage、expected-vs-realized、category
  breakdown、pnl simulation、comparison 深链）。
- **Factors**：行动作 `Publish`/`Retire`（governed，按状态门控）；行→详情。
- **Comparison**：hidden route `/research/comparisons/:id`，从 backtest 详情进入。

创建流（plan/build/train/backtest）：表单 modal 收集领域字段 → `useGovernedAction().governed`
补 acting-role + reason → `governedPost`。

### 3.3 实时 WS 三 producer

| 通道 | CoreEvent | 发布点 | 前端消费 |
|---|---|---|---|
| `materialization.run_update` | `MaterializationRun{run_id,kind,status}` | web boundary（build/train/backtest 成功后） | `useResearchStore().bumpRevision` → catalog 重查 |
| `quant.reconciliation` | `Reconciliation{execution_order_id,order_intent_id,result,operator_resolved}` | `ReconciliationService`（reconcile_one/resolve/apply_unresolvable 写后） | `useReconciliationStore().revision` → 队列/recovery/pipeline 重查 |
| `quant.settlement` | `Settlement{settlement_redeem_id,market_id,state}` | `SettlementRedeemService`（mark_submitted/confirm/mark_failed 后） | `useSettlementRedeemStore().revision` → 结算账本重查 |

`WsChannel::ALL` 8→10；`resource()`：reconciliation → `Reconciliation`，settlement →
`SettlementRedeem`。前端 `WS_CHANNELS`/`WS_CHANNEL_PERMISSIONS`/`ws-dispatch` 同步扩展，
`ws-dispatch.test.ts` 覆盖三个新 case。**约束**：WS 只 bump revision，列表始终 REST。

materialization 采用 **web-boundary producer**（build/train/backtest 目前同步执行，HTTP 返回
最终结果）：成功后按视图状态发 `Completed`/`Failed`，供其它 operator 的 open catalog 刷新。
未来若引入异步 job queue，可在服务层补 `Running`/`Queued` 中间态。

### 3.4 Recovery 收敛 Dashboard

`ExecutionRecoveryCard`（首页）升级为恢复驾驶舱：

- `next_steps` 用 `enum.executionRecoveryStep.*` i18n 有序渲染（替换 raw snake_case）。
- 展示 `kill_switch`（state tag + requires_ack）；`requires_ack` 时内联 `Acknowledge` 按钮，
  复用 `useKillSwitchAction().setTo(current, closed)` governed（唯一 ack 路径）。
- 阻塞行深链 `/quant/reconciliations?open=<id>`（唯一解阻塞路径 = reconciliation resolve）。
- 实时：在 reconciliation/settlement store revision + `system.status` bump 时重查；
  `ExecutionPipelineCard` 亦在对应 bump 时重算在途计数。

**不新增 system 菜单/页**（保留 menu seed「无 system」断言）；recovery 无自有 mutation。

**关键文案**：`report_only` 非 dry-run（sizing 基于真实 venue account，缺凭证 fail-closed）—
沿用 10.2 header/dashboard 文案。

## 5. 生产不变量与 UX 语义

1. **不造假 catalog**：catalog 由真实 `GET /research/*` list 端点驱动；无端点即无列表。
2. **WS 只 bump revision**：所有列表刷新走 REST；新通道在类型层/permission map/dispatch/测试同时存在。
3. **Governance 与 execution 分离**：research governed mutation 不影响 intent 页面逻辑。
4. **Recovery 只读**：无自有 mutation，解阻塞唯一路径 = reconciliation resolve + kill-switch ack。
