## 1. 目标与闭环定位（已落地）

单一治理入口 `/runtime-config` 页承载三件事，职责不重叠：

1. **Resource 生命周期**：六类 policy revision + independent review/approve/activate/rollback + typed field diff。
2. **Config workspace（热激活）**：`/system/config/:resource` — 专用 typed editor；不提供 auto activate，
   raw JSON 仅作只读技术详情。
3. **Deploy Config（重启生效）**：`GET /api/system/deploy-config` credential-masked 只读快照，
   页内只读 drawer + restart-bound 横幅。

> **架构决策**：runtime-config 编辑器不寄生在通用 Vben preferences 抽屉；逻辑在 app 的
> `/system/config` 模块。preferences 抽屉仅承载 UI/主题偏好。

## 3. 契约与模块设计（当前实现态）

### 3.1 UiText（双语，locale-map）

后端 `UiText { locales: BTreeMap<String,String> }`，key 为 SPA locale id（`en-US`、`zh-CN`）。
前端 `resolveUiText` 按 `当前 locale → en-US → zh-CN → 首项` 回退。新增语言是数据变更而非 schema 变更。

### 3.2 widget / semantics / UiProps 三职责分离

- `widget`：纯渲染（`decimal_string`/`secret_string`/`integer`/`boolean`/`enum_select`/`enum_set`/
  `string_list`/`enum_decimal_map`/`json_tree`/`schedule_list`）。
- `semantics`：行为/治理语义，`credential` | `empty_means_all` | `governance_critical`。danger 确认由
  `governance_critical` 驱动（curated 集合见 `schema/ui.rs` 的 `.critical()`）。
- `ui_props`（新增）：纯呈现提示 `UiProps { placeholder, prefix, suffix, col_span, read_only }`，
  绝不影响校验与提交值。money/bps/secs/% 字段带单位后缀。

### 3.3 布局树：Section / Field / Union（`when` 条件联动）

- `tree: Vec<SchemaNode>`，顶层为 `Section`；`Section` 可嵌套（如 `execution.exit_monitor` →
  `signal_reinference` / `opportunistic_sell` 子 section；`portfolio` → budget/constraints/sizing/
  optimizer + correlation 子 section）。`Field` 按 path 引用字典条目。
- `Union`（discriminated）：仅渲染 discriminator 命中的 case。**真实消费**：
  `execution.kill_switch.emergency_exit` — discriminator `kind`，`liquidate_all` case 展示
  `max_slippage_bps`，`manual_only` case 为空（滑点上限只对自动平仓有意义）。
- `when`：`FieldWhen { effect: if|require, operator: eq|ne, target_path, value }`，为父 toggle 门控子
  字段可见/必填（bool 或 enum 值）。前端 `field-when.ts` 求值（draft 覆盖 config）。后端只保留真实
  使用的 `if`/`eq` 子集（避免死枚举）；前端引擎实现通用集合，后续扩展无需改前端。
- lint（`preferences_schema_ui_gaps`）强制：每个 schema 叶子在树中出现且仅一次、有 UI 字典条目、
  label/help 双语且 `help != label`；树引用的 path 必须存在于 schema。

### 3.4 Runtime Config 编辑器（`/runtime-config` 页）

- `runtime-config-editor.vue`：加载 `GET /runtime-config/schema` + `GET /runtime-config`，Form /
  Advanced-JSON 两模式。Form 用 `topSections()` + `buildFieldIndex()`。
- **顶层 section 手风琴（自管 DOM + BorderBeam）**：`runtime-config-top-sections.vue` +
  `runtime-config-section-panel.vue` 取代顶层 `Collapse`（`destroy-on-hidden` 已移除，各 section
  `ConfigSectionCard` 常驻挂载，`v-show` 控制 body 可见性）。当前展开 section 由 antdv-next
  `BorderBeam` 装饰边框；流光颜色按状态：`governance_critical` → warning 渐变、`dirty` →
  processing 渐变、默认 → primary 渐变（Tag 仍承担业务状态语义）。嵌套 collapsible section 仍用
  `config-node-children.vue` 内 `Collapse`，不加 Beam。
- **切换守卫**：离开 dirty section 时 `Modal.confirm`；确认后切换并保留草稿。
- **展开记忆**：`localStorage` key `runtime-config-editor.active-section`。
- `config-section-card.vue`：每个顶层 section 一张 governed 卡片（per-section draft + zod 校验 +
  `field-when`/union 可见性 + diff 预览 + governance-critical ack），产出 sparse `config_patch`。
- `config-node.vue`：递归渲染 `Section`（嵌套卡片）/`Field`（`runtime-config-field.vue`，含 UiProps）/
  `Union`（按 discriminator 选 case）。
- Apply：`useGovernedAction` → `POST /runtime-config/versions`(patch|json) → `POST .../activate`。
  部分失败（created 但 activate 失败）捕获 version id，页内 Alert + 「查看版本」直达 detail。
- WS `config.activated` 经 `systemStore.activeConfigVersion` 触发 editor + grid 重载。

### 3.5 结构化 report schedules（`schedule_list`）+ cron 预览

- `runtime-config-schedule-list-field.vue`：行式增删 `ReportScheduleConfig`（`schedule_id` 非空且
  唯一高亮、`enabled` 开关、`top_n`/`knowledge_lag_secs` 数字、cadence 子编辑器）。复用 governed
  create → activate 主流程，无新增写 API。
- `runtime-config-cadence-field.vue`：`interval`/`cron` 二选一（interval → 秒数；cron → 6 段表达式 +
  IANA 时区 Select）。
- `runtime-config-cron-field.vue`：6 段 cron（`秒 分 时 日 月 周`，对齐后端 croner 方言）原始表达式 +
  常用预设按钮；6 段校验。
- **服务端预览**：`POST /api/runtime-config/schedule-preview`（`runtime_config:read`）→
  `SchedulePreviewView { next_fire_times }`。后端 `quant_pivot_models::runtime_config::preview_fire_times`
  用与调度器**同源的 `croner`**（6 段、含 IANA 时区壁钟语义）计算下次 N 次触发，作为「下次运行」权威来源。

### 3.6 Deploy Config 只读

`GET /api/system/deploy-config`（`system:read`）返回 masked 子集（`polymarket`、`market_data`、
`observability`、`db`、`cache`、`keys.private_key_present`、`web`）。页内只读 `JsonEditorShell`(tree)
+ restart-bound 横幅。**故意 omit**：`[quant]`、`[research]`、`[polymarket.relayer]`、
`[market_data.data_api]` —— ops 直读 `config/quant-pivot.toml`，UI 不伪造。

## 4. 生产不变量与 UX 语义

- Deploy config **never** mutable from UI（restart-bound、ops-side TOML + git）。
- Runtime config **never** simulates deploy fields；两套 authority 不混用。
- `report_only` sizing 不被 runtime config UI 误导为 dry-run。
- Governed create/activate/rollback 必须 reason + acting role；`governance_critical` diff 强制
  danger 确认 + ack。sensitive 字段空 patch = 不变（保留已存凭证）。
- schedule-preview 为纯只读 dry-run，绝不触碰运行中调度器；非法 cadence（零间隔/坏 cron/未知时区）→ 400。

## 6. 延后 / 缺口（后续 phase 明确设计）

### 6.1 Config drift 检测（后续 ops 工具）

现状：`GET /system/deploy-config` 反映**运行中进程**的 deploy 配置。

目标设计：`GET /api/system/deploy-config/drift`（`system:read`）比对运行中快照 vs 磁盘
`config/quant-pivot.toml`（+ env 覆盖），返回逐字段 drift 列表（`{ path, running_value, disk_value }`，
credential 字段只报 `changed: bool` 不泄漏值）；页内 deploy section 高亮漂移字段，提示「需重启以对齐」。
纯只读诊断，不提供写入。前置：deploy config loader 暴露「磁盘重载」只读入口（不 apply）。

### 6.2 Union / operator / effect 能力按需扩展

现状：后端只 emit `Union` + `when(if/eq/require)` 的真实使用子集（避免死枚举）；前端 `field-when`
引擎已实现通用 operator（`ne`/未来 `gt`/`in`/…）与 effect。后续若出现真实场景（如「A>0 才显示 B」），
按需在 `schema/ui.rs` emit 新 operator/effect 并补前端分支，保持「emit 即用、无死枚举」。

### 6.3 永久非目标

- Deploy config 全量 TOML 树 UI 编辑器 —— ops 用文件 + git，不做。
- `[quant]` / `[research]` deploy 字段前端展示 —— API 故意 omit，ops 直读 TOML。

### 6.4 Section 导航与编辑器深链

- URL：`/runtime-config?editor=1&section=execution`（`section` 为顶层 `SchemaSection.id`）。
- 打开 EditorDrawer 时解析 query，设置 `activeSectionKey`；无效 id fallback 首 section。
- 与 version deep-link（`?version_id=`）正交；与 `localStorage` 展开记忆冲突时 **query 优先**。

### 6.5 跨 section 草稿治理

- 现状（10.7）：per-section apply；切换 section 保留多 section dirty；离开 dirty section 有
  `Modal.confirm`。
- 目标：editor 工具栏显示「N 个 section 有未保存更改」汇总；关闭 EditorDrawer 时若存在任一
  dirty section → 统一 confirm（放弃关闭 / 继续编辑）。
- 远期（非目标本期）：「全部应用」批量 governed patch —— 需后端评估 patch 合并顺序、
  applicator 原子性与部分失败语义。

### 6.6 Section 内搜索 / Command Palette

- 快捷键 `Ctrl+K` / `⌘K`：按 schema `tree` + `fields` 索引 section/field 标签与 path。
- 选择结果：展开目标顶层 section、滚动到 field DOM（`data-field-path`）、短暂高亮 field shell
  （非 BorderBeam）。
- 与 WS `config.activated` 重载后的 `localStorage` section 记忆协同。
