# 10.7 — Runtime Config Console and Deploy Readiness

<!-- quant-pivot-deployment-contract:v2 -->
> **Clean-break contract**：六类 Runtime resource、单文件 Deploy loader 与 typed Config Console 是唯一有效
> 契约。旧 `operational_control`、`execution_authorization`、递归 JSON Schema editor、`--config-dir`、local
> overlay、default-fill 和 raw Deploy serialization 全部删除。

## 1. Product boundary

`/system/config` 同时展示两种严格隔离的 authority：

1. governed Runtime resources：revisioned、validated、approved、preflighted、CAS activated/rolled back；
2. restart-bound Deploy readiness：descriptor 生成的 read-only safe projection。

Web 不编辑 TOML、不显示 secret literal、不执行 migration/reset/cutover。live runtime controls 位于 Config，
但与 revisioned policy 以独立 card/heading/permission/action semantics 呈现。

## 2. Runtime resources

固定资源：

- `recommendation_policy`
- `execution_risk_policy`
- `model_routing`
- `report_schedule`
- `operations_policy`
- `execution_authorization_policy`

每类只接受唯一 clean-install `schema_version = 1`；它仅校验持久化完整性，不提供版本兼容分派。控制面可在六类尚未全部 ready 时启动；report/execution capability fail closed。
不存在历史 payload converter、upgrade draft、version dispatcher 或 compatibility reader；合同变化直接重写唯一 fresh-v1 bootstrap/schema/types。

## 3. Descriptor and validation contract

后端从强类型 resource 生成 field descriptor：

```text
pointer (RFC 6901), title, description, unit, format,
required, default, example, bounds, enum,
control, group, order, risk_level, apply_effect,
readonly, writeonly, visibility_condition, documentation_url
```

每个 editable pointer 必须有唯一 consumer/apply boundary 和唯一 UI control。validation error 统一返回：

```json
{
  "pointer": "/portfolio/tail_risk/cvar_cap_usd",
  "code": "outside_allowed_range",
  "severity": "error",
  "message_parameters": {"minimum": "0.01"},
  "remediation": "Set a positive CVaR cap."
}
```

点分路径、前端无法定位的 free-form message、隐式 `0 = unlimited` 与 serde defaults 禁止。

## 4. Typed editor architecture

删除通用递归 `policy-field.vue` 主路径，建立六个 domain editors：

```text
views/config/editors/
├── recommendation-policy-editor.vue
├── execution-risk-policy-editor.vue
├── model-routing-editor.vue
├── report-schedule-editor.vue
├── operations-policy-editor.vue
└── execution-automation-policy-editor.vue
```

可复用金额、概率、时长、cron、artifact picker、exposure matrix 等原子 control。每个 control 暴露唯一
`data-config-pointer`；component contract test 比较后端 editable descriptor pointer set 与实际 rendered set，
要求双向集合完全相等且无重复。

Resource workspace 必须提供：

- Current 与 Draft 清晰分栏；
- group/unit/risk/apply-effect/help；
- inline error + focusable Error Summary + keyboard jump/return；
- semantic diff、preflight evidence、approval、activation、rollback 与 stale CAS；
- create、approve、activate 是独立 audit actions，无组合快捷操作；
- dirty-leave protection、permission-based readonly、backend recovery；
- pointer/resource-scoped zh-CN i18n key，避免同名 leaf 冲突。

## 5. API

```text
GET  /api/config/resources
GET  /api/config/{resource}/current
GET  /api/config/{resource}/schema
GET  /api/config/{resource}/revisions
POST /api/config/{resource}/drafts
POST /api/config/{resource}/drafts/{id}/validate
POST /api/config/{resource}/drafts/{id}/approve
POST /api/config/{resource}/drafts/{id}/preflight
POST /api/config/{resource}/drafts/{id}/activate
POST /api/config/{resource}/revisions/{id}/rollback
GET  /api/config/activity
GET  /api/config/deployment
```

所有 mutation 携带 actor/RBAC、reason、idempotency key、expected generation/revision/hash。409 stale CAS 保留
用户 draft，展示 server current 与可审阅 diff；禁止 silent replay/overwrite。

## 6. Deploy Config descriptor and loader

Rust type/derive metadata 是 TOML、validator、safe projection、docs 和 CI inventory 的单一来源。每个 leaf 必须
声明 purpose、required/optional、recommended value、type/unit/range/enum、operational impact、restart/apply
semantics、sensitivity/redaction 与 cross-field constraints。

两份 tracked 文件由以下命令生成：

```bash
cargo xtask config render
cargo xtask config audit
```

- 每个 static leaf 在两份文件恰好一次；optional 用 commented assignment；
- tagged union 每个 variant 提供完整互斥 example；dynamic map 每种 supported binding 提供 canonical example；
- production example 不遗漏字段，secret 使用拒绝启动的明确 placeholder；
- render-diff、descriptor/serde path、consumer、comment completeness、duplicate path 进入 CI。

Loader 仅接受 required `--config-file <absolute-path>` 与 required expected environment。单个 explicit file 必须
`deny_unknown_fields`、所有字段 required、无 default/overlay。Unix 通过 `O_NOFOLLOW` 打开后检查同一 fd metadata，
拒绝 symlink、非 regular file、错误 owner/mode；production 仅允许 runtime owner 的 0400/0600。placeholder、空
secret、environment mismatch 一律拒绝。

`SecretText` plaintext-at-rest 模型保持，但必须 zeroize、non-Serialize、redacted Debug/log。开发真实 config 也
必须 0600 且 gitignored；tracked template 不得包含真实 secret。

## 7. Deploy safe projection

`GET /api/config/deployment` 穷尽所有 descriptor leaf：

- public operational value 可显示 typed/redacted summary；
- Secret 仅 `configured`/`missing`；
- sensitive URL/host 只显示 purpose/readiness，不显示 literal、length、source path；
- 每项显示 restart/apply semantics 与 validation readiness。

禁止直接 `Serialize<DeployConfig>` 或基于 denylist 删除敏感字段；projection coverage 必须等于 descriptor set。

## 8. Screenshot and accessibility release gate

Config screenshot states：overview、六 resource Current/Draft/editor、validation、semantic diff、preflight、
approval、activation、rollback、stale CAS、live controls、deployment projection、viewer readonly、backend recovery。

矩阵：390×844、768×1024、1280×720、1440×900；light/dark；zh-CN；fixed timezone/clock/seed/font；
Chromium/Linux；reduced motion/animations disabled。

必须 `expect(page).toHaveScreenshot()`；关键 money/risk/action regions 零像素差，只 mask 已登记的窄范围
`data-screenshot-volatile`。axe critical/serious、keyboard flow/focus order、horizontal overflow、console error/
warning、pageerror、unexpected response/requestfailed 都是硬失败。两个独立 fresh production-stack 全矩阵连续
通过，baseline 变更人工审阅。

## 9. Blockers

- 任一 descriptor pointer 无 consumer/UI control，或 UI control 无 descriptor；
- 任一错误没有 RFC 6901 pointer；
- Runtime 仍含旧 resource/parser/alias；
- Deploy leaf 未出现在任一 TOML、comment 或 safe projection；
- loader 仍接受 directory/default/overlay/relative file/symlink/insecure permissions；
- generic recursive editor 仍是 mutation 主路径；
- screenshot 只 capture 不 compare，或用 mock page 替代真实 production-stack。
