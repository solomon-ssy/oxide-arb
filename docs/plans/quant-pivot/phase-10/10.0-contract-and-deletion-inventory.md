## 1. 目标与闭环定位

交付五类冻结物：

1. **DTO 字段清单**：确认后端 View/Request 与前端 TS type 一一对应；money/price/shares/bps 均为 `string`。
2. **菜单树 + 权限码表**：每个 seed `component` 对应真实 `views/${component}.vue`。
3. **API matrix + governed mutation matrix**：按 domain 命名 API module；标注 POST 是否走 `governedPost`。
4. **WS channel allowlist**：只允许后端已定义 channel；标注 permission、store effect、UI effect。
5. **删除清单 + API gap register**：旧 Endgame 符号全量列出；无 list endpoint 的页面不做伪列表。

本子phase完成后，10.1 可直接按契约建 types/API/store，10.2 可直接同步 menu seed。

## 3. 契约与模块设计

### 3.1 菜单树契约（与 `seed/rbac/menus.rs` v8 冻结一致）

菜单路径为后端 seed 的最终目标。`component` 不带 `views/` 前缀、不带 `.vue` 后缀，且每个 `component` 必须对应真实 `views/${component}.vue`。菜单节点 `name` 全局唯一（`MenuId = uuid_v5(name)`），故每个按钮权限码在整棵树中**只定义一次**（canonical page 下），前端按钮的可见性由该角色的全量 access-code 集判定，与所在页面无关——因此 header 状态灯与 dashboard quick-action 复用 dashboard 节点下已定义的 `system:*` 按钮码。

**关键路径纠偏（相对旧设计草案）：**

- account 在 `/api/quant/account/*`（非 `/api/account`）。
- 创建 intent 是 `POST /api/quant/intents`（body 带 `recommendation_id`），**不存在** `/recommendations/{id}/create-intent`。
- operation-log API 路径为 `/api/operation-logs`（复数）。
- halt/resume/emergency **不是**独立端点：统一 `POST /api/system/kill-switch`（`state` ∈ `closed|report_only_forced|execution_halted|exit_only|emergency_halted`；清除 `emergency_halted` 需 `ack:true`）；recovery 为 `GET /api/system/execution-recovery`。

**Governed mutation 必须包含：**

- report run/revoke
- market block/unblock（subscribe/unsubscribe 为 `market:update` 授权，无 governed body）
- intent create/approve/reject/cancel/submit
- reconciliation resolve
- runtime-config create/activate/rollback
- system quant-mode（`system:switch_mode`）、kill-switch（按 transition 动态判权：收紧=`system:halt`、放松到低 restriction rank=`system:resume`、进入/清除 emergency=`system:emergency`）
- research training-dataset plan/build、model train/backtest、model publish/rollback/retire、factor publish/retire

### 3.3 WebSocket 契约

**Wire envelope（`domain/ws/envelope.rs`）**：server→client 为 `{ "type": <channel|sync|pong|error>, "timestamp": <RFC3339 millis>, "data": <payload> }`——**没有** `channel`/`payload`/`revision` 字段。"revision" 是前端 store 概念（见 §5），不是 wire 字段。client→server 命令按 `action` 标签：`subscribe`/`unsubscribe`/`sync`/`ping`（book 频道带 `market_id`）。

| Channel (`type`) | Permission | Producer 状态 | Store Effect | UI Effect |
|---|---|---|---|---|
| `system.status` | `system:read` | 已实现 | `systemStore.applyStatus` | header/dashboard 刷新；连接时即推一帧 |
| `system.alert` | `system:read` | 已实现 | alert revision | toast/notification |
| `config.activated` | `runtime_config:read` | 已实现 | active config revision | runtime-config/system toast |
| `quant.report` | `quant_report:read` | 已实现 | report revision | reports/latest/dashboard 刷新（子事件在 `data.event`） |
| `quant.intent` | `order_intent:read` | 已实现 | intent revision | intents/dashboard 刷新（子事件在 `data.event`） |
| `market.resolved` | `market:read` | 已实现（10.2：Gamma 落库处 settled 迁移发布） | market revision | markets list 标记 resolved |
| `market.book_update` | `market:read` + market-scoped | 已实现（10.2：coalescer + scoped fanout） | `marketStore.setBook` | market drawer 刷新 book |
| `materialization.run_update` | `materialization:read` | **未 emit（producer 延后，见 §8）** | research revision | workbench polling hint |

- 权限纠偏：`materialization.run_update` 后端已从 `publication:read` 改为 `materialization:read`（`domain/ws/channel.rs`）。
- `sync` snapshot 第一版只消费 `system_status`（`data.system_status`，权限门 `system:read`，无权限时 `data` 为 `{}`）；未来新增 section 必须先补类型和权限。
- 前端契约：把 server frame 按 `{ type, timestamp, data }` 解析；订阅未 emit 的频道（仅剩 `materialization.run_update`）按"占位、不报错"处理，直到 producer 落地。

### 3.4 DTO 基线（TS type 命名）

序列化基线（对照 `quant-pivot-models`，`WebResponse<T>` = `{ code, message, data }`，list 为 `Paginated<TView>`）：

- money/price/shares/bps/probability newtype（`Usd`/`Price`/`Shares`/`Bps`/`Probability`）与裸 `rust_decimal::Decimal` 均序列化为 **JSON string**（`#[serde(transparent)]` + workspace `serde-with-str`）——TS 中一律 `string`。
- UUID id（`RecommendationId` 等）为**连字符 UUID 字符串**；外部 id（`MarketId`/`TokenId`/`EventId`/`OrderId`）为不透明字符串；`ContentHash` = `"blake3:<hex>"`。
- 枚举 wire 名为 snake_case（`#[serde(rename)]`）；`Side` 例外为 `"BUY"`/`"SELL"`。

| 后端 View | 前端 type 文件 | 关键约束 |
|---|---|---|
| `QuantReportView` / `QuantReportDetailView` | `types/quant-report.ts` | decimal 全 `string`；detail 内嵌 `ReportSummary` |
| `QuantRecommendationView` / `QuantEvidenceView` / `RecommendationAttributionView` | `types/quant-recommendation.ts` | entry/sizing/exit/risk plans + eligibility 强类型 |
| `ReportDiffView` / `RecommendationDeltaView` | `types/quant-report.ts` | diff 增量，`Usd` string |
| `OrderIntentView` | `types/order-intent.ts` | lifecycle + approval + `EntryOrderSpec`/`ExitPolicySpec` |
| `ExecutionOrderView` | `types/execution-order.ts` | venue refs、`OrderTypeKind` |
| `PositionView` | `types/position.ts` | `position_plane="system_lot"`，realized PnL `string` |
| `ReconciliationView` | `types/reconciliation.ts` | `evidence_json` chain |
| `SettlementRedeemView` / `SettlementRedeemDetailView` | `types/settlement-redeem.ts` | batch + lots |
| `LiveAccountView` / `AccountSnapshotView` / `EquitySnapshotView` | `types/account.ts` | venue 持仓金额为预格式化 string；`drawdown_pct` string |
| Research：`TrainingDatasetView`/`TrainingDatasetPlanView`/`TrainedModelView`/`BacktestReportView`/`ModelComparisonReportView`/`FactorDefinitionView` | `types/research.ts` | ID-driven，无 list |
| `SystemStatus` / `KillSwitchView` / `QuantModeView` / `ExecutionRecoveryView` | `types/system.ts` | 三态 mode + kill-switch 五态 |
| `DataQualitySnapshot`（注意：非 `*View` 后缀） | `types/data-quality.ts` | 计数快照 |
| WS envelopes | `types/ws.ts` | `{ type, timestamp, data }`；8 channel union |

**运行模式：**

```typescript
type QuantRuntimeMode = 'report_only' | 'semi_auto' | 'auto_execution';
type KillSwitchState = 'closed' | 'report_only_forced' | 'execution_halted' | 'exit_only' | 'emergency_halted';
```

默认 `report_only`；`report_only` 下不允许创建真实执行 intent（以后端 `ExecutionEligibility.eligible_modes` 为准，前端不臆造）。

### 3.5 API Gap Register

| Gap（后端缺 endpoint） | 前端降级 UI 原则 |
|---|---|
| Research 无 model list | workbench 只做 train/get-by-id/backtest/polling |
| Research 无 training dataset list | plan/build/get-by-id，不展示历史列表 |

## 5. 生产不变量与 UX 语义

1. **零兼容**：禁止 re-export shim、旧命名 alias、mock-only 生产页面。
2. **`report_only` ≠ dry-run**：Dashboard/System 文案必须说明 credential-gated real account sizing。
3. **Governed POST**：所有真实资金/模式/kill-switch/config mutation 必须 `reason` + `X-Acting-Role`。
4. **Fail-closed 展示**：409/403/422 必须展示后端 detail，不做通用"操作失败"。
5. **WS revision only**：列表数据永远 REST query，WS 只 bump revision。

## 6. 验收测试

- [ ] 删除清单 grep 规则覆盖旧主路径
- [ ] governed mutation 矩阵完整
- [ ] API gap 每项有降级 UI 原则

## 7. Blocker

- 任一 quant 页面无法映射到 backend endpoint 且未列入 API gap → **Blocker**
