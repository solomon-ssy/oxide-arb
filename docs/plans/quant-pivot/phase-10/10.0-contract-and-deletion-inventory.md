# 10.0 — Canonical Contract & Clean-Break Inventory

## 1. Fresh-boot 硬契约

quant-pivot 尚未生产运行。首次部署只支持空数据库 bootstrap 与 canonical seed：

- 不迁移旧前端 URL、menu id、role-menu、locale、截图或浏览器本地状态。
- 不保留 redirect、alias、deprecated export、forwarding re-export、双写、旧 parser 或 legacy DTO。
- 数据库和缓存从 canonical migration/seed 直接生成当前结构；旧测试 fixture 不能成为运行期兼容理由。
- old URL 必须 404。canonical URL 必须直接渲染业务 workspace，不能经中间资源页转发。

## 2. 路由与菜单契约

可见动态页面恰好为 12 个，路径见 [Phase 10 索引](README.md#2-canonical-页面树)。后端 seed 的每个 `component` 必须存在且只对应一个 workspace 入口；role-menu 与 Casbin permission 必须覆盖同一集合。

详情路由只允许：

```text
/<workspace>?module=<module>&entity=<entity>&id=<canonical-id>
/system/config?module=policy&resource=<config-resource-kind>
```

禁止 `/quant/*`、`/markets`、`/research/model-specs` 等旧 SPA resource route。HTTP API 的 `/api/quant/*` 不属于 SPA 路由，不受此命名约束。

## 3. 语义删除 inventory

静态 inventory 覆盖：

- 旧 resource view 目录、旧 router modules 与空目录。
- `StatCard`、`StateBadge`、`DashboardPanel`、`DetailSectionCard`、`PagePlaceholder` 等被新设计系统取代的组件。
- `tag-options`、旧 dashboard helper、旧 route-time helper 与死 API function。
- `redirect:`、`alias:`、`@vueuse/motion` 和 compatibility barrel。
- 四个旧 E2E script、旧 milestone spec/harness、旧 PNG snapshots 与无引用 docs evidence。

`ui-clean-break-inventory.test.ts` 是路径/符号归零的机器证明；Knip/Vite import graph 负责孤儿模块，locale contract 负责中英文对称与 dead key。

## 4. 枚举契约

Rust enum schema 是 wire value 集合的唯一真理。生成器产出 TypeScript catalog，presentation registry 必须以 `satisfies Record<EnumMemberKey, EnumPresentation>` 穷尽覆盖。

未知值同时触发：

1. danger 描边、警示图标与原始文本；
2. 结构化 `console.error` drift report；
3. enum catalog/locale contract 失败。

## 5. 业务边界

- money/price/shares/bps 保持 decimal string。
- 所有报告使用真实 account truth；凭证缺失时报告生成失败。
- `OrderIntent` 是推荐到执行的唯一桥梁。
- mutation 权限只由服务端决定；UI capability 只改善交互，不构成 AuthZ。
- operation log、governance receipt 与 Activity Center 必须能回到 canonical entity deep link。
