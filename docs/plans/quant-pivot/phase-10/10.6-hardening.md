> - `lifecycle_assumption`: 项目尚未正式生产上线，当前状态为 `pre_production_resettable`，系统自有基线统一为 `boot` / schema version `1`。

## 1. 目标与闭环定位

交付五类收尾物：

1. **Architecture lint**：CI 扫描旧符号，阻止回流。
2. **Unit tests**：WS、menu、governed-action、schema renderer、intent gate。
3. **Playwright E2E**：全菜单可达 + 关键 governed flows + WS reconnect。
4. **Build & quality gates**：typecheck/build/lint/test 全绿。
5. **删除证明**：grep 报告、seed 验证、permission 对照、WS allowlist 测试报告。

本子phase是前端重构的**出口标准**；未通过 Blocker 不得宣称 Phase 10 完成。

## 3. 契约与模块设计

**允许例外：**

- `docs/plans/quant-pivot/` 设计文档中的删除清单描述。
- 测试中显式断言"旧符号不存在"的字符串。

**CI 集成：** 加入 frontend job 或 extend existing lint workflow。

### 3.2 Unit Tests

| 区域 | 覆盖点 |
|---|---|
| WS dispatch | 每个 allowed channel 的 store side effect |
| WS permission | 未授权不订阅；market scoped 不全局订阅 |
| Menu adapter | seed component → view glob 解析 |
| governed-action | acting role/reason/confirmation、错误透传 |
| runtime-config renderer | UiText、enum、when、sensitive、money_critical |
| recommendation intent gate | permission/mode/eligibility/validity/report status |
| 旧 channel | 必须是 reject case |

**原则：** 纯逻辑测试不依赖 backend。

### 3.3 Playwright E2E

| 路径 | 场景 |
|---|---|
| 登录 | 菜单可达（每个 seed component path） |
| RBAC | 无权限按钮不可见 |
| Dashboard | run report governed flow |
| Reports | latest / detail / recommendations / diff |
| Recommendation → intent | 成功 + 409 fail-closed |
| Intents | approve / reject / cancel / submit |
| Ledger | execution orders / positions 只读跳转 |
| Reconciliations | resolve |
| Runtime config | create / activate / rollback |
| System | switch mode / kill-switch |
| WS | 断线 / 重连 / 订阅恢复 / 推送刷新 |

**原则：** E2E 不依赖 mock-only 页面；需要 test backend 或 recorded fixtures。

## 5. 生产不变量与 UX 语义

1. **Lint 是最后一道门：** 10.6 之后任何 PR 引入旧符号必须 fail CI。
2. **E2E 覆盖 governed mutation：** 高风险路径必须有自动化，不能仅 manual。
3. **删除证明可审计：** PR 描述链接 grep 报告，供 release review。

## 6. 验收测试

本子phase **即** 验收测试落地 phase。§4 全部 checklist 为 Phase 10 出口标准。

## 7. Blocker

- architecture lint 未进 CI → **Blocker**
- 任一旧 view 仍可导航 → **Blocker**
- E2E 全 skip 无 documented reason → **Blocker**
- typecheck/build 失败 → **Blocker**
- 删除证明缺 permission catalog 对照 → **Blocker**

## 8. 延后 / 缺口

- Visual regression **不做**（除非团队已有 infra）。
- 100% E2E coverage **非目标**；§3.3 表格路径为最小集。
- Performance/load test **不属于** Phase 10。

### 8.1 后端 WS 闭环收口（backend hardening，纳入本 phase 出口）

对照 10.0 §8.3，本 phase 需完成以下后端 WS 修复并补测试；未完成不得宣称 WS 契约闭环：

- `market.resolved` producer：在市场 resolve 落库处 `events.publish(CoreEvent::MarketResolved { market_id, outcome })`。
- `market.book_update`：spawn `TaskId::BookUpdateCoalescer`（按 `market_id` 节流发布 `MarketBookView`）；修 `SessionRegistry` fanout 对非 always-on 频道用 `SubscriptionKey::scoped` 匹配（当前用 global key，market-scoped 订阅收不到）。
- WS 投递 RBAC 复核：`system.status`/`system.alert` 广播投递前复核 `system:read`（当前仅 subscribe 时校验，投递 fail-open）。
- 防回流 lint 扩展到 Rust：`ResourceType::Analytics|Audit`、`Operation::Reset|Shadow`、`Publication` 的 `Reject|Shadow|Emergency`、菜单 name `quant_report:run|quant_model:*`（见 10.0 §2.4）。

## 9. Phase 10 完成定义（Exit Criteria）

全部满足方可关闭 Phase 10：

1. 10.0–10.5 各子phase Blocker 清零。
2. §4 全部 checklist 勾选。
3. CI 绿（frontend + backend gates）。
4. 删除证明 attach 到合并 PR。
5. [`README.md`](README.md) 子phase索引状态更新为"已落地"（实施完成后由 owner 更新）。
