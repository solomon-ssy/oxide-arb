## 1. 出口标准

Phase 10 hardening 必须同时证明：

1. 旧 Endgame 页面、API、store、wire type、permission 与 WS taxonomy 无生产消费者。
2. backend menu seed 的每个 component 都能映射到真实 Vue 页面，permission catalog 与按钮能力一致。
3. money/Decimal wire value 保持 string；`report_only` 明确使用真实账户，不被表达为 dry-run。
4. governed mutation 的 RBAC、acting role、reason、confirmation、CAS/idempotency 与错误响应完整可见。
5. Config governance 与 protected business flow 在独立 fresh backend 中执行，测试不依赖 mock-only 页面。
6. responsive、theme、keyboard、focus、reduced motion、accessibility 与视觉基线按风险矩阵覆盖。
7. lint、typecheck、unit、production build、dependency、bundle budget 与 Rust backend gates 可从同一 CI 入口复现。

## 2. 防回流与删除证明

architecture/boundary/dead-semantics lint 必须拒绝：

- `Opportunity`、`ScoredOpportunity`、`EndgameDetector` 与旧 Endgame view/API/store；
- `ExecutionMode::{DryRun,Paper,Live}` 和旧 `opportunity:*` / `trade:*` / `risk:*` / `pnl:*` permission；
- 旧 WS channel `opportunity.detected`、`trade.*`、`risk.*`、`pnl.update`、`control.published`；
- `/runtime-config`、旧全局 config-version API、兼容 parser/alias/re-export；
- `DeploySecret`、`SystemdCredentialRef`、runtime/migration 双 DB identity；
- Darwin snapshot suffix、字符串-only scenario manifest 与被 skip 的伪验收。

删除证明由 lint 输出、menu seed test、permission catalog test、WS allowlist test 和 production bundle scan
共同构成，不额外维护容易漂移的手写 deletion report。

## 3. Playwright 风险矩阵

### 3.1 Config governance

`config-governance.spec.ts` 直接注册 24 个可执行 test：

- `CFG-01..22` 覆盖真实资源总览、typed draft、inline validation、immutable diff、approval、consumer
  preflight、CAS activation、双 browser context stale conflict、rollback、artifact picker、schedule preview、
  operational control、deployment redaction、lifecycle/seal confirmation、frozen、viewer RBAC、transient
  recovery 与 execution authorization。
- `X-01` 对所有主页面执行 1024px overflow contract。
- `X-02` 对动画页面执行 reduced-motion contract。

仅 frozen/seal 与瞬时传输失败允许受控 fault injection；对应后端必须有 integration coverage。并发冲突
使用两个真实 browser context，read-only 使用真实 seed viewer，不用 DOM patch 伪造权限。

### 3.2 Protected business flow

`phase-11-7-protected-flow.spec.ts` 覆盖登录/refresh/deep link/404、dashboard operator action、
recommendation executable semantics、intent claim/cancel、trade-policy workbench、model binding、exit monitor、
market funnel 与 report lifecycle。API response、lineage、signature、download、audit 和 lifecycle 断言必须与
页面断言同时存在，截图不能替代业务语义。

### 3.3 视觉与可访问性

- Linux Chromium 是唯一 snapshot 基线，禁止伪装 Darwin suffix。
- 核心页覆盖桌面明暗主题；关键治理页覆盖移动端；所有主页面覆盖 1024 overflow；密集布局覆盖 1280。
- 视觉比较使用稳定业务 evidence region；动态时间/ID 可在截图层屏蔽，但必须保留独立语义断言。
- axe 只是自动化子集；键盘顺序、dialog 初始焦点、错误 summary 聚焦、关闭后焦点恢复、label/description 关联必须显式断言。
- `prefers-reduced-motion` 下移除非必要动画和长 transition，不删除状态反馈。

## 4. Canonical gates

CI 与本地均调用 `scripts/check-production-gates.sh`：

| Group | 内容 |
|---|---|
| `rust-static` | fmt、workspace clippy/tests、architecture/import/boundary/error/dead-semantics/docs/config/persistence/secret lint、dependency 与 feature gates |
| `ui` | Config type sync、lint、circular/dependency、typecheck、unit、production build、bundle/semantic-color gate |
| `network` | bounded provider contract tests |
| `docker` | 完整 Docker integration 连续两次 |
| `protected-e2e` | Config governance 与 protected flow 两个独立 fresh-backend Playwright invocation |

Config activation 会使 frozen execution artifact 失效，因此两个 Playwright suite 禁止共享 backend lifecycle。
CI archive 浏览器 report/test-results，但 archive 本身不能把失败提升为通过。

## 5. 失败与证据规则

- 任一 test 失败时保留首个根因、命令、恢复步骤；不得通过删 test、扩大 snapshot threshold 或 blanket skip 关闭。
- snapshot 只有在 Linux Chromium 容器中重新生成并人工审查后才能更新。
- 运行过的 gate 才能写入 Execution Ledger；旧文档中的历史 test count 不作为当前证据。
- Docker、network、credential 或浏览器环境缺失属于明确 Blocked/未执行，不得写成 passed。
- remote CI 结果、soak、真实 provider、destructive reset 与 seal 必须各自有独立 evidence，不能由本地 unit/E2E 推断。

## 6. 永久非目标

- 状态 × viewport × theme 的全量笛卡尔积；
- 100% E2E 行覆盖率；
- 不稳定 p50/p95/p99 作为 CI hard gate；
- Web destructive reset、secret editor 或 mock-only production page；
- 为未来字段构建无真实 consumer 的通用 schema/rendering DSL。
