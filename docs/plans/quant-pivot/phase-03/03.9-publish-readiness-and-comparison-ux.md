## 1. 目标与闭环定位

`dataset → train → backtest → compare → gate → publish` 的离线闭环在 03.6/03.7
已后端打通，但缺少**决策面**：

- 模型/回测的训练指标与分类拆解以原始 JSON 树呈现，无法快速判断。
- 发布门禁 `QualityGateReport`（hard/soft、observed vs threshold）只在发布尝试
  时计算并落 `quant_model_version.quality_gate_report`，从不外泄到任何 wire
  view，运营只能在点击发布后从 `409 QualityGateFailed` 得知结果。

本子 phase 让门禁**完全可自省**并前移到发布前，让对比报告可读。

## 2. 本期已交付（Phase 03.9）

### 2.1 门禁完全可自省（`quant-pivot-research`）

`DefaultModelQualityGate` 从“只记录 hard_failures / soft_warnings”升级为输出
**完整逐门禁结果**：

```rust
pub enum GateClass { Hard, Soft }
pub enum GateStatus { Pass, Fail, Warn, NotApplicable }
pub struct GateOutcome {
    pub gate: GateId,
    pub class: GateClass,
    pub status: GateStatus,
    pub observed: String,
    pub threshold: String,
    pub detail: String,
}
// QualityGateReport.gates: Vec<GateOutcome>（完整评估集）
// hard_failures / soft_warnings / passed 改为其派生投影
```

- 每个 `evaluate_*` helper 对通过与失败都记录一行；被 intent 跳过的门禁（如
  candidate 下的 shadow / liquidity）记为 `NotApplicable`。
- `report_hash` 仍只对决策投影（`subject, intent, hard_failures, soft_warnings,
  passed`）哈希，完整 `gates` 不入 hash，哈希语义不变。
- `GateId` / `GateClass` / `GateStatus` / `GateIntent` 提供 `wire_name()`（稳定
  snake_case），供跨 crate 映射，无枚举镜像漂移。

### 2.2 共享评估 + dry-run 预览端点

- `ModelGovernanceService::evaluate_gate(version, intent, backtest_report_id?)`
  抽取为 `publish()` 与预览共用的唯一评估路径（shadow 仅在需要它的 intent 拉取）。
- 新增只读 `ModelGovernancePort::preview_gate(...)`（不落库、不改状态）。
- 新增 `GET /research/models/{id}/quality-gate?intent=&backtest_report_id=`
  （`Materialization:Read`），返回 `QualityGateReportView`。
- wire view 只带 `gates`（每项含 `class`/`status`）+ `passed` + 元信息，
  **不重复** hard/soft 数组；research→view 映射在 `quant-pivot-core`（唯一同时
  看到两侧的层），models 不依赖 research。

### 2.3 前端决策面（`web-antdv-next`）

- `research/shared/quality-gate-scorecard.vue`：结论 Alert（ready / warnings /
  blocked）+ 逐门禁行（状态 Tag、observed vs threshold、detail tooltip）+
  `not_applicable` 折叠。单一实现，三处复用。
- 模型详情：顶部“发布就绪”卡（`intent=publish`）；`model-metrics-panel.vue`
  类型化渲染 WeightedFactor / Classical（validation folds、feature importances
  条形），仅**未知 family** 保留原始 JSON 兜底。
- 发布流：`models/index.vue` 发布前 preflight 门禁；hard 失败给出清晰中止并打开
  详情抽屉查看评分卡，soft 警告在治理确认框显式提示。
- 回测详情：`backtest-category-breakdown.vue` 类型化表 + 样本集中度条替换 JSON 树；
  报告级评分卡用 `intent=candidate`（不含 shadow 噪音）。
- 对比详情：并行拉取 baseline/candidate 两份回测报告 → 结论 Alert + delta 统计卡
  + 绝对值并排表 + `category-diff-table.vue`（分类 Rank IC diff + 分歧条）。

## 3. 延后闭环（后续 phase 明确设计）

以下缺口本期不推进，但闭环设计在此定稿，避免遗漏。

### 3.1 门禁历史时间线（承接“不在 View 暴露持久化门禁”的决策）

- 现状：`quant_model_version.quality_gate_report` 每次发布尝试覆盖写入，只保留最新一次；
  就绪度由实时 `preview` 端点提供，列表/详情不暴露持久化标量（避免 stale 误导）。
- 目标：改为**追加式**门禁评估账本 `quant_model_gate_evaluation`（version_id,
  intent, evaluated_at, passed, report_hash, gates_json, actor），
  `GET /research/models/{id}/quality-gate/history` 分页返回；前端在模型详情加
  “门禁历史”时间线（每次尝试的 verdict + 差异）。
- 迁移：`publish()` 落库改为 append；旧单列 `quality_gate_report` 保留为“最近一次”
  冗余或迁移后删除（破坏式，无向前兼容）。

### 3.2 Shadow 监控页

- 现状：`ShadowOverlapStability` 门禁只暴露一个标量 `mean_topn_overlap`。
- 目标：`GET /research/models/{id}/shadow-stability?window=`（复用
  `ShadowComparisonRepository::summary`）返回窗口内 overlap 时间序列 + 样本量 +
  `any_hard_divergence` 标记；前端 shadow 监控页展示趋势折线 + 是否满足
  `required_shadow_window_secs`，直接回答“何时可发布”。

### 3.3 Auto-execution 就绪

- 现状：`preview_gate` 已支持 `intent=auto_execution`（含 `LiquidityExitFeasible`
  硬门禁），但前端未提供入口。
- 目标：模型详情增加“Auto 就绪”标签页（`intent=auto_execution` 评分卡）+ 一个
  “升级到 auto”治理动作（需 `publication:*` 之上的自动执行授权，落 governance audit）。

### 3.4 Promotion 工作流

- 目标：对比详情在“候选优于基线”结论下提供“提升候选”CTA，深链到
  `/research/models?open=<candidate>` 并预填发布 reason（引用 comparison_report_id），
  把“对比 → 发布”串成一步。

### 3.5 Sell-family（exit scorer）门禁

- 现状：通用评分卡已能渲染 `sell_l2_book_fidelity` / `sell_fallback_ratio` 等
  `GateId`（`wire_name` + locale 已就位）。
- 目标：卖出发布路径（06.x）落地时，补 exit scorer 专属的 in-sample/validation
  面板与 sell 阈值对照，无需改评分卡骨架。

### 3.6 hit_rate 阈值治理（一致性 debt）

- 现状：`evaluate_backtest_gates` 的 `HitRate` soft 门禁硬编码 `< 0.5`，而
  `min_rank_ic` / `max_category_concentration` 走治理化 `quality_gate` 阈值。
- 目标：为 `QualityGateConfig` 增 `min_hit_rate`（默认 `0.50`）并接入
  `thresholds_from_config`，消除硬编码；或在文档明确 0.5 为固定语义并移除“可配置”
  预期。二选一在实现前拍板。
