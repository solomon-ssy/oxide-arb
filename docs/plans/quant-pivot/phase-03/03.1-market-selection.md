## 1. 目标与闭环定位

- 实现 `MarketSelector`，按 runtime-config `selection` 段 + 数据质量 + 模型需求
  产出确定性的市场选择快照。
- 用 7 层 filter pipeline 表达过滤，每层产出可统计的排除原因。
- 补齐缺失的 `MarketSelectionRepository` Postgres 实现，持久化快照 + 成员。
- 空选集是正常业务结果，必须带原因，不算系统异常。

输出 `MarketSelectionSnapshot` 后，3.2 `FeatureBuilder` 对每个 included member
构建特征向量。

## 2. 删除清单

- 无旧代码可删（`MarketSelectionRepository` trait 已存在但**无 impl**，本子phase
  补 impl；selector 为净新增）。
- 确认不复用任何 Endgame hotset selection 逻辑——Phase 2 的行情订阅 ingest policy
  只决定**订阅**哪些 book，与本子phase的**研究选择（market selection）**是两件事，
  禁止耦合。

## 3. 新领域类型 / 表 / ClickHouse fact

### 3.1 research 计算类型（`research::selection`）

### 3.2 Postgres

复用既有表 `quant_market_selection` / `quant_market_selection_member`
（Phase 1 已建）。本子phase**补 repo impl**，仅修正一处 schema iden bug（成员表
`Volume24hUsd` 列经 `DeriveIden` snake_case 会生成 `volume24h_usd`，已用
`#[sea_orm(iden = "volume_24h_usd")]` 钉死为规范列名，与 entity/DTO 字段对齐）。映射：

- `MarketSelectionSnapshot` → `NewMarketSelection`（`selector_hash` 存
  `ContentHash` 的字符串、`market_count` = `included.len()`、`exclusion_summary` JSONB）。
- 成员表只存**入选市场**：`SelectedMarket` → `NewMarketSelectionMember`，`reason`
  列写哨兵 `"selected"`；`category` / `status` 由强类型 `Display` 落 `String` 列；
  `event_id` 取自 registry（恒有）。**注意**：snapshot→DTO 映射含强类型→String 落库，
  归属 core/bin 接线层（research crate 不依赖 repository）。
- 排除市场不进成员表，也不再持久化单独 id list；每市场排除原因留在内存快照
  `excluded` 中供报告层解释，durable 聚合使用 `exclusion_summary`。人工禁用通过
  `MarketStatus::ManuallyBlocked` 表达，并由 catalog / operation log 审计。

### 3.3 ClickHouse fact

无。市场选择是 Postgres 权威产物；选择不写 CH（CH 只承载高频/分析事实）。

### 3.4 `MarketCandidate`（models 域中立冻结投影）—— core/research 解耦点

新增 [`MarketCandidate`](../../../crates/quant-pivot-models/src/domain/quant/candidate.rs)
于 `quant-pivot-models`：决策时刻（`as_of`）的市场事实冻结快照，**只承载原始测量**，
所有阈值判定留给 research filter。这样 research 永不依赖 core（倒挂禁止），二者通过
models 中立类型对话。

```rust
pub struct MarketCandidate {
    pub market_id: MarketId,
    pub event_id: EventId,
    pub category: MarketCategory,          // registry CategorySet::fee_category()
    pub status: MarketStatus,
    pub primary_token_id: TokenId,
    pub secondary_token_id: Option<TokenId>,
    pub end_date: Option<DateTime<Utc>>,
    pub liquidity_usd: Option<Usd>,        // Gamma
    pub volume_24h_usd: Option<Usd>,       // Gamma
    pub best_bid: Option<Price>,           // BookStore 实时
    pub best_ask: Option<Price>,
    pub depth_usd: Option<Usd>,            // BookStore bid+ask 总深度
    pub book_age_ms: Option<u64>,          // now - snapshot.timestamp_ms
    pub crossed: bool,
    pub empty: bool,
    pub ingest_lag_ms: u64,                  // IngestPipelineLagTracker::peek_worst_ms
    pub observed_at: DateTime<Utc>,        // = as_of
}
```

core 侧由 [`MarketCandidateProvider`](../../../crates/quant-pivot-core/src/pipeline/market_candidate_provider.rs)
生产：遍历 `registry.active_markets()` → `get_market` 投影元数据；按主 token 从
`BookStore` 取盘口/深度/book age/crossed/empty；`ingest_lag` 取一次平面级值。**一次性快照、
循环内零 DB / 零可变态读取**。

#### Gamma 流动性/成交量真实数据链路（full_populate）

`liquidity_usd` / `volume_24h_usd` 走完整生产链路：Gamma wire DTO 补 `liquidityNum`
/ `volume24hr`（`Option<Decimal>` + `#[serde(default)]`，因部分 payload 缺省）→
`CatalogMarket`（`liquidity_usd: Option<Usd>` / `volume_24h_usd: Usd`）→
`MarketRegistryInfo`（新增 `liquidity_usd`，`volume_24h` 已存在）。两个 Gamma 端点
（`/events/keyset` 全量、`/markets?condition_ids=` 单查）均会在市场有数据时返回这两个
字段；keyset 为部分覆盖（缺省即 `None`，由 fail-closed filter 兜底），condition_ids
则稳定返回。`best_bid/ask/depth_usd` 仍 None——这些是 book 实时权威，投影时取。

### 5.1 Trait（3.1 破坏式改签名）

```rust
pub trait MarketSelector: Send + Sync {
    async fn build_snapshot(
        &self,
        request: MarketSelectionBuildRequest,         // 策略意图（config + 模型需求）
        candidates: Vec<MarketCandidate>,             // 冻结世界事实（models 域）
    ) -> QuantResult<MarketSelectionSnapshot>;
}
```

`build_snapshot` 对 `(request, candidates)` 是 **100% 纯函数**：无 I/O、不读时钟、不读可变运行态。
`candidates` 是 `MarketCandidate` 切片——见 §3.4。

### 5.2 Filter chain（父文档 §2.2，顺序固定）

```rust
pub trait SelectionFilter: Send + Sync {
    fn name(&self) -> &'static str;
    /// 对单个候选市场判定保留或给出排除原因。
    fn evaluate(&self, ctx: &MarketCandidateCtx<'_>) -> FilterOutcome;
}

pub enum FilterOutcome { Keep, Exclude(ExclusionReason) }
```

1. `MarketStatusFilter` —— 只保留 open/active；`ManuallyBlocked` 映射为 operator exclusion。
2. `CategoryFilter` —— `enabled_categories`。
3. `LiquidityFilter` —— `min_liquidity_usd` / `min_volume_24h_usd` / `max_spread_bps`。
4. `DataQualityFilter` —— book age、crossed/empty、ingest pipeline lag（来自
   `MarketCandidateProvider` 冻结的 `ingest_lag_ms`，源头是 `IngestPipelineLagTracker`；
   **不在循环里查 DB**）。
5. `ResolutionAmbiguityFilter` —— `allow_near_resolution` + resolution 时间窗 +
   规则模糊度（本期用 metadata 启发式，外部裁决源延后）。
6. `ModelEligibilityFilter` —— 模型要求的 feature 是否可用（来自
   `ModelFeatureRequirements`）。

`MarketCandidateCtx<'_>` 借用 `&MarketCandidate` + 一次解析好的 `SelectionThresholds`
（把 `DecimalString → Usd`、included override、`max_ingest_lag_ms` 等预解析，
热循环零解析零分配）+ `as_of` + `&ModelFeatureRequirements`。`FilterChain` 短路求值，
首个排除原因即定案，并累加 `SelectionExclusionSummary`（stale/liquidity/operator/other）。
数据输入即 §3.4 的 `Vec<MarketCandidate>`（由 `MarketCandidateProvider` 一次性冻结）；
`max_selection_size` 在 chain 之后按确定性排序（liquidity desc → market_id asc）裁剪。

## 6. 生产不变量与失败语义

- **确定性**：相同 `as_of` + config + 输入快照，必产相同 `selector_hash` 与成员集。
- **空选集正常**：`included` 为空时仍持久化快照，`exclusion_summary` 给出主因；
  下游报告输出空选集原因 `empty_selection`（Phase 04）。
- **无 DB 循环查询**：filter 输入预取为快照。
- **near-resolution 默认排除**（`allow_near_resolution = false`），符合"和钱相关，
  谨慎优先"。
- `max_selection_size` 裁剪用稳定排序（liquidity desc → market_id asc）。

## 9. Blocker

- 若 selector 在 filter 循环内查 DB 或读 `BookStore` mutable 态，本子phase失败。
- 若空选集被当成 error 抛出而非正常快照，本子phase失败。
- 若 selection 逻辑与 ingest/订阅 hotset policy 耦合，本子phase失败。

## 10. 延后 / 缺口

- 规则模糊度的**外部裁决数据源**（垂直数据）延后；本期用 metadata 启发式打分。
- `model_requirements` 的来源（已发布模型的 feature 需求）在 3.4 模型加载后才完整；
  本期接受空需求或测试桩需求（`ModelEligibilityFilter`：空需求全保留；非空因缺
  **每市场 feature 可用性 oracle** 而 fail-closed）。该 oracle 在 03.2 特征面板落地。
- **durable 每市场排除原因审计**延后（本期仅 `exclusion_summary` 聚合 + 内存快照
  `excluded`）。人工禁用不再另建 runtime block list；权威是
  `MarketStatus::ManuallyBlocked` + governed operation log。
- 报告**定时调度 / 触发器**不在本子phase（属 Phase 04）；本期只装配 selector / repo /
  candidate provider 三件套，不加调度。
