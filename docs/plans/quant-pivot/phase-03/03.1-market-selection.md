# 03.1 — Market Selection

> 父：[`README.md`](README.md) · 概念规格：[`../03-data-factor-model-pipeline.md`](../03-data-factor-model-pipeline.md) §2
>
> 闭环定位：**在线闭环第一站**。把"哪些市场进入本轮研究/报告"固化为一个可回放、
> 可解释、可 hash 的 `MarketSelectionSnapshot`。下游 3.2 特征只对选中成员计算。

## 1. 目标与闭环定位

- 实现 `MarketSelector`，按 runtime-config `selection` 段 + 数据质量 + 模型需求
  产出确定性的市场选择快照。
- 用 7 层 filter pipeline 表达过滤，每层产出可统计的排除原因。
- 补齐缺失的 `MarketSelectionRepository` Postgres 实现，持久化快照 + 成员。
- 空选集是正常业务结果，必须带原因，不算系统异常。

输出 `MarketSelectionSnapshot` 后，3.2 `FeatureBuilder` 对每个 included member
构建特征向量。

## 2. 删除清单

- 无旧代码可删（`MarketSelectionRepository` trait 已存在但**无 impl**，本子phase
  补 impl；selector 为净新增）。
- 确认不复用任何 Endgame hotset selection 逻辑——Phase 2 的行情订阅 ingest policy
  只决定**订阅**哪些 book，与本子phase的**研究选择（market selection）**是两件事，
  禁止耦合。

## 3. 新领域类型 / 表 / ClickHouse fact

### 3.1 research 计算类型（`research::selection`）

pub struct MarketSelectionBuildRequest {

### 3.2 Postgres

复用既有表 `quant_market_selection` / `quant_market_selection_member`
（Phase 1 已建）。本子phase**补 repo impl**，不改 schema。映射：

- `MarketSelectionSnapshot` → `NewMarketSelection`（`selector_hash` 存
  `ContentHash` 的字符串、`market_count` = `included.len()`、`included_market_ids` /
  `excluded_market_ids` / `exclusion_summary` JSONB）。
- `SelectedMarket` → `NewMarketSelectionMember`（`category` / `status` 当前为
  `String` 列，写入时由强类型 `MarketCategory` `Display`）。

### 3.3 ClickHouse fact

无。市场选择是 Postgres 权威产物；选择不写 CH（CH 只承载高频/分析事实）。

### 5.2 Filter chain（父文档 §2.2，顺序固定）

```rust
pub trait SelectionFilter: Send + Sync {
    fn name(&self) -> &'static str;
    /// 对单个候选市场判定保留或给出排除原因。
    fn evaluate(&self, ctx: &MarketCandidateCtx<'_>) -> FilterOutcome;
}

pub enum FilterOutcome { Keep, Exclude(ExclusionReason) }
```

1. `MarketStatusFilter` —— 只保留 open/active。
2. `CategoryFilter` —— `enabled_categories`；included/excluded 覆盖。
3. `LiquidityFilter` —— `min_liquidity_usd` / `min_volume_24h_usd` / `max_spread_bps`。
4. `DataQualityFilter` —— book age、crossed/empty、fact lag（来自 `BookDataQualityService` /
   `FactLagTracker` 的 PIT 快照，**不在循环里查 DB**）。
5. `ResolutionAmbiguityFilter` —— `allow_near_resolution` + resolution 时间窗 +
   规则模糊度（本期用 metadata 启发式，外部裁决源延后）。
6. `ManualBlockFilter` —— operator block（`excluded_market_ids` + 运维 block 列表）。
7. `ModelEligibilityFilter` —— 模型要求的 feature 是否可用（来自
   `ModelFeatureRequirements`）。

数据输入来自冻结快照（`MarketRegistry` 当前态 + data-quality 快照），由调用方在
进入 selector 前一次性准备好；`max_selection_size` 在 chain 之后按确定性排序裁剪。

### 5.3 selector hash

```text
selector_hash = blake3_json(canonical {
  as_of_bucket, runtime_config_version_id,
  sorted(enabled_categories), sorted(included), sorted(excluded),
  liquidity/volume/spread/resolution thresholds, max_selection_size,
  sorted(included_market_ids 结果)
})
```

同输入必产同 hash；用于回放与 dedupe。

## 6. 生产不变量与失败语义

- **确定性**：相同 `as_of` + config + 输入快照，必产相同 `selector_hash` 与成员集。
- **空选集正常**：`included` 为空时仍持久化快照，`exclusion_summary` 给出主因；
  下游报告输出空选集原因 `empty_selection`（Phase 04）。
- **无 DB 循环查询**：filter 输入预取为快照。
- **near-resolution 默认排除**（`allow_near_resolution = false`），符合"和钱相关，
  谨慎优先"。
- `max_selection_size` 裁剪用稳定排序（liquidity desc → market_id asc）。

## 8. 验收测试

- `selector_keeps_only_open_markets`。
- `category_filter_respects_enabled_and_overrides`。
- `liquidity_filter_excludes_below_thresholds`。
- `data_quality_filter_excludes_stale_book_and_fact_lag`。
- `manual_block_excludes_listed_market`。
- `model_eligibility_excludes_missing_required_feature`。
- `selector_hash_is_deterministic`。
- `empty_selection_persists_with_reason`。
- `max_selection_size_truncation_is_stable`。
- repo：`create_snapshot_then_find_and_list_members`。

## 9. Blocker

- 若 selector 在 filter 循环内查 DB 或读 `BookStore` mutable 态，本子phase失败。
- 若空选集被当成 error 抛出而非正常快照，本子phase失败。
- 若 selection 逻辑与 ingest/订阅 hotset policy 耦合，本子phase失败。

## 10. 延后 / 缺口

- 规则模糊度的**外部裁决数据源**（垂直数据）延后；本期用 metadata 启发式打分。
- `model_requirements` 的来源（已发布模型的 feature 需求）在 3.4 模型加载后才完整；
  本期接受空需求或测试桩需求。
