# 03.3 — Factor Plane

> 父：[`README.md`](README.md) · 概念规格：[`../03-data-factor-model-pipeline.md`](../03-data-factor-model-pipeline.md) §4
>
> 闭环定位：**在线/离线因子层**。把 `FeatureVector` 经治理的 `FactorDefinition`
> 转成可解释的 `FactorValue`（raw / normalized / confidence / direction /
> explanation / input refs）。因子分**不等于** recommendation 分——必须经 3.4 模型。

## 1. 目标与闭环定位

- `FactorDefinition` registry：稳定 name、family、输入 feature schema、输出类型、
  score direction、normalization、explanation builder、owner、quality gates。
- 实现 9 个通用因子的 `FactorComputer`。
- domain 因子仅注册接口 + by-category registry（additive capability）。
- 每个因子输出 raw / normalized / confidence / direction / explanation / input refs。
- 补 `FactorRepository` PG impl + `quant_factor_event` CH writer。

## 2. 删除清单

- `FactorRepository` trait 已存在但**无 impl**——本子phase补 impl。
- 无旧因子代码可删（净新增）。Endgame 的 `ScoredOpportunity` / detection scoring
  必须保持已删除状态（CI gate 已覆盖）。

## 3. 新领域类型 / 表 / ClickHouse fact

### 3.1 research 计算类型（`research::factors`）

> **契约精炼（落地真理，偏离 3.0 的占位 trait）**：`FactorComputer` 拆成
> **raw / normalize 分离** —— computer 只产 per-market `RawFactor`（无归一、无横截面），
> 归一化（含 cross-sectional ZScore/Rank）由 `FactorEngine` 负责，杜绝"伪横截面"
> blocker。`FactorValue` 仍是最终持久化载体；新增 `RawFactor` /
> `MarketFactorOutcome` / `ScoredFactor` / `FactorEligibility`。

```rust
pub struct FactorName(Cow<'static, str>);    // stable_name! 宏

// 权威定义：quant-pivot-models/src/enums/factor.rs + enums/domain.rs
pub enum FactorFamily { Liquidity, Microstructure, Momentum, MeanReversion,
                        Volatility, Activity, Resolution, DataQuality, Domain(DomainFamily) }
// FactorFamily::as_wire() → "liquidity".."data_quality" / "domain.<vertical>"（append-only 列契约）
// FactorsConfig.enabled_factor_families: Vec<FactorFamily>（仅 generic 变体；Domain 由 category 路由）

pub struct FactorDefinitionSpec {
    pub name: FactorName,
    pub family: FactorFamily,
    pub input_features: Vec<FeatureName>,
    pub output_kind: FactorOutputKind,
    pub default_direction: FactorDirection,
    pub normalization: NormalizationSpec,
    pub owner: String,
    pub quality_gates: Vec<FactorQualityGate>,   // 非空 ⇒ 该因子"必需"（RejectCandidate 口径）
}

pub enum NormalizationSpec {
    ZScore { clamp_sigma: Decimal },             // 横截面：批 mean/std
    MinMax { lo: Decimal, hi: Decimal },         // per-market
    Rank,                                        // 横截面 rank → [0,1]
    Logistic { k: Decimal, x0: Decimal },        // per-market
}   // NormalizationSpec::is_cross_sectional() ⇒ ZScore | Rank

pub struct NormalizationClampAudit { pub method: String, pub raw: Decimal, pub clamped_to: Decimal }
pub struct FactorExplanation {
    pub headline: String,
    pub drivers: Vec<FactorDriver>,              // (feature_name, signed contribution)
    pub clamp: Option<NormalizationClampAudit>,  // 越界 raw 的显式 clamp 审计（禁止静默吞掉）
}

/// computer 的纯 per-market 产物（未归一）。raw_value = None ⇒ 输入缺失（绝不静默 0）。
pub struct RawFactor {
    pub definition_id: FactorDefinitionId, pub name: FactorName, pub family: FactorFamily,
    pub raw_value: Option<Decimal>, pub direction: FactorDirection, pub confidence: Probability,
    pub headline: String, pub drivers: Vec<FactorDriver>, pub input_feature_refs: Vec<FeatureName>,
}

/// FactorValue + transient 打分资格（不持久化，见 §6）。
pub struct ScoredFactor { pub value: FactorValue, pub contributes: bool, pub below_confidence_floor: bool }
pub enum FactorEligibility { Eligible, RejectCandidate { reason: String } }
pub struct MarketFactorOutcome {
    pub market_id: MarketId, pub as_of: DateTime<Utc>,
    pub eligibility: FactorEligibility, pub factors: Vec<ScoredFactor>,
}
```

`FactorValue`（3.0 已定）是输出载体；缺失因子 `raw_value = None`、`confidence = 0`、
`normalized_score` 为中性占位（`weight × score × confidence = 0`，永不贡献），保持持久化行完整可审计。

### 3.2 Postgres

复用 `quant_factor_definition`（治理元数据：`definition_json` 存
`FactorDefinitionSpec` canonical JSON、`input/output_schema_version`、`status`；
definition id 为 **UUIDv5(factor_name)** 确定性铸造，`create_definition` 幂等 upsert）+
`quant_factor_value`（每个因子值一行：`raw_value` / `normalized_score: Probability` /
`direction` / `confidence: Probability` / `explanation: Json`）。

**破坏式 schema 变更（本期）**：`quant_factor_value` 新增 `model_run_id` 列 +
`idx_quant_factor_value_run` 索引（`model_run_id, as_of desc`）。因子值是
factor-set 特定的（同一 feature vector 在 active / shadow 不同 factor set 下产不同因子值），
故以 `model_run_id` 为归属键，与 CH 事实 + `list_values_for_run` 一致。
**本期不加 FK**：`quant_model_run` 行的创建/收尾在 3.4 owns（run id 由线上轮次开始时
铸造、贯穿 feature/factor/CH），3.4 owns run 生命周期时再补 `factor_value.model_run_id`
→ `model_run` 外键。补 `FactorRepository` impl（`create_definition` / `create_values` /
`find_definition` / `list_values_for_run`）。

### 3.3 ClickHouse fact

复用 `QuantFactorEventRow` / `quant_factor_event`。新增 `FactorEventWriter`
（core 侧 over `AsyncWriter<QuantFactorEventRow>`，落 `ChQuantFactRepository::insert_factor_events`）。
**仅 eligible market 的 present 因子值**各一行（rejected market / 缺失因子不投影），含
`model_run_id` 归属（由线上轮次贯穿）、`as_of`、`raw_value: ChDecimal64`、
`normalized_score` / `confidence: ChProbability`、`direction: i8`（`FactorDirection::as_i8`）、
`factor_family`（`FactorFamily::as_wire`）。

## 4. deploy-config key 与 runtime-config v3 path

- 消费 [`FactorsConfig`](../../../crates/quant-pivot-models/src/runtime_config/sections/config.rs)
  ：`enabled_factor_families: Vec<FactorFamily>`、`factor_weights`（name→DecimalString，权重供 3.4 模型，
  非因子计算本身）、`min_factor_confidence`、`missing_factor_policy`。
- factor set 身份 = `enabled_factor_families` 推导 → `FactorSet` → `factor_schema_hash`（content-addressed，无独立 set id）。
- `min_factor_confidence` 决定低 confidence 因子是否参与下游打分；
  `missing_factor_policy`（`ZeroWeight` / `RejectCandidate`）决定缺因子时的处理。
- 无新增 deploy key。

### 5.1 Trait + engine

```rust
pub trait FactorComputer: Send + Sync {
    fn definition_id(&self) -> FactorDefinitionId;
    fn spec(&self) -> &FactorDefinitionSpec;
    /// 纯 per-market raw 计算；缺失输入 ⇒ RawFactor{ raw_value: None }，绝非错误/0。
    fn compute_raw(&self, features: &FeatureVector) -> QuantResult<RawFactor>;
}

pub struct FactorEngine { registry: FactorRegistry }
impl FactorEngine {
    pub fn new(factors: &FactorsConfig, features: &FeaturesConfig) -> Self;  // features 解析窗口因子输入名
    pub fn factor_set(&self) -> FactorSet;
    pub fn factor_schema_hash(&self) -> QuantResult<ContentHash>;
    /// 单市场：任一启用因子为 cross-sectional 即 Err(ResearchError::FactorRequiresBatch)。
    pub fn compute_all(&self, features: &FeatureVector, config: &FactorsConfig)
        -> QuantResult<MarketFactorOutcome>;
    /// 批量：同一 as_of 横截面，cross-sectional 归一在此完成。
    pub fn compute_all_batch(&self, features: &[FeatureVector], config: &FactorsConfig)
        -> QuantResult<Vec<MarketFactorOutcome>>;
}
```

> `Rank` / `ZScore` 横截面归一化只在 batch 接口做（需同一 `as_of` 全选集）。单市场
> 接口遇 cross-sectional 因子返回 typed `FactorRequiresBatch` 错误，而非伪造横截面。

## 6. 生产不变量与失败语义

- **因子分 ≠ recommendation 分**：`FactorValue` 仅是模型输入，禁止直接当推荐分。
- **可解释**：每个因子必产 `explanation`（headline + 带符号 drivers + 可选 clamp 审计）
  与 `input_feature_refs`；报告需同时展示正/负贡献（Phase 04）。
- **confidence floor / 策略归属（transient，不持久化）**：引擎按 `min_factor_confidence`
  + `missing_factor_policy` 产出 per-market `MarketFactorOutcome`：每个 `ScoredFactor`
  带 transient `contributes`（present 且 `confidence >= floor`）/ `below_confidence_floor`；
  market 级 `FactorEligibility`（`ZeroWeight` ⇒ 低 confidence 因子 `contributes=false`、market 仍
  `Eligible`；`RejectCandidate` ⇒ **必需因子**缺失/低于 floor 时 `RejectCandidate{reason}`）。
  这些是会随 config 热更的打分决策，**不写入 `quant_factor_value`**（DB 只存不可变
  `FactorValue` 事实，加权在 3.4）。
  **"必需因子"口径**：`FactorDefinitionSpec.quality_gates` **非空**的因子视为必需
  （本期 generic 集中 `liquidity_depth`、`spread_efficiency` 带 gate）；用 enabled-all 会
  让任意单薄因子拖垮整个 market，违反 additive 哲学。
- **normalization 决定性 + 范围**：`normalized_score` 一律 clamp 进 `Probability`
  合法域 `[0,1]`，clamp 显式记录于 `FactorExplanation.clamp`，禁止静默吞掉异常 raw。
  `f64`（logistic exp / z-score sqrt）一律 `round_dp(12)` 量化后才进 `Probability`，
  对齐 `features::stats` scale，杜绝跨硬件 ULP 漂移。
- **factor schema hash**：`FactorSet` 变更改变 factor_schema_hash（供模型/数据集绑定）。

## 7. 第三方 crate 引入

- base numeric stack（`ndarray` / `ndarray-stats` / `statrs`，03.2 起为 base dep）：
  z-score、rank、分布归一。
- 禁止：polars（因子在单/批 `FeatureVector` 上算，不引 dataframe）、ML 训练 crate。

## 8. 验收测试（含父文档 §23）

- `factor_normalization_clamps_into_probability`。
- `factor_confidence_floor_zero_weights_low_confidence`（`ZeroWeight` 策略）。
- `factor_missing_reject_candidate_policy`（`RejectCandidate` 策略）。
- `factor_explanation_lists_positive_and_negative_drivers`。
- `cross_sectional_rank_requires_batch`。
- `factor_set_change_changes_schema_hash`。
- 9 个通用因子各一个 `*_factor_basic_compute` 单测。
- repo：`create_definition_and_values_then_list_for_run`；CH：`factor_event_writer_batches`。

## 9. Blocker

- 若因子分被当作 recommendation 分直接排序输出（绕过 3.4 模型），本子phase失败。
- 若 `Rank` 类因子在单市场路径产出"伪横截面"分而非要求 batch，本子phase失败。
- 若归一化静默吞掉越界 raw 而不记录，本子phase失败。

## 10. 延后 / 缺口

- **`market.category` 编码归一**（03.2 已交付 `FeatureValue::Category` + 稳定
  `table_index` CH 投影）：因子层负责 one-hot / target encoding / 横截面 dummy 展开；
  **禁止**把 `table_index` 当 ordinal 数值直接进 z-score / rank。generic 因子可
  把 category 作为分组键做横截面归一，但不得静默吞掉缺失类目。
- domain 因子的**真实计算**延后（依赖 3.2 domain feature 的外部数据；03.2 已交付
  `DomainDataMissing` 骨架，见 [`03.x-vertical-domain-design.md`](03.x-vertical-domain-design.md)）。
  本期仅 `DomainFactorComputer` trait（精炼为 `compute_raw`）+ 空的 by-category
  `DomainFactorRegistry`。
- 因子权重的**学习**属于 3.6 trainer；本子phase只消费 config 里的人工权重做联调。
- **`factor_value.model_run_id` → `quant_model_run` 外键**延后到 3.4（owns ModelRun
  create/finalize 生命周期与建行顺序）；本期为带索引的归属列（无 FK）。
- **`contributes` / `FactorEligibility` 的持久化**延后/不做：它们是随 config 热更的
  打分决策（transient），仅作引擎输出喂给 3.4，DB 只存不可变 `FactorValue`。
- 归一化参数（lo/hi/k/x0/sigma）本期为确定性启发式默认；学习/调参在 3.6。
