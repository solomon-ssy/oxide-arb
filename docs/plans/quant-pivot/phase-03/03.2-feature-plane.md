# 03.2 — Feature Plane

> 父：[`README.md`](README.md) · 概念规格：[`../03-data-factor-model-pipeline.md`](../03-data-factor-model-pipeline.md) §3
>
> 闭环定位：**在线/离线特征层**。把 PIT 市场上下文转成 point-in-time 正确、带
> null policy、可 hash 的强类型 `FeatureVector`。线上单市场与离线批量必须共用同一
> 套 feature **定义**。

## 1. 目标与闭环定位

- 建立 feature schema registry：每个 feature 声明完整元数据（§3.2 八要素）。
- 实现通用 feature builder：market metadata / price&book / time-series /
  microstructure；domain builder 仅接口 + schema 骨架。
- null policy 引擎：`reject_market` / `neutral_value` / `penalize` / `domain_missing`，
  **禁止静默填 0**。
- 一套 feature 定义，两个执行后端：线上（live PIT 单市场，来自
  `LiveBookDataSource`）与离线（历史 PIT 批量，3.5 提供，polars materialization）。
- 补 `FeatureRepository` PG impl + `quant_feature_event` ClickHouse writer。
- canonical `feature_hash` + `feature_schema_version`。

## 2. 删除清单

- `FeatureRepository` trait 已存在但**无 impl**——本子phase补 impl。
- `FeatureVectorInfo.payload: Json`（不透明）保留作**持久化投影**，但计算路径不得
  直接消费它——强类型 `FeatureVector`（3.0 定义）是计算真理，`payload` 仅为它的
  canonical JSON 序列化结果。删除任何"直接对 payload JSON 做业务运算"的诱惑（本期
  净新增，无既有违规可删）。
- 无 ClickHouse `quant_feature_event` 生产者（trait 已就绪）——本子phase补生产者。

### 3.2 Null policy（`research::features::null_policy`）

```rust
pub enum NullPolicy { RejectMarket, NeutralValue(Decimal), Penalize, DomainMissing }

pub enum NullDecision {
    Reject(NullReason),                  // market 不进 candidate
    Substitute { value: FeatureValue },  // 中性值替换；置信度惩罚在 3.4 治理
    KeepMissing(NullReason),             // domain_missing：通用模型继续
}
```

引擎依据 `FeatureSpec.null_policy` + `critical` + runtime-config
`features.domain_feature_policy` / `data_quality.feature_staleness_policy` 决策。
**禁止任何隐式 0 填充**：唯一允许的中性值来自 `NullPolicy::NeutralValue(_)` 且必须
记录在 `FeatureValue::Missing → Substitute` 审计里。

### 5.1 FeatureBuilder + 输入

```rust
pub trait FeatureBuilder: Send + Sync {
    fn schema_version(&self) -> SchemaVersion;
    async fn build(&self, input: FeatureBuildInput<'_>) -> QuantResult<FeatureVector>;
}

pub struct FeatureBuildInput<'a> {
    pub market: &'a SelectedMarket,
    pub as_of: DateTime<Utc>,
    pub knowledge_lag: Duration,
    pub required_features: &'a [FeatureName],
    pub pit: PitView<'a>,                 // 线上 or 离线统一视图
    pub config: &'a FeaturesConfig,
    pub data_quality: &'a DataQualityConfig,
}

/// 线上/离线共用的 PIT 视图，屏蔽数据来源差异。
pub enum PitView<'a> {
    Live(&'a dyn PointInTimeDataSource),  // 现有 live 源 (Phase 2)
    Historical(&'a dyn PointInTimeSnapshotSource),   // 3.5 历史源
}
```

`FeaturePipeline` 组合多个 `FeatureBuilder`，合并成单一 `FeatureVector`，跑 null
policy，计算 `feature_hash`，决定 `data_quality`。

### 5.2 Feature 分组（父文档 §3.1）

- **Market metadata**：category、event age、time to resolution、outcome count、
  neg-risk flag、market status、rule ambiguity score。
- **Price & book**：best bid/ask、mid、spread bps、top-N depth、depth imbalance、
  order book slope、visible liquidity、book age、crossed/empty flags。
- **Time-series**：return 1m/5m/15m/1h、realized vol、price reversal、momentum
  decay、volume/spread/depth trend（窗口来自 config）。
- **Microstructure**：quote update rate、book churn、queue depletion、sudden
  liquidity withdrawal、adverse selection proxy、stale quote frequency。
- **Domain（两层向量，见 §5.4）**：仅承载**该 market category 映射到的那一个垂直**的特征
  （由 `DomainFamily::for_category` 决定），由真实 `DomainFeatureBuilder` 计算（Crypto 参考实现
  消费冻结 `MarketLinkage` + domain PIT）；外部数据不可用时输出
  `NullReason::DomainDataMissing`，禁止伪造默认值。非 domain category（Finance/Tech/…）domain
  slice 为**空**。完整闭环见 [`03.8-vertical-domain-closed-loop.md`](03.8-vertical-domain-closed-loop.md)。

时间序列/microstructure 的历史输入：线上来自 `BookStore` 近窗 + CH 近期事实；离线
来自 3.5 历史 PIT。窗口与 `knowledge_lag` 一律按 `as_of` 截断。

### 5.3 线上/离线共用约定

- **定义共用**：`FeatureSchema` + 每个 `FeatureBuilder::build` 的语义在两种
  `PitView` 下完全一致（同一公式、同一 null policy）。
- **执行不同**：离线 materialization 用 `polars` lazy frame 批量算 rolling/window
  特征（`dataframe` feature），但产出必须能逐样本还原为与线上一致的 `FeatureVector`，
  并由验收测试断言一致性。
- **polars 只在离线**：线上热路径不依赖 polars。

### 5.4 两层特征向量（generic slice + category-scoped domain slice）

> **破坏式修订（取代旧"全 5 垂直 Missing"妥协，零兼容已授权）**。完整理由见
> [`03.8-vertical-domain-closed-loop.md`](03.8-vertical-domain-closed-loop.md) §3 D2。

旧做法为保 `feature_hash` 维度恒定，对**每个** market emit 全 5 垂直 `DomainDataMissing`，把"该
category **结构上不适用**该垂直"与"数据源**缺失**"两种语义混淆——和钱相关下危险（无意义 Missing 污染
hash 与训练矩阵）。新做法把 `FeatureVector` 分两层：

- **generic slice**：market-metadata / price&book / time-series / microstructure。category 无关、
  **定宽**、永远存在。
- **domain slice**：仅该 market category 经 `DomainFamily::for_category` 映射到的**那一个**垂直特征集；
  非 domain category domain slice 为**空**。

**复合 `feature_hash`**：

```text
feature_hash = blake3_json(canonical {
  generic_feature_hash,            // generic slice 的稳定 hash
  domain_family: Option<DomainFamily>,  // None = 非 domain category
  domain_feature_hash,             // domain slice 的稳定 hash（domain_family=None ⇒ 空 slice 的恒定 hash）
  generic_schema_version,
  domain_schema_version,
})
```

在 `(generic_schema_version, domain_family, domain_schema_version)` 内布局定序固定 ⇒ hash 决定性；
Decimal 量化继续防 ULP 漂移（§6）。**模型输入契约**：generic 模型只消费 generic slice（domain-family
无关）；category-specific 模型消费 `generic ⊕ 该垂直 domain slice`（[`03.4`](03.4-model-runtime-weighted-scorer.md)
路由）。"不适用"由 `domain_family` 标签表达，彻底消除 5×Missing。

> **与 3.8 的落地关系**：两层向量与复合 hash 的**实现**统一在 [`03.8`](03.8-vertical-domain-closed-loop.md) §6.3
> （W3）；3.5 已交付定宽 `FeatureVector` 与 dataset 产物，3.8 扩展承载 domain slice（§6.6 W6），**不回推 3.5**。

## 6. 生产不变量与失败语义

- **PIT 正确性**：任何 feature 只能读 `published_at <= as_of - knowledge_lag` 的
  事实；历史源越界即返回 `NullReason::SourceUnavailable`，绝不 look-ahead。
- **禁止静默 0**：缺失只能走 null policy 四态之一。
- **critical missing → reject_market**：`required_features` 缺失则该 market 不进
  candidate（`FeatureVector.data_quality = Insufficient`）。
- **feature_hash 决定性（复合，见 §5.4）**：相同输入 → 相同 hash；`generic_schema_version` /
  `domain_schema_version` 任一变更必须改变 hash；同一 `(market, as_of)` 不同 `domain_family` 必产不同
  hash（杜绝跨 category 串味）。`f64` 统计（realized vol）一律在 `features::stats` 量化到固定 Decimal
  scale 后才进入向量，杜绝跨硬件 ULP 漂移破坏 hash 决定性。
- **范围校验**：超 `valid_range` 按 null policy 处理（`OutOfValidRange`），不 clamp
  到静默值。
- **per-feature staleness（本期已强制）**：present 值若其最新输入早于
  `FeatureSpec.staleness_policy` 的界（`MaxBookAge`→`max_book_age_ms`、
  `MaxFeatureBucketAge`→`max_feature_bucket_age_secs`），转 `NullReason::StaleBeyondPolicy` 走 null
  policy（`feature_staleness_policy = AllowDegraded` 时 required/critical 降级而非
  拒绝）。聚合 `DataQualityStatus` 按 book-age 与 feature-bucket-age **两个维度分别**对照各自阈
  值，绝不把 feature-bucket-age 用 book-age 阈值衡量。
- **observed_at 单一真理（本期已强制）**：book 的观测时间唯一来源是 `timestamp_ms`，
  live 与 historical 用同一规则推导 `observed_at`，所以 `book.age_ms`（及 feature
  hash）在线上/离线**由构造即一致**。`BookSnapshotAt` 不再带独立 `observed_at` 字段。

## 9. Blocker

- 若任一 feature 在缺失时静默填 0 / 任意默认值，本子phase失败。
- 若历史路径读取 `as_of` 之后的事实，本子phase失败。
- 若线上/离线 feature 定义分叉（parity 测试失败），本子phase失败。
- 若计算路径直接对 `payload` JSON 做业务运算而非强类型 `FeatureVector`，本子phase失败。

## 10. 延后 / 缺口

- 垂直领域 feature 的**真实外部数据接入 + 两层向量（D2）** → **3.8**（设计与实现见
  [`03.8-vertical-domain-closed-loop.md`](03.8-vertical-domain-closed-loop.md)；3.2 已交付 skeleton +
  `DomainDataMissing` 语义，本子phase scope 不含垂直落地）。
- 离线 materialization 的大规模 polars 性能 spike（父文档 §12.1）在 3.5 数据集
  构建时一并做。
- **每市场 feature 可用性 oracle**（03.1 `ModelEligibilityFilter` 的输入）在本子phase
  落地：特征面板需暴露"某 market 是否具备模型所需 feature"的判定，供 selector 把
  `ModelFeatureRequirements::required_features` 翻译为 `MarketCandidate` 级可用性，
  从而替换 03.1 当前的 fail-closed 占位（非空需求即排除）。
- **Phase 4 定时调度器**（`live_report_inference`）延后；3.2 交付
  [`FeaturePipelineService`](../../../crates/quant-pivot-core/src/service/feature_pipeline.rs) +
  e2e，不含常驻 cron。

### 10.1 schema 已移除的"注册但不可算"特征（依赖未就绪，登记于此）

default schema 移除，待依赖就绪后由对应 phase 重新引入：

- `volume_trend`（成交量趋势时序）：当前 `book_microstructure_1s` fact **无成交量列**，
  需 Phase 2 ingest 给微结构事实增加成交量聚合列后，再在本面板按既有 TS 模式实现。
- tick 级微结构特征 / `SourceRequirement::TickWindow`：需 `tick_events` 窗口 provider
  （与 3.5 历史 PIT 一并设计）；未就绪前不注册该 source。
