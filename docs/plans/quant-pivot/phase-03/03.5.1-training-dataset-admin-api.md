# 03.5.1 — Training Dataset Admin API (UI contract)

**Status:** delivered with Phase 3.5 core  
**Consumers:** Admin SPA (Phase 07), internal ops  
**Replaces:** `quant-pivot-xtask research build-dataset` (removed — UI + API is the product path)

## 1. Purpose

Expose offline training-dataset **plan** and **build** through the existing Admin HTTP
surface so operators never need a CLI. The library implementation remains
`TrainingDatasetService` in `quant-pivot-core`; the web layer is a thin port +
validated DTOs.

## 2. Endpoints

Base prefix: `/api` (v1 guard via `Accept-Api-Version: v1`).

| Method | Path | RBAC | Handler |
|--------|------|------|---------|
| GET | `/research/training-datasets/{id}` | `materialization:read` | Poll ledger row |
| POST | `/research/training-datasets/plan` | `materialization:create` + `X-Acting-Role` | Dry plan (no I/O artifact) |
| POST | `/research/training-datasets/build` | `materialization:create` + `X-Acting-Role` | Plan + Parquet + ledger |

Route module: `quant-pivot-web/src/routes/training_datasets.rs`  
DTOs: `quant-pivot-models/src/domain/api/training_dataset.rs`  
Port: `TrainingDatasetPort` → `CoreTrainingDatasetPort` (`quant-pivot-core`)

### 2.1 Request body (`BuildTrainingDatasetRequest`)

Shared by plan and build. Training PIT/label bounds come from the frozen runtime
config `training` section (`training.max_book_staleness_ms`,
`training.min_exit_depth_usd`), not from the request body.

```json
{
  "model_spec_id": "<uuid>",
  "runtime_config_version_id": "<uuid>",
  "window_start": "2026-01-01T00:00:00Z",
  "window_end": "2026-01-08T00:00:00Z",
  "sample_interval_secs": 3600,
  "horizons_secs": [86400],
  "knowledge_lag_secs": 10,
  "feature_schema_version": 1,
  "reason": "weekly retrain dataset",
  "training_dataset_id": "<uuid from plan response — build only>"
}
```

`reason` is required (audit / operation log). **Build** must include
`training_dataset_id` returned by plan so poll GET targets the same ledger row.
Plan ignores this field (always mints a fresh id).

### 2.2 Plan response (`TrainingDatasetPlanView`)

```json
{
  "training_dataset_id": "<uuid>",
  "model_spec_id": "<uuid>",
  "runtime_config_version_id": "<uuid>",
  "window_start": "...",
  "window_end": "...",
  "planned_samples": 42
}
```

No ledger row is written. UI should block build when `planned_samples == 0`.

### 2.3 Build / poll response (`TrainingDatasetView`)

Returns full ledger projection including `status`, `dataset_hash`, `parquet_uri`,
`sample_count`, and `coverage_json` (build diagnostics).

Terminal statuses for UI gating:

| `status` | UI meaning |
|----------|------------|
| `built` | Artifact persisted; awaiting validation → trainer (03.6) |
| `insufficient_labels` | Artifact persisted but label coverage too thin |
| `failed` | Hard failure persisted to ledger (e.g. zero built examples) |
| `ready` | Passed validation; trainer may consume |
| `expired` | Superseded / TTL |

**Not a ledger status:** future-feature **leakage** aborts the HTTP build with an
error and writes **no** row (fail-closed before Parquet/Postgres).

Poll **GET** until status is terminal. Build is **synchronous** today (HTTP may
block minutes); Phase 03.7 adds async job queue + `materialization.run_update` WS.

## 3. Recommended SPA flow (Phase 07)

1. Runtime-config picker → frozen `runtime_config_version_id`.
2. Model-spec picker → `model_spec_id`.
3. Window + grid controls → map to request fields.
4. **Plan** → show `planned_samples` + pre-assigned `training_dataset_id`.
5. Confirm → **Build** with the same body plus `training_dataset_id` from step 4.
6. Poll **GET** by `training_dataset_id` until terminal status.
7. Link forward to trainer/backtest screens (03.6) when `status == ready`.

## 4. RBAC seed

- `materialization:read` — all built-in roles via `READ_RESOURCES`.
- `materialization:create` — `risk_owner` (same persona as runtime-config promote).

Existing deployments: re-run Casbin seed or grant manually for non-`risk_owner`
research operators.

## 5. Out of scope (later phases)

- List/catalog pagination (`GET /research/training-datasets`)
- Async build job + progress WebSocket (03.7)
- Admin menu seed entry (07 UI)
- Trainer trigger API (03.6)
