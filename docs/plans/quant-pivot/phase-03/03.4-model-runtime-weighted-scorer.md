# 03.4 — Model Runtime & Weighted Scorer

> 父：[`README.md`](README.md) · 概念规格：[`../03-data-factor-model-pipeline.md`](../03-data-factor-model-pipeline.md) §5/§27/§28
>
> 闭环定位：**在线推理闭环收口**。把 `FactorValue` 经统一 `QuantModelRuntime`
> 推成 `SignalCandidate`，并落 `ModelRun` + ClickHouse signal 事实。本子phase完成后，
> `MarketSelection → Feature → Factor → Model → SignalCandidate` 在线链路打通。

## 1. 目标与闭环定位

- 统一推理入口 `QuantModelRuntime` + `ModelRuntimeFactory`（唯一感知 concrete
  artifact 类型处）。
- 主路径 `WeightedFactorRuntime`：受治理的 weighted factor scorer。
- `WeightedFactorModelArtifact` + `ModelArtifact` enum（serde_json/bitcode 序列化 +
  canonical hash）。
- 强类型 `SignalCandidate`（3.0）落地 + `quant_signal_candidate_event` CH writer。
- 补 `ModelRunRepository` PG impl + 按需 ModelRun worker（`run_kind` =
  `live_inference` / `Backtest` / `Shadow` / `Training` 由调用方指定，本期主用前者 +
  ad-hoc）。
- 推理降级策略（父文档 §28）。

## 2. 删除清单

- `ModelRunRepository` trait 已存在但**无 impl**——本子phase补 impl。
- 3.0 已删除 `SignalCandidate` stub；本子phase落地其 CH 映射，确认 stub 不复活。
- `ModelRegistryRepository` 已有 impl（create/publish/retire），本子phase复用，
  不重写。

### 5.1 统一入口（3.0 已定 trait，本期实现 weighted）

```rust
pub trait QuantModelRuntime: Send + Sync {
    fn model_version_id(&self) -> ModelVersionId;
    fn model_family(&self) -> ModelFamily;
    fn feature_schema_hash(&self) -> ContentHash;
    async fn infer_batch(&self, input: ModelRuntimeInput) -> QuantResult<ModelRuntimeOutput>;
}

pub trait ModelRuntimeFactory: Send + Sync {
    async fn load(&self, model_version: &ModelVersionInfo)
        -> QuantResult<Box<dyn QuantModelRuntime>>;
}
```

`ModelRuntimeFactory` 是唯一读 artifact 字节、知道 concrete artifact 类型的地方；
`ModelRunner` / Phase 04 `ReportBuilder` 只依赖 `dyn QuantModelRuntime`。

### 5.2 Weighted scorer 公式（父文档 §5.1）

```text
candidate_score =
  Σ (normalized_factor_i * weight_i * confidence_i)
  * data_quality_multiplier
  * liquidity_multiplier
  * horizon_multiplier
```

实现要点：

- 输入 `ModelRuntimeInput::FactorTable(FactorInferenceTable)`（每 market 的因子向量）。
- `weight_i` 来自冻结 `WeightedFactorModelArtifact.weights`（已发布）或 config
  权重（候选联调）。
- 输出 `composite_score: Probability`、`confidence`、`expected_return_bps`、
  `downside_bps`、`factor_breakdown`（正/负贡献）、`model_explanation`。
- 全程 `Decimal` / `Probability`，**无 f64**。

### 5.3 ModelRunner（在线编排）

```rust
pub struct ModelInferenceRequest {
    pub model: Box<dyn QuantModelRuntime>,
    pub selection: MarketSelectionSnapshot,
    pub features: Vec<FeatureVector>,
    pub factor_values: Vec<Vec<FactorValue>>,
    pub as_of: DateTime<Utc>,
    pub run_kind: ModelRunKind,
}
```

`ModelRunner::infer` 写 `ModelRun`（`input_hash` = hash(selection+features+factors+
model_version)、`output_hash` = hash(candidates)、metrics），并把 SignalCandidate 批量
写 CH。**事务/副作用边界**：ModelRun 状态与 candidates 先落库再写非权威 CH 事实。

### 5.4 推理降级（父文档 §28）

| 失败 | 行为 |
|---|---|
| active weighted model load failed | run 失败，critical alert |
| shadow model failed | active 继续，记录 shadow failed |
| classical shadow failed | active weighted 继续 |
| feature_schema_hash mismatch | 拒绝加载，typed error |
| artifact hash mismatch | 拒绝加载 |

`ModelRuntimeFactory::load` 失败返回 typed error，不 panic。自动执行禁止用
fallback model（除非 fallback 本身是 active published）——本期仅记录约束，执行在
Phase 05/06。

## 6. 生产不变量与失败语义

- **统一入口隔离**：业务层（runner/report）只依赖 `dyn QuantModelRuntime`，永不
  依赖 weighted/classical concrete 类型。
- **schema hash 校验**：runtime 的 `feature_schema_hash` / `factor_schema_hash` 与
  当前 feature/factor schema 不匹配则拒绝推理。
- **artifact 不可变**：已发布 artifact 字节 + hash 固定；权重热更新只对未发布候选生效。
- **ModelRun 必写**：每次在线推理写 `run_kind = live_inference` 的 ModelRun（status /
  input_hash / output_hash / metrics）。
- **无 f64 泄漏**：scorer 全程 Decimal/Probability。

## 9. Blocker

- 若 `ReportBuilder` / runner 出现 weighted/classical concrete 类型依赖，本子phase失败。
- 若在线推理不写 `ModelRun`，本子phase失败。
- 若 scorer 用 f64 表达 money/price/probability，本子phase失败。
- 若 artifact/feature schema hash 不匹配仍加载推理，本子phase失败。

## 10. 延后 / 缺口

- **`ModelFeatureRequirements` 的真实来源**（已发布模型声明的 feature 需求）在本子phase
  随模型加载落地：模型版本元数据给出 `required_features`，注入 03.1
  `MarketSelectionBuildRequest::model_requirements`，驱动 `ModelEligibilityFilter`。
  在此之前 03.1 接受空需求（全保留）或测试桩需求。
- **定时 `live_report_inference` scheduler + TopN 报告生成** → Phase 04；本期只提供
  按需可调用的 `ModelRunner`（report builder 在 Phase 04 复用它）。
- **完整 PortfolioPlanner** → Phase 04；本期 SignalCandidate 止于 `rank_before_portfolio`。
- **classical runtime 实现** → 3.6；本期仅 enum/ factory 分支占位。
- **ONNX runtime** → Phase 06（`ModelRuntimeInput::Onnx` / `ModelArtifact::Onnx`
  保留 arm）。
