# 03.4 — Model Runtime & Weighted Scorer

> 父：[`README.md`](README.md) · 概念规格：[`../03-data-factor-model-pipeline.md`](../03-data-factor-model-pipeline.md) §5/§27/§28
>
> 闭环定位：**在线推理闭环收口**。把 `FactorValue` 经统一 `QuantModelRuntime`
> 推成 `SignalCandidate`，并落 `ModelRun` + ClickHouse signal 事实。本子phase完成后，
> `MarketSelection → Feature → Factor → Model → SignalCandidate` 在线链路打通。

## 1. 目标与闭环定位

- 统一推理入口 `QuantModelRuntime` + `ModelRuntimeFactory`（唯一感知 concrete
  artifact 类型处）。
- 主路径 `WeightedFactorRuntime`：受治理的 weighted factor scorer。
- `WeightedFactorModelArtifact` + `ModelArtifact` enum（serde_json 序列化 +
  canonical hash；**内容寻址** 见 §11）。
- 强类型 `SignalCandidate`（3.0）落地 + `quant_signal_candidate_event` CH writer。
- 补 `ModelRunRepository` PG impl + 按需 ModelRun worker（`run_kind` =
  `live_inference` / `Backtest` / `Shadow` / `Training` 由调用方指定，本期主用前者 +
  ad-hoc）。
- 推理降级策略（父文档 §28）。

### 1.1 落地与文档的关键修正（本期实施决定）

> 本期落地相对原始 §5 草案做了以下**生产级修正**，已在代码中实现，并在此登记。

1. **`ModelRunner` 位于 core，不在 research**。`quant-pivot-research` 只依赖
   `quant-pivot-models`/`quant-pivot-error`，不依赖 repository/core；真正写
   `ModelRun` + CH 事实的编排器只能放
   [`crates/quant-pivot-core/src/service/model_runner.rs`](../../../crates/quant-pivot-core/src/service/model_runner.rs)，
   与 `feature_pipeline.rs` / `factor_pipeline.rs` 一致。research 只保留纯推理
   （`runtime` / `factory` / `weighted` / `artifact` / `signal` 投影 / `degrade`）。
   §5 模块树相应作废。
2. **内容寻址 artifact**：artifact 字节存于 `models/<artifact_hash_hex>.json`，
   URI 是 hash 的纯函数；`quant_model_version` 不新增 `artifact_uri` 列、也不把 URI
   塞进 `metrics_json`。`ArtifactStore` 增加 `get_by_key` / `exists_by_key`。
3. **drop artifact `normalization` 字段**：因子值在 `FactorEngine` 已归一到
   `[0,1]`，`factor_schema_hash` 绑定该契约；weighted artifact 只承载“打分治理”
   （weights + multipliers + return_model + substitution rules），不重复归一化。
4. **`quant_model_run` 生命周期 `audit` → `runtime`**：run 需要
   `Running → Succeeded/Failed` 的 UPDATE 收尾（写 `output_hash`/`metrics`），与
   append-only WORM（`audit`）冲突；改为 `runtime`（可变操作记录）。
5. **`quant_factor_value → quant_model_run` 硬 FK 落地**：因此在线轮次固定顺序为
   selection 落库 → 建 `ModelRun(Running)` → feature 落库 → factor 落库（FK 成立）→
   推理 → 落 candidate / 收尾 run。`ModelRunner` 负责按此顺序编排。
6. **打分语义（见 §5.2 细化）**：composite_score 为 `[0,1]` 纯排序“信念”，
   side 由因子带符号方向净值决定，`expected_return_bps`/`downside_bps` 由 artifact
   内可治理 `ReturnModelSpec`（本期 `Heuristic`，3.6 标定 `Calibrated`）产出，
   provenance 显式标注，绝不臆造。
7. **shadow 本期落地**：独立 `ModelRun(run_kind=Shadow)` + live/shadow diff，shadow
   失败不影响 active（§5.4 降级表）。
8. **`FactorsConfig.factor_weights` 不在 3.4 在线消费**：已发布模型的 scorer 权重
   唯一来源是内容寻址 artifact 内 `WeightedFactorModelArtifact.weights`；
   `ModelRunner` / `WeightedFactorRuntime` **不读取** runtime config 的
   `factor_weights`（config 层仍 validation，供 3.6 训练初值与 3.7 候选热覆盖）。

### 5.2 Weighted scorer 公式（本期细化的生产语义）

分离 **排序模型** 与 **收益/风险映射**，两者都冻结在 hash 后的 artifact 内：

```text
signed_i   = dir_sign_i · normalized_i · confidence_i          (∈ [-1, 1])
net        = Σ weight_i · signed_i                              (∈ [-1, 1])
side       = sign(net)  → BuyYes (>0) / BuyNo (<0)             (net=0 ⇒ 不出候选)
conviction = |net|
composite  = clamp0_1(conviction · dq_mult · liq_mult · horizon_mult)
confidence = clamp0_1( weighted_mean(confidence_i)             // 仅在场且 conf>0 的因子
                       · Π substitution_penalty )              // §10 治理折减
(expected_return_bps, downside_bps) = artifact.return_model.estimate(composite, confidence)
```

实现要点：

- 输入 `ModelRuntimeInput::FactorTable(FactorInferenceTable)`；每行 `FactorInferenceRow`
  额外携带强类型 `MarketInferenceContext`（entry price / liquidity / data_quality /
  time_to_resolution / substitutions），由 `ModelRunner` 从 selection + feature 投影。
- `weight_i` 来自冻结 `WeightedFactorModelArtifact.weights`（已发布）；缺失/未加权因子
  贡献 0（缺失因子 confidence=0）。
- `side` = BuyYes 取 YES token，BuyNo 取 NO token（缺 NO 价时用 `1 − yes_price`
  二元补价）。Sell* 为 Phase 5 退出，scorer 不产出。
- `entry_price_ref` 取 `book.mid`（缺则 best_bid/ask 中点）。
- `expected_return_bps`/`downside_bps` 由 `ReturnModelSpec` 产出：本期 `Heuristic`
  （单调、可审计、显式标注未标定），3.6 由 `WeightedFactorTrainer` 从回测真实结果
  标定 `Calibrated`（见 [`03.6`](03.6-trainer-classical-ml-backtest.md)）。candidate
  的 `model_explanation.headline` 标注 `heuristic`/`calibrated` provenance——绝不臆造收益。
- `candidate_score_floor` / `min_model_confidence` 由 `ModelRunner` 施加：未达标
  的候选仍写入 CH 事实（`rejection_reason = score_below_floor / low_confidence`），但
  不进入返回给 Phase 4 的 `accepted` 集。
- 全程 `Decimal` / `Probability` / `Price`，**无 f64**。

### 5.3 ModelRunner（在线编排）

```rust
pub struct ModelInferenceRequest {
    pub model: Box<dyn QuantModelRuntime>,
    pub selection: MarketSelectionSnapshot,
    pub features: Vec<FeatureVector>,
    pub factor_values: Vec<Vec<FactorValue>>,
    pub as_of: DateTime<Utc>,
    pub run_kind: ModelRunKind,
}
```

`ModelRunner::run` 写 `ModelRun`（`input_hash` = hash(run_kind + selection id +
feature_vector ids + factor_schema_hash + model_version + as_of)、`output_hash` =
hash(candidates)、metrics），**先** `succeed`/`fail` 落 PG 终态，**再**批量写非权威
CH 事实（`quant_signal_candidate_event`）。若 PG 终态失败，CH 不写入。

### 5.4 推理降级（父文档 §28）

| 失败 | 行为 |
|---|---|
| active weighted model load failed | run 失败，critical alert |
| shadow model failed | active 继续，记录 shadow failed |
| classical shadow failed | active weighted 继续 |
| feature_schema_hash mismatch | 拒绝加载，typed error |
| artifact hash mismatch | 拒绝加载 |

`ModelRuntimeFactory::load` 失败返回 typed error，不 panic。自动执行禁止用
fallback model（除非 fallback 本身是 active published）——本期仅记录约束，执行在
Phase 05/06。

## 6. 生产不变量与失败语义

- **统一入口隔离**：业务层（runner/report）只依赖 `dyn QuantModelRuntime`，永不
  依赖 weighted/classical concrete 类型。
- **schema hash 校验**：runtime 的 `feature_schema_hash` / `factor_schema_hash` 与
  当前 feature/factor schema 不匹配则拒绝推理。
- **artifact 不可变**：已发布 artifact 字节 + hash 固定；权重热更新只对未发布候选生效。
- **ModelRun 必写**：每次在线推理写 `run_kind = live_inference` 的 ModelRun（status /
  input_hash / output_hash / metrics）。
- **无 f64 泄漏**：scorer 全程 Decimal/Probability。

### 7.1 内容寻址 artifact（本期落地）

- `ModelArtifact::content_hash()` = artifact canonical JSON 的 `blake3:` 摘要；

## 9. Blocker

- 若 `ReportBuilder` / runner 出现 weighted/classical concrete 类型依赖，本子phase失败。
- 若在线推理不写 `ModelRun`，本子phase失败。

- 若 artifact/feature schema hash 不匹配仍加载推理，本子phase失败。
