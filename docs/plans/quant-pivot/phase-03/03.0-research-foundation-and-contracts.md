# 03.0 — Research Foundation & Contracts

> 父：[`README.md`](README.md) · 概念规格：[`../03-data-factor-model-pipeline.md`](../03-data-factor-model-pipeline.md)
>
> 闭环定位：**契约 / 脚手架层**。本子phase不交付业务能力，而是把整个研究平面
> 的"地基"打实：crate 模块树、ML 依赖 feature-gate、全部计算 trait 与计算域值
> 类型、缺失的 typed IDs、canonical hashing、`ArtifactStore`。后续 3.1–3.7 全部
> 依赖本子phase的契约。

## 1. 目标与闭环定位

把 `quant-pivot-research` 从空壳脚手架变成"契约完备、依赖就绪"的 crate：

- 建立 `quant-pivot-research` 的完整模块树与 `[features]`。
- 在 research crate 定义全部计算 trait 与计算域值类型（强类型，与持久化 DTO 解耦）。
- 在 `quant-pivot-models` 补齐缺失 typed IDs、`Hash` / `ArtifactUri` newtype。
- 落地 `ArtifactStore`（本地目录实现）+ deploy 配置。
- 破坏式替换 `SignalCandidate` stub 为强类型计算域类型。

本子phase完成后，3.1–3.7 可以"只填实现，不改契约"。

### 3.2 `quant-pivot-models` 新增内容寻址 newtype（`types/` 或 `hashing.rs`）

```rust
/// Canonical `blake3:<hex>` content hash. Wraps a validated digest string.
#[derive(Debug, Clone, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub struct ContentHash(String);

/// Artifact location URI, e.g. `file://<root>/datasets/<id>.parquet`.
#[derive(Debug, Clone, PartialEq, Eq, Hash, Serialize, Deserialize)]
```

`ContentHash` 只能由 §6 的 hashing 工具构造（私有字段 + 校验 `blake3:` 前缀），
保证"hash 一定来自 canonical digest"。

### 3.3 表 / CH fact

本子phase**不新增**表或 CH fact（3.5 / 3.6 / 3.7 负责）。仅约定后续表的 PK 用
上面 typed IDs。

## 4. 计算域值类型（全部归属 `quant-pivot-research`）

> 原则：持久化 DTO（`*Info` / `New*`，在 `quant-pivot-models`）= 库表投影；
> 计算域类型（这里）= 在线/离线运算的强类型载体。两者通过显式 `From` / 映射函数
> 互转，绝不合并。

## 5. 计算 trait（全部归属 `quant-pivot-research`）

本子phase**只定义 trait 与其输入/输出类型，不写实现**（实现分布到 3.1–3.7）。
全部返回 `QuantResult<T>`。

```rust
// research::selection
pub trait MarketSelector: Send + Sync {
    async fn build_snapshot(&self, request: MarketSelectionBuildRequest)
        -> QuantResult<MarketSelectionSnapshot>;
}

// research::features
pub trait FeatureBuilder: Send + Sync {
    fn schema_version(&self) -> SchemaVersion;
    async fn build(&self, input: FeatureBuildInput<'_>) -> QuantResult<FeatureVector>;
}

// research::factors
pub trait FactorComputer: Send + Sync {
    fn definition_id(&self) -> FactorDefinitionId;
    fn compute(&self, features: &FeatureVector) -> QuantResult<FactorValue>;
}

// research::model
pub trait QuantModelRuntime: Send + Sync {
    fn model_version_id(&self) -> ModelVersionId;
    fn model_family(&self) -> ModelFamily;
    fn feature_schema_hash(&self) -> ContentHash;
    async fn infer_batch(&self, input: ModelRuntimeInput) -> QuantResult<ModelRuntimeOutput>;
}

pub trait ModelRuntimeFactory: Send + Sync {
    async fn load(&self, model_version: &ModelVersionInfo)
        -> QuantResult<Box<dyn QuantModelRuntime>>;
}

// research::model::trainer
pub trait ModelTrainer: Send + Sync {
    fn model_family(&self) -> ModelFamily;
    async fn train(&self, request: TrainModelRequest) -> QuantResult<TrainedModelArtifact>;
}

// research::training
pub trait TrainingDatasetPlanner: Send + Sync {
    async fn plan(&self, request: DatasetPlanRequest) -> QuantResult<DatasetPlan>;
}
pub trait TrainingDatasetBuilder: Send + Sync {
    async fn build(&self, plan: DatasetPlan) -> QuantResult<TrainingDatasetArtifact>;
}
pub trait Labeler: Send + Sync {
    fn label_name(&self) -> LabelName;
    async fn build_label(&self, input: LabelBuildInput<'_>) -> QuantResult<LabelBuildOutput>;
}

// research::backtest
pub trait Backtester: Send + Sync {
    async fn run(&self, request: BacktestRequest) -> QuantResult<BacktestReport>;
}

// research::gates
pub trait ModelQualityGate: Send + Sync {
    fn evaluate(&self, input: QualityGateInput) -> QuantResult<QualityGateDecision>;
}

// research::artifact
pub trait ArtifactStore: Send + Sync {
    async fn put(&self, key: ArtifactKey, bytes: &[u8]) -> QuantResult<ArtifactUri>;
```

## 6. Canonical Hashing

复用既有
[`models::hashing::CanonicalDigest`](../../../crates/quant-pivot-models/src/hashing.rs)
（BLAKE3 + `blake3:` 前缀）。在 research 侧封装类型化 hasher，**不重复造轮子**：

```rust
// research::hashing
pub struct ResearchHasher;
impl ResearchHasher {
    pub fn feature_schema(spec: &FeatureSchema) -> QuantResult<ContentHash>;
    pub fn feature_vector(v: &FeatureVector) -> QuantResult<ContentHash>;
    pub fn factor_schema(set: &FactorSet) -> QuantResult<ContentHash>;
    pub fn dataset(artifact: &TrainingDatasetArtifact) -> QuantResult<ContentHash>;
    pub fn model_artifact(artifact: &ModelArtifact) -> QuantResult<ContentHash>;
}
```

硬规则：集合（feature 名集、id 集）序列化前必须排序，保证 hash 与顺序无关
（`CanonicalDigest::blake3_json` 逐字节 hash，determinism 责任在调用方）。

## 10. 生产不变量与失败语义

- research crate 默认 build（`default = []`）链接 base numeric stack（ndarray /
  statrs / rayon），**不链接** polars / smartcore / argmin；report_only 服务不被迫
  加载重依赖。
- `ContentHash` 不可由外部裸字符串构造。
- 所有 trait `Send + Sync`，便于跨 tokio task 共享 `Arc<dyn _>`。
- `LocalArtifactStore::get` 对不存在 URI 返回 typed error，不 panic。

## 11. 验收测试

- `signal_candidate_typed_replaces_stub`：旧 `SignalCandidate` 不再存在于
  `quant-pivot-models`；research 强类型版本可构造、可映射为
  `QuantSignalCandidateEventRow`。
- `content_hash_rejects_non_blake3_prefix`。
- `research_hasher_is_order_independent_for_sets`：feature 名集合乱序输入产生同一 hash。
- `local_artifact_store_roundtrip`：put → get bytes 相等；get 缺失 URI 返回 error。
- `research_default_build_excludes_heavy_deps`：`cargo tree -p quant-pivot-research`
  默认不含 polars/smartcore/argmin（CI 断言）。

## 12. Blocker

- 若 `quant-pivot-models` 仍存在旧 `SignalCandidate` stub，本子phase失败。
- 若任何第三方 ML concrete type 出现在 research crate 的 `pub` 契约（trait 签名 /
  导出类型）中，本子phase失败。
- 若 default build 链接了 polars / smartcore / argmin，本子phase失败。

## 13. 延后 / 缺口

- 各计算 trait 的**实现**全部留给 3.1–3.7。
- `ModelArtifact::Onnx` / 深度学习 arm 仅占位，不实现（Phase 06/08）。
- 对象存储 `ArtifactStore` 实现延后；本期仅 `LocalArtifactStore`。
