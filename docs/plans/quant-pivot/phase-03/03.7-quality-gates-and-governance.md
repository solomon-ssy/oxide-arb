# 03.7 — Quality Gates & Governance

> 父：[`README.md`](README.md) · 概念规格：[`../03-data-factor-model-pipeline.md`](../03-data-factor-model-pipeline.md) §8/§12/§18/§19/§20/§29
>
> 闭环定位：**离线治理闭环收口**。把训练/回测产物经质量门禁、shadow 对比、
> publish/retire/rollback 生命周期治理起来。本子phase完成后，离线闭环
> `dataset → train → backtest → gate → shadow → publish/rollback` 打通。

## 1. 目标与闭环定位

- `ModelQualityGate` + quality gate report（父文档 §18 gates）。
- shadow 比较：Phase 03 在 **signal-candidate / rank 层**（report-level 完整比较留
  Phase 04），并持久化 `quant_shadow_comparison`。
- publish / retire / rollback 生命周期 + governance audit（复用既有
  `ModelRegistryRepository`）。
- 候选模型 factor 权重 / 数据质量阈值热更新（runtime config applicator）。

## 2. 删除清单

- `ModelRegistryRepository` 已有 `publish_model_version` / `retire_model_version`
  impl——本子phase**扩展**为受门禁/shadow 约束的治理流程，不重写底层 CRUD。
- 无旧 governance 代码可删（control_factor governance 在 Phase 0/1 已重建为 quant）。

## 3. 新领域类型 / 表 / ClickHouse fact

### 3.1 Quality gate（`research::gates`）

```rust
pub struct QualityGateInput {
    pub model_version_id: ModelVersionId,
    pub backtest: BacktestReport,
    pub dataset: DatasetCoverage,
    pub thresholds: QualityGateThresholds,   // 来自 config / spec
    pub leakage_findings: LeakageFindings,
}

pub enum QualityGateDecision {
    Pass { report: QualityGateReport },
    Fail { report: QualityGateReport, hard_failures: Vec<QualityGateFailure> },
}

pub trait ModelQualityGate: Send + Sync {    // 3.0 已定
    fn evaluate(&self, input: QualityGateInput) -> QuantResult<QualityGateDecision>;
}
```

Gates（父文档 §18，hard/soft + 默认阈值）：

- hard：`sample_count >= 500`、`label_coverage >= 70%`、
  `critical_feature_coverage >= 95%`、`no_pit_leakage = 0 violations`、
  `max_drawdown <= configured`、`liquidity_exit_feasible >= 90%`（auto 专用）、
  `shadow_overlap_stability >= threshold`（publish 专用）。
- soft：`rank_ic > 0`、`top_decile_return > median`、`category_concentration within budget`。

`QualityGateReport` 序列化为 JSON，写入 `quant_model_version.quality_gate_report`
（列已存在），可在 UI 展示。

### 3.1.1 Dataset → Ready 晋升（消费 3.5 coverage）

- `QualityGateInput.dataset` 使用 `DatasetCoverage`（含 `book_decode_failures`、
  `labels_not_mature` 等）。
- `Built → Ready` **仅**在 gate pass 后由 operator/job 调用 `mark_status(Ready)`。
- `InsufficientLabels` **永不可** `Ready`（repo 状态机 `Conflict`）。

### 3.2 Shadow 比较（`research::governance::shadow`，signal/rank 层）

```rust
pub struct ShadowComparison {
    pub shadow_comparison_id: ShadowComparisonId,
    pub active_model_version_id: ModelVersionId,
    pub shadow_model_version_id: ModelVersionId,
    pub as_of: DateTime<Utc>,
    pub topn_overlap: Probability,
    pub rank_delta: RankDelta,
    pub score_delta: ScoreDelta,
    pub matured_outcome_delta: Option<OutcomeDelta>, // label 成熟后回填
    pub hard_divergence: bool,
}
```

> Phase 03 的 shadow 在 **SignalCandidate 排序层** 比较（active vs shadow 的 TopN
> 候选 overlap / rank delta / score delta）。完整 report-level 比较（capital
> allocation delta、would-execute delta、risk envelope delta）依赖 Phase 04 报告
> 生成，**显式延后**（见 §10）。

### 3.3 Publish / rollback 治理（`research::governance::publish`）

复用 `ModelRegistryRepository`，新增治理编排（父文档 §20）：

```rust
pub async fn publish_model_version(req: PublishModelRequest, deps: &ModelGovernanceDeps)
    -> QuantResult<ModelVersionInfo>;
// 1. ensure_candidate_or_shadow
// 2. quality.ensure_publishable()
// 3. shadow.ensure_stable(required_shadow_window)
// 4. governance.require_role(actor, RiskManagerOrOperator)
// 5. publish + 写 governance audit（before/after status hash）
```

rollback（父文档 §29）：保留 previous published version；runtime config 只引用
model version id；rollback 写 reason + audit；回滚后新报告记录新 version。

### 3.4 Postgres 新增表 `quant_shadow_comparison`

- iden/entity/domain DTO/repo（`ShadowComparisonRepository`：`create` /
  `summary(version_id, window)`）。列：`shadow_comparison_id` PK、active/shadow
  version id、`as_of`、`topn_overlap`、`rank_delta_json`、`score_delta_json`、
  `matured_outcome_json`、`hard_divergence`、`comparison_hash`、`created_at`。
  生命周期=audit（WORM append-only），注册进 schema graph。

### 3.4.1 Postgres 新增表 `quant_model_governance_audit`（专用治理审计）

> **决策纠偏**：原计划"复用 operation_log"。但 `operation_log` 是 HTTP 导向
> （含 `http_method` / `http_path` / `http_status`），不适合承载离线治理动作。
> 改为新建专用审计表，参照 `runtime_config_activation` 范式，完整可查询、与 HTTP 解耦。

- iden/entity/domain DTO/repo（`ModelGovernanceAuditRepository`：`create` /
  `list_by_version`）。列：`audit_id` PK、`model_version_id` FK、`action`
  （新枚举 `ModelGovernanceAction`：Publish/Retire/Rollback/DatasetReady）、
  `actor_username`、`actor_role`(null)、`reason`、`before_status`、`after_status`、
  `before_hash`(null)、`after_hash`(null)、`quality_gate_passed`、
  `rollback_target_version_id`(null)、`shadow_window_secs`(null)、`detail_json`、
  `audit_event_id`(`AuditEventId`)、`created_at`。生命周期=audit（WORM append-only）。
- **角色**：本期 `actor_role` 仅作审计记录，**不做硬角色校验**（见 §10）。

### 3.5 ClickHouse fact

无新增（治理是 Postgres 权威；shadow 明细可选落 Parquet）。

### 3.6 Candidate weight overlay（热更新闭环）

**目标**：operator 可在 **不 republish / 不改 artifact hash** 的前提下，对 **非
Published** 的 active/shadow 候选版本做权重试验。

**Publication gate**

- `ModelPublicationStatus::Published` → 仅 artifact 权重（3.4 行为），config overlay **禁止**。
- `Candidate | Shadow`（及 trainer 产出未 publish 版本）→ 允许 overlay。

**Overlay 语义**（research 层，不污染 artifact bytes）

- 新增 `WeightOverlay`：`BTreeMap<FactorName, Decimal>`，由 `FactorsConfig.factor_weights`
  + enabled factor set 解析。
- `WeightedFactorRuntime::new(artifact, overlay: Option<WeightOverlay>)`：overlay 存在时
  **替换** artifact 权重表，仍跑 `validate()`（非负、和为 1）；未知因子名 fail-closed。
- Overlay **不参与** `content_hash()`；审计写入 `ModelRun.metrics_json`
  （如 `weight_source: "artifact" | "config_overlay"`）。

**Runtime config applicator**（core）

- 订阅 `factors.factor_weights` 段变更 → 更新内存 `Arc<WeightOverlaySnapshot>`（按
  `active_model_version_id` / `shadow_model_version_id` 解析）。
- `ModelRunner` 在 `load` 后、构建 runtime 前：查 registry `publication_status`，决定是否
  传入 overlay。

**Governance 不变量**

- 热更新 **不得** mutate 已发布 artifact 文件或 `quant_model_version.artifact_hash`。
- Publish 必须将 overlay 试验结果 **回写 trainer artifact**（新 version + 新 hash），而非
  永久依赖 overlay。

**与 3.4 shadow diff**

- Shadow 若指向 Candidate 版本，可独立 overlay；diff 仍用 `shadow_diff`（composite/side）。

## 4. deploy-config key 与 runtime-config v3 path

### 4.0 新增治理 `quality_gate` 段（runtime-config v3，hot-reloadable）

> gate 阈值是受治理的、应可热更新的面（父文档 §9"数据质量阈值热更新"）。本期在
> runtime-config v3 新增 `QualityGateConfig` 段（`#[serde(default)]` 加性，
> `schema_version` 仍为 3），由 gate + 治理服务消费、经 §3.6 applicator 热更新：
> `min_sample_count`、`min_label_coverage`、`min_critical_feature_coverage`、
> `max_drawdown`、`min_liquidity_exit_feasibility`（auto）、
> `min_shadow_overlap_stability`（publish）、`min_rank_ic`（soft）、
> `required_shadow_window_secs`。`QualityGateThresholds`（research）由 core 从该段装配。

### 4.1 本子 phase 消费

- **治理 / load-time**（扩展 3.4 registry 解析）：
  - `ModelConfig.min_quality_gate_age_secs` — 拒绝 quality gate 报告过期的 active/shadow
    load（3.4 **未**实现；本子 phase 在 `ModelRuntimeFactory::load` 或 runner 入口 enforce）。
  - `ModelConfig.active_model_version_id` / `shadow_model_version_id` — publish/rollback 目标。
  - `ModelConfig.shadow_diff_threshold` — 与 3.4 shadow metrics 对齐，用于 `hard_divergence` 判定。
  - `ModelConfig.min_model_confidence` — gate 评估口径（与 3.4 runner floor 一致语义，治理层只读评估）。
- **Auto-execution 口径**（只读评估，不执行）：`AutoExecutionConfig.require_shadow_passed`、
  `min_score`、`min_confidence`。
- **热更新边界**（父文档 §9，实现见 §3.6）：
  - **可热更新**——非 Published 候选/ shadow 模型的 factor 权重
    （`FactorsConfig.factor_weights` → `WeightOverlay`）、`DataQualityConfig` 阈值、
    active/shadow model version 引用。
  - **不可热更新**——已发布 model artifact（hash 固定）、历史报告、已批准 intent
    核心字段（经新版本/撤销流程）。runtime config applicator 增订阅 `factors` 段。

### 4.2 3.4 已消费、3.7 不重复实现

| key | 3.4 | 3.7 |
|-----|-----|-----|
| `candidate_score_floor` | `ModelRunner` 过滤 `accepted` | gate 可引用同一 config 快照 |
| `shadow_diff` 计算 | `ModelRunner` metrics | 持久化 `ShadowComparison` + alert |
| `min_quality_gate_age_secs` | **不读** | **本子 phase 落地** |
| `prediction_horizon_secs` | **不读**（artifact 权威） | **不读**（3.6 写入 artifact） |

## 5. 必建模块与 trait

> **架构纠偏（强制）**：原计划把 publish/rollback/shadow 编排放在
> `research/src/governance/`，但 `quant-pivot-research` 仅依赖 `error`+`models`，
> **够不到 repository / audit 层**。现有范式（`core/src/service/backtest.rs`）一律把
> "编排 + repo + 审计" 放 core。因此：**research 只放纯计算**（gate 评估、shadow
> delta、weight overlay parse/validate、leakage 扫描），**core 放编排**（publish /
> rollback / dataset 晋升 / shadow 持久化 / 审计写入 / actor 记录）。

```text
research/src/gates/
├── mod.rs              # ModelQualityGate trait + QualityGateDecision
└── model_quality.rs    # DefaultModelQualityGate + QualityGateInput/Report/Thresholds/GateIntent
research/src/governance/
├── mod.rs
└── shadow.rs           # ShadowComparison + RankDelta/ScoreDelta/OutcomeDelta + compute_shadow_comparison（纯计算，signal/rank 层）
research/src/training/
└── leakage.rs          # LeakageFindings + scan_future_leakage（结构化，gate 消费）
research/src/model/
└── overlay.rs          # WeightOverlay parse + validate（3.7）
core/src/governance/
├── model_governance.rs # publish / rollback / promote_dataset_ready 编排 + 审计（受 gate/shadow 约束）
└── weight_overlay.rs   # applicator snapshot + publication gate（3.7）
quant-pivot-web/src/routes/
└── model_governance.rs # POST publish/rollback + Casbin publication:publish|rollback
```

治理服务对外经 `ModelGovernancePort`（models 定义，core 实现），接入 `AppContext`。
Admin HTTP 路由（`POST /research/models/{id}/publish|rollback`）经 Casbin
`publication:publish|rollback` + `X-Acting-Role` 门禁，actor 写入
`quant_model_governance_audit`。

## 6. 生产不变量与失败语义（父文档 §12.2 生命周期硬规则）

- `draft ModelSpec` 不能线上推理。
- `trained` 未回测不能进 candidate。
- `quality_failed` 不能 shadow。
- `shadow` 未完成最小 shadow window 不能 publish。
- `published` 不可变，修正必须新建 version。
- 任何训练输入变化必须改 dataset hash 或 artifact hash。
- publish 必须写：model version、factor definitions、quality gate report、operator
  reason、config constraints、rollback target（父文档 §8.2）。
- quality gate hard failure → 拒绝 advance；输出 `QualityGateReport` 含
  `hard_failures`。
- shadow `hard_divergence` → critical alert（`AlertCategory`），但不自动改 active。

- `quality_gate_blocks_pit_leakage`。
- `shadow_comparison_records_topn_delta`（signal/rank 层）。
- `publish_requires_shadow_stability`（核心）。
- `publish_requires_quality_gate_pass`。
- `published_version_is_immutable_correction_creates_new_version`。
- `rollback_retains_previous_and_writes_reason`。
- `stale_quality_gate_report_denies_active_load`（§4.1 时效门禁）。
- `dataset_insufficient_labels_cannot_promote_ready`（§3.1.1）。
- `hot_update_changes_candidate_weights_not_published_artifact`：同一 **Candidate**
  版本，改 config `factor_weights` → 下一 round composite 变化；**Published** 版本
  composite 不变（overlay 禁止，仅 artifact 权重）。
- repo/schema：`quant_shadow_comparison_migration_and_crud`、
  `quant_model_governance_audit_migration_and_crud`；治理 audit 写入校验。

## 9. Blocker

- 若 `quality_failed` 模型能进入 shadow / publish，本子phase失败。
- 若 publish 绕过 quality gate / shadow stability，本子phase失败。
- 若热更新改变了已发布 artifact 或历史报告，本子phase失败。
- 若 shadow 未完成最小 window 即允许 publish，本子phase失败。

## 10. 延后 / 缺口

- **shadow `matured_outcome_delta` 回填**：本期 `quant_shadow_comparison.matured_outcome_json`
  落 null；label 成熟后的异步回填（attribution 闭环）→ Phase 04。
- **3.4 shadow diff operator 告警**：3.4 将 `exceeds_threshold` 写入 shadow run
  `metrics_json`；本子 phase 落地 critical/warn alert + `quant_shadow_comparison` 持久化。
- **durable 每市场排除原因审计**（03.1 market selection）→ 后续治理增强：
  当前 03.1 仅持久化 `exclusion_summary` 聚合 + 快照内存 `excluded`，缺逐市场可查询的
  排除审计表；治理面需要时另建审计表 + 保留策略。
- **人工禁用权威已收敛到 market status**：不再设计 runtime block list 或旧 config block 字段。
  动态运维封禁通过 governed market block/unblock API 写
  `MarketStatus::ManuallyBlocked`，并由 operation log 审计。
- **外部裁决数据源**（03.1 `ResolutionAmbiguityFilter` 规则模糊度的垂直数据）→ 延后；
  03.1 本期用 metadata 启发式（resolution 时间窗）。
- **report-level shadow 完整比较**（capital allocation delta / would-execute delta /
  risk envelope delta，父文档 §19）→ Phase 04（依赖报告生成）。本期 shadow 止于
  signal-candidate / rank 层。
- **auto-execution 门禁的真正生效**（kill switch、auto policy 执行）→ Phase 06；
  本期仅按 `require_shadow_passed` 等口径**评估**门禁，不触发执行。
- **operator UI 展示** quality gate / shadow report → Phase 07；本期产出 JSON 与
  持久化即可。
