## 1. 目标与闭环定位

- 唯一 `ModelQualityGate` 对冻结的 dataset、CPCV/backtest、calibration、feature
  parity、explainability 与 shadow evidence 产生 content-addressed
  `QualityGateReport`。
- 每次候选 serving preimage 封存为不可重新绑定的 `ModelCandidateManifest`；模型 bytes、
  dataset、serving contract、calibration、CPCV、explanation、feature parity 与最终
  gate evidence 共同参与 hash。
- `quant_model_version` 只表达 immutable artifact lifecycle。`Inactive`、`Shadow`、
  `Champion` 均按一个精确 `ModelRouting` route generation 派生，不是 model row 上的
  全局可变状态。
- bootstrap、feedback promotion 与 rollback 共用唯一 route owner。route activation
  只改变 serving pointer，不扩大 execution authority ceiling、当前 entry authorization policy、capital、funder 或 signing
  authority。
- shadow comparison、permit、activation、audit 与 outbox 全部可追溯、可重放并 fail closed。

闭环：

```text
Training / Calibration
 -> immutable ModelVersion
 -> CPCV + QualityGateReport + FeatureParity + Explanation
 -> ModelCandidateManifest
 -> Comparison + non-executing shadow
 -> PromotionGateArtifact
 -> operator permit
 -> atomic route activation
 -> config revision rollback
```

## 2. 删除清单

以下旧合同必须不存在：

- `ModelPublicationStatus::{Draft,Candidate,Shadow,Published,Retired,Rejected}` 以及
  `quant_model_version.publication_status/published_at/retired_at/quality_gate_report`。
- 任何 `publish_model_version`、`retire_model_version` 或 runner 首次推理后 best-effort
  修改 model status 的路径。
- `POST /research/models/{id}/publish`、
  `POST /research/models/{id}/bind-calibration`、
  `POST /research/models/{id}/bind-publish-path-set` 及对应 UI action。
- model-global rollback。rollback 只回滚当前 config revision/route generation。
- runtime factor-weight overlay。权重或 calibration 变化必须创建新的 immutable
  artifact/model version；既有 version 不得 mutate 或 rebind。

## 3. 新领域类型 / 表 / ClickHouse fact

### 3.1 唯一质量门

`GateIntent` 只包含：

- `Candidate`
- `RouteActivation`
- `PolicyAutomatic`

完整 scorecard 至少覆盖 sample/label/materialization coverage、No-PIT、backtest/CPCV、
rank IC、Deflated Sharpe Ratio、PBO、track-record length、drawdown、turnover、tail loss、
calibration、explainability、shadow stability 与 PolicyAutomatic liquidity feasibility。
每个尝试过的 recipe/trial 都必须进入 multiple-testing universe；不能只统计胜出候选。

`QualityGateReport` 是 immutable content-addressed artifact。它绑定到
`ModelCandidateManifest`/`PromotionGateArtifact`，不得回写 model version。

### 3.2 Candidate manifest 与 promotion aggregate

`ModelCandidateManifest` 一次性绑定：

- model version、model bytes/serving contract 与 category scope；
- training dataset 与 research profile；
- calibration、CPCV path set、backtest；
- exact explanation validation（weighted closed form 或 exact TreeSHAP efficiency）；
- feature parity run/state/evidence；
- validation、comparison、shadow 与 decision evidence。

`PromotionGateArtifact` 聚合并重新 hash：

- `TruthFreeze`
- `AttributionPlan`
- `Validation` / `QualityGateReport`
- `Comparison`
- `Shadow`
- decision policy/profile
- CPCV、explanation 与 feature parity

permit 签发和 activation transaction 必须重验相同 aggregate hash。

### 3.3 PostgreSQL authority

- `quant_model_candidate_manifest`: content-addressed immutable manifest。
- `quant_shadow_comparison`: WORM shadow comparison。
- `quant_feedback_promotion_permit`: DB-clock TTL、CAS revision、revoke 与 consumed state。
- `quant_model_governance_audit`: `BootstrapRoute`、`PromoteRoute`、`SealCalibration`
  append-only audit。
- `policy_activation`、`policy_activation_audit`、
  `policy_activation_event_outbox`: 原子 route/config revision transaction 与 outbox。

ClickHouse 不保存 serving authority；它只保存分析事实。

## 4. Deploy 与 runtime config

- gate thresholds 来自 immutable research profile/policy artifact，不来自可热更新的
  model-global lifecycle config。
- `ModelRouting` 的 category/pooled/exit active pointer 与 shadow pointer 构成当前
  route generation；所有 pointer 变化走 policy activation transaction。
- serving loader 必须验证 exact model artifact、serving contract、feature schema、
  trade-policy binding、calibration 与 route generation；任一 hash/revision drift
  fail closed。
- 本系统当前按单 AWS 实例部署，不引入 leader election 或 replica coordination。
  PostgreSQL durable state、transaction、lease/retry、idempotency 与 crash recovery
  仍是强制合同。

## 6. 生产不变量与失败语义

- model version 封存后不可修改；任何 bytes、dataset、feature contract、calibration、
  policy 或 evidence 变化都创建新 version/manifest。
- route bootstrap 只允许空 route；promotion 必须消费 `CandidateReady` feedback cycle
  与当前 shadow candidate。
- scheduled/manual retraining 最多自动运行到 `CandidateReady`，绝不自动签 permit 或
  activation。
- permit 的 candidate、route、当前 entry-authorization policy、runtime-control revision、base revisions 与 gate hashes 全由服务端
  推导。客户端不得提交这些 authority 字段。
- stale、expired、revoked、replayed-with-different-body、gate drift、route drift、
  runtime/control drift 或 protected authority drift 必须在同一 PostgreSQL transaction
  原子拒绝。
- permit issuance 与 activation 分别记录 authenticated actor；允许同一操作者完成，
  不伪造 system actor。
- activation receipt 必须包含 before/after route generation、activation/audit/outbox
  IDs、transaction hash 与 server timestamp。
- `ModelRouteBindingCheck` 在每次 execution admission 重验 intent model 仍由当前 active
  route 授权。route activation 本身不能使既有 intent 获得更高 execution authority。

## 7. 第三方 crate

本子 phase 不新增 ML/runtime crate。统计门使用现有 `statrs`/`ndarray-stats`，hash 使用
现有 canonical BLAKE3 contract，事务使用现有 SeaORM/PostgreSQL adapter。

## 8. 验收测试

- quality gate：No-PIT、coverage、rank IC、DSR、PBO、calibration、turnover/tail loss、
  feature parity、explainability 与完整 trial accounting。
- manifest：任一绑定/hash 篡改均失败；calibration 必须派生新 model version。
- bootstrap：只允许 empty route；事务、audit、outbox 与 receipt 原子一致。
- permit：TTL/revoke/stale/CAS/replay、同操作者双动作、DB clock 与 server-derived scope。
- activation：并发 route conflict、gate/hash/revision drift、transaction rollback、
  execution/capital/signing invariants。
- rollback：复用 config revision rollback，恢复精确上一 route generation。
- API/schema：三个旧 publish/bind route 返回不存在，且 schema 中不存在
  model-publication enum/columns。
- UI：CandidateReady → permit → activation → receipt → rollback 深链，包含键盘、Axe、
  双主题与错误恢复。

## 9. Blocker

以下任一成立即判定本子 phase 未闭合：

- model row 或 runner 仍能独立改变 serving authority；
- 存在第二条 publish/activate/rollback 写路径；
- failed quality gate 能进入 comparison/shadow/`CandidateReady`；
- permit/activation 未重验同一 promotion aggregate；
- route mutation 能改变 `EntryAuthorizationPolicy`、capital、funder 或 signing authority；
- UI 通过客户端字段选择 candidate、route 或 gate hash；
- 旧 endpoint、enum、column、alias、compatibility wrapper 或 dual write 仍存在。

## 10. Phase 11.9 扩展边界

Phase 11.9 在本合同之上增加 `TruthFreeze → Coverage → AttributionPlan → Drift →
DatasetSeal → Training → Calibration → CPCV → Validation → Comparison → Shadow →
Decision`、durable scheduler、attribution、Weather 8-family 与完整 UI/ops。11.9 是这些
能力的唯一后继节点；11.10 已合并，不形成循环依赖。
