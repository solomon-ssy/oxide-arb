## 1. 闭环定位

报告允许同时包含 Pooled、Crypto、Weather 及后续受支持 Route。模型输出只在各自 Route 内解释；
跨 Route 比较必须经过 calibrated probability、真实 L2/fees/slippage、Trade Policy cashflow、capital
occupancy 和联合场景的统一 USD 转换。

主流程：

```text
RepresentedRouteSet
  -> atomic RouteReadinessBundle
  -> per-route evaluated candidate
  -> ExecutableEconomicTier[]
  -> PortfolioScenarioArtifact
  -> lexicographic HiGHS MILP
  -> exact Decimal verifier
  -> GlobalPortfolioPlan
  -> leave-one-out Recommendation ranking
```

## 2. Represented Route 与 readiness

`RepresentedRouteSet` 在 catalog discovery 和不可变 venue/lifecycle eligibility 之后、模型相关过滤之前
形成。这样缺少模型的 Route 不能通过“没有候选”被隐藏。

每个 represented Route 必须同时具备：

- active Champion model 和 serving contract；
- compatible calibration artifact 与 uncertainty evidence；
- compatible Trade Policy artifact 与 capital-occupancy evidence；
- Research Profile、feature/PIT lineage；
- 与完整 Route set、serving/calibration contract 和 time buckets 一致的
  `PortfolioScenarioArtifactBinding`。

任一项缺失或 digest/schema 不一致，整个 report run 失败。完整 Route 经过正常 admission 后零候选，
记录 `zero_candidate` 并允许报告继续。catalog/data discovery 失败不是 zero-candidate。

## 3. ExecutableEconomicTier

每个候选从真实订单簿 walking 生成有限个离散 cumulative tiers：

```rust
pub struct ExecutableEconomicTier {
    pub tier_id: EconomicTierId,
    pub route: BuyModelRoute,
    pub market_id: MarketId,
    pub event_id: EventId,
    pub token_id: TokenId,
    pub side: Side,
    pub shares: Shares,
    pub entry_notional_usd: Usd,
    pub reference_entry_price: Price,
    pub fee_usd: Usd,
    pub slippage_usd: Usd,
    pub scenario_cashflows: ScenarioCashFlowVector,
    pub capital_occupancy: CapitalOccupancyVector,
    pub economics: TierEconomics,
    pub lineage: EconomicTierLineage,
}
```

`TierEconomics` 至少包含 nominal/robust expected net USD、profit-probability lower bound、maximum loss、
CVaR input 和 capital USD-hours。raw score、confidence、category rank 和 Kelly fraction 不进入 optimizer。

## 4. PortfolioScenarioArtifact

artifact 是 Research 平面产生、content-addressed、不可变且经过 promotion/governance 的联合场景合同：

- 使用 point-in-time residual block/bootstrap，而不是未来信息或当前报告样本拟合。
- calibration confidence set 转换为允许的 scenario-distribution set。
- 显式包含同 market/outcome、同 event 的 payout/exclusivity 关系和跨 Route stress dependence。
- 冻结 report-as-of discount/capital-cost curve 与统一 capital time buckets。
- 绑定 ordered Route set digest、每 Route serving/calibration contract、schema 和 source evidence。
- 禁止运行时 Pearson、category proxy、assume-independent 或 dynamically synthesized fallback。

artifact 缺失、过期或不兼容时 report fail closed。

## 5. 唯一 MILP 模型

production 唯一 backend 为安全 Rust `highs` API 驱动的 HiGHS MILP。完整稀疏矩阵每个 portfolio solve
只构建并上传一次；后续 lexicographic stage 只修改 column cost、追加上一阶段的 exact epsilon lock，
并以完整上一阶段最优解作为 MIP start。HiGHS 使用固定线程、固定 seed、固定 tolerance 和稳定输入顺序；
不提供 runtime backend selector、第二 modeling layer 或重建式 stage runner。

每个 candidate tier 有 binary one-hot variable `x_{i,t}`；每个 candidate 最多选择一个 tier。现金和
scenario objective 使用经过范围证明的 fixed-scale integer coefficient。solver 内部 numeric representation
不得成为业务 Money 类型，最终只读取 binary tier identity。

四阶段 lexicographic solve：

1. 引入 `z`，对每个允许 distribution/stress set 加 `z <= expected_net_usd_d(x)`，最大化 `z`。
2. 固定 robust optimum，最大化 nominal expected net USD。
3. 固定前两阶段 optimum，最小化 CVaR，再最小化 capital USD-hours。
4. 固定经济 optimum，按 canonical Route/market/tier order 最小化稳定 tie-break ordinal。

禁止通过任意权重把 score、probability、confidence、return 和金额混合。

## 6. Hard constraints

- `sum(entry_notional) <= min(real_available_cash - reserve, max_open_capital)`。
- 每个 time bucket 的 existing locked capital + selected tier occupancy 不超过 bucket cap。
- recommendation、market、event、category、Route exposure caps 全部包含现有持仓。
- scenario loss、CVaR、drawdown 和 execution-risk hard caps。
- `sum(selected candidates) <= top_n`。
- 同一 candidate one-hot、互斥 outcome/event structural constraints。
- candidate admission 已满足 profit probability lower bound、probability-interval width、minimum nominal/
  robust net USD、liquidity buffer 和 exact execution constraints。

零 allocation 是合法可行结果并产生带 rejection evidence 的 empty recommendation report；配置互相矛盾
应在 policy validation 阶段拒绝，而不是依赖 optimizer infeasible。

## 7. Exact verification 与失败

solver 返回后按选中的 tier identity 使用 Decimal/newtype 重新计算：

- 所有现金流、目标值和每条 hard constraint；
- 每个 lexicographic optimum equality/tolerance；
- one-hot、TopN、结构约束和 existing exposure；
- input/output digest 和 deterministic ordering。

只有 `Optimal` 且 exact verifier 全部通过才可持久化 plan。timeout、non-optimal、solver error、numeric
overflow、contract infeasible 或 post-check mismatch 使 report run 失败。无 relaxation、greedy、empty-plan
或 feature-off fallback。

## 8. 排名与解释

对最终选中的每条 recommendation 在相同 frozen input 下禁止该 candidate 并重新求解，计算：

```text
marginal_portfolio_value_usd = full_robust_optimum - leave_one_out_robust_optimum
```

按 marginal value、robust net USD、nominal net USD、canonical identity 排序。API/UI 同时展示
profit probability、max loss、CVaR contribution、capital occupancy、binding constraints 和完整 Route
lineage，不再展示 `risk_adjusted_score` 或 Kelly provenance。

## 9. Runtime policy

`ExecutionRiskPolicy.portfolio` 只包含 `budget`、`exposure_limits`、`tail_risk`、`admission`。删除 sizing、
Kelly、correlation 和 optimizer config。`ModelRouting` 必须绑定一个兼容
`PortfolioScenarioArtifactBinding`。

## 10. 必须验收

- mixed Pooled/Crypto/Weather 在同一全局计划中竞争。
- 费用、滑点、tail risk 或 capital time 可以反转 raw score 排名。
- 小规模输入与 brute-force optimum 完全一致。
- 输入重排不改变 selected tiers、objectives 或 report hash。
- event exclusivity、stress dependence、existing positions、time buckets、CVaR 和所有 exposure caps 生效。
- missing/mismatched Route artifact 使整份报告失败；complete zero-candidate Route 不失败。
- timeout/non-optimal/post-check mismatch 不发布报告。
- solver 边界外没有 `f64` Money；selected tier 使用 exact Decimal 重算。
- 100-candidate benchmark 在 report compute SLO 内稳定获得 `Optimal`；性能不足时优化模型，不增加降级。
