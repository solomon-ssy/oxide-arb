# 05.5 — Reconciliation

> 父：[`README.md`](README.md) · 概念规格：[`../05-execution-risk-and-governance.md`](../05-execution-risk-and-governance.md) §11、
> [`../09-account-capital-position-reconciliation.md`](../09-account-capital-position-reconciliation.md) §4
>
> 闭环定位：**对账闭环**。让内部账本（`quant_execution_order` / `quant_capital_allocation` /
> `quant_position`）与 Polymarket 场内真值一致。对每个待对账订单按固定证据顺序收集证据，产出
> `ReconciliationResult`，据此校正 capital/position；`unresolvable` 阻断 auto execution 直到人工处理。
> 只服务新执行订单，不服务旧 trade（父文档 §11）。

## 1. 目标与闭环定位

1. **对账 worker**（`ReconciliationWorker`，`TaskId::ReconciliationWorker`）：拉取需对账订单
   （`Submitted`/`Accepted`/`Ambiguous`/挂单超时），按证据顺序定真相。
2. **证据链**（父文档 §11 固定顺序）：CLOB order status → CLOB trades → token balance delta →
   account balance delta → book context → operator note，写 `quant_reconciliation.evidence_json`。
3. **结果 5 态**：filled / not_filled / partially_filled / cancelled / unresolvable，据此校正
   capital FSM（spent/released/impaired）+ position 账本。
4. **`unresolvable` 阻断 auto**：`ReconciliationRepository::has_unresolvable()` → admission #17 /
   05.1 preflight / dispatcher worker 早退（auto 停摆直到人工 resolve）。
5. **metric**：`quant_reconciliation_unresolvable_total`。

本子phase完成后，05.4 的 `Ambiguous`/挂单订单得到终态裁决，05.6 exit monitor 基于校正后的真实
position 运行。

## 4. 证据链（父文档 §11，固定顺序，逐级提升置信度）

```rust
pub trait EvidenceCollector: Send + Sync {
    async fn collect(&self, order: &ExecutionOrderInfo) -> QuantResult<Vec<ReconciliationEvidence>>;
}
```

按顺序收集（每级写一条 `ReconciliationEvidence`，`kind` 对应）：

| # | 证据 | 来源 | 用途 |
|---|---|---|---|
| 1 | `ClobOrderStatus` | `get_open_orders`（按 `venue_order_id` 判定是否仍挂单） | 订单是否仍在工作 |
| 2 | `ClobTrades` | `get_trades(token, after=submitted_at)` 客户端按 `order_id` 过滤 | 实际成交真值（shares/vwap） |
| 3 | `TokenBalanceDelta` | `token_balance(CONDITIONAL, token_id)` —— **当前绝对余额** | 持仓旁证（≥ 成交 shares） |
| 4 | `AccountBalanceDelta` | `collateral_balance` —— **当前绝对余额** | 抵押旁证 |
| 5 | `BookContext` | `BookStore.load` 当前 published snapshot（version + ts_ms） | 价格合理性上下文 |
| 6 | `OperatorNote` | 人工备注（unresolvable resolve 时） | 人工裁决证据 |

**裁决权威性**：#1 order status + #2 trades 是机器可判的成交真值，**决定结果**；#3/#4 因 05.4 未在
提交时点捕获基线，无法算真 delta，故改为采集**当前绝对余额做旁证**（记入证据链，不翻转裁决）——
仅当与 status/trades **硬矛盾**（如 trades 显示成交但 `token_balance < filled`）时降级
`Unresolvable`。#5 上下文；#6 仅人工兜底（机器路径只产出 #1–#5）。

## 5. 结果裁决 + 校正（父文档 §11）

```rust
pub fn decide(evidence: &[ReconciliationEvidence], order: &ExecutionOrderInfo)
    -> ReconciliationOutcome
{
    // 证据收敛规则（高置信优先）：
    // - order status == filled && trades 一致 && token delta == shares      → Filled
    // - order status == cancelled/expired && token delta == 0               → Cancelled
    // - order status open 超时且 token delta == 0                            → NotFilled（GTD 过期）
    // - trades 部分 && token delta == partial                               → PartiallyFilled
    // - 证据互相矛盾 / venue 不可达 / token delta 与 trades 不符 / 多次重试未收敛 → Unresolvable
}
```

校正动作（与对账记录同事务，幂等）：

| result | execution_order | capital | position |
|---|---|---|---|
| `Filled` | `Filled` | `locked → spent`（含 fee） | `upsert_from_fill`（若 05.4 ambiguous 未写则补写） |
| `PartiallyFilled` | `PartiallyFilled` | 部分 `spent` 余 `released` | `upsert_from_fill`（部分） |
| `NotFilled` | `Failed`/`Cancelled` | `locked → released` | 不变 |
| `Cancelled` | `Cancelled` | `locked → released` | 不变 |
| `Unresolvable` | 保持 | `locked → impaired` | 不变 | + 置 `requires manual` |

- **Ambiguous → 终态**：05.4 的 `Ambiguous` 订单经对账后得到 filled/not_filled/...；filled 补
  capital spent + position，not_filled 释放（解除 05.4 锁住的资金）。
- **Unresolvable**：capital `Impaired`、订单留待人工，写 `quant_reconciliation.result=Unresolvable`；
  `has_unresolvable()` 立即 true → auto 停摆。人工 `resolve`（带 `OperatorNote` 证据）后转终态。
- **熔断器 feed（recon 维度，接入 05.4 `ExecutionBreaker` §6.5）**：裁决出 `Unresolvable` 时，除
  `has_unresolvable()` 被动门控（admission `#17` / preflight / dispatcher 早退）外，**主动**通知
  `ExecutionBreaker::observe_unresolvable_recon()`，将 kill-switch **升级为 `execution_halted` latch**
  （需 operator ack）。区别：`has_unresolvable()` 是"当前仍有未解 → 拒新单"的被动只读门；breaker
  升级是"把运营态显式收紧并要求人工确认"的主动 latch，避免 resolve 一条后其它问题被自动放行。
  resolve 全部 unresolvable 后由 operator 经 kill-switch ack 恢复（breaker 不自动解除已升级的
  kill-switch，fail-closed）。

**实现：终态一次性校正 + 守卫幂等**。校正经单事务
`ExecutionSubmissionRepository::apply_reconciliation(write: ReconciliationLedgerWrite)`：

- 进入即 `lock_exclusive` 锁 order；若 order **已终态**（Filled/PartiallyFilled/Cancelled/Failed）→
  幂等返回（不再校正），保证重复对账不双扣 capital / 不双写 position。
- capital 校正用守卫式 `reconcile_capital`：仅当当前 `Locked`（或 operator 路径下 `Impaired`）才动账；
  已 `Spent`/`Released` → no-op；裁决与终态资金矛盾 → 强制 `Impaired`（fail-closed）。
- position `apply_fill` 仅在订单首次离开非成交态时写一次（worker 只处理 capital 仍 `Locked`、未写
  position 的 `Submitted`/`Ambiguous` 订单，天然单次）。
- recon 行 **upsert**：已存在（提交时 `Pending` 行）则原地更新 result/venue 字段/`resolved_*` 并
  **追加**本轮证据（WORM，不改历史）；不存在（resting `Open` 单）则新插。
- `decide` 返回 `Pending` 时**不做任何 ledger 写**，留待下一轮 sweep。

## 6. worker + 触发

```text
crates/quant-pivot-core/src/execution/reconciliation/   # reader / collector / decide / service
crates/quant-pivot-core/src/app/reconciliation_worker.rs # register_reconciliation_worker
                                                          # (TaskId::ReconciliationWorker)
```

触发：

- **事件驱动 enqueue**（05.4，既有）：提交 `Ambiguous` 立即写一条 `Pending` recon 行；boot recovery
  对在飞订单补写 `Pending`。周期 sweep 兜底解析（无需额外 wake 通道）。
- **周期 sweep**：`ReconciliationWorker`（`PeriodicTask`，cadence 取 runtime-config
  `execution.reconciliation.interval_secs`，每轮热读；`enabled=false` 跳过）。worker **不按 mode 门控**
  （在飞资金任何模式都要对账，fail-closed）。扫描 `find_reconcilable()`（`Submitted`/`Ambiguous`）。
- **主动撤单**：挂单超 `execution.reconciliation.stale_open_secs`（或 GTD 已过）→ 调
  `PolymarketOrderClient::cancel` 主动撤单 → 重采证据 → 按撤单后真值对账（未成交资金及时 released）。
- **重试 + 退避**：`ClobClient` 读自带 retry；venue 读失败时**不**立即判 NotFilled —— 未超
  `stale_open_secs` 留 `Pending` 下轮重试，超 `stale_open_secs` 仍不可读 → `Unresolvable`（不无限挂起、
  不错放资金）。

## 7. 生产不变量与失败语义

- **只服务执行订单**：对账主键是 `execution_order_id`，不涉及旧 trade（父文档 §11）。
- **证据顺序固定**：始终按 §4 的 1→6 收集；高置信证据（order status/trades/token delta）决定结果，
  矛盾即 `Unresolvable`（绝不臆测）。
- **unresolvable 阻断 auto**：`has_unresolvable()` 为 true 时，auto_execution 不得提交新单（admission
  #17 + dispatcher 早退 + 05.1 preflight），直到人工 resolve（父文档 §11 / §15 第 8 条）。
- **校正幂等**：同一订单多次对账结果一致；已 `spent`/`released` 的不重复扣减（基于 capital FSM 当前
  态校验）。
- **WORM**：`quant_reconciliation` append-only；resolve 追加 `OperatorNote` 证据 + 更新 result/
  resolved_by/resolved_at，不改历史证据。
- **fail closed**：venue 读失败不得判 `NotFilled` 释放资金（可能已成交）；只能保持待对账或最终
  `Unresolvable`（锁资金等人工），宁可冻结不可错放。
- **可恢复**：worker 崩溃重启后继续扫非终态订单；对账与校正同事务，无半完成。
- **错误分层**：`ExecutionError::ReconciliationUnresolvable`；venue 错误经 `ApiError`。

## 10. Blocker

- 若对账释放了可能已成交订单的资金（venue 不可达即判 not_filled），失败。
- 若 `unresolvable` 不阻断 auto execution，失败。
- 若证据顺序与父文档 §11 不符，失败。
- 若对账校正非幂等（可双扣 capital），失败。
- 若 `quant_reconciliation` 可篡改历史证据（非 WORM），失败。
- 若对账服务旧 endgame trade，失败。
