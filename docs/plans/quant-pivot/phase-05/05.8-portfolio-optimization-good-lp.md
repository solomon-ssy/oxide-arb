> **As-built（已实施，取代下文中"greedy 保留为默认 + fallback"的措辞）**：经评审决定**彻底删除
> greedy allocator**，组合分配统一为单一 `good_lp` LP/MILP 代码路径（生产 + 回测共用
> `LinearProgrammingPortfolioAllocator`）。关键修正：纯 Rust `microlp` 已支持完整 binary MILP，故
> `lp-solver`(microlp) 为 research 默认 feature、零 native、进 report_only build。失败阶梯替代
> greedy 兜底：① MILP（microlp 默认 / 可选 native HiGHS）→ ② 连续 LP relaxation + 确定性取整（纯
> microlp）→ ③ 空 plan（`catch_unwind` 兜住 panic）→ 现有空报告路径（**报告永不因求解器崩溃而崩**）。
> 目标函数定稿：`maximize Σ wᵢ·uᵢ，wᵢ = scoreᵢ·(1+λ·ret_normᵢ)`，`uᵢ ≤ desired_usdᵢ·xᵢ`（Kelly
> 风险锚），`Σ xᵢ ≤ top_n`（binary 基数，预算只被发布名消耗）；λ 默认 0（≡ conviction 排序）。求解
> provenance 落 `quant_portfolio_plan.optimizer_meta_json`（`PortfolioOptimizerMeta`：solver /
> solve_mode / status / fell_back_to_relaxation / objective / elapsed / correlation_source /
> conflicts）。runtime-config 升级 schema **v6**。下文 §2–§13 的设计意图不变，仅"greedy 默认"调整为
> "greedy 删除、relaxation+空 plan 兜底"，相应枚举为 `PortfolioSolverKind` / `PortfolioSolveMode` /
> `OptimizerSolverStatus{…, FellBackRelaxation, SolverUnavailable}`。
>
> **延后（已登记）**：Prometheus 优化器 metric（`quant_portfolio_optimizer_*`）——可观测性已由强类型
> `optimizer_meta_json`（落库 + API 可查）满足，独立 metric 计数器为后续观测增强。
>
> **`time_limit_ms` 刻意未实现**：wall-clock 超时破坏确定性重放（与回测 `report_hash` / 生产 replay
> 冲突），故 runtime-config 不含此字段，`OptimizerSolverStatus` 亦无 `TimeLimit` 变体；失败统一走
> MILP → relaxation → 空 plan 阶梯。

## 1. 目标与闭环定位

1. 引入 `good_lp`（feature-gated `lp-solver`），实现 `LinearProgrammingPortfolioAllocator`，与
   `GreedyPortfolioAllocator` **共享 `PortfolioAllocator` trait**（无第二套接口）。
2. LP/MILP 建模（08 §16.3）：全局最优 capital 分配 + binary TopN inclusion，满足 budget / 单笔 /
   per-market/event/category / liquidity / **correlation** / top_n 约束。
3. **相关性约束真正生效**：`CorrelationEstimator`（研究层，历史中价共动估计 + 确定性 proxy fallback）
   产出相关性分组；优化器对相关簇敞口加约束（greedy 近似 + LP 精确）。
4. **生产护栏**（08 §16.5）：time limit、超时/infeasible/feature-off → fallback greedy、solver
   status + infeasibility 进 plan_row/report summary、native solver **绝不**成为 report_only 启动
   硬依赖。
5. 配置 `portfolio.optimizer` 选择 greedy/lp；planner 据此与 feature gate 选优化器。

本子phase完成后，组合分配在预算/约束冲突下给出全局更优解，且相关持仓敞口受控；greedy 仍是
零依赖确定性基线。

## 5. LP/MILP 建模（08 §16.3）

变量：

```text
x_i ∈ {0,1}   是否选择 candidate i（MILP；连续 relaxation 时 x_i ∈ [0,1]）
u_i ≥ 0       分配 USD
```

目标（08 §16.3）：

```text
maximize  Σ risk_adjusted_score_i · x_i  +  λ · Σ expected_return_i · u_i
```

约束：

```text
Σ u_i ≤ min(total_budget, available_usd)                       // 预算/可用现金
min_usd_i · x_i ≤ u_i ≤ max_single_usd · x_i                   // 单笔上下限（含 inclusion 联动）
u_i ≤ liquidity_cap_i                                           // 流动性
Σ_{i∈market m} (held_m + u_i) ≤ max_market_exposure_usd        // per-market（含已有持仓净额）
Σ_{i∈event e}  (held_e + u_i) ≤ max_event_exposure_usd          // per-event
Σ_{i∈category c}(held_c + u_i) ≤ max_category_exposure_usd      // per-category
Σ_{i∈cluster k}(held_k + u_i) ≤ max_correlated_exposure_usd     // **相关簇（本期首次生效）**
Σ x_i ≤ top_n                                                   // TopN inclusion
```

- `held_*` = `AllocationInput.initial_exposures` 的对应桶（账户当前持仓净额，与 greedy 一致）。
- `binding_constraint` 归因：LP 解出后，对每条 candidate 找"紧约束"（shadow price / 达到上界的
  约束）映射回 `BindingConstraint`（与 greedy 的 `decide_ceiling` 语义对齐，保证报告字段一致）。
- 输出转回 `AllocationOutput`（`allocated_usd` = `round_money(u_i)`，`*_exposure_after_usd` =
  `held + Σ`），下游 planner classify/rank/SizingPlan **完全复用**（`planner.rs` §264+）。

## 6. solver backend（native 依赖治理，08 §16.4/§16.5）

| backend | feature | 依赖 | 能力 | 定位 |
|---|---|---|---|---|
| `microlp`（good_lp pure-Rust） | `lp-solver`（默认仍关，但**无 native 依赖**，可安全进 report_only build） | 纯 Rust | 连续 LP（relaxation + 确定性取整） | **可 ship 的默认 LP 层** |
| HiGHS（good_lp `highs`） | `lp-solver-highs`（默认关，native） | native runtime | MILP 精确 binary | 需全局整数最优时启用 |

- **铁律（08 §16.5）**：native solver（HiGHS）**绝不**成为 report_only 启动硬依赖 → 仅
  `lp-solver-highs` feature 开启时链接；`integer_inclusion=true` 但未启用该 feature → fallback
  greedy + `solver_status=FellBackGreedy`（不 panic）。
- **pure-Rust 默认 LP 层**：`integer_inclusion=false` 用 `microlp` 连续 relaxation + 确定性取整
  （按 `x_i` relaxed 值 + top_n 截断 + 重算可行性），零 native 依赖，可进默认 build。
- 选择逻辑：`optimizer_from_config(config, features)`：
  - config=greedy → greedy。
  - config=lp + `lp-solver` 关 → greedy（编译期不可达 LP，配置校验 warn）。
  - config=lp + integer_inclusion + `lp-solver-highs` 关 → greedy fallback（运行期 warn）。
  - 否则 → LP（micro/highs）。
- **time limit + fallback**：LP 求解超 `time_limit_ms` 或 infeasible → fallback greedy，
  `OptimizerOutcome.fell_back_to_greedy=true` + `solver_status` 记录；**绝不**因求解失败阻塞报告。

## 9. 生产不变量与失败语义

- **同一 trait、零分叉**：LP 与 greedy 输出 `AllocationOutput` 结构相同，下游 classify/rank/
  SizingPlan/RiskEnvelope 不分支（报告字段一致、快照可对比）。
- **greedy 永远可用**：LP 任何失败（feature 关 / 超时 / infeasible / solver error）→ fallback
  greedy，报告照常产出；solver status 进报告（可观测降级）。
- **native 不进 report_only 硬依赖**（08 §16.5）：HiGHS 仅 `lp-solver-highs`；默认 build 不链接
  native runtime。
- **相关性约束生效**：`max_correlated_exposure_usd` 从"仅快照"变为"真正约束"（LP 精确 / greedy
  近似）；correlation 关闭时行为等价 Phase 4（向后语义可控，非向后兼容代码）。
- **确定性可重放**：LP 解确定（固定参数、确定性 tie-break、无 wall-clock），同
  `(candidates, account, config)` 必产同一 plan（与 greedy 同保证）。
- **money newtype**：LP 内部 `f64`（solver 数值）严格隔离在 optimizer 边界，输出 `round_money` 回
  `Usd`；`f64` 不泄漏到 SizingPlan/报告。
- **infeasible 透明**：约束冲突（如 budget < Σ min_usd 且 top_n 要求过多）→ `solver_status=Infeasible`
  + `constraint_conflicts` 可读输出 + fallback greedy（greedy 天然部分可行）。

## 12. Blocker

- 若 native solver 成为 report_only 启动硬依赖（违背 08 §16.5），失败。
- 若 LP 失败不能 fallback greedy（阻塞报告），失败。
- 若 `max_correlated_exposure_usd` 仍只落快照、不约束，失败。
- 若 LP 与 greedy 走两套下游接口（报告字段分叉），失败。
- 若 `f64` 从 solver 泄漏到 money domain，失败。
- 若 LP 解不可确定性重放，失败。

## 13. 延后 / 缺口

- **CBC / SCIP 等其他 MILP solver backend** → 仅在 HiGHS 不满足时评估（08 §16.4 谨慎）；本期
