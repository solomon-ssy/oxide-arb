## 1. 目标

05.0 定义执行链后续服务共用的强类型合同和 owner 边界，不在这一层制造平行决策轴。

```text
Recommendation
 -> ExecutionAuthorityCeiling + blockers + policy binding
 -> EntryAuthorizationPolicy
 -> OrderIntent + AuthorizationEvidence
 -> AdmissionInput / AdmissionDecision
 -> ExecutionOrder / Reconciliation / StrategyPositionLot
```

## 2. 核心类型

### 2.1 三个不可合并的 authorization 事实

```rust
pub enum EntryAuthorizationPolicy {
    OperatorApprovalRequired,
    PolicyAutomatic,
}

pub enum ExecutionAuthorityCeiling {
    AnalysisOnly,
    OperatorApproval,
    PolicyAutomatic,
}

pub enum AuthorizationKind {
    OperatorApproval,
    ActivePolicy,
}
```

- `EntryAuthorizationPolicy` 是当前 runtime control。
- `ExecutionAuthorityCeiling` 是 recommendation 上不可变的最大能力。
- `AuthorizationEvidence` 是 intent 上不可变的 grant，并且必须与 `AuthorizationKind` 一致。

三者不得折叠成 bool、单个等级字段或派生状态集合。

### 2.2 `OrderIntent` FSM

```text
PendingAuthorization
Authorized
AdmissionPending
AdmissionRejected
Submitted
PartiallyFilled
Filled
AuthorizationRejected
Cancelled
Failed
Expired
Invalidated
```

- `PendingAuthorization` 只允许来自 operator-approval 路径。
- `Authorized` 必须已冻结类型一致的 `AuthorizationEvidence`。
- `AdmissionPending` 是 row-locked submission claim，不是新授权。
- `AdmissionRejected`、`AuthorizationRejected` 分别表示 execution preflight 与 operator grant 的不同失败 owner。
- 历史 intent 不因当前 entry policy 变化而重写状态或 evidence。

### 2.3 Runtime controls

`system_runtime_control` 单例只拥有：

- `entry_authorization_policy`
- `settlement_write_policy`
- `kill_switch_state`
- kill-switch latch/ack 事实
- revision、actor、reason、changed_at

kill switch 是四态：`Closed`、`ExecutionHalted`、`ExitOnly`、`EmergencyHalted`。报告不读它作为可见性开关。

### 2.4 金钱与 identity

- USD、price、shares、probability 使用 Decimal newtypes。
- UUID-backed ID 和 `ContentHash` 为 fixed-width typed value。
- `OrderIntentId`、`ExecutionOrderId`、venue order identity、reconciliation identity 不得在 retry 时重新生成。
- `RiskEnvelope::envelope_hash`、prepared order hash、authorization evidence hash 和 account-chain source hash 是不同 anchor。

## 4. 事务边界

### 4.1 Intent creation

同一 PostgreSQL transaction 原子完成：

- intent insert
- capital allocation insert
- sibling-intent exclusion / idempotency
- 任何 repository-owned operation log/outbox

### 4.2 Operator authorization

对 intent 行加锁后，在同一 transaction 重读 recommendation/report、runtime control、capital 与 invalidation 事实。只能收紧下单参数，然后原子：

- `PendingAuthorization -> Authorized`
- 写 operator `AuthorizationEvidence`
- 缩小 capital reservation（如有 override）
- 记录 governed audit

### 4.3 Submission claim

`Authorized -> AdmissionPending` 与 entry-condition `Claimed -> Consumed` 在一个短事务中原子完成。Venue 调用不得持有数据库锁。

### 4.4 Recovery

已持久化的 submission 不再取 nonce、不换 target、不重签。进程重启后由 durable identity 继续 polling/reconciliation。

## 5. 错误与失败语义

- Domain denial 是 typed result/error，不使用 catch-all string bucket。
- 缺 credentials、缺 account truth、stale book、无效 evidence、degraded economic health、recovery incident、kill switch 都 fail closed。
- Absence 不编码为 zero、unfilled 或 success。
- Operator grant 不能绕过 recommendation blocker、risk envelope、account recovery 或 admission。
- 外部账户成交进入 strict recovery，不伪造 intent/order 来补历史。
