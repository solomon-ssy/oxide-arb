# 05.0 — Execution Foundation & Contracts

> 父：[`README.md`](README.md) · 概念规格：[`../05-execution-risk-and-governance.md`](../05-execution-risk-and-governance.md) §2/§4/§8/§9/§11、
> [`../09-account-capital-position-reconciliation.md`](../09-account-capital-position-reconciliation.md) §4
>
> 闭环定位：**契约 / 脚手架 / 破坏式重构**。把 05.1–05.7 要消费的全部强类型、表、FSM 枚举、
> repository trait、RBAC 资源/操作、typed error、核心 trait 骨架一次性立好，使后续子phase都
> 建立在稳定契约上。本子phase**不**实现 mode preflight / 审批 / admission / 下单 / 对账 / 退出
> 业务逻辑，只立"地基"。

## 1. 目标与闭环定位

交付六类地基：

1. **三张缺失表**（catalog 驱动 entity/iden/迁移/DTO）：`quant_capital_allocation`（资金状态机）、
   `quant_position`（持仓账本）、`quant_reconciliation`（对账证据链 + 结果）。
2. **执行 FSM 枚举**：`CapitalAllocationState` / `PositionLedgerState` / `ReconciliationResult` /
   `ReconciliationEvidenceKind` / `KillSwitchState` / `AdmissionOutcome` / `AdmissionCheckId` /
   `EntryExecutionState` / `ExitState` / `ExitReason` / `ModeDenialReason`。
3. **kill switch operational 单例**：`system_kill_switch` 表 + 破坏式删除 runtime-config 布尔
   `KillSwitchPolicy.enabled`。
4. **repository 补齐**：`PgExecutionOrderRepository`、`CapitalAllocationRepository`、
   `PositionRepository`、`ReconciliationRepository`、`KillSwitchStateRepository`、扩展
   `OrderIntentRepository`、`PgAttributionRepository`。
5. **RBAC 扩展**：新增 `ResourceType::{OrderIntent, ExecutionOrder, Position}`、新增
   `Operation::{Approve, Cancel, Submit}`，更新 `RESOURCE_OPERATIONS` 目录。
6. **错误分层 + 核心 trait 骨架**：`ExecutionError` typed sub-error；`RuntimeModeGate` /
   `OrderIntentService` / `ExecutionAdmissionEngine` / `ExitMonitor` / `PolymarketOrderClient`
   trait 签名（实现留各自子phase）。

本子phase完成后，05.1 可直接消费 kill-switch 表 + 模式转换契约，05.2 可消费 capital FSM +
intent service trait，05.3+ 可消费 admission/exit trait。

```rust
    AdmissionDenied,           // 详见 AdmissionDecision.trace（类型化结果，非 message）
    #[error("approval invalid: {0:?}")]
    ApprovalInvalid(ApprovalInvalidation),
    #[error("kill switch blocks {0}")]
    KillSwitchBlocks(&'static str),
    #[error("capital recovery failed for intent {0}")]
    CapitalRecoveryFailed(String),
    #[error("reconciliation unresolvable blocks auto execution")]
    ReconciliationUnresolvable,
    #[error("mode transition {from:?} -> {to:?} forbidden")]
    ModeTransitionForbidden { from: QuantRuntimeMode, to: QuantRuntimeMode },
    #[error("mode preflight failed: {0}")]
    ModePreflightFailed(String),
}
```

`QuantError` 加 `#[from] execution::ExecutionError`（变体 `Execution`），`code()` 加 `"execution"`。
web `error.rs` 映射：`ReportOnlyMode`/`AdmissionDenied`/`KillSwitchBlocks`/`ModeTransitionForbidden`
→ 409 Conflict；`RecommendationExpired`/`ApprovalInvalid` → 409；`ModePreflightFailed` → 409；
`CapitalRecoveryFailed`/`ReconciliationUnresolvable` → 503/409（05.1/05.4 定稿）。
**admission denial 是 `AdmissionDecision`（类型化结果），不是 error**——只有"无法评估"才走 error。

## 6. 生产不变量与失败语义

- **catalog 驱动 schema**：三张新表 + kill-switch 表只改 iden + entity + DTO + `schema/graph.rs`
  catalog 列表 + `pg_enum_catalog` 计数；**禁止手写 SQL 迁移**。
- **资金守恒（capital FSM）**：任一时刻 `allocated_usd = locked_usd + (allocated 未锁定部分)`；
  `spent_usd ≤ locked_usd`；终态 `released_usd + spent_usd = allocated_usd`（cancel/fail 全释放、
  fill 部分 spent 部分释放）。违反即 `Impaired` + 人工。
- **money newtype**：三表所有金额/价格/份额用 `Usd`/`Price`/`Shares`；`f64` 不进 DTO/表。
- **WORM 审计**：`quant_reconciliation` append-only（lifecycle = audit），结果只追加证据/resolve，
  不可篡改历史。
- **kill switch 单例可恢复**：boot 时 `KillSwitchStateRepository::load` 缺行 → fail-closed 重 seed
  `Closed`（仿 `restore_quant_runtime_mode`，[`bundles/governance.rs`](../../../crates/quant-pivot-core/src/app/bundles/governance.rs) §153–163）。
- **错误分层**：本期所有新错误进 `ExecutionError`；生产 `src/` 禁止 `QuantError::Internal(`
  （`lint-quant-pivot-errors.sh` 强制）；venue SDK 错误经 `ApiError` façade。
- **trait-only 不留死实现**：05.0 立 trait + repository impl 骨架，但**不**接 worker/handler；
  未消费的 trait 不得在 `AppContext` 暴露（避免死代码 lint）。

## 7. 第三方 crate 引入

- `good_lp` 在 **05.8** 引入（feature-gated）；05.0 本期不引入第三方 crate，portfolio 仍 greedy。

## 9. Blocker

- 若三张新表任一未进 catalog 或仍走手写 SQL 迁移，失败。
- 若 capital FSM 金额可破坏守恒（无 `Impaired` 兜底），失败。
- 若 kill-switch operational 状态仍由 runtime-config 布尔表达（未删 `enabled`），失败。
- 若 money 域出现 `f64`，失败。
- 若新增错误未进 `ExecutionError` 或生产 `src/` 用 `QuantError::Internal(`，失败。
- 若 `quant-pivot-error` 直接依赖 venue SDK 类型，失败。
- 若 05.0 暴露未实现的 trait 到 `AppContext` 造成死代码，失败。
