# 05.9 — Equity History, Drawdown and Capital-Occupancy Constraints

<!-- quant-pivot-deployment-contract:v1 -->
> **Clean-break contract**：drawdown 不再缩放 Kelly/sizing fraction。真实 equity、high-water mark、
> drawdown 与 locked capital 作为全局 portfolio 的 frozen state 和 hard constraints。

## 1. 目标

维护可审计 `EquitySnapshot`、high-water mark、drawdown、existing exposure 与 capital-occupancy state，供
每次跨 Route `GlobalPortfolioPlan` 使用。报告和执行都基于真实 venue account；不存在模拟资金或 configured-budget fallback。

## 2. Frozen state

报告开始冻结：

- collateral、positions、pending/reserved intents；
- net liquidation value 与 configured budget cap；
- high-water mark、current drawdown USD/bps；
- market/event/category/Route exposure；
-各 capital time bucket 的 existing locked capital；
- source timestamps、credential/account identity 和 reconciliation evidence。

任一必需 account/equity read 失败时报告 fail closed，不用 configured budget 冒充账户。

## 3. Global constraints

- `capital_base = min(real NLV, policy total budget)`。
- available allocation 同时扣除 cash reserve、reserved intents 和 existing locked capital。
- current drawdown + worst scenario loss 不得超过 max drawdown hard cap。
- scenario CVaR 不得超过 policy cap。
- 每个 future time bucket 的 existing + selected tier capital occupancy 不得超过 bucket cap。
- existing positions 进入 market/event/category/Route exposure constraints。

drawdown、capital time 或 exposure 不能作为独立 multiplier 静默缩小 candidate；必须成为可解释的
binding constraint/rejection evidence。

## 4. Persistence

`quant_equity_snapshot` 保存 venue/account identity、collateral、position value、NLV、high-water mark、drawdown、
reserved capital、source timestamps 和 reconciliation digest。`GlobalPortfolioPlan` 引用 exact snapshot ID/
hash，并保存各 time bucket before/after usage。

## 5. Execution reconciliation

execution admission 在提交前重新读取实时 balance/positions/reservations，并只能 deny/defer 或向下选择报告
已允许的 lower economic tier；不能扩大、重新优化或改变 Route lineage。fill/exit/settlement 更新 equity
history，不能回写已发布报告。

## 6. 验收

- real NLV、budget cap、cash reserve 与 reserved intent accounting。
- high-water mark/drawdown deterministic replay。
- current drawdown + scenario loss hard-cap binding。
- overlapping Route positions 在同一 time bucket 争用资本。
- venue/account failure 不生成报告。
- report/execution snapshot lineage 与 restart recovery。
