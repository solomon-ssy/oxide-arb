## 1. 目标

`CoreOrderIntentService` 是 recommendation 进入执行平面的唯一常规路径。它负责：

- 重读当前 recommendation/report/account/policy/runtime-control truth。
- 根据 recommendation ceiling/blockers 和 `EntryAuthorizationPolicy` 决定初始 authorization state。
- 冻结 entry order、exit policy、risk envelope、model/profile/policy lineage 和 execution account。
- 与 capital allocation 在一个 transaction 中创建 intent。
- 执行 operator approve/reject/cancel 与 background expire/invalidate。
- 在 intent 获得 `Authorized` 后只发出 wake hint；PostgreSQL 行才是 durable queue。

## 2. 创建路径

### 2.1 共同前置

任何 create 都必须验证：

1. feature-parity latch clear；
2. recommendation 未过期且允许新 intent；
3. source report 仍 `Published`，且 report facts verified；
4. global plan、Route、economic tier 与 represented-routes lineage 一致；
5. recommendation ceiling/blockers/policy binding 完整；
6. model/profile/trade-policy 仍可执行，calibration 可验证；
7. 报告冻结的真实 account snapshot 存在；
8. kill switch 允许新入场；
9. 同 recommendation 没有 sibling-blocking intent；
10. entry-condition instance 存在，需要自动 settlement recovery 时对应独立门禁 ready。

### 2.2 Operator approval policy

```text
EntryAuthorizationPolicy::OperatorApprovalRequired
 + ceiling allows operator
 + blockers empty
 -> PendingAuthorization
 -> authorization_kind = OperatorApproval
 -> authorization_evidence = None
```

`expires_at` 由 canonical operator-approval TTL 和 entry valid window 共同限制。创建 intent 不等于授权，也不允许 dispatcher 提交。

### 2.3 Policy-automatic policy

```text
EntryAuthorizationPolicy::PolicyAutomatic
 + ceiling == PolicyAutomatic
 + blockers empty
 + exact active policy binding
 + fresh Healthy RouteEconomicHealth
 + account recovery / kill switch / preflight ready
 -> Authorized
 -> authorization_kind = ActivePolicy
 -> immutable ActivePolicy AuthorizationEvidence
```

任一事实 missing、stale、degraded 或 identity mismatch 都 fail closed，不降级为 operator grant，不生成缺 evidence 的 intent。

## 3. Operator authorization

`POST /api/quant/intents/{id}/approve` 是对 `PendingAuthorization` 的 governed grant。服务端在 intent 行锁内重读不可绕过的事实：

- recommendation/report 仍 actionable；
- frozen lineage 仍存在且可验证；
- account/capital 仍与冻结 execution account 一致；
- kill switch/account recovery 不阻断；
- intent 未过期，没有并发 terminal transition。

Operator override 只能收紧：

- shares 不增加；
- limit price 不放宽；
- max notional/capital reservation 只减少。

成功时原子完成：

```text
PendingAuthorization
 -> Authorized
 -> AuthorizationEvidence::OperatorApproval { operator_id, reason, authorized_at }
 -> shrink reservation if requested
 -> governed audit
```

如重读发现 invalidation，intent 进入 `Invalidated` 并释放 capital，不部分写入 evidence。

## 4. Reject / cancel / expiry / invalidation

| Action | Allowed source | Result | Capital |
|---|---|---|---|
| reject | `PendingAuthorization` | `AuthorizationRejected` | release |
| cancel | 未提交且 FSM 允许的 pre-submission state | `Cancelled` | release |
| expire | 到达 immutable expiry 的 active pre-submission state | `Expired` | release |
| invalidate | report/recommendation/policy/account lineage 不再成立 | `Invalidated` | release |

HTTP governed mutations 使用 authenticated actor、`X-Acting-Role`、reason 和 operation audit。Background expiry/invalidation 在同一 repository transaction 写 operation log/outbox。

## 5. FSM 与并发

```text
PendingAuthorization --approve--> Authorized
PendingAuthorization --reject--> AuthorizationRejected
PendingAuthorization --expire/cancel/invalidate--> terminal

Authorized --claim--> AdmissionPending
Authorized --expire/cancel/invalidate--> terminal

AdmissionPending --defer--> Authorized
AdmissionPending --deny--> AdmissionRejected
AdmissionPending --submit--> Submitted
```

- 一个 recommendation 同时只能有一个 sibling-blocking intent。
- approve/reject/cancel/expire/invalidate 对同一行串行化，只能有一个 transition 成功。
- 幂等 retry 返回相同 terminal/current fact；不因 request retry 产生第二份 capital allocation 或 evidence。
- Runtime-control policy 后续变化不改写已冻结 evidence，但 submission admission 仍会读当前 fail-closed controls。

## 6. API

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/api/quant/intents` | paginated read |
| `GET` | `/api/quant/intents/{id}` | intent + condition/exit observation |
| `POST` | `/api/quant/intents` | create from recommendation |
| `POST` | `/api/quant/intents/{id}/approve` | freeze operator authorization |
| `POST` | `/api/quant/intents/{id}/reject` | reject pending authorization |
| `POST` | `/api/quant/intents/{id}/cancel` | cancel eligible pre-submission intent |

前端不传 recommendation-derived ceiling/blockers/policy evidence，不自行推导 authorization state。所有 wire money 使用 decimal string。

## 7. Observability

- intent created/authorized/rejected metrics 按 `authorization_kind` 低基数标注。
- lifecycle event 区分 `Created`、`Approved`（event action）、`AuthorizationRejected`、`Invalidated` 等，事件名不是第二套持久化 FSM。
- 不把 operator reason、intent id 或错误文本放入 Prometheus label。

## 8. 验收

- operator create/approve/reject/cancel/expire/invalidate 的 repository 事务和 race matrix。
- policy-automatic ceiling/blocker/policy hash/economic-health/preflight 正反例。
- operator downscale 不能增加 shares/price/notional，capital 缩小与 intent 原子。
- sibling intent、stale report、revoked recommendation、kill switch、recovery incident 全部 fail closed。
- API RBAC/acting-role/reason/audit 与 Rust↔TypeScript schema sync 通过。
- 旧 approval status/field/parser 在 active code/schema/UI/docs 中不存在。
