## 1. 目标与闭环定位

1. `ExecutionAdmissionEngine` impl（`DefaultAdmissionEngine`）：按父文档 §4.2 固定顺序执行 20 个
   check，任一 hard check fail 即 `deny`（短路或全量评估见 §6）。
2. `AdmissionInputBuilder`：把 intent + 最新 book snapshot + account snapshot + active config +
   risk state + kill switch + 当前敞口 + recommendation evidence 聚合为 `AdmissionInput`（只读、
   决策时刻冻结）。
3. `AdmissionDecision`：`outcome` + `trace: Vec<AdmissionCheckTrace>` + `state_version`，每个 trace
   含 check id / threshold / actual / elapsed / denial reason。
4. **metric**：`quant_admission_denied_total`（按 check id 分桶）。

本子phase完成后，05.4 `submit_if_admitted` 直接调 `engine.evaluate(input)`，仅 `allow` 才建单提交。

## 3. 新领域类型 / 表 / ClickHouse fact

- 无新表。
- 新值类型（`core/src/execution/admission/` 模块目录）：`AdmissionInput` / `AdmissionDecision` /
  `AdmissionCheckTrace` / `StateVersion` / `VenueHealth` / `AdmissionCheck` trait。
- 复用枚举（05.0）：`AdmissionOutcome` / `AdmissionCheckId`。**check 级结果直接复用
  `AdmissionOutcome { Allow, Deny, Defer }`**（`Allow` = 通过）；不再引入 `AdmissionCheckOutcome`

**as-built（与 05.0 草案的差异）**：05.0 草案里的 `ModelPublicationState` / `DataQualitySnapshotInfo`
两个类型不存在；改为 builder 预解析的 `model_published: bool`（由 `ModelRegistryRepository` 查
`publication_status == Published`）与现成的 live `DataQualitySnapshot`（`DataQualityPort::snapshot()`）。
`config: Arc<RuntimeConfig>` 不进入冻结输入：builder 把它蒸馏成 `budget_total_usd` 与 `manual_block`
两个判定值（无 check 直接读 config，避免冗余冻结态；config 版本由 `state_version.config_version_id`
负责可回放）。`#18 VenueGuard` / `#19 CredentialReadiness` / `#20 ExitMonitorReadiness` 通过 seam
字段读取（见 §6 与 05.4/05.6）。

```rust
pub struct AdmissionInput {
    pub intent: OrderIntentInfo,
    pub recommendation: RecommendationInfo,     // 含 EntryPlan/SizingPlan/RiskEnvelope/Eligibility

pub struct AdmissionDecision {
    pub outcome: AdmissionOutcome,               // Allow / Deny / Defer（fold：任一 Deny→Deny；否则有 Defer→Defer；否则 Allow）

    pub state_version: StateVersion,
    pub elapsed_ms: u64,

pub struct AdmissionCheckTrace {
    pub check: AdmissionCheckId,
    pub outcome: AdmissionOutcome,               // Allow=通过 / Deny / Defer
    pub threshold: Option<String>,
    pub actual: Option<String>,
    pub elapsed_us: u64,                          // 由引擎逐 check 计时填充
    pub detail: String,
}
```

## 4. 20 个 check（固定顺序，父文档 §4.2）

每个 check 是 `trait AdmissionCheck { fn id(&self) -> AdmissionCheckId; fn severity(&self) -> Severity;
fn run(&self, input: &AdmissionInput) -> AdmissionCheckTrace; }`，引擎按下表顺序执行。

| # | check | severity | 判定 | 拒绝映射 |
|---|---|---|---|---|
| 1 | `IntentStateCheck` | hard | intent ∈ {Approved, ApprovedByPolicy}、未过期 | deny |
| 2 | `RecommendationFreshnessCheck` | hard | `rec.valid_until ≥ now`、entry 窗口 `valid_from ≤ now ≤ valid_until` | deny |
| 3 | `ReportStatusCheck` | hard | report `Published`（非 revoked/expired） | deny |
| 4 | `RuntimeModeCheck` | hard | mode ∈ {semi_auto, auto_execution}；auto 需 `ApprovedByPolicy` | deny |
| 5 | `ModelPublicationCheck` | hard | intent.model_version 仍 published（未 retire） | deny |
| 6 | `DataQualityCheck` | hard | DQ snapshot ≥ 阈值、新鲜；plane stale ratio ≤ `data_quality.max_stale_book_ratio_bps` | deny |
| 7 | `BookFreshnessCheck` | hard | book 存在且 `age_ms ≤ entry.max_book_age_ms` | defer（可重试）/ deny if 缺 book |
| 8 | `EntryTriggerCheck` | hard | 触发条件满足：`Immediate` 直过；`Limit` 价格满足 `trigger_price`；**Phase 4 仅发布此二者**（`derive_entry_plan`），其它 kind → deny | defer（未触发）/ deny（unsupported kind） |
| 9 | `RiskEnvelopeHashCheck` | hard | 重算 rec `RiskEnvelope` canonical hash == `intent.risk_envelope_hash` | deny |
| 10 | `CapitalBudgetCheck` | hard | `account.available_usd ≥ intent size` 且 ≤ `budget.total_budget_usd` 剩余 | deny |
| 11 | `MarketExposureCheck` | hard | `account.exposures.per_market + size ≤ constraints.max_market_exposure_usd` | deny |
| 12 | `EventExposureCheck` | hard | per_event + size ≤ max_event_exposure_usd | deny |
| 13 | `CategoryExposureCheck` | hard | per_category + size ≤ max_category_exposure_usd | deny |
| 14 | `LiquidityDepthCheck` | hard | book 深度 ≥ `entry.min_depth_usd`（size 可成交） | defer/deny |
| 15 | `SlippageCheck` | hard | 预估滑点 ≤ `entry.max_slippage_bps`（按 book 模拟吃单） | deny |
| 16 | `ManualBlockCheck` | hard | 市场未被人工封禁（`input.manual_block == false`） | deny |
| 17 | `KillSwitchCheck` | hard | `kill_switch.allows_new_entry()`（05.1） | deny |
| 18 | `VenueGuardCheck` | hard | venue 健康（无连续失败/熔断；`ClobClient` 近期 error rate） | defer/deny |
| 19 | `CredentialReadinessCheck` | hard | 签名凭证就绪（私钥 + L2 已 auth）；semi_auto/auto 才需签名 | deny |
| 20 | `ExitMonitorReadinessCheck` | hard | exit monitor 可注册（05.6 worker 健康） | deny |

- **defer vs deny**：`defer` 表示"现在不行，但可稍后重试"（book stale / 未触发 / 流动性暂不足 /
  venue 暂态），不计审计失败；`deny` 表示"硬违例，本 intent 不应执行"（hash mismatch / 过期 /
  超敞口 / kill-switch / 人工封禁）。任一 hard `deny` → 整体 `Deny`；无 deny 但有 hard `defer` →
  整体 `Defer`；全 pass → `Allow`。
- `has_unresolvable_recon == true` 在 auto_execution 下使 `KillSwitchCheck` 等价 deny（父文档 §11：
  unresolvable 阻断 auto）；实现可作为 `KillSwitchCheck` 的附加条件或独立 hard 条件（保持 20 项编号，
  unresolvable 并入 #17 语义）。

## 5. 引擎执行（父文档 §16.4）

```rust
impl ExecutionAdmissionEngine for DefaultAdmissionEngine {
    async fn evaluate(&self, input: AdmissionInput) -> QuantResult<AdmissionDecision> {
        let start = Instant::now();
        let mut trace = Vec::with_capacity(20);
        let mut outcome = AdmissionOutcome::Allow;
        for check in &self.checks {                 // 固定顺序（编译期数组，1..=20）
            let t = check.run(&input);
            match t.outcome {
                HardFail => { outcome = Deny; trace.push(t); break; }   // 短路（§6 可选全量）
                Defer if outcome == Allow => outcome = Defer,
                _ => {}
            }
            trace.push(t);
        }
        record_metric(&trace, outcome);
        Ok(AdmissionDecision { outcome, trace, state_version: input.state_version,
                               elapsed_ms: start.elapsed().as_millis() as u64, denial_reason })
    }
}
```

> **短路 vs 全量**：默认 hard deny 即短路（生产路径快、安全优先）；提供 `evaluate_full`（全量跑完
> 所有 check 用于诊断/审计/测试），决策语义一致（首个 deny 决定 outcome）。trace 始终记录已执行项。

**as-built seams / hash anchor**:
- **#9 `RiskEnvelopeHashCheck`** recomputes via the single shared
  `quant_pivot_models::types::canonical_risk_envelope_hash` (the portfolio planner mints the hash with
  the same function — zero duplication, byte-identical), then compares to `intent.risk_envelope_hash`.
- **#18 `VenueGuardCheck`** reads `input.venue_health` (`VenueHealth`); 05.3 supplies `Healthy`. The
  real auto-trip **execution breaker** (consecutive venue failures / error-rate window → escalate
  kill-switch) lands in **05.4** (see that doc); it drives `venue_health` and is fed by the venue
  client / reconciliation / realized-loss signals.
- **#19 `CredentialReadinessCheck`** reads `credentials_ready` (read+sign keystore + funder present in
  05.3; a dedicated signer-health probe lands with the venue client in 05.4).
- **#20 `ExitMonitorReadinessCheck`** reads `exit_monitor_ready` (placeholder `true`; real worker
  health in 05.6).

- account snapshot：复用 04.0 `AccountProvider`（决策时刻真实账户）。
- book：`BookStore` published snapshot（热读，无 I/O）。
- config：`DecisionPolicyStore` 当前快照（ArcSwap）；builder 蒸馏 `budget_total_usd`、
  `manual_block`、`max_stale_book_ratio_bps`（check 不直接读 config）。
- mode/kill-switch：05.1 handle 热读。
- `state_version`：聚合各源版本/时间戳，写入 decision（可回放、可比对）。
- builder I/O：recommendation 串行首读（需 `report_id`）；report / model / recon / allocation /
  config-version / account snapshot **并行** `tokio::join!`。

## 6. 生产不变量与失败语义

- **固定顺序**：20 个 check 顺序由编译期数组保证（父文档 §4.2 顺序，测试断言）；不可配置乱序。
- **只读 / 不下单 / 不改报告**：admission 无写 DB（除 metric）、无 venue 调用产生副作用
  （VenueGuard 只读健康态）；输出仅 `AdmissionDecision`。
- **类型化结果非 error**：`deny`/`defer` 是 `AdmissionOutcome`，不是 `QuantError`；只有"无法构建
  输入/无法评估"（如 account 读失败）才返回 `QuantError`（fail closed → 视同不可执行）。
- **fail closed**：缺 book、缺 account、缺 config → 不 allow（deny/defer + denial_reason），绝不
  默认放行。
- **hash 锚执行层 ↔ 报告层**（README §5.5）：`RiskEnvelopeHashCheck` 是两层唯一锚；mismatch 必拒。
- **state_version 可回放**：decision 落 trace + state_version，05.4 提交时一并记录到
  execution_order / op-log，事后可复现"为什么允许/拒绝"。
- **确定性**：同一 `AdmissionInput` 必产同一 `AdmissionDecision`（check 纯函数，无随机/无 wall-clock
  除 `input.now`）。
- **money newtype**：所有阈值/实际值比较用 `Usd`/`Price`/`Bps`；trace 的 string 仅展示。

## 9. Blocker

- 若 check 顺序与父文档 §4.2 不符，失败。
- 若 admission 写报告 / 下单 / 产生 venue 副作用，失败。
- 若任一缺输入时默认 allow（非 fail-closed），失败。
- 若 `deny`/`defer` 被建模为 error（而非类型化结果），失败。
- 若 hash mismatch 不拒，失败。
- 若 unresolvable 对账不阻断 auto，失败。
