## 1. 目标

Admission 是 `Authorized` intent 和真实 venue submission 之间的唯一固定顺序判定门。

- `AdmissionInputBuilder` 是唯一 I/O owner，它一次性读取并冻结所有 decision-time facts。
- 26 个 `AdmissionCheck` 都是对 immutable input 的纯函数。
- `DefaultAdmissionEngine` 产生 `Allow | Deny | Defer` + per-check trace + replayable `StateVersion`。
- Admission 不改 recommendation，不缩放 order，不写数据库，不调 venue。

## 2. `AdmissionInput`

Builder 必须在一个 decision boundary 内冻结：

| Domain | Required facts |
|---|---|
| Intent | `Authorized` status、immutable authorization kind/evidence、expiry、entry/exit/risk hashes |
| Recommendation/report | status、valid window、Route/model/profile/policy/global-plan lineage、risk envelope |
| Runtime control | current `EntryAuthorizationPolicy`、kill switch、`SettlementWritePolicy`、revision |
| Economic feedback | exact model/profile/policy identity 的 latest Route economic health、state、freshness、hash |
| Account/capital | real venue account snapshot、当前 allocation、budget/open-intent/reserved/exposure totals |
| Market/book | published L2、book version/age、data quality、official venue metadata、tick/neg-risk |
| Economics | PIT fee schedule、maker rebate evidence、full-depth executable walk |
| Recovery | blocking ambiguous/unresolvable exposure、settlement-recovery readiness |
| Operational seams | venue breaker health、credential readiness、exit-monitor readiness |

任一 mandatory I/O 失败都是 fail-closed build error；只有明确允许缺席的 fact（例如缺 book）才编码为 `None`，并由对应 check 转成 typed deny/defer。

## 3. Authorization 合同

`AuthorizationPolicyCheck` 验证 current policy 与 frozen intent provenance 一致：

| Current policy | Required intent evidence |
|---|---|
| `OperatorApprovalRequired` | `Authorized` + `AuthorizationKind::OperatorApproval` + matching operator evidence |
| `PolicyAutomatic` | `Authorized` + `AuthorizationKind::ActivePolicy` + matching active-policy evidence |

这一重验不改写 intent。Policy drift 时 fail closed，操作者必须使用当前策略创建新 intent，不能将历史 evidence 转成另一类 grant。

`EconomicHealthCheck` 只能收紧：

- `Degraded` / `DataIncomplete` 对所有入场 deny。
- Active-policy authorization 还必须是 fresh `Healthy`。
- Operator authorization 不需要正向 Healthy 证据，但不得绕过已知 degraded/data-incomplete 证据。

## 4. Canonical 26-check order

| # | Check | Owner / result |
|---:|---|---|
| 1 | `IntentState` | intent 必须 `Authorized` 且未过期 |
| 2 | `RecommendationFreshness` | recommendation 与 entry window |
| 3 | `ReportStatus` | source report 仍 `Published` |
| 4 | `AuthorizationPolicy` | current policy 与 frozen evidence 一致 |
| 5 | `EconomicHealth` | Route economic state/freshness |
| 6 | `SettlementRecovery` | 冻结 exit promise 需要时具有当前 recovery path |
| 7 | `ModelRouteBinding` | current Route 仍授权 frozen model |
| 8 | `DataQuality` | data-plane quality 不越界 |
| 9 | `BookFreshness` | exact token book 存在且新鲜 |
| 10 | `VenueMetadata` | registry 与 official venue tick/neg-risk 一致 |
| 11 | `EntryConditionPlan` | condition 与 frozen entry plan 可 claim |
| 12 | `RiskEnvelopeHash` | 重算 hash 与 intent anchor 一致 |
| 13 | `CapitalBudget` | real available collateral 与 governed total budget |
| 14 | `MaxOpenIntents` | concurrent capital-holding intents cap |
| 15 | `MaxReservedCapital` | total reserved capital cap |
| 16 | `MarketExposure` | market cap |
| 17 | `EventExposure` | event cap |
| 18 | `CategoryExposure` | category cap |
| 19 | `LiquidityDepth` | full-depth executable fill |
| 20 | `Slippage` | executable walk 不越过 frozen bound |
| 21 | `ManualBlock` | manual market/blocking-inflight guard |
| 22 | `KillSwitch` | 只有 `Closed` 允许新入场 |
| 23 | `VenueGuard` | transient venue health；可恢复状态 defer |
| 24 | `CredentialReadiness` | signer/CLOB credentials ready |
| 25 | `ExitMonitorReadiness` | exit worker 已完成首次扫描 |
| 26 | `CalibratedReturnModel` | frozen return model/calibrator 当前可验证 |

顺序是合同：经济、身份和安全不变量早于较贵的 L2/economics 判定，并使首个 hard denial 稳定可观测。

## 5. Decision semantics

### `Allow`

26 个 check 全部通过。`Allow` 只授权 dispatcher 继续它自己的 write-ahead transaction，不是 venue acceptance 事实。

### `Deny`

不可在同一 frozen input 上通过重试恢复的违反。Dispatcher 把 intent 收敛为 `AdmissionRejected`，保存 trace/state version 并释放未使用 capital。

### `Defer`

当前不可执行但可由时间/健康恢复的状态，例如 entry window 未开或 venue breaker transient degraded。Dispatcher 把 claim 收敛回 `Authorized`，保留原 authorization evidence 并等待 durable queue 重试。

## 6. Determinism and replay

`StateVersion` 至少冻结：

- config snapshot id
- account/book observation identity
- PIT fee/maker-rebate hashes
- kill-switch and settlement-write states
- settlement deployment/finality evidence
- Route economic-health id/hash/state

`evaluate` 在首个 hard deny 后 short-circuit；`evaluate_full` 运行全部 checks。两者对同一 input 必须产生相同 final outcome，差异只在 trace 完整度。

## 7. 失败语义

- Builder mandatory read 失败是 typed error，caller 必须当作 not executable。
- Check violation 是 typed outcome，不用 exception 伪装。
- 缺 book/account/fee/economic-health/calibration 不得回落旧 snapshot、configured default 或 zero。
- Operator evidence 不能跳过 risk、recovery、kill switch、economic degradation 或 model binding。
- Checks 不读 wall clock，只使用 `input.now`。

## 8. 验收

- 26-check order/count 是 compile-time invariant，ID 与 trace 稳定。
- 每个 check 有 allow/deny/defer boundary tests，经济授权与 account-recovery 有正反例。
- short-circuit/full evaluation 的 final outcome 一致。
- Builder 覆盖并行 read、missing mandatory source、stale identity 和 exact PIT economics。
- Admission 不产生 DB write、venue call 或第二套 book/fee engine。
- metrics 只使用 closed check ID 标签，不记录高基数 detail。
