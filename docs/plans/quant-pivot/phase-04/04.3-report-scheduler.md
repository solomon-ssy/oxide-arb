## 1. 被取代的历史边界

Phase 04.3 曾采用进程内 `tokio-cron-scheduler`、per-schedule overlap guard、内存 job registry 和
ephemeral fire。该实现完成了单进程阶段的基础调度，但无法闭合以下生产不变量：

- 进程重启后无法恢复 occurrence、run 或 missed tick 真相；
- 多副本会各自注册相同 schedule；
- overlap 只记录 metric，不形成 durable gap；
- ad-hoc 与不同 schedule 在 lifecycle 全局 mutex 后排队，可能携带过时 trigger time；
- report build 和 schedule execution 没有 durable identity/lease/CAS。

因此 Phase 11.8 破坏式删除：

- `tokio-cron-scheduler` dependency；
- `TokioCronScheduleRunner`、`ScheduleOverlapGuard`、`job_factory`；
- 内存 job registry 和 lifecycle global waiting mutex；
- “skip silently / no catch-up record”的历史策略。

## 2. 当前权威语义

- PostgreSQL `quant_report_schedule_state` 是 schedule cursor 真相。
- `quant_report_run` 是 scheduled/ad-hoc execution 真相。
- `quant_report_schedule_gap` 是 missed/coalesced/reconfigured occurrence 真相。
- `croner` 仅计算 next occurrence，不持有 job lifecycle。
- coordinator 使用 `FOR UPDATE SKIP LOCKED`、lease、heartbeat、partial unique index 支持多副本。
- 同 schedule 只保留 latest queued occurrence；更旧 occurrence 聚合为 gap。
- 永不历史 backfill；`decision_at` 是实际 DB claim time，`scheduled_for` 只用于审计。
- report TTL/intent TTL 等 deadline scheduler 仍是各自独立 worker，不并入 report coordinator。
