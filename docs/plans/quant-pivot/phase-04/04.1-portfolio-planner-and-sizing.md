### 5.1 `SizingModel` trait

```rust
/// 单候选规模建议（资本基数比例）。纯函数：无 I/O、无 clock、无可变状态。
pub trait SizingModel: Send + Sync {
    fn kind(&self) -> SizingModelKind;

    /// 给定候选 + 资本基数，产出"建议下注的 USD"（未受 caps 收敛）或拒绝。
    fn suggest(&self, input: &SizingInput<'_>) -> QuantResult<SizingOutcome>;
}

pub struct SizingInput<'a> {
    pub candidate: &'a SignalCandidate,
    pub equity_usd: Usd,               // = AccountSnapshot.equity_usd
    pub drawdown_state: DrawdownState, // 当前回撤（驱动 drawdown_scaling）
}

pub enum SizingOutcome {
    Sized(SizingSuggestion),
    Rejected(RejectionReason),         // NoPositiveSignal | InvalidEdgeInputs
}

pub struct SizingSuggestion {
    pub desired_usd: Usd,                       // 建议规模（受 max_position_pct 后、caps 前）
    pub edge_bps: Option<Bps>,                  // 可审计 edge（provenance；曲线模型 None）
    pub kelly_fraction_applied: Option<Decimal>,// 实际施加的分数乘子（kelly·shrink·dd）
    pub binding_kelly_cap: bool,                // 是否触达 max_position_pct
}
```

### 5.2 Kelly 公式（生产语义，钱相关，逐项可审计）

> **设计纠偏（相对早期草案）**：`confidence` 是模型的**证据/置信质量**（见
> `weighted/mod.rs` 的 `confidence_mass`），**不是校准胜率**，因此**绝不**直接当 `q`。
> 文献（fractional / Bayesian Kelly）一致要求"按估计不确定性收缩下注"——本期让
> `confidence` 作 **Kelly 分数的收缩曲线**，即"Kelly × 置信度曲线"组合；`q` 由
> 期望均值 + 止损 + 目标倍数严格反解。

Polymarket 二元 outcome token：把"持有到 horizon 后按 target/stop 退出"建模为**两结果
赌局** `{win +g, lose −l}`：

```text
l    = downside_bps        / 10_000    // 止损幅度（占下注额）
E[r] = expected_return_bps / 10_000    // 模型期望均值（非条件目标涨幅）
g    = R · l                            // 目标涨幅（R = target_reward_multiple 配置, >0）
q    = clamp( (E[r] + l) / (g + l), 0, 1 )   // 由赌局结构反解的胜率

# 两结果 Kelly 最优下注比例（对数效用最大化）：
f_star = ( q·g − (1−q)·l ) / (g·l)

# fractional + 置信度收缩 + 回撤缩放 + 上限：
f = clamp( kelly_fraction · confidence_shrink(confidence) · drawdown_scale(dd)
           · max(f_star, 0),
           0, max_position_pct )
desired_usd = round_money( f · equity_usd )
edge_bps    = (q·g − (1−q)·l) · 10_000        // provenance（= expected_return_bps，自洽）
```

硬规则：

- `l ≤ 0`（无有效止损）或 `g ≤ 0` ⇒ `Rejected(InvalidEdgeInputs)`，不臆造赌局结构。
- `edge = q·g − (1−q)·l ≤ 0` 或 `f_star ≤ 0`（无正 edge）⇒ `Rejected(NoPositiveSignal)`，
  0 配资。绝不为负 edge 配资。
- `q` 由 `(E[r], l, g)` 反解（用 clamp 后的 `q` 重算 edge，杜绝退化输入虚增 edge）；`q`
  的校准质量由 3.6/3.7 负责。`confidence` 仅作收缩乘子（`confidence_shrink`），与 `q`
  正交、不重复计数。
- 全程 `Decimal`（Kelly 仅四则运算 + 除法，无 log），**完全不出现 `f64`**；`desired_usd`
  始终 `Usd`。
- `max_position_pct` 是**硬上限**：即便 Kelly 建议更大也不超 `max_position_pct·equity`
  （触发即 `binding_kelly_cap = true`，planner 落 `binding_constraint = KellyCap`）。

`KellySizingModel` 参数来自 `SizingModelConfig::Kelly { kelly_fraction, max_position_pct,
target_reward_multiple, confidence_weighting, drawdown_scaling }`。

`confidence_shrink(c)`：`Linear → c`；`Step → {c<0.5: 0.25, c<0.8: 0.5, else: 1.0}`。
`drawdown_scale`：`Fixed → 1.0`；`Conservative → clamp(1 − drawdown, 0, 1)`（本期中性
回撤恒 `1.0`，真实回撤来源 Phase 5）。

### 5.3 `ConfidenceCurveSizingModel`（基线 / shadow）

```text
base = max_single_recommendation_usd
desired_usd = round_money( base · curve(confidence) · drawdown_scale )
# curve = Linear: f(c)=c；Step: 分档常数
edge_bps = None（曲线模型不声明 edge）；从不因 edge 拒绝（size 过小由 planner 标 BelowMinSize）
```

用途：确定性回归基线、与 Kelly 做 shadow 对比（report-level shadow 留 Phase 5；本期
仅支持配置切换 active sizing model）。

### 5.4 `PortfolioPlanner` trait

```rust
pub trait PortfolioPlanner: Send + Sync {
    fn plan(&self, input: PortfolioPlanInput<'_>) -> QuantResult<PortfolioPlanOutput>;
}

/// 规划输入候选（仅市场元数据；desired_usd 由 planner 经 sizing 计算）。
pub struct PlanCandidate<'a> {
    pub candidate: &'a SignalCandidate,
    pub category: MarketCategory,
    pub event_id: Option<EventId>,
    pub liquidity_usd: Option<Usd>,
}

pub struct PortfolioPlanInput<'a> {
    pub portfolio_plan_id: PortfolioPlanId,
    pub model_run_id: ModelRunId,
    pub market_selection_id: MarketSelectionId,
    pub as_of: DateTime<Utc>,
    pub candidates: Vec<PlanCandidate<'a>>,
    pub account: &'a AccountSnapshot,         // 资本基数 + 当前敞口净额（09 §2）
    pub caps: &'a PortfolioCaps,              // budget+constraints 已投影（含 total/single/min/敞口/liquidity）
    pub max_correlated_exposure_usd: Usd,     // 仅写入 plan 快照（本期不真正生效）
    pub sizing: &'a dyn SizingModel,
    pub entry_max_slippage_bps: Bps,          // 落入 RiskEnvelope
    pub top_n: usize,
}

pub struct PlannedRecommendation {
    pub candidate: SignalCandidate,
    pub sizing: SizingPlan,                   // 04.0 强类型
    pub risk_envelope: RiskEnvelope,          // 04.0 强类型（flags 由 04.2 composer 终定）
    pub risk_adjusted_score: Probability,     // 组合约束后排序分
    pub rank: u32,
}

pub struct RejectedCandidate {
    pub signal_candidate_id: SignalCandidateId,
    pub market_id: MarketId,
    pub reason: RejectionReason,              // NoPositiveSignal | InvalidEdgeInputs | BelowMinSize
                                             //  | Budget/AvailableCash/Market/Event/CategoryExhausted
                                             //  | LiquidityInfeasible | BeyondTopN
    pub detail: String,
}

pub struct PortfolioPlanOutput {
    pub planned: Vec<PlannedRecommendation>,  // 已按 risk_adjusted_score 稳定排序、截 top_n
    pub rejected: Vec<RejectedCandidate>,
    pub plan_row: NewPortfolioPlan,           // 直接落 quant_portfolio_plan
}
```

### 5.5 `DefaultPortfolioPlanner::plan` 流程（确定性）

```text
1. 对每个 candidate 调 sizing.suggest：
     Rejected(reason) ⇒ 落 rejected（NoPositiveSignal / InvalidEdgeInputs）。
     Sized(suggestion) ⇒ desired_usd 注入 allocator CandidateMeta。
2. 构造 AllocationInput {
     candidates,
     caps,                                        // PortfolioCaps::from(budget+constraints)
     initial_exposures: account.exposures,        // 净额起点
     available_usd: account.available_usd,        // 总部署 room = min(total_budget, available)
   }
3. allocator.allocate → 每候选 allocated_usd + binding_constraint + *_exposure_after。
   total room 受 min(total_budget, available) 约束；available 更紧时 binding=AvailableCash。
4. allocated_usd < min_recommendation_usd 或 =0 ⇒ rejected，原因按 binding 映射：
     PortfolioBudget→BudgetExhausted | AvailableCash→AvailableCashExhausted |
     SingleMarketCap→MarketCapExhausted | EventCap→EventCapExhausted |
     CategoryCap→CategoryCapExhausted | LiquidityCap→LiquidityInfeasible | 其余→BelowMinSize。
5. published binding = allocator binding；若 binding=None 且 binding_kelly_cap ⇒ KellyCap。
   risk_adjusted_score：base = composite·confidence
     · liquidity_feasible 折减（×0.5）
     · scarcity binding（budget/cash/market/event/category/liquidity 压缩）折减（×0.9）
   稳定排序（父文档 §21.5）：risk_adjusted desc → composite desc → liquidity desc →
   market_id asc → token_id asc；排名超 top_n ⇒ rejected BeyondTopN。
6. 每条产 SizingPlan（suggested/max/min/shares/weight/exposure_after/binding/reason/model/
   edge_bps/kelly_fraction_applied）+ RiskEnvelope（§5.6）。
7. plan_row = NewPortfolioPlan{ budget_usd=total_budget, allocated_usd=Σ(published),
   risk_budget_json{capital_base=equity, reserved, allocated, remaining},
   constraints_json, rejected_summary }。
```

```text
requires_approval        = (由 04.2 composer 按 mode/eligibility 设)

envelope_hash = blake3(canonical(上述数值字段))               // admission 校验锚
```

## 6. 生产不变量与失败语义

- **无正 edge 不配资**：`f_star ≤ 0` 必拒；负 edge 绝不进报告。
- **政策 ∩ 状态 ∩ edge**：最终 `suggested_usd = min(Kelly建议, max_position_pct·equity,
  single_cap, budget_room, market_room, event_room, category_room, liquidity_room)`；
  `binding_constraint` 精确归因到最小项。
- **敞口净额必须含已有持仓**：`initial_exposures = account.exposures`（来自 04.0 真实账户
  快照读路径，非 `quant_position` 账本）；`exposure_after = 已有 + 本轮新配`。账户**恒为真实**
  （credential-gated，无绿场/无模拟）；持仓为空（新账户）是合法真实状态，无需 warning。
- **available 约束**：Kelly/曲线建议的 `desired_usd` 还受 `account.available_usd`
  （equity − reserved）上限；semi_auto/auto 下 reserved 来自 pending intent 读聚合。
- **确定性可重放**：同一 (candidates, account, config) 必产同一 plan（排序 + sizing
  全确定，无随机、无 wall-clock 依赖）。
- **money newtype**：sizing 中间 `f64` 不外泄；`desired_usd`/`allocated_usd`/`max_loss`
  全 `Usd`。
- **envelope_hash 稳定**：canonical 序列化，字段顺序固定；admission（Phase 5）据此校验。
- **min size 丢弃语义**：低于 `min_recommendation_usd` 的配额归零并标 rejected，不产生
  "买 0.3 美元"的噪声建议。

## 9. Blocker

- 若为负/零 edge 配资，本子phase失败。
- 若 sizing 把 `f64` 泄漏到 `Usd`/报告，失败。
- 若 exposure_after 不含 `account.exposures`（已有持仓被忽略），失败。
- 若 semi_auto 忽略 `reserved_usd` 导致 available 虚高，失败。
- 若 plan 不可确定性重放，失败。
- 若 planner 依赖 weighted/classical concrete 类型或 live `BookStore`，失败。

## 10. 延后 / 缺口

> 完整索引见 [`README.md`](README.md) §6。

- **`good_lp` LP/MILP 全局最优组合** → Phase 5（greedy 非全局最优，本期可接受且确定性更优）。
- **report-level shadow（Kelly vs ConfidenceCurve 完整 capital/would-execute delta）** →
  Phase 5；本期仅支持配置切换 active sizing model + signal 层 shadow（3.4/3.7 已在）。
- **`Sell*` 退出侧 sizing** → Phase 5；本期只 Buy 侧（3.4 已定 scorer 不产 Sell）。
- **相关性敞口 `max_correlated_exposure_usd` 真正生效** → 需相关性矩阵（domain/3.8 数据），
  本期 caps 中保留字段并作硬上限近似（按 event/category 代理），完整相关性建模延后。
- **回撤状态 `DrawdownState` 真实来源** → 依赖 Phase 5 权益历史/PnL 账本（跨 tick equity
  曲线）；本期 `DrawdownState` 取中性（无回撤），所有 mode 一致——账户快照虽含持仓未实现
  PnL，但单点快照不足以推回撤历史，故 `drawdown_scaling` 待权益历史账本落地后才有真实输入。
