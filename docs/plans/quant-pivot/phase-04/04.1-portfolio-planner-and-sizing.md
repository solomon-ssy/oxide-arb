# 04.1 — Executable Economic Tiers and Global Portfolio Planning

<!-- quant-pivot-deployment-contract:v1 -->
> **Clean-break contract**：本文件彻底取代旧 fractional-Kelly、confidence sizing、greedy allocator 与
> `risk_adjusted_score` 设计。唯一组合优化规格见
> [`05.8`](../phase-05/05.8-portfolio-optimization-highs.md)。

## 1. 目标

把各 Route 的 calibrated candidate 转换为同一经济尺度的离散 `ExecutableEconomicTier`，并使用真实
账户、联合 scenario artifact 和 ExecutionRiskPolicy 生成一个 exact-verified `GlobalPortfolioPlan`。

本 phase 不允许：

- per-candidate Kelly 或任何独立 sizing model；
- score/confidence/category rank 参与跨 Route objective；
- 连续 USD 解后再 snap 到盘口；
- historical Pearson/category proxy；
- greedy、relaxation、empty-plan 或 solver/backend fallback。

## 2. 输入冻结

`GlobalPortfolioInput` 必须引用同一报告冻结的：

- `DecisionPolicySnapshot`；
- 真实 `AccountSnapshot` 与 existing exposures；
- `RepresentedRouteSet` 和全部 `ReportRouteRun` lineage；
- compatible `PortfolioScenarioArtifact`；
- Route-specific calibrated candidates 与 Trade Policy cash-flow evidence；
- report `as_of`、TopN 和 exact L2 facts。

任一 identity/hash/as-of 不一致立即返回 typed report failure。

## 3. ExecutableEconomicTier

一个 candidate 从零到 policy/venue 最大值生成有限个 cumulative tiers。每个 tier 必须已经完成真实
L2 walk、fee、slippage、tick/lot、minimum order 和 book-depth 验证，并包含：

- exact shares、entry notional/VWAP/fee/slippage；
- 每个 joint scenario/time bucket 的 exit/settlement net cashflow；
- capital-lock vector 与 discounted cashflow；
- nominal/robust expected net USD、profit probability lower bound、maximum loss、CVaR inputs；
- market/event/category/Route exposure deltas；
- model/calibration/trade-policy/research/book/fee/scenario lineage digest。

不同 tier 使用 stable `EconomicTierId`；optimizer 只能选择完整 tier identity，不能修改金额。

## 4. Candidate admission

进入 MILP 前逐 tier 验证：

- nominal 与 robust expected net USD 均达到 required floor；
- calibrated profit-probability lower bound 达标；
- probability interval width 不超过 cap；
- liquidity buffer、data quality、entry window 和 Trade Policy contract 合法；
- maximum loss 与单 recommendation cap 合法；
- scenario/time-bucket cash-flow vector 完整。

拒绝是正常 funnel evidence；artifact/pipeline/contract error 不是 rejection，必须失败整份报告。

## 5. GlobalPortfolioPlan

调用唯一 `GlobalPortfolioPlanner::solve_and_verify`。MILP 以 tier one-hot binary variables 满足 cash、reserve、
existing exposure、time-bucket capital、recommendation/market/event/category/Route、scenario loss、CVaR、
drawdown、structural exclusivity 和 TopN hard constraints。

四阶段 lexicographic objective：robust expected net USD → nominal expected net USD → minimum CVaR/capital
USD-hours → stable identity tie-break。只有 optimal + exact Decimal verification 可以产出 plan。

## 6. SizingPlan

`SizingPlan` 是选中 economic tier 的只读投影：

- `economic_tier_id`
- `hard_reserved_cash_usd` / `requested_shares`
- `reference_entry_price` / `fee_usd` / `slippage_usd`
- portfolio weight
- market/event/category/Route exposures after
- capital occupancy by bucket
- binding constraints
- `RecommendationEconomics`

删除 `sizing_model`、`edge_bps`、`kelly_fraction_applied`、confidence/drawdown multiplier 和 Kelly cap。
执行层只能在该 tier 边界内创建 `OrderIntent`，且必须重新验证当前 book/admission；不能放大或重算报告。

## 7. Ranking

对每个 selected candidate 在相同 frozen input 下做 leave-one-out solve：

```text
marginal_portfolio_value_usd = full robust optimum - leave-one-out robust optimum
```

按 marginal value、robust net USD、nominal net USD、Route/market/tier identity 稳定排序。

## 8. 持久化

`quant_portfolio_plan` 保存 input/scenario/route-set digest、四阶段 objective、selected tier identities、
constraint evidence、solver provenance、elapsed time 和 exact verifier result。Recommendation 保存
`economic_tier_id` 与 `RecommendationEconomics`，并 FK 到 `ReportRouteRun`。

## 9. 验收

- mixed Route 的 raw-score 顺序会被 fee/slippage/tail-risk/capital-time 正确反转。
- 小规模输入与 brute-force optimum 一致。
- input reorder 不改变 plan/report hash。
- all caps、existing exposures、event structure、time buckets 与 CVaR 生效。
- complete zero-candidate Route 正常；missing Route artifact 整体失败。
- non-optimal、timeout、overflow、post-check mismatch 不发布 plan。
- solver boundary 外无 `f64` Money；输出全部由 Decimal/newtype 重算。
