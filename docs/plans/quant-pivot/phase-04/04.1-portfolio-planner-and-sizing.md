## 1. 目标与闭环定位

1. 引入可插拔 `SizingModel` trait：默认 **fractional Kelly**，保留确定性
   **ConfidenceCurve** 基线 / shadow。
2. 引入受治理 `PortfolioPlanner` trait + `DefaultPortfolioPlanner`：消费
   `PortfolioPlanInput { candidates, account, budget, constraints, sizing }`，**复用**
   Phase 3 `PortfolioAllocator`（增强后），产出：
   - 每条 `SizingPlan`（`suggested_usd` / `*_exposure_after_usd` / `binding_constraint`
     / `sizing_reason` / Kelly provenance）。
   - 每条 `RiskEnvelope`（执行 admission 输入）。
   - `risk_adjusted_score`（组合约束后排序分）。
   - rejected candidate 摘要（含原因）。
3. exposure_after = **账户快照净额(snapshot.exposures) + 本轮新配额**，而非从零起算。

本子phase完成后，04.2 composer 只需把 plan 结果包装成强类型 recommendation。

### 5.1 `SizingModel` trait

```rust
/// 单候选规模建议（资本基数比例）。纯函数：无 I/O、无 clock、无可变状态。
pub trait SizingModel: Send + Sync {
    fn kind(&self) -> SizingModelKind;

    /// 给定候选 + 资本基数，产出"建议下注的 USD"（未受 caps 收敛）。
    /// 返回值 ≤ 0 表示无正 edge（候选应被拒绝，原因 NoPositiveSignal）。
    fn suggest(&self, input: &SizingInput<'_>) -> QuantResult<SizingSuggestion>;
}

pub struct SizingInput<'a> {
    pub candidate: &'a SignalCandidate,
    pub equity_usd: Usd,            // = AccountSnapshot.equity_usd
    pub drawdown_state: DrawdownState, // 当前回撤（驱动 drawdown_scaling）
}

pub struct SizingSuggestion {
    pub desired_usd: Usd,           // 建议规模（受 max_position_pct 后、caps 前）
    pub edge_bps: Option<Decimal>,  // 可审计 edge（provenance）
    pub kelly_fraction_applied: Option<Decimal>,
}
```

### 5.2 Kelly 公式（生产语义，钱相关，逐项可审计）

Polymarket 二元 outcome token：入场价 `p = entry_price_ref`。本期把"持有到 horizon
后按 target/stop 退出"建模为**两结果赌局**（与 §3.4 scorer 的 target/stop 投影一致）：

```text
g = expected_return_bps / 10_000      // 命中 target 的盈利比例（占下注额）
l = downside_bps        / 10_000      // 触发 stop 的亏损比例（占下注额）
q = confidence                         // 命中 target（先于 stop）的概率代理（∈[0,1]）

# 两结果 Kelly 最优下注比例（对数效用最大化）：
f_star = q / l  −  (1 − q) / g        // 当 g>0, l>0
       = ( q·g − (1−q)·l ) / (g·l)     // 等价形式

# fractional + 上限 + 回撤缩放：
f = clamp( kelly_fraction · drawdown_scale(drawdown_state) · max(f_star, 0),
           0, max_position_pct )
desired_usd = round_money( f · equity_usd )
edge_bps    = (q·g − (1−q)·l) · 10_000    // provenance
```

硬规则：

- `f_star ≤ 0`（无正 edge）⇒ `desired_usd = 0`，候选**拒绝**（rejected，原因
  `NoPositiveSignal`）。绝不为负 edge 配资。
- `g ≤ 0` 或 `l ≤ 0`（模型未给出有效 target/stop）⇒ 视为无效，拒绝并告警（不臆造）。
- `q` 取 `confidence`，**不是** `composite_score`（后者是排序信念，非校准概率）。
  `q` 的校准质量由 3.6/3.7 负责；本期显式标注 provenance（heuristic/calibrated）。
- 全程 `Decimal`；`f_star` 计算允许 `f64` 中间值（log/除法边界），但 `desired_usd`
  必须回到 `Usd`，绝不把 `f64` 传出 sizing 层。
- `max_position_pct` 是**硬地板**：即便 Kelly 建议更大也不超 `max_position_pct·equity`
  （触发即 `binding_constraint = KellyCap`）。

`KellySizingModel` 参数来自 `SizingModelConfig::Kelly`。

### 5.3 `ConfidenceCurveSizingModel`（基线 / shadow）

```text
base = max_single_recommendation_usd   // 或 budget·weight
desired_usd = round_money( base · curve(confidence) · drawdown_scale )
# curve = Linear: f(c)=c；Step: 分档常数
edge_bps = None（曲线模型不声明 edge）
```

用途：确定性回归基线、与 Kelly 做 shadow 对比（report-level shadow 留 Phase 5；本期
仅支持配置切换 active sizing model）。

### 5.4 `PortfolioPlanner` trait

```rust
pub trait PortfolioPlanner: Send + Sync {
    fn plan(&self, input: PortfolioPlanInput<'_>) -> QuantResult<PortfolioPlanOutput>;
}

pub struct PortfolioPlanInput<'a> {
    pub candidates: Vec<CandidateMeta<'a>>,   // accepted（含 category/event/liquidity）
    pub account: &'a AccountSnapshot,         // 资本基数 + 当前敞口净额（09 §2）
    pub budget: &'a PortfolioBudget,
    pub constraints: &'a PortfolioConstraints,
    pub sizing: &'a dyn SizingModel,
    pub top_n: usize,
}

pub struct PlannedRecommendation {
    pub candidate: SignalCandidate,
    pub sizing: SizingPlan,                   // 04.0 强类型
    pub risk_envelope: RiskEnvelope,          // 04.0 强类型（flags 由 04.2 composer 终定）
    pub risk_adjusted_score: Probability,     // 组合约束后排序分
    pub rank: u32,
}

pub struct RejectedCandidate {
    pub signal_candidate_id: SignalCandidateId,
    pub market_id: MarketId,
    pub reason: RejectionReason,              // NoPositiveSignal | BelowMinSize | BudgetExhausted | ...
    pub detail: String,
}

pub struct PortfolioPlanOutput {
    pub planned: Vec<PlannedRecommendation>,  // 已按 risk_adjusted_score 稳定排序、截 top_n
    pub rejected: Vec<RejectedCandidate>,
    pub plan_row: NewPortfolioPlan,           // 直接落 quant_portfolio_plan
}
```

### 5.5 `DefaultPortfolioPlanner::plan` 流程（确定性）

```text
1. 对每个 candidate 调 sizing.suggest → desired_usd（≤0 ⇒ rejected NoPositiveSignal）。
2. 构造 AllocationInput {
     candidates: desired_usd 注入每个 CandidateMeta,
     initial_exposures: account.exposures,        // 净额起点
     caps: PortfolioCaps::from(budget + constraints),
   }
3. allocator.allocate → 每候选 allocated_usd + binding_constraint + *_exposure_after。
4. allocated_usd < budget.min_recommendation_usd ⇒ rejected BelowMinSize（不出报告）。
5. 组合后排序分 risk_adjusted_score：
     base = composite·confidence（与 allocator 排序键一致）
     · liquidity_feasible 折减（不可行流动性下调）
     · 受 binding cap 时下调（受预算/敞口压缩的仓位排序分下调）
   稳定排序（父文档 §21.5）：risk_adjusted desc → composite desc → liquidity desc →
   market_id asc → token_id asc，再截 top_n。
6. 每条产 SizingPlan（suggested/max/min/weight/exposure_after/binding/reason/Kelly
   provenance）+ RiskEnvelope（§5.6）。
7. plan_row = NewPortfolioPlan{ budget_usd, allocated_usd=Σ, risk_budget_json,
   constraints_json, rejected_summary }。
```

### 5.6 `RiskEnvelope` 推导（planner 产骨架，composer 终定 flags）

```text
max_loss_usd            = suggested_usd · l                  // 最坏止损损失
max_slippage_bps        = entry_plan.max_slippage_bps        // 与 entry 对齐
max_position_usd        = budget.max_single_recommendation_usd
max_market_exposure_usd = constraints.max_market_exposure_usd
max_event_exposure_usd  = constraints.max_event_exposure_usd
max_category_exposure_usd = constraints.max_category_exposure_usd
requires_approval        = (由 04.2 composer 按 mode/eligibility 设)
auto_execution_allowed   = (由 04.2 composer 按 mode/eligibility 设)
envelope_hash = blake3(canonical(上述数值字段))               // admission 校验锚
```

## 6. 生产不变量与失败语义

- **无正 edge 不配资**：`f_star ≤ 0` 必拒；负 edge 绝不进报告。
- **政策 ∩ 状态 ∩ edge**：最终 `suggested_usd = min(Kelly建议, max_position_pct·equity,
  single_cap, budget_room, market_room, event_room, category_room, liquidity_room)`；
  `binding_constraint` 精确归因到最小项。
- **敞口净额必须含已有持仓**：`initial_exposures = account.exposures`（来自 04.0 真实账户
  快照读路径，非 `quant_position` 账本）；`exposure_after = 已有 + 本轮新配`。账户**恒为真实**
  （credential-gated，无绿场/无模拟）；持仓为空（新账户）是合法真实状态，无需 warning。
- **available 约束**：Kelly/曲线建议的 `desired_usd` 还受 `account.available_usd`
  （equity − reserved）上限；semi_auto/auto 下 reserved 来自 pending intent 读聚合。
- **确定性可重放**：同一 (candidates, account, config) 必产同一 plan（排序 + sizing
  全确定，无随机、无 wall-clock 依赖）。
- **money newtype**：sizing 中间 `f64` 不外泄；`desired_usd`/`allocated_usd`/`max_loss`
  全 `Usd`。
- **envelope_hash 稳定**：canonical 序列化，字段顺序固定；admission（Phase 5）据此校验。
- **min size 丢弃语义**：低于 `min_recommendation_usd` 的配额归零并标 rejected，不产生
  "买 0.3 美元"的噪声建议。

## 9. Blocker

- 若为负/零 edge 配资，本子phase失败。
- 若 sizing 把 `f64` 泄漏到 `Usd`/报告，失败。
- 若 exposure_after 不含 `account.exposures`（已有持仓被忽略），失败。
- 若 semi_auto 忽略 `reserved_usd` 导致 available 虚高，失败。
- 若 plan 不可确定性重放，失败。
- 若 planner 依赖 weighted/classical concrete 类型或 live `BookStore`，失败。

  曲线）；本期 `DrawdownState` 取中性（无回撤），所有 mode 一致——账户快照虽含持仓未实现
  PnL，但单点快照不足以推回撤历史，故 `drawdown_scaling` 待权益历史账本落地后才有真实输入。
