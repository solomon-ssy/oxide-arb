## 1. 目标与闭环定位

1. Read API：列表 / 详情 / scope current / recommendations / 单条 / evidence / diff / durable runs / health / timeline。
2. Mutation API（受治理 + operation log）：`reports/run`、run retry、publication retry、`reports/{id}/revoke`。
3. 强类型 `*View`：报告头 / recommendation（含 entry/sizing/exit/eligibility）/ evidence。
4. WebSocket 事件：durable report-run 与 persisted report/delivery lifecycle。
5. 分级通知：info/warning/critical/emergency；TopN 通知含 top3 + total capital + mode。
6. RBAC：viewer/analyst/operator 角色（05 §10.3）。

## 3. 新领域类型 / 表 / ClickHouse fact

无新表 / 无 CH fact。新增对外 DTO（`quant-pivot-models::domain::api`，遵循
[`quant-pivot-dto-api.mdc`](../../../.cursor/rules/quant-pivot-dto-api.mdc)）：

```text
domain/api/quant_report.rs        # 重写：QuantReportView / QuantReportDetailView /
                                  #   QuantReportListQuery / RunReportRequest /
                                  #   RevokeReportRequest / ReportDiffView
domain/api/quant_recommendation.rs # 新：QuantRecommendationView / QuantEvidenceView
```

- `*View`：`Serialize`-only，**剥离内部 hash / 内部 id 的敏感投影**（如 `envelope_hash`
  作为不透明字符串可暴露；feature/model 内部 id 以字符串暴露供回放查询）。
- `RunReportRequest` / `RevokeReportRequest`：`Deserialize + Validate`（reason 长度等）。
- `*View` 不直接复用 04.0 持久化强类型直出（避免泄漏内部结构 drift）。`QuantReportView` /
  `QuantReportDetailView` 由 `From<RecommendationReportInfo>` 构建；`QuantRecommendationView`
  经 **`RecommendationViewContext`**（recommendation + `report_status` + `active_order_intent_id`）
  在 core port 层 join recommendation / report / order_intent 三仓库组装——不再有
  `From<RecommendationInfo>` 直转，确保 view 必带治理事实（父报告状态 + 阻塞 intent）。

## 5. 必建模块与 trait

### 5.1 Read API（父文档 §16.1）

```text
GET /api/quant/reports                       → Paginated<QuantReportView>
GET /api/quant/reports/current?profile_id&kind → QuantReportDetailView
GET /api/quant/reports/{id}                  → QuantReportDetailView
GET /api/quant/reports/{id}/recommendations  → Vec<QuantRecommendationView>
GET /api/quant/recommendations/{id}          → QuantRecommendationView
GET /api/quant/recommendations/{id}/evidence → QuantEvidenceView
GET /api/quant/reports/{id}/diff/{other_id}  → ReportDiffView
```

handler 经 service 读 repository（`RecommendationReportRepository` /
`RecommendationRepository` 只读）；分页 `Paginated<_>`；响应一律经 `*View` 投影。

### 5.2 Mutation API（父文档 §16.2；受治理 + op-log）

```text
POST /api/quant/reports/run            → new 202 / idempotent replay 200 + ReportRunView
POST /api/quant/reports/{id}/revoke    → QuantReportDetailView（lifecycle.revoke）
```

- `reports/run`：受 `reports.ad_hoc_report_enabled` + governed RBAC；写 op-log；幂等键
  `ad_hoc:{request_id}` 的唯一 authority 是 `quant_report_run`。新建返回 202，同键重放返回既有
  `ReportRunView` 和 200；客户端立即进入 durable run detail，不依赖 ephemeral WS。
- `reports/{id}/revoke`：受 RBAC（`QuantReport:Revoke`，operator/risk_owner）；
  `lifecycle.revoke` 写 `revoked_at` + reason + op-log；发 `quant.report` 的 `revoked`
  事件。
- **新增 `Operation::Revoke`**（语义精准，优于复用 `Delete`）；`QuantReport` 权限收敛为
  `[Read, Enqueue, Revoke]`。
- **本期不提供** `recommendations/{id}/create-intent`（父文档 §16.2 列出，但执行属
  Phase 5）：路由**不注册**；若需占位，返回 `501 Not Implemented` + 明确
  "execution available in Phase 5" body（不静默 404）。

### 5.3 WebSocket 事件（父文档 §17）

Phase 11.8 使用两个职责清晰的频道；payload 都有 durable backing，客户端收到后重新读取 REST：

```text
quant.report_run = queued | running | succeeded | failed | skipped | abandoned
quant.report     = prepared | published | superseded | obsolete | revoked | expired |
                   delivery_retrying | delivery_failed
```

- build 状态由 `quant_report_run` 持久化；报告只在完整 artifact commit 后发 `prepared`。
- valid empty 使用普通 `published` event + `empty_reason`，不再拥有 `empty` lifecycle event。
- WS 是 revision hint，不承担 refresh/reconnect replay truth。
- 删除 WS 频道枚举中的 endgame 残留：`opportunity.detected` / `trade.filled` /
  `trade.settled` / `pnl.update` / `risk.circuit_breaker` / `risk.position_update`（均无
  producer）。`quant.recommendation.*` Phase 5 才引入。

### 5.4 通知（父文档 §18）

分级：

| 级别 | 触发 |
|---|---|
| info | report published / empty |
| warning | report delayed / data quality degraded |
| critical | model quality gate failed / fact writer lag |
| emergency | auto execution halted / kill switch open（Phase 5） |

TopN published 通知 payload：report id、top 3 recommendations（market/side/score/
suggested_usd）、total suggested capital、runtime mode、warnings、报告链接（相对路径
`/quant/reports/{id}`，**不新增 deploy key**）。受 `notification.policies.report_published`
+ `reports.delivery_policy`（`StoreOnly` 不发）。

该历史通知热更方案已由 boot Config 基线替代：通知 endpoint/secret 属 Deploy
Credential，事件路由属于 `OperationalControl.notifications`。激活由
`PolicySnapshotApplicator` prepare 后原子发布，通知 consumer 必须登记 validator、
preflight、apply boundary 和 rollback test，不再读取旧 notification 聚合。

### 5.5 RBAC（05 §10.3）

| 角色（代码） | 权限 |
|---|---|
| viewer | `QuantReport:Read`（report/recommendation/evidence/diff/latest） |
| analyst（**本期新增内置角色**） | + `QuantReport:Enqueue`（`reports/run`） |
| operator / risk_owner | + `QuantReport:Revoke`（`reports/{id}/revoke`） |

经现有 Casbin 中间件 + governed（`ActingRoleGoverned`）路由；`QuantReport` 资源 policy 扩为
`[Read, Enqueue, Revoke]`，casbin seed 同步授权。注意计划原文的 `risk_manager` 在代码中对应
内置角色 `risk_owner`。

## 6. 生产不变量与失败语义

- **`*View` 剥离敏感**：不暴露 `password_hash` 类字段（报告域无凭证，但 evidence 的
  内部 id 以字符串暴露，不暴露可变内部句柄）。
- **API 不暴露旧语义**：无 opportunity / trade 路由或字段（架构 lint）。
- **eligibility 与 mode 分离**：view 同时展示三态 eligibility + 当前 mode，不混淆
  "可执行"与"已执行"。
- **mutation 必写 op-log**：`reports/run` / `revoke` 均落 operation log（治理审计）。
- **不可变读**：read API 永不改状态；revoke/expire 只经 lifecycle 状态迁移。
- **执行延后显式**：create-intent 返回 501 + 明确文案，不静默；避免误以为已下单。
- **handler 不直连**：handler → service → repository；handler 不直接持 DB 连接或
  Polymarket client（05 §17）。

## 9. Blocker

- 若 API 暴露旧 opportunity/trade 语义或字段，本子phase失败。
- 若 mutation 不写 operation log，失败。
- 若 `*View` 泄漏内部可变句柄 / 敏感字段，失败。
- 若 create-intent 静默成功或静默 404（误导执行已发生），失败。
- 若 handler 绕过 service 直连 repository/venue client，失败。
