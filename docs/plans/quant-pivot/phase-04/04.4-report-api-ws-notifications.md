# 04.4 — Report API / WS / Notifications

> 父：[`README.md`](README.md) · 概念规格：[`../04-topn-report-and-recommendation.md`](../04-topn-report-and-recommendation.md) §16–§18、
> [`../05-execution-risk-and-governance.md`](../05-execution-risk-and-governance.md) §10/§13
>
> 闭环定位：**对外可观测闭环**。把不可变报告通过只读 API、受治理 mutation、WebSocket
> 事件、分级通知暴露出去。本期**不**做执行（create-intent/admission），但对外语义要把
> "为何延后"表达清楚。

## 1. 目标与闭环定位

1. Read API：列表 / 详情 / latest / recommendations / 单条 / evidence / diff。
2. Mutation API（受治理 + operation log）：`reports/run`（ad-hoc）、`reports/{id}/revoke`。
3. 强类型 `*View`：报告头 / recommendation（含 entry/sizing/exit/eligibility）/ evidence。
4. WebSocket 事件：report started/published/empty/failed/revoked。
5. 分级通知：info/warning/critical/emergency；TopN 通知含 top3 + total capital + mode。
6. RBAC：viewer/analyst/operator 角色（05 §10.3）。

## 3. 新领域类型 / 表 / ClickHouse fact

无新表 / 无 CH fact。新增对外 DTO（`quant-pivot-models::domain::api`，遵循
[`quant-pivot-dto-api.mdc`](../../../.cursor/rules/quant-pivot-dto-api.mdc)）：

```text
domain/api/quant_report.rs        # 重写：QuantReportView / QuantReportDetailView /
                                  #   QuantReportListQuery / RunReportRequest /
                                  #   RevokeReportRequest / ReportDiffView
domain/api/quant_recommendation.rs # 新：QuantRecommendationView / QuantEvidenceView
```

- `*View`：`Serialize`-only，**剥离内部 hash / 内部 id 的敏感投影**（如 `envelope_hash`
  作为不透明字符串可暴露；feature/model 内部 id 以字符串暴露供回放查询）。
- `RunReportRequest` / `RevokeReportRequest`：`Deserialize + Validate`（reason 长度等）。
- `*View` 由 `From<RecommendationReportInfo>` / `From<RecommendationInfo>` 构建；**不**
  直接复用 04.0 持久化强类型直出（避免泄漏内部结构 drift）。

## 5. 必建模块与 trait

### 5.1 Read API（父文档 §16.1）

```text
GET /api/quant/reports                       → Paginated<QuantReportView>
GET /api/quant/reports/latest                → QuantReportDetailView
GET /api/quant/reports/{id}                  → QuantReportDetailView
GET /api/quant/reports/{id}/recommendations  → Vec<QuantRecommendationView>
GET /api/quant/recommendations/{id}          → QuantRecommendationView
GET /api/quant/recommendations/{id}/evidence → QuantEvidenceView
GET /api/quant/reports/{id}/diff/{other_id}  → ReportDiffView
```

handler 经 service 读 repository（`RecommendationReportRepository` /
`RecommendationRepository` 只读）；分页 `Paginated<_>`；响应一律经 `*View` 投影。

### 5.2 Mutation API（父文档 §16.2；受治理 + op-log）

```text
POST /api/quant/reports/run            → 202 + report_id（ad-hoc，enqueue_ad_hoc）
POST /api/quant/reports/{id}/revoke    → QuantReportDetailView（lifecycle.revoke）
```

- `reports/run`：受 `reports.ad_hoc_report_enabled` + RBAC（analyst+）；写 op-log；
  幂等键 `ad_hoc:{request_id}`。
- `reports/{id}/revoke`：受 RBAC（operator/risk_manager）；`lifecycle.revoke` 写
  `revoked_at` + reason + op-log；发 `quant.report.revoked`。
- **本期不提供** `recommendations/{id}/create-intent`（父文档 §16.2 列出，但执行属
  Phase 5）：路由**不注册**；若需占位，返回 `501 Not Implemented` + 明确
  "execution available in Phase 5" body（不静默 404）。

### 5.3 WebSocket 事件（父文档 §17）

新增 `quant.report.*`：

```text
quant.report.started        # build 开始（可选）
quant.report.published      # 发布（含 report_id / top_n / actual_count / total_usd）
quant.report.empty          # published_empty（含 empty_reason）
quant.report.failed         # build 失败（含 error code）
quant.report.revoked        # 撤销（含 reason）
```

删除（若 WS 频道枚举仍有）：`opportunity.detected` / `trade.opened` / `trade.filled`
/ `trade.settled`。`quant.recommendation.intent_created` / `.attributed` 列入枚举但
**Phase 5 才 emit**（本期文档化，不 fire）。

由 `ReportPublisher`（04.2）在事务提交后经 `CoreEventPublisher` 发出。

### 5.4 通知（父文档 §18）

分级：

| 级别 | 触发 |
|---|---|
| info | report published / empty |
| warning | report delayed / data quality degraded |
| critical | model quality gate failed / fact writer lag |
| emergency | auto execution halted / kill switch open（Phase 5） |

TopN published 通知 payload：report id、top 3 recommendations（market/side/score/
suggested_usd）、total suggested capital、runtime mode、warnings、报告链接。受
`notification.policies.report_published` + `reports.delivery_policy`（`StoreOnly` 不发）。

### 5.5 RBAC（05 §10.3）

| 角色 | 权限 |
|---|---|
| viewer | 只读全部 report/recommendation/evidence |
| analyst | + `reports/run`（ad-hoc） |
| risk_manager / operator | + `reports/{id}/revoke` |

经现有 Casbin 中间件；新增 quant report 资源 policy。

## 6. 生产不变量与失败语义

- **`*View` 剥离敏感**：不暴露 `password_hash` 类字段（报告域无凭证，但 evidence 的
  内部 id 以字符串暴露，不暴露可变内部句柄）。
- **API 不暴露旧语义**：无 opportunity / trade 路由或字段（架构 lint）。
- **eligibility 与 mode 分离**：view 同时展示三态 eligibility + 当前 mode，不混淆
  "可执行"与"已执行"。
- **mutation 必写 op-log**：`reports/run` / `revoke` 均落 operation log（治理审计）。
- **不可变读**：read API 永不改状态；revoke/expire 只经 lifecycle 状态迁移。
- **执行延后显式**：create-intent 返回 501 + 明确文案，不静默；避免误以为已下单。
- **handler 不直连**：handler → service → repository；handler 不直接持 DB 连接或
  Polymarket client（05 §17）。

## 9. Blocker

- 若 API 暴露旧 opportunity/trade 语义或字段，本子phase失败。
- 若 mutation 不写 operation log，失败。
- 若 `*View` 泄漏内部可变句柄 / 敏感字段，失败。
- 若 create-intent 静默成功或静默 404（误导执行已发生），失败。
- 若 handler 绕过 service 直连 repository/venue client，失败。
