# 04.2 — Report Builder / Composer / Publisher / Lifecycle

> 父：[`README.md`](README.md) · 概念规格：[`../04-topn-report-and-recommendation.md`](../04-topn-report-and-recommendation.md) §1/§3/§19–§22、
> [`../00-quant-pivot-architecture.md`](../00-quant-pivot-architecture.md) §9.3
>
> 闭环定位：**报告生成闭环**。把 04.1 的 plan 组装成不可变、可审计、可回放的
> `RecommendationReport`，单事务落库，提交后才副作用（WS / 通知 / metrics / CH 镜像）。

## 1. 目标与闭环定位

1. `ReportBuilder`：编排 freeze config → selection → feature → model → account →
   planner → draft（复用 04.1 + Phase 3 服务）。
2. `RecommendationComposer`：plan → 强类型 recommendation（entry/sizing/exit/risk/
   factor/evidence/eligibility）+ rejected 摘要 + `ReportSummary`。
3. `ReportLifecycleService`：`run_scheduled` / `run_ad_hoc` / `revoke` / `expire`。
4. `ReportPublisher`：事务提交后 WS + 通知 + metrics + CH 镜像。
5. 空报告（`published_empty` + `EmptyReason`）是正常路径，非异常。
6. **单事务**写 account_snapshot + portfolio_plan + report + recommendations + op-log。

## 2. 删除 / 合并 / 重构清单

### 2.1 重构（破坏式，钱/审计相关）

### 5.1 `ReportBuilder`

```rust
#[async_trait]
pub trait ReportBuilder: Send + Sync {
    /// 从冻结的 runtime/config/model 快照构建不可变报告草稿。
    async fn build(&self, request: BuildReportRequest) -> QuantResult<ComposedReport>;
}

pub struct BuildReportRequest {
    pub schedule_id: Option<String>,           // scheduled fire；ad-hoc 为 None
    pub ad_hoc_request_id: Option<String>,     // 幂等键
    pub report_kind: ReportKind,
    pub trigger_time: DateTime<Utc>,
    pub as_of: DateTime<Utc>,                   // = trigger − source_delay（永不裸 now）
    pub runtime_config_version_id: RuntimeConfigVersionId,
    pub top_n: usize,
}
```

`DefaultReportBuilder::build` 流程（与父文档 §21.2 对齐，落地修正）：

```text
1. config = runtime_config_version_repo.load_version(req.version_id)  // 冻结快照
   （RuntimeConfigStore 无 version_id；从 version repo 取该版本 config_json 解析）
2. model = model_registry.active_version(config.model.active_model_version_id)
   model_requirements = runtime.required_features()                  // 注入 selection
3. candidates = candidate_provider.candidates(as_of)                 // 冻结世界事实
   selection = market_selector.build_snapshot(req, candidates)
   selection.included.is_empty() ⇒ empty(EmptySelection)
4. features = feature_pipeline.run(selection, as_of, config)
   features.accepted.is_empty() ⇒ empty(InsufficientDataQuality)
5. outcome = model_runner.run(selection, features, config, top_n)    // SignalCandidate
   outcome.accepted.is_empty() ⇒ empty(NoPositiveSignal)
6. account = account_provider.snapshot(as_of)                        // 资本基数 + 敞口
7. plan = portfolio_planner.plan(candidates=accepted, account, budget,
            constraints, sizing=select_sizing_model(config))
   plan.planned.is_empty() ⇒ empty(PortfolioBudgetExhausted | NoPositiveSignal)
8. composed = composer.compose(req, selection, account, plan, mode)
9. return composed   // 落库 + 副作用由 lifecycle 负责
```

> 每个 empty 分支携带 `EmptyReportContext`（selection count / rejected summary /
> warnings），由 §5.5 构造 `published_empty` 草稿（仍写 account_snapshot + 空
> portfolio_plan，保持 header 完整可回放）。

### 5.2 `RecommendationComposer`

```rust
pub trait RecommendationComposer: Send + Sync {
    fn compose(&self, input: ComposeInput<'_>) -> QuantResult<ComposedReport>;
}

pub struct ComposeInput<'a> {
    pub request: &'a BuildReportRequest,
    pub selection: &'a MarketSelectionSnapshot,
    pub account: &'a AccountSnapshot,
    pub plan: PortfolioPlanOutput,
    pub mode: QuantRuntimeMode,
    pub config: &'a RuntimeConfig,
}
```

composer 职责：

- 每条 `PlannedRecommendation` → `NewRecommendation`（强类型 entry/sizing/exit/
  risk_envelope/factor_breakdown/evidence_refs；`valid_from = as_of`，`valid_until =
  as_of + horizon`）。
- **EntryPlan**：`trigger_kind` 默认 `Immediate`（受 mode gate）；`limit_price` /
  `max_slippage_bps` / `min_depth_usd` / `max_book_age_ms` 来自 selection 的市场上下文
  + config；`entry_reason` 引用 model_explanation headline。
- **ExitPlan**：`take_profit_price` = entry·(1+er)、`stop_loss_price` = entry·(1−dd)
  （与 sizing 的 g/l 一致）；`partial_exit_nodes` 由 config exit 策略生成（本期可单节点
  TP/SL）；`settlement_policy` 默认 hold-to-resolution。
- **FactorBreakdown**：从 `SignalCandidate.factor_breakdown`（正负贡献都展示，父文档
  §12）映射，含 `source_refs`。
- **EvidenceRefs**：feature_vector_id / model_run_id / market_selection_id /
  runtime_config_version_id / model_version_id / factor_definition_versions。
- **ExecutionEligibility**（本期仅计算/落库，父文档 §14）：
  ```text
  eligible_in_report_only   = true
  eligible_in_semi_auto     = risk_envelope 有效 && !manually_blocked
  eligible_in_auto_execution = model published && data fresh && confidence≥auto.min
                               && shadow_passed(若 require_shadow_passed) && !blocked
  ineligibility_reasons     = 上述未满足项
  requires_approval / approval_role = 按 mode（semi_auto 需 approval）
  ```
  并回填 `RiskEnvelope.requires_approval` / `auto_execution_allowed`。
- **ReportSummary**（父文档 §3）：聚合 selection/candidate/rejected/published 计数、
  total/max suggested、category/event allocation、score 统计、confidence/DQ 摘要、
  top rejection reasons、eligibility 摘要。
- header：`runtime_mode` / `runtime_config_version_id` / `model_version_id` /
  `market_selection_id` / `portfolio_plan_id` / `account_source` / `capital_base_usd`
  / `account_snapshot_ref` / `top_n` / `actual_count`。

### 5.4 事务边界（父文档 §21.3，硬规则）

// RecommendationReportRepository 重构后的事务契约：

一个报告事务**一次性**写入（顺序满足 FK）：

```text
1. quant_account_snapshot          (report.account_snapshot_ref FK)
2. quant_portfolio_plan            (report.portfolio_plan_id FK)
3. quant_recommendation_report
4. quant_recommendation (insert_many)
5. operation_log（report_published / report_empty）
COMMIT
```

提交**后**才允许（lifecycle，非 repo）：

```text
- ReportPublisher.publish：WS 事件 + Telegram/webhook + Prometheus metrics
- CH 镜像：quant_recommendation_event（fire-and-forget，PG 为 source of truth）
```

### 5.6 `ReportLifecycleService`（父文档 §22）

```rust
#[async_trait]
pub trait ReportLifecycleService: Send + Sync {
    async fn run_scheduled(&self, schedule_id: &str) -> QuantResult<RecommendationReport>;
    async fn run_ad_hoc(&self, request: AdHocReportRequest) -> QuantResult<RecommendationReport>;
    async fn revoke(&self, report_id: RecommendationReportId, reason: GovernanceReason)
        -> QuantResult<RecommendationReport>;
    async fn expire_due_reports(&self, now: DateTime<Utc>) -> QuantResult<ExpiredReportCount>;
}
```

- `run_scheduled` / `run_ad_hoc`：解析 active config 版本 → 组 `BuildReportRequest`
  （`as_of = trigger − source_delay`）→ `builder.build` → `repo.create_report`（事务）
  → `publisher.publish`。两者共用同一路径（ad-hoc 幂等键 `ad_hoc:{request_id}`）。
- `revoke`：状态 `Published|PublishedEmpty → Revoked`，写 `revoked_at` + reason +
  op-log；**不删行**；发 `quant.report.revoked`。
- `expire_due_reports`：`published` 超 `report_ttl_secs` → `Expired`（状态迁移，不删行）。
  由 `PeriodicTask` 周期调用（与调度 fire 解耦，04.3）。

### 5.7 `ReportPublisher`

```rust
#[async_trait]
pub trait ReportPublisher: Send + Sync {
    async fn publish(&self, report: &RecommendationReport) -> QuantResult<()>;
}
```

消费 `reports.delivery_policy`：`StoreAndNotify` 全发；`StoreOnly` 仅 WS + metrics，
跳过 Telegram/webhook。失败不回滚已提交报告（提交后副作用，best-effort + 告警）。

## 6. 生产不变量与失败语义

- **`as_of` 冻结**：永不裸 `Utc::now()`；整轮 pipeline 用同一 `as_of` +
  `runtime_config_version_id`。
- **不可变报告**：发布后行不可改；撤销/过期仅状态迁移 + 时间戳，绝不 UPDATE 内容或 DELETE。
- **单事务原子**：account_snapshot + portfolio_plan + report + recommendations + op-log
  要么全成要么全败；任一失败回滚，不留半截报告。
- **提交后副作用**：WS/通知/CH 必须在 COMMIT 之后；提交前发通知 = 幻读，禁止。
- **空报告正常**：每个空分支有明确 `EmptyReason`；空报告也可回放（写快照 + 空 plan）。
- **报告失败隔离**：build 失败写 `Failed` 报告行（或仅 metrics+alert，不写半截）；
  绝不 panic、不拖垮 ingest（04.3 scheduler 捕获）。
- **可追溯**：每条 recommendation 经 `EvidenceRefs` 可回到 feature/model/factor/
  selection/config 版本。
- **CH 非权威**：PG 提交成功才 enqueue CH；CH 写失败仅告警，不影响报告状态。

## 9. Blocker

- 若报告事务不原子（出现无 portfolio_plan / 无 account_snapshot 的 report 行），失败。
- 若 commit 前发通知/WS，失败。
- 若撤销/过期通过 DELETE 或改内容实现，失败。
- 若 build 失败导致 panic 或拖垮 ingest，失败。
- 若 recommendation 无法经 evidence 回放，失败。
