## 1. 已落地边界

- PG 是唯一权威；WS / 通知 / metrics / CH mirror 只能在 report transaction commit 后触发。
- 构建失败不写半成品 `Failed` report 行；只允许 operation log / alert / metrics 记录失败。
- `AccountUnavailable` 不是 empty report。凭证缺失、CLOB/Data API 读取失败、账户快照失败均 fail closed，不写 report。
- `ReportOnly` 不是 dry-run；empty report 仍写真实 `quant_account_snapshot`。
- Kelly 是唯一 production sizing model；04.2 不依赖 `ConfidenceCurveSizingModel`。

## 2. 持久化契约

Phase 11.8 后，trigger identity/幂等字段迁入 `quant_report_run`；完整 report 通过 run 的
`output_report_id` 一对一关联。report 新增 `profile_id`、`successor_report_id`、
`superseded_at/obsoleted_at`，并以 `(profile_id, report_kind) WHERE status='published'` 唯一索引
约束 current authority。`expired_at/status_reason` 等 lifecycle 字段继续保留其新语义。

`quant_portfolio_plan.model_run_id` nullable，用于 `EmptySelection` / `InsufficientDataQuality` 等未产生 model run 的完整空报告。

`NewReportTransaction` 一次提交：

```text
quant_account_snapshot
quant_report_data_quality_snapshot
quant_portfolio_plan
quant_recommendation_report
quant_recommendation[]
operation_log
COMMIT
```

`create_report` 事务遵循 SeaORM transaction 语义：任一插入失败自动 rollback；commit 成功后 lifecycle 才调用 publisher。

### 4.1 Rank score 列（持久化契约）

| 列 | 单一真相源 |
|---|---|
| `liquidity_score` | `SignalCandidate.factor_breakdown` 中 `liquidity_depth.normalized_score` |
| `data_quality_score` | `factor_breakdown` 中 `data_quality.normalized_score` |
| `model_score_percentile` | post-floor accepted 截面上 `annotate()`（runtime 构造时 `ZERO` 占位） |

缺失 factor → `Probability::ZERO` + `SignalWarning::Other`；`MarketDecisionCapture.liquidity_score` 仅用于 DQ 快照/可读性，**不**写入 recommendation rank 列。

### 4.2 Empty / failure / publication 矩阵（Phase 11.8）

| 结果 | 条件 | PG report | WS |
|---|---|---|---|
| Build failure | 账户/配置/infra | 无 report；ReportRun=Failed | durable `quant.report_run.failed` |
| Valid empty | 完整业务评估得到零 recommendation | Prepared → fact Verified → Published；`summary.empty_reason` 必填 | `prepared` → `published` |
| Non-empty | 正常 TopN | Prepared → fact Verified → Published | `prepared` → `published` |
| Fact failure | CH 写入/验证失败 | report 保持 Prepared；旧 current 不变 | durable `delivery_retrying/failed` |

Runtime v16 删除 `publish_empty_reports`；任何完整有效的 empty 结果都必须发布并取代旧 current。
系统 readiness、账户或 active model 不满足仍是 build failure，不得伪装成 empty。

### 4.3 Active model / gate 拒绝

`active_load_ok` / 未配置 active / registry 缺失 → typed build error + durable ReportRun Failed，不产 report。

## 3. Trigger 与幂等

`ReportLifecycleService` 统一 scheduled / ad-hoc 路径：

```text
scheduled: scheduled:{schedule_id}:{trigger_time_rfc3339}
ad-hoc:    ad_hoc:{request_id}
```

enqueue 先按 `quant_report_run.trigger_key` 做 durable idempotency。并发竞争由 run 表 unique index 做最终保护；
相同 request id 返回既有 run，不从 report 表推断运行状态。

scheduled `decision_at` 是 coordinator 实际 claim 的 DB 时间；`scheduled_for` 只用于审计。
knowledge lag 只推导 source cutoff，不把历史 scheduled instant 冒充在线 decision time。

## 4. Builder 流程

1. 按 `trigger_time` 加载单一 frozen runtime config version。
2. 在 selection 前加载 active model runtime，执行 `active_load_ok`，读取 `required_features`。
3. freeze market candidates，构建并持久化 market selection。
4. 获取真实 account snapshot；失败即 build failure，不写 report。
5. empty selection → Prepared report，`empty_reason=EmptySelection`。
6. feature pipeline accepted empty → Prepared report，`empty_reason=InsufficientDataQuality`。
7. model accepted empty → Prepared report，`empty_reason=NoPositiveSignal`。
8. portfolio planner planned empty → Prepared report，`empty_reason=PortfolioBudgetExhausted | NoPositiveSignal`。
9. 非空 plan → composer 产完整 recommendations。

## 5. Composer 契约

`RecommendationComposer` 输出 `ComposedReport`：

- `NewAccountSnapshot`
- `NewPortfolioPlan`
- `NewRecommendationReport`
- `Vec<NewRecommendation>`
- `Vec<QuantReportRecommendationFactRow>`（Phase 11.8 decision snapshot，无 live status）
- `ReportNotificationPayload`
- `NewOperationLog`

每条 recommendation 强类型落库：

- `EntryPlan`
- `SizingPlan`
- `ExitPlan`
- `RiskEnvelope`
- `RecommendationFactorBreakdown`
- `EvidenceRefs`
- `ExecutionEligibility`

`ReportSummary` 聚合 selection / candidate / rejected / published、USD allocation、score/confidence、data quality、eligibility、top rejection reasons。

`ExecutionEligibility` 只计算和落库；04.2 不创建 intent。

Factor evidence 必须能回到 factor definition、feature/model run、selection、config、model version。Weighted runtime 将 factor definition id / family / raw value / confidence / source refs 透传到 recommendation factor breakdown。

## 6. ExitPlan Closed Loop

04.2 实现 **报告级 ExitPlan 完整闭环**：生成、强类型落库、可审计、可回放，并供 Phase 5/6 Exit Monitor 消费。

04.2 不实现实际退出执行：不创建 sell intent，不监听 TP/SL，不做退出成交/对账。

生成规则固定：

```text
l = downside_bps / 10_000
g = target_reward_multiple * l
stop_loss_price = entry_price * (1 - l)
take_profit_price = entry_price * (1 + g)
stop_loss_pct = l
take_profit_pct = g
# 数据驱动的逐条有效期（不再用扁平 report_horizon_secs）：
effective_horizon = min(candidate.suggested_horizon_secs || reports.fallback_horizon_secs,
                        market.time_to_resolution_secs)
max_hold_secs = effective_horizon
time_exit_at = as_of + effective_horizon
# recommendation.valid_until = entry_plan.valid_until = as_of + effective_horizon * reports.entry_window_ratio
settlement_policy = HoldToResolution
```

禁止使用 `expected_return_bps` 作为止盈价来源；它是期望均值，不是条件目标收益。

本期 deterministic `partial_exit_nodes`：

- `tp_full`: `TakeProfit`, `sell_pct = 1`
- `sl_full`: `StopLoss`, `sell_pct = 1`
- `time_exit`: `TimeExit`, `sell_pct = 1`

`exit_reason` 必须引用 Kelly 赌局结构与 model headline。Phase 5/6 执行侧必须消费持久化 `ExitPlan`，不得重新推导 TP/SL。

## 7. Publisher 契约

`ReportPublisher` 只做 post-commit side effects；以下 Phase 4 的 CH best-effort 设计已由 Phase 11.8
破坏式替换为 `ReportFactBundleV2` + PG outbox + exact ClickHouse verification：

- `CoreEvent::ReportPublished/ReportRevoked/ReportExpired`
- `WsChannel::QuantReportUpdate`
- report metrics
- `quant_report_recommendation_fact` 由 durable fact worker 在 publication 前投递验证，不由 publisher fire-and-forget
- `StoreOnly` 跳过 Telegram/webhook；`StoreAndNotify` 且 `notification.policies.report_published=true` 才发 operator notification。

CH decision fact 不含 lifecycle；PG report/recommendation rows 是 lifecycle 唯一 source of truth。

## 8. Revoke / Expire

`revoke` / `expire` 是事务状态迁移，不 delete：

- 更新 report `status`、`status_reason`、`revoked_at` / `expired_at`
- 更新 child recommendation `status`
- 同事务写 `operation_log`
- commit 后发送对应 CoreEvent / WS

## 9. 当前验证重点

- Repository transaction 原子写 snapshot / plan / report / recs / op-log。
- Duplicate `trigger_key` 幂等。
- Account unavailable 不写 report。
- EmptySelection / InsufficientDataQuality / NoPositiveSignal / PortfolioBudgetExhausted 均产完整 Prepared empty report，事实验证后正式 Published。
- 不存在 empty suppression；有效 empty 必须取代旧 current。
- Prepare only after complete artifact transaction；Published only with fact Verified in the atomic publication transaction。
- ExitPlan TP/SL/time-exit/partial nodes 快照或单测锁定。
