## 0. 实现增量（04.0 as-built — 相对本规格的偏差，已落地）

> 本节记录实现期相对原始规格的偏差与增强，均已编码并通过质量门禁。原规格其余
> 部分仍为权威；冲突处以本节为准。

1. **强类型 payload / 账户值类型落 `types/`（非 `domain/quant`）**：JSONB 列内容类型是
   **entity 列类型**，而 entity 层在 `domain` 之下、不得依赖 `domain`（架构约束：无 entity→domain
   依赖）。因此 `EntryPlan`/`SizingPlan`/`ExitPlan`/`PartialExitNode`/`TrailingStop`/
   `SignalInvalidationRule`/`RiskEnvelope`/`FactorBreakdownEntry`/`RecommendationFactorBreakdown`/
   `EvidenceRefs`/`ExecutionEligibility`/`ReportSummary`(+子结构) 落
   [`types/report_payload.rs`](../../../crates/quant-pivot-models/src/types/report_payload.rs)；
   `PositionSnapshot`/`ExposureBreakdown`/`AccountPositions` 落
   [`types/account.rs`](../../../crates/quant-pivot-models/src/types/account.rs)；
   portfolio 计划三段 JSON 落 [`types/portfolio_plan.rs`](../../../crates/quant-pivot-models/src/types/portfolio_plan.rs)。
   它们沿用既有 `FromJsonQueryResult` + `IntoActiveValue` JSONB 模式（与 `SelectionExclusionSummary` 一致），
   `*Info`/`New*` 1:1 引用。`AccountSnapshot` 聚合仍在 research（`portfolio/account.rs`），复用上述 models 值类型。
2. **`AccountSource` 枚举落 `enums/quant.rs`**（`pg_enum!` → `qp_account_source` 列 + JSON 内枚举）。
3. **portfolio 计划 3 个 JSON 字段强类型化**（零裸 `Value`）：`PortfolioRiskBudget` /
   `PortfolioConstraintsSnapshot` / `PortfolioRejectedSummary`。
4. **`SizingPlan.edge_bps: Option<Bps>`**（非裸 `Decimal`）；bps 语义统一用 `Bps` newtype。
5. **`quant_recommendation` 新增第 7 个 JSONB 列 `execution_eligibility`**（`ExecutionEligibility`）：
   父文档 §14 的 execution_eligibility 是 per-recommendation，需独立列承载（避免未来破坏式加列）。
6. **`ExecutionEligibility` 用 `eligible_modes: Vec<QuantRuntimeMode>`**（替代三个 `eligible_in_*` bool；
   语义等价且消除 clippy `struct_excessive_bools`），含 `is_eligible(mode)` 辅助。
7. 旧统一 Runtime Config 版本递增已删除；报告语义直接进入 `RecommendationPolicy` boot schema `1`。
8. **`create_report` 单事务在 04.0 即修复（非推迟 04.2）**：签名改为接收
   `NewReportTransaction { account_snapshot, portfolio_plan, report, recommendations }`，按
   FK 顺序 `account_snapshot → portfolio_plan → report → recommendations` 单事务写入，
   修复原 `portfolio_plan_id` NOT NULL FK 必违例的 bug。revoke reason + op-log 仍留 04.2。
9. **`ReservedCapitalReader` 端口在 core、PG 聚合在 repository**：core 不得依赖 sea_orm（架构 lint），
   故新增 repository 侧 `ReservedCapitalRepository` + `PgReservedCapitalRepository`（按
   locked intent → recommendation.sizing_plan.suggested_usd 求和），core 侧 `ReservedCapitalReader`
   端口 + `RepoReservedCapitalReader` 适配器。
10. **凭证校验：所有 mode 都要求 private key + funder**（`validate_credentials_quant_mode`）：
    report_only ≠ dry-run，缺任一即 config 校验 error（fail closed）；`AccountBundle` 启动时
    `Keystore::from_config` + `ClobClient::connect` 进一步 fail closed。删除 `load_credentials_in_report_only`。
11. **方向语义破坏式拆分（后续轮次落地）**：删除 4 路 `SignalSide`（混淆 outcome×action）。
    recommendation/candidate 层改用 `OutcomeSide{Yes,No}`（开仓恒 buy-to-open，方向只在 yes/no），
    执行层 `quant_execution_order.side` 改用 `common::Side{Buy,Sell}`；CH fact `side` 语义随层
    区分（candidate/recommendation = outcome、execution = buy/sell），列类型不变。
12. **闭环缺口补齐 + payload 去裸 Value**：`quant_recommendation` 增标量列
    `expected_return_bps` / `downside_bps`（模型原始 edge 估计，可审计/可训练），`EvidenceRefs`
    增 `signal_candidate_id`（回溯 candidate fact）；`quant_recommendation_attribution` 与
    `quant_order_intent` 的 JSONB 列从裸 `serde_json::Value` 强类型化为
    `EntryOutcome`/`ExitOutcome`/`AttributionDetail` 与 `EntryOrderSpec`/`ExitPolicySpec`
    （`types/attribution_payload.rs` / `types/execution_payload.rs`；仅立契约，写入仍属 Phase 5/6）。
13. **composer 语义纠偏**：`entry_plan.min_depth_usd` 取 `data_quality.min_book_depth_usd`、
    `max_book_age_ms` 取 `data_quality.max_book_age_ms`、`Immediate` 触发下
    `cancel_if_not_triggered=false`；`exit_plan` 以 TP/SL/time 标量为唯一真相源（删除复制标量的
    全量 `partial_exit_nodes`，仅真分批时非空），`settlement_policy` 由出场配置推导。

## 1. 目标与闭环定位

交付五类地基：

1. **强类型报告 payload**（serde ↔ 既有 JSON 列）：消灭裸 `serde_json::Value`，让
   04.2 composer 产出可快照、可断言、可演化的结构。
2. **账户资本抽象**：`AccountSnapshot` / `PositionSnapshot` / `ExposureBreakdown` 值类型
   + `AccountProvider` trait + 唯一 `VenueAccountProvider`（credential-gated 真实账户，
   **所有 mode** 通用，凭证缺失则 fail closed），并落 `quant_account_snapshot` 表，使
   sizing 资本基数可审计、可回放。
3. **runtime-config 破坏式重构**：`PortfolioConfig` 三段化、`ReportScheduleConfig`
   cadence 化。
4. **repository 补齐**：新建 `PortfolioPlanRepository`、收敛 `RecommendationRepository`
   为只读、扩展报告创建事务契约（impl 在 04.2）。
5. **报告 header 增列**：`account_source` / `capital_base_usd` / `account_snapshot_ref`。

本子phase完成后，04.1 可直接消费 `AccountSnapshot` + 三段 config，04.2 可直接
组装强类型 payload 并走统一事务。

- **新增** `[market_data.data_api].base_url`（默认 `https://data-api.polymarket.com`）——
  Data API 持仓读取端点（公开 keyless）。
- **新增** `[quant.account].funder`（`Option<String>`，Polymarket **proxy/funder 地址**，
  独立于 signer EOA）——Data API `user=<funder>` 参数；报告生成时若为 `None` → fail closed。
- **删除** `[quant.execution].load_credentials_in_report_only`：凭证在**所有 mode** 都
  加载用于**读**（CLOB 抵押），不再 mode-gated。私钥的**签名**用途仍仅 semi_auto/auto。
- `deploy.quant.workers.report_scheduler_tick_secs`：**已删除**（04.3），由
  `report_expire_sweep_secs`（仅 expire sweep cadence，非主触发器）取代。

> 语义铁律：`report_only` 不是 dry-run。它**需要**私钥（读 CLOB 抵押、派生 L2 读凭证）
> 与 funder（读 Data API 持仓）才能生成报告；私钥**不用于**签名/下单（仅 semi_auto/auto）。

#### 5.2.1 持仓：快照读路径 vs 持久化账本（关键边界）

**报告生产依赖「决策时刻真实持仓快照」，不依赖 `quant_position` 账本表。**

| 问题 | Phase 4 答案 |
|---|---|
| sizing 要不要知道当前持有什么？ | **要**——否则 `market/event/category_exposure_after_usd` 与 cap room 错误 |
| 数据从哪来？ | 持仓 = Data API `GET /positions?user=<funder>`（keyless）；抵押余额 = CLOB（私钥）|
| 要不要写 `quant_position`？ | **不要**——快照落 `quant_account_snapshot.positions_json` 即可回放 |
| 账本何时需要？ | Phase 5：execution fills 驱动写入 + 对账与 venue 对齐 |

账户读取（**所有 mode 一致，credential-gated**）：

| 维度 | 来源 | 凭证 |
|---|---|---|
| `venue_net_liquidation_usd` | `available_collateral + Σ position.current_value` | 私钥（抵押）+ funder（持仓）|
| `capital_base_usd` | `min(venue_net_liquidation_usd, budget.total_budget_usd)` | 治理 runtime config |
| `positions` | Data API `GET /positions?user=<funder>` | keyless（仅需 funder 地址）|
| `available_usd` | `available_collateral − reserved_usd` | 私钥 |
| `reserved_usd` | semi_auto/auto：pending intent 聚合；report_only：`0`（§5.2.4）| — |
| `source` | 恒 `Polymarket` | — |

任一真实读路径失败 / 私钥或 funder 缺失 → **报告不生成（fail closed）**。

#### 5.2.2 `VenueAccountProvider`（唯一 provider，所有 mode）— **Phase 4 落地**

```rust
pub struct VenueAccountProvider {
    pub client: Arc<dyn PolymarketAccountClient>,  // CLOB 抵押 + Data API 持仓
    pub registry: Arc<MarketRegistry>,             // conditionId→market/event/category
    pub budget_cap: PortfolioBudget,               // 治理护栏（最大可部署上限）
    pub reserved_reader: Arc<dyn ReservedCapitalReader>,
    pub funder: String,                            // Polymarket proxy 地址（≠ signer EOA）
}
```

- `available_collateral()` = CLOB pUSD（需私钥 L2 凭证）。
- `positions(funder)` = Data API（keyless）→ 经 `registry` 映射为 `PositionSnapshot`
  （含 `current_value`）。
- `venue_net_liquidation_usd = available_collateral + Σ position.current_value`。
- `capital_base_usd = min(venue_net_liquidation_usd, budget_cap.total_budget_usd)`。
- `available_usd = available_collateral − reserved_usd`。
- `reserved_usd = ReservedCapitalReader::sum_locked()`（见 §5.2.4）。
- 任一读路径失败 → **Err**，lifecycle 不生成报告（fail closed；**绝不**用配置 budget 冒充）。

## 6. 生产不变量与失败语义

- **强类型 ↔ JSON 列**：所有 payload 块 serde round-trip 稳定；列仍是 JsonBinary，
  schema 演化通过结构体字段 + `#[serde(default)]`，绝不裸 `Value`。
- **政策 ≠ 状态**：`PortfolioConfig` 只表达限额；账户现实只来自 `AccountSnapshot`。
  04.0 不得在 config 里塞任何"当前余额/持仓"字段。
- **资本基数可回放**：每份报告必引用一条 `quant_account_snapshot`；positions /
  exposures 一并持久化，保证 `exposure_after` 可复现。
- **持仓快照 vs 账本**：planner 只读 `AccountSnapshot.positions`/`exposures`（来自
  04.0 快照读路径）；**不**读 `quant_position` 表（Phase 5）。
- **report_only ≠ dry-run**：报告强制建立在真实账户上；`report_only` **需要**私钥
  （读 CLOB 抵押、派生 L2 读凭证）+ funder（读 Data API 持仓）。私钥**仅用于读**，
  签名/下单仅 semi_auto/auto。
- **credential-gated 真实账户**：账户真实性由凭证就绪决定、与 mode 正交；
  `equity = min(真实净清算价值, budget 护栏)`，budget **永不**充当 equity。
- **fail closed（所有 mode）**：`VenueAccountProvider` 余额/持仓/reserved 任一读失败、
  或私钥/funder 缺失 → **不生成报告**；**无模拟、无绿场、绝不用配置 budget 冒充**。
- **money newtype**：`Usd`/`Price`/`Shares`/`Probability`；`f64` 不进 DTO/表。
- **catalog 驱动 schema**：新表/新列只改 iden + entity + DTO + catalog 列表；禁止手写
  SQL 迁移。
- **校验前移**：config 破坏式重构后，`validation.rs` 必须拒绝非法 budget/constraints/
  cadence；`deny_unknown_fields` 保持。

## 9. Blocker

- 若报告 payload 仍以裸 `serde_json::Value` 暴露给 04.2，本子phase失败。
- 若 `PortfolioConfig` 里出现任何"当前余额/持仓"状态字段（政策 ≠ 状态被破坏），失败。
- 若 `quant_account_snapshot` 未进 catalog 或 report header 缺三列，失败。
- 若存在 `ConfiguredAccountProvider`/`SimulatedAccountProvider` 或任何「配置 budget 充当 equity」路径，失败。
- 若凭证缺失（无私钥/无 funder）仍生成报告（应 fail closed），失败。
- 若 venue 读失败时静默降级为配置 budget sizing（任何 mode），失败。
- 若把 mode 当作账户真实性的选择维度（mode-gated 余额），失败。
- 若 planner 直接读 `quant_position` 表而非 `AccountSnapshot`，失败。
- 若删除清单中的 DEAD 类型仍被引用，失败。
