# 11.6 — Training-Serving Parity & No-Silent-Zero

> 关闭审计点:**#10(历史 registry PIT 返回 None → 依赖 registry 的特征离线/在线不对称,潜在静默 skew)**、
> **#11(classical ML 缺失非关键特征 `fill_missing:0.0`,违反禁止静默填零不变量)**。

## 1. 目标与闭环定位

消除**训练-服务偏斜(training-serving skew)**与**静默填零**这两个"安静杀手"。它们不报错、测试全绿,
却让模型线上表现悄悄劣化。本子phase把"一份特征定义、离线在线同源、PIT 一致、缺失显式"钉成硬不变量。

设计立场(权威来源):

- Google Rules of ML #29/#32/#37:复用训练/服务代码是消除 skew 的**结构性**修法;PIT(AS-OF)join 是
  时间偏斜的修法;分别监控 train-holdout / holdout-nextday / nextday-live gap
  (<https://datarekha.com/mlops/training-serving-skew/>)。
- Feature store 的核心价值是"一份定义、两条路径同源 + PIT 正确 + 在线/离线 parity 校验"
  (<https://scalemind.dev/ai/ml/mlops/feature-stores-and-training-serving-consistency/>、
  <https://hld.handbook.academy/curriculum/ai-ml-system-design/feature-stores-model-serving/>)。
- 特征缺失时"missing 当 0"是经典 skew 来源(Redis TTL 过期→模型当 0);必须显式 missing 语义。

闭环定位:它是 11.1(因子)与 11.4/11.5(训练/验证)之间的**数据契约地基**,保证离线学到的东西在线成立。

## 2. 删除 / 合并 / 重构清单

| 对象 | 现状 | 处置 |
|---|---|---|
| `PitView::resolve_registry` 历史源恒返回 `None`(`features/mod.rs`) | 离线缺 registry 字段 | **重构**:历史 PIT 从 Postgres market metadata 版本 + ClickHouse 按 `as_of` 解析 registry 真值(fee/identity/neg_risk/outcome_count 等),与在线 `MarketRegistry` **同一读取语义**。 |
| classical 训练 `fill_missing: 0.0`(`service/model_training.rs`) | 静默填 0 | **删除静默填零**:缺失走 null policy(reject / neutral-with-audit / penalize / domain-missing),与在线特征层一致(#11)。 |
| 训练矩阵与在线推理可能走不同缺失处理 | 潜在 skew | **统一**:一份 `FeatureContract` 决定缺失/编码/单位,离线在线共用(§3)。 |

## 3. 契约与算法设计

### 3.1 单一特征契约(one definition, both paths)

```rust
/// The single source of truth for a feature's semantics. Both the online feature
/// builder and the offline dataset builder consume THIS — never a second impl.
pub struct FeatureContract {
    pub name: FeatureName,
    pub family: FeatureFamily,
    pub value_kind: ValueKind,
    pub unit: Unit,
    pub valid_range: Option<(Decimal, Decimal)>,
    pub null_policy: NullPolicy,          // RejectMarket | NeutralValue(audited) | Penalize | DomainMissing
    pub pit_rule: PitRule,                // e.g. book.version.published_at <= as_of
    pub staleness_policy: StalenessPolicy,
    pub source_requirement: SourceRequirement,
}
```

在线 `FeatureBuilder` 与离线 `TrainingDatasetBuilder` 都从**同一** `FeatureContract` 注册表取语义;
CI 断言不存在第二份缺失/编码实现。

### 3.2 历史 registry PIT 解析(#10)

```rust
/// Historical registry resolution at as_of: same fields the online MarketRegistry
/// exposes, resolved from versioned Postgres metadata + ClickHouse facts. Returns
/// an explicit Missing (never a silent None that downstream treats as default).
pub trait HistoricalRegistryResolver {
    fn resolve_registry_at(&self, market_id: &MarketId, as_of: DateTime<Utc>)
        -> QuantResult<RegistryResolution>;   // Resolved(MarketRegistryView) | Missing(reason)
}
```

- 若某 registry 字段在 `as_of` 无版本 → `Missing(reason)`,依赖它的特征走该特征的 null policy,
  **不静默用当前值或 0**。
- 消除"离线 registry=None → 特征缺失;在线 registry 有值 → 特征存在"的不对称。

### 3.3 缺失处理统一(#11)

- 删除 classical 训练里的 `fill_missing: 0.0`。改为:critical 缺失 → 拒绝样本;non-critical 缺失 →
  按该特征 `NullPolicy`(neutral-with-audit / penalize),并在训练矩阵记录 `SubstitutionAudit`。
- NaN/inf → 拒绝样本(与全平面一致)。

### 3.4 在线/离线 parity 校验(持续)

新增 parity 测试与运行期抽样(Google Rule #29/#37):

```rust
/// Recompute a sampled (market, as_of) through BOTH the online and offline paths
/// and assert identical feature vectors (bit-for-bit within Decimal scale).
pub trait FeatureParityChecker {
    async fn check(&self, sample: ParitySample) -> QuantResult<ParityReport>;
}
```

- CI parity 测试:同一 raw 输入过两条路径,断言输出向量相同。
- 运行期:周期性抽样在线请求,离线重算,比对分布/缺失率/精确值,漂移入 metrics + 告警。
- 监控三段 gap:train↔holdout、holdout↔nextday、nextday↔live(只有最后一段暴露真实 serving skew)。

## 6. 生产不变量与失败语义

- **一份定义**:同一 `FeatureContract` 服务 online + offline;CI 禁止第二份缺失/编码实现。
- **PIT AS-OF**:离线取值 = `as_of` 时点最近可得值(`≤ as_of`),永不取当前值回填历史。
- **禁止静默填零**:全平面(含 classical 训练矩阵)无 `fill 0`;缺失显式且审计。
- **registry 对称**:离线 registry 解析与在线同字段同语义;缺失显式 Missing。
- **parity 门禁**:CI parity 测试失败即 red;运行期 skew 超阈值告警。
