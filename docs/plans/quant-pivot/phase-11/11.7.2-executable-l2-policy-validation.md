## 1. 目标与闭环定位

本阶段必须真实完成：

```text
PIT full-L2 + fee + metadata
  → executable trajectory
  → complete frozen-policy path simulation
  → purged CPCV + uniqueness/effective-N + complete trial ledger
  → DSR/PBO/utility/coverage gates
  → Validated → Published TradePolicyArtifact
  → dataset/model exact hash binding
  → ReportOnly shadow
  → isolated SemiAuto execution + attribution
```

11.7.2 不是另建 policy schema，也不是恢复启发式 TP/SL。它只实现研究激活能力：至少一个非
synthetic cohort 以真实 L2、PIT 费用和完整验证证据发布，并被 serving 使用。AutoExecution 仍由
[11.11](11.11-execution-governance-hardening.md) readiness gates 控制。

## 3. 权威输入与完整冻结策略路径模拟器

### 3.1 PIT 输入契约

权威事实源是 ClickHouse `quant_book_l2_event` v2 与 WORM 日分区 Parquet；
`quant_book_l2_checkpoint` 只作为重放加速点。每个 observation 必须：

- 按 `(token_id, event_time, ingestion_time, sequence)` 确定性去重，且 `observed_at/ingested_at` 不超过
  artifact 的 `pit_cutoff`；
- bid 递减、ask 递增、非 crossed，价格处于 `[tick, 1 - tick]`，数量使用 Decimal newtype；
- `top_n/levels_count` 与实际 ladder 一致，truncated、gap、lag、缺腿、乱序均输出 typed unavailable；
- 费用、tick、NegRisk、scheduled end/resolution metadata 必须有 decision 当时可见的 provenance；缺失
  fee evidence 不能当零费率，当前 metadata 不能回填历史。

批量读取必须在 research repository 边界完成，禁止 per-observation N+1 和 core service 手写 JSON/
Decimal 交易计算。simulator contract 固化输入 hash、fee model、metadata snapshot、latency/slippage 假设、
code version、seed 和 simulator version。

### 3.2 完整路径模拟

模拟单位是“一个 observation × 一个精确 notional tier × 一个冻结候选策略”，必须逐事件执行：

1. entry：目标 USD 对 ask ladder 逐档 walk，应用 fee、tick 定向舍入、price bound、触发确认和 latency；
2. barrier gap：条件或 barrier 被越过后，使用下一份可执行 fresh book 成交，不假设正好在 barrier price；
3. exit：对实际剩余 shares 逐档 walk bid，计 fee、深度不足和 partial fill；未成交残仓继续进入后续事件；
4. 按累计比例执行最多三档 `scale_out_targets`，用固定 entry-filled denominator 计算 delta；
5. 每事件更新 peak mark/effective trailing stop，并按冻结优先级处理 full TP、stop、thesis invalidation、
   vertical exit 和 resolution；
6. 同一时间桶上下障碍均越过、且更细 L2 事件仍不能证明顺序时，输出 `AmbiguousBarrierTouch`，该路径
   unavailable，禁止按任意顺序结算；
7. 输出完整路径 entry/exit fills、费用、slippage、depth failures、net executable return，以及
   `policy_net_positive = net executable return > 0`；raw MFE/MAE 独立扫描完整 horizon，不被 barrier censor。

### 3.3 Prediction Market 边界与 resolution

- 每个候选价格按 registry tick 做 side-aware projection，并限制在 `[tick, 1 - tick]`；投影后上下 barrier
  重合或次序反转时，该候选不可用。
- vertical deadline 是 `min(policy horizon deadline, PIT-known scheduled resolution/end deadline)`。
- 市场实际提前 resolution 只能在该事件当时变为可观测后处理，禁止用未来修正的 resolution timestamp
  回填历史路径。
- 结构波动输入至少包括 entry price、time-to-resolution、spread、full depth、order flow、volume 和
  resolution regime；禁止直接套普通资产 ATR/GBM 或忽略二元价格边界。

## 4. Structural volatility、cohort 与 deterministic shrinkage

cohort provenance 必须版本化并内容寻址：

```text
methodology_id + methodology_hash + bucket_id + parent_bucket_id + complete shrink_path
```

叶 cohort 固定包含 category、horizon/resolution semantics、entry-price bucket、精确 notional tier、
liquidity bucket 和 structural-volatility bucket。category 只是候选维度，不预设 category-specific 一定
优于 pooled parent。

收缩顺序固定为：

1. category-specific → pooled category；
2. estimator 声明的 volatility parent；
3. liquidity parent；
4. price-bucket parent。

每一步都必须保持 notional tier 与 resolution horizon 不变，并记录 parent、样本数、coverage、
effective-N 和 utility confidence bound 的变化。notional 禁止跨档 shrink，resolution 语义禁止跨 horizon
合并。任一 parent 仍无法得到正的可信效用下界时，该 leaf 不可执行。

## 5. Exact-tier selector 与 serving 一致性

fit、backtest、shadow comparison 和 recommendation composer 必须调用同一纯领域 selector：

- 风险预算先独立计算，再向下选择不超过预算的最大 validated tier；禁止 nearest/up-rounding，且
  不得跨 tier 做 cohort shrink。
- category、horizon、price、liquidity、volatility、tick 与 metadata 均精确验证。
- 当前 L2 无法完整支持 frozen tier 时返回 `TradePlanBlocker::LiquidityInsufficient`，不得静默缩量。
- 缩量只能通过重新 composer 生成另一条精确 tier 推荐，或 approval 的单位安全 downscale；后者仍在
  Ready admission 重新校验可执行深度与策略约束。
- ModelVersion、dataset、artifact 和 recommendation 的 policy ID/hash 任一不一致都 fail closed。

## 6. Purging、uniqueness 与有效样本量

每个 observation 的信息区间定义为 `[decision_at, matured_at]`。CPCV/purging 以区间重叠判断 fold
污染，而不是只比较 decision timestamp。embargo 从前一阶段真实 PIT cutoff/validation boundary 开始：

```text
policy fit cutoff → embargo → model training cutoff → embargo
  → calibration cutoff → embargo/frozen boundary → final evaluation
```

根据同时活跃事件数计算 observation concurrency 与 average uniqueness。uniqueness 是训练、候选评估、
utility confidence interval、DSR 的权重，并据此计算 effective sample size。quality gate 同时报告 raw row
count 和 effective-N，但发布判断使用 effective-N。purging 解决信息泄漏，uniqueness 解决重叠样本冗余，
两者不可互相替代。

## 7. 完整 trial ledger 与真实性门禁

trial ledger 必须记录全部尝试，而非只记 winner：

- entry condition、barrier、vertical、最多三档 scale-out、trailing、invalidation 的所有组合；
- 所有超参数、cohort、shrink path、失败候选及失败原因；
- trial ordering、seed、dataset/input hash、code/simulator version；
- 每条路径的 purged folds、effective-N、coverage、ambiguity/depth failure、utility distribution。

CPCV path count 必须达到 frozen quality gate；DSR 使用完整 trial count 和 effective-N；PBO 使用所有
候选表现，禁止只计算 winner。缺失证据必须是 `None + TradePolicyPublicationBlocker`，禁止零值、占位
hash、自报 `passed` 或 free-form publication decision。Validate 与 Publish 每次都从 immutable payload
和 frozen gate 重新推导 blockers；API/UI 不复制阈值逻辑。

## 8. 模块、存储与任务运行

- research/training：typed ladder parser、trajectory builder、full policy simulator、structural volatility
  estimator、exact-tier selector、purged CPCV/trial ledger。
- repository：按 token/window/cutoff 批量读取 L2/fee/metadata/resolution evidence；coverage reason 是稳定 enum。
- async fit job：阶段进度、cooperative cancel、restart idempotency；相同 canonical payload 返回同一 artifact。
- policy artifact v3：保存 serving cohorts/per-cohort summary 与 evidence bundle ref；row-level evidence
  位于 WORM Parquet bundle，固化 trial ledger hash、CPCV/DSR/PBO、effective-N 和 frozen gate，
  然后计算 content hash。治理转换只改状态并追加 WORM audit，不回写 payload。
- dataset/model v4：固化 exact policy ID/hash；旧 artifact 全部重建，不提供兼容 loader。

## 9. 测试、上线与 Blocker

必须覆盖：

- full ask-entry/bid-exit、fee、gap fill、partial depth、累计 scale-out、trailing/invalidation/vertical/resolution；
- tick collapse、`[tick,1-tick]`、提前 resolution 的 PIT visibility、同桶双穿越；
- exact-tier、禁止 cross-tier shrink、完整 shrink provenance；
- interval purging、concurrency、average uniqueness、effective-N；
- complete trial ledger、DSR trial count、PBO all-candidate；
- missing L2/fee/CPCV/DSR/PBO/utility evidence 均不能 Validate/Publish；
- hash determinism、restart idempotency、dataset/model/recommendation binding；
- 从空库完成 ReportOnly shadow，并在隔离环境完成 SemiAuto 交易/退出/归因。

任一以下情况是 phase blocker：样本使用未来 metadata/fee/resolution；mid/top-of-book 被当完整成交；
notional fallback；trial ledger 缺候选；raw row count 替代 effective-N；任何缺失证据能 Publish；或受保护
E2E 无法稳定驱动状态。

## 10. 研究激活退出标准

11.7.2 只有同时满足以下条件才完成：

1. 至少一个非 synthetic cohort 通过 full-L2、PIT fee、coverage、正 utility lower bound、CPCV、DSR、
   PBO、ambiguity 和 depth-failure 门禁，并成功 `Published`。
2. Published artifact hash 与 dataset/model/recommendation 中绑定的 hash 完全一致。
3. 完成真实 `policy fit → publish → dataset labels → model train/publish → report`；ReportOnly shadow 可与
   旧研究基线对比，但旧启发式结果永不进入 execution contract。
4. 在隔离测试环境完成 `approve/arm → trigger → order → fill → scale-out/full exit → attribution`。
5. recommendation、intent、model、policy、position 受保护页面通过真实登录/RBAC E2E，以及相同桌面
   viewport 和窄屏 drawer 的视觉比较。
6. AutoExecution 保持关闭，直至 11.11 readiness gates 独立通过。

本阶段完成前，不得把 Draft artifact、测试 fixture、占位 evidence 或 UI 可展示性描述为 research
activation；Phase README 必须继续显示“11.7 执行/运营闭环已收口，真实研究激活受 11.7.2 阻断”。
