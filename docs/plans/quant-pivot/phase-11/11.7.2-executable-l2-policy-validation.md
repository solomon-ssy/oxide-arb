# 11.7.2 — 可执行 L2 策略拟合与验证激活

> 状态：设计冻结、待实施。11.7 已完成 artifact/label/执行契约和 fail-closed 骨架；在本子阶段
> 完成前，只有 top-of-book 或无费用证据的 `TradePolicyArtifact` 必须停留在 `Draft`，不得开放
> SemiAuto/AutoExecution。

## 1. 目标与非目标

本阶段只关闭 11.7 当前唯一的研究激活缺口：把已经存在的 `book_snapshots.bids_json/asks_json`
历史 L2 事实、PIT 费用证据和 11.5 的 purge/CPCV/DSR/PBO 方法论接入 policy fit，使 artifact 能以
真实可执行净收益通过质量门禁。它不新增交易所抽象，不实现 11.7.1 condition AST，也不保留第二套
policy schema、兼容 loader 或 top-of-book 发布后门。

## 2. 权威数据输入

复用现有 ClickHouse `book_snapshots`，不再建一张语义重复的 ladder 表。每个进入 fit 的 snapshot 必须：

- `token_id/event_time/ingestion_time/sequence` 满足 PIT cutoff，按现有稳定顺序去重；
- `bids_json/asks_json` 可解析成强类型 `BookLevel`，价格/份额均为 Decimal newtype；
- bid 递减、ask 递增、非 crossed、价格位于 `[tick, 1-tick]`，每档满足当时 registry tick；
- `top_n/levels_count` 与实际数组一致，目标 notional 所需一侧梯子完整；
- snapshot gap、ingestion lag、缺腿或 truncated ladder 写入 coverage reason，不静默补齐。

费用必须来自 decision 时已知的 PIT evidence。优先消费冻结在 decision capture 的 `fee_rate` 及其
metadata provenance；若 venue fee schedule 不能证明在 entry/exit 时点有效，则样本 unavailable。不得使用
当前费率回填历史，也不得把 `None` 当零费率。

## 3. 可执行轨迹构建器

为每个 training example 和每个 notional tier 构建独立轨迹：

1. decision 时对 ask ladder 逐档成交，得到 entry VWAP、shares、fee 和未成交余量；
2. horizon 内每个可证明 observation 对固定 shares 走 bid ladder，得到 exit VWAP、fee、net return；
3. ladder 不足只能得到 `InsufficientDepth`，不能用最后一档、mid 或 top-of-book 外推；
4. 同桶上下障碍都被跨越且没有更细 observation 时输出 `AmbiguousBarrierTouch`；
5. vertical deadline 使用 deadline 前最后一个 PIT-valid、fresh、可完整退出的 bid ladder；
6. 输出 raw MFE/MAE 全轨迹和 policy-derived triple/meta labels，前者不受 barrier 截断。

fill simulator v2 的 canonical 输入包括 ladder、tick、fee evidence、notional、side、cutoff 和 simulator
version；相同输入必须产生相同 hash。v1 degraded simulator 只允许生成 Draft shadow artifact，不能与 v2
结果合并计算 coverage。

## 4. Cohort、搜索与确定性收缩

cohort key 固定为 category、horizon、entry-price bucket、notional tier、liquidity tier、volatility regime。
候选网格只在 policy-fit fold 内搜索：entry comparison/threshold、上下障碍、vertical、最多三档累计
scale-out、可选 trailing 和 thesis invalidation。目标函数使用净可执行 utility，并对 tail loss、turnover、
depth failure 和 unresolved ambiguity 施加显式惩罚。

样本稀疏时只按以下固定顺序收缩，不运行数据驱动的任意邻居选择：

```text
volatility regime → liquidity tier → entry-price bucket → category parent
```

artifact 保存 parent cohort index、收缩前后样本量和可信下界。父 cohort 仍不足、utility 下界 `<= 0`
或 executable coverage 未达 contract 时，该叶 cohort 不生成可执行策略。

## 5. 验证与不可变 artifact

窗口顺序是单向的：

```text
policy fit → embargo → model training → embargo → calibration → final evaluation
```

policy fit 自身使用 purged/CPCV trial grid；DSR 的 trial count 必须覆盖所有实际尝试组合，PBO 使用同一
trial ledger，不得只登记胜出参数。最终 `TradePolicyArtifactPayload` 在 async fit job 内一次性写入完整
CPCV/DSR/PBO 和 L2/fee coverage，再计算 content hash。后续 `Draft → Validated → Published` 只改变治理
状态和追加 WORM audit，绝不回写 payload 或“补挂”验证结果。

发布硬门禁：

- `full_l2_coverage >= contract.minimum_executable_coverage`，且 degraded 样本不计入分子；
- 所有可执行 cohort 有 PIT fee evidence、正 utility 下界和确定性 shrink provenance；
- CPCV path count、DSR、PBO、ambiguity/depth failure rate 全部通过；
- dataset hash、policy hash、ModelVersion header 与 composer 读取结果完全一致；
- shadow report 的 wire projection 通过 FOK/FAK/GTD、BUY USD、tick/NegRisk admission 测试。

## 6. 实施清单与清理

      service 手写 JSON/Decimal 计算。

      `book_snapshots_between`；禁止 N+1 查询。
- [ ] 新增 fee provenance contract 和 coverage reason enum；删除当前字符串化的
      `"fees-not-applied"`/`"unclassified"` 发布路径。
- [ ] 把 11.5.1 遗留的 opportunistic Sell 决策阈值（confidence、P(exit)、alpha、累计退出上限）
      固化进 cohort policy 并冻结到 intent；线上与 CPCV 都从同一冻结值构造 `SellSignalPolicy`。runtime
      最终只保留 worker cadence、shadow rollout switch 和只能收紧的 dust/风险安全上限，删除
      `try_from_runtime` 与策略选择字段；完成前 opportunistic Sell 只能 shadow，禁止真实提交。
- [ ] 用 fill simulator v2 与 policy CPCV search 替换当前 empirical quantile fitter；v1 仅保留明确命名的
      degraded Draft shadow 路径，禁止自动 fallback。
- [ ] fit job 增加 phase progress、cooperative cancel 和 restart idempotency；重复内容返回同一 artifact。
- [ ] 补齐 full-L2/fee/ambiguous/sparse/CPCV/property tests 和从空库的端到端闭环。
- [ ] seed harness 必须写入真实 serving-evidence completion 或明确预期 parity containment；不得再用
      缩略 evidence 冒充可执行基线。
- [ ] 获得 Published policy 后，重录 recommendation/intent/model 同视口基线与结果截图，并完成审批弹窗、
      Waiting→Confirming→Ready、Cancel、report revoke cascade 的浏览器 E2E。

不新增旧 v2 artifact 读取、runtime 策略参数、`DataEvent` 占位、manual NegRisk、第二套 scale-out state
或 submit endpoint。完成替换后，任何不再被 Draft shadow/诊断消费的 empirical fitter helper 和字符串
coverage reason 必须删除，不留 alias/re-export。

## 7. Exit criteria

1. 至少一个非合成、PIT 完整的 cohort 以 full L2 + fee + CPCV/DSR/PBO 证据通过 Validate/Publish。
2. `policy fit → model train/publish → report → approve/arm → trigger → fill → scale-out/full exit → attribution`
   在 ReportOnly shadow 与 SemiAuto 测试环境各完成一次；AutoExecution 仍受 11.11 阻断。
3. 降级、费用缺失、双穿越、深度不足、hash/tick/NegRisk 不一致均有明确 unavailable/blocker，且测试证明
   不会静默回退。
4. 全量 Rust/UI/architecture/browser 门禁通过，受保护页面存在同 viewport 的可审计前后证据。
