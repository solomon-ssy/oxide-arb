## 1. 目标与退出边界

11.7.2 关闭的不是“能生成策略 JSON”，而是以下可独立重放、可审计、可撤销的业务链：

```text
完整 PIT 市场目录
→ content-addressed Source Slice v2
→ L2 / trade tape / PIT fee / Weather 事实重放
→ 不可变 Research Profile 下的完整策略实验
→ append-only trial ledger + CPCV / DSR / PBO / ESS
→ Evidence Bundle v3（九类 typed objects）+ WORM
→ row-level Validate + governed Publish
→ ReportOnly shadow
```

任一数据、成本、horizon、统计、证据或 lineage 不完整，只能返回 typed blocker。禁止创建空 Draft、
伪造 evidence、发布 synthetic winner 或把 `ResearchOnly` 结果激活为 SemiAuto。

## 2. 唯一治理契约

当前版本组合固定为各 boot policy/artifact schema `1`。旧对象不能进入 build、fit、Validate、Publish、report、activation 或 order admission；
不提供旧 parser、compat reader、双写、alias、conversion shim 或 compatibility re-export。

`ResearchProfileArtifact` 是 horizon、fit span、source、cash-budget tier、激活资格和 publication quality
gate 的唯一真相。Runtime Policy 只保存真正需要热更新的决策参数；CPCV `N=8,k=3`、56 splits、
21 paths、8 PBO blocks、95% one-sided utility confidence 与 2× latency stress 是版本化方法常量，
进入 methodology hash，不是可编辑配置。Fit request 不接受自由 horizon、tier、window 或 quality gate。

Runtime v15 只注册：

- `pooled_1h_control@1`：研究和回归基线，永远 `ResearchOnly`；
- `weather_forecast_24h@1`：90 个自然日 fit、精确 24h horizon、每小时决策、最新完整 GEFS cycle、
  每 market/hour 一个样本、唯一 `$25` 最大总现金支出档位，可进入 `SemiAutoCandidate`。

Sports、deadline narrative、scheduled release 与 crypto 在各自 PIT source、resolution、cost、horizon、
validation contract 完整前不得注册空画像。Phase 11.9 承接 profile expansion；Phase 11.11 才允许
AutoExecution。

## 3. PIT 数据与 Source Slice

ClickHouse 是通用 raw fact 的唯一查询面。L2 event/checkpoint/session 与 trade tape 按月分区；最近
14 天位于 hot volume，之后由原生 storage policy/`TTL MOVE` 进入 cold/object volume。应用层
Parquet archive worker、archive manifest、partition-drop scheduler/repository/config/test 已删除，禁止
重建第二套 raw 查询系统。

每次 fit 先物化 `SourceSliceManifestV2`。fitter 与 Validate 只能读取该 slice，不再访问 Gamma、CLOB、
weather 或动态 ClickHouse query。Manifest 必须绑定 profile/program/runtime/dataset/window/cutoff，并记录：

- catalog watermark、完整 sync sequence、snapshot hash；
- CLOB market info、L2 event/checkpoint/session/gap、trade tape、Weather/calibration/resolution、
  decision/feature/label 对象；
- 每对象 URI、byte/schema hash、row count、min/max event/availability time；
- first-failure session invalidation、reader/schema/runtime version 与所有 PIT cutoff。

内容相同对象按 hash 去重。WORM 只封存被 Dataset/Policy Evidence 引用的 slice，不承担通用历史查询。
Validate 必须逐行重放 fills、cost、barrier、cohort、coverage 和 blocker；只比较汇总 JSON 不构成验证。

Raw retention 为 `max(180, 2 × max(required_days(profile)))`，其中 `required_days = fit span + feature
lookback + target horizon + purge/embargo`。`TTL DELETE` 只有在 signed retention plan、slice WORM seal、
逐对象校验、恢复演练、容量预算和读取基准全部通过后才可启用；backup、retention、evidence 是三个责任边界。

## 4. CLOB 参数与执行语义

`ClobMarketInfoVersion` 是 append-only 双时态唯一真相，保存 condition/token、tick、minimum order、
negative risk、taker delay、完整 `fd={r,e,to}`、builder maker/taker schedule、`effective_at`、
`available_at` 和 payload hash。官方 endpoint 不提供可追溯的历史 effective time，因此首个采集时间之前的
样本一律 unavailable，禁止推断或 category fallback。Gamma fee 字段只可作来源审计，不能参与计算。

费用按实际 market 和 match time 读取，遵循 5 位小数规则。缺少 `fd`、builder schedule、PIT version、
解析失败或 SDK/raw mismatch 均为 typed unavailable；不得默认为零费率。
当前 order route 明确不附加 `builderCode`，因此 builder attribution 固定为 `NoBuilderCode`，builder fee
为零但 advertised `mbf/tbf` 仍作为 market-info 事实封存。未来若启用 builder route，必须升级 route/
execution artifact 契约并同时重建研究与 live policy，禁止静默改变既有 PnL。

共享执行引擎的 BUY 输入是最大总现金预算，输出 `gross_order_amount`、fee、`total_cash_delta`、fills、
unfilled、VWAP、worst price 和全部 input hash，并强制 `gross + fee <= cash_budget`。SELL 输入 shares，
fee 从 proceeds 扣除。FOK 必须全成或全撤；FAK 可部分成交；market `price` 是 worst-price limit。
Admission 原子生成 `PreparedVenueOrder`，dispatcher 只能 exact-submit，不能重算 amount、fee 或 price。

Allocation、report sizing、simulator、composer、admission、exit 与 attribution 必须消费同一纯执行语义；
任何重复 tier selector、fee formula、gross-notional sizing 或 `unwrap_or(Decimal::ZERO)` 均应删除。
Training label 必须从 Source Slice 读取 decision-time schedule；reconciliation 优先消费 venue actual fee，
否则只可使用 `PreparedVenueOrder` 冻结 schedule。两者都不得用进程内最新 fee cache 重算历史事实。

统一 BUY 业务对象定义为已经过 `walk_buy_cash_budget` 的 `ResolutionBuyEconomics`：
`cash_outlay = gross_order_amount + entry_fee`，`all_in_price = cash_outlay / filled_shares`，
`expected_pnl = q × filled_shares - cash_outlay`，`realized_pnl = settlement_payout - cash_outlay`。
Kelly、model backtest / calibration / quality gates、Policy CPCV utility 和 report sizing 只能从该对象读取
edge、`f*`、shares 与 PnL，不得再从 quote/mid/`entry_price_ref` 推导无费收益。Policy tier 是离散可执行
预算：optimizer 若受 portfolio cap 压缩，只能向下选择另一个已经走过盘口且 Kelly-eligible 的 tier；不能在
composer 中事后制造任意 USD/shares。

“共同消费”按事实边界区分：counterfactual 路径使用同一纯 walk；lot replay 消费由 labeler 以
`walk_sell_exact_shares` 冻结生成的 hold-vs-exit label，禁止在 replay 时用另一份盘口重复计算；attribution /
reconciliation 消费真实 venue fill、position 与 capital ledger，缺观测时才回退到 prepared frozen expected fee，
禁止用事后 book walk 覆写实际成交。三者共享 fee/cash-flow 类型、schedule hash 和执行 lineage，但不混淆
“可执行反事实”与“已发生事实”。

## 5. L2 回放与路径模拟

批量 reader 按 token page/window/cutoff 查询，查询类型和次数不得随候选数线性增长。每个 session 必须
从 snapshot 开始，sequence 是唯一排序真相；首次 gap、reset、tick inconsistency 或 typed numeric decode
error 后立即 invalid，直到新 snapshot。

完整 observation 路径覆盖 entry、exit、upper/lower/vertical barrier、同事件歧义、最多三档累计
scale-out、trailing、thesis invalidation 和 resolution。FOK/FAK 使用真实深度；passive fill 只接受已对账
opposite-side trade tape，不能以 top-of-book、mid-price 或静态 slippage 降级。`matured_at` 是首次可证明
touch 或 vertical deadline；顺序不可证明的 double touch 必须作废。

Weather 只支持 airport daily-high subject，ICAO、时区、本地日期、单位、整数区间、station binding 和
resolution rule 必须完全匹配。GEFS cycle 必须 31/31 members；AWC 用于实时观测/修正，GHCNh 只用于
历史 QC、bias 与 calibration，financial label 以 Polymarket 最终 token resolution 为准。任一 mapping、
provider rule 或 resolution 冲突即作废。距截止/已知 resolution 不足 24h 的样本以
`insufficient_horizon` 排除，不缩短 horizon。

## 6. 反过拟合与发布

所有 attempted、failed、cancelled、successful candidate 必须写入同一 append-only trial ledger，禁止只
保留赢家。Experiment family 在请求前由 profile、evaluation track 和 canonical candidate set 冻结。

- CPCV 固定 `N=8,k=3`，强制 purge/embargo、market isolation、uniqueness 与 common support；
- DSR `>= 0.95`，PBO `<= 0.50`；
- 每个 served cohort ESS `>= 100`；
- full-L2/common/passive coverage `>= 95%`，fee/source/resolution coverage `= 100%`；
- ambiguity/depth-failure `<= 5%`；
- market-cluster bootstrap one-sided 95% utility lower bound必须严格 `> 0`；
- 注入 2× 最近完整 24h production p95 latency 后仍须通过。

Structural-volatility 只能作为 Polymarket OOS risk baseline，不是 entry candidate。当前 producer 以
Polymarket 每小时 active mid-price innovation、decision-time spread 与前一小时已对账 volume 为输入，
对每个合约先完成 48 个 causal warm-up observations，再按自然月 expanding-window OOS；DR 为无参数
deadline baseline，DR-AS 的非负 `K` 只用 prior folds 做 volume-weighted Gaussian QML，输出 clipped 95%
interval 的 volume-weighted Winkler score/coverage。不得移植其他 venue 系数。Romano–Wolf 不作为
单 profile 11.7.2 发布门槛；仅当 Phase 11.9 在同一次治理决策中跨 profile 选 winner 或分配资金时使用。

只有 fit job 全部成功才创建 Draft。Validate 逐行重算并通过后才可进入现有 FSM；Publish 必须再次验证
Object Lock/versioning、manifest/object hash、actor/reason 和所有 publication blocker。

## 7. Report 与末端守恒

每份报告为每个 `catalog_visible` market 写且只写一条 `ReportMarketFunnelRow`：

```text
catalog_visible → business_eligible → executable_data_eligible
→ feature_ready → model_scored → model_gate_passed
→ sizing_eligible → portfolio_funded → published
```

每阶段必须满足 `input = output + excluded`，summary 只从行事实派生。资源 ceiling 使整份 report 失败，
不能伪装为市场排除或截断 survivor。PostgreSQL report header/recommendation 与 ClickHouse funnel 的跨库
写入必须由 transactional outbox、delivery acknowledgement 和 reconciliation 闭合；仅“先写 ClickHouse、
再写 PostgreSQL”会在后者失败时留下 orphan row，不满足 Phase Exit。

Policy → model → report → recommendation → intent → prepared order → venue fill/exit/settlement/attribution
必须串联 profile、dataset、source slice、model、policy、book、fee schedule 和 latency hash。任何 reconciliation
或 evidence 告警都清除 active binding 并回到 ReportOnly。

## 8. API 与页面

Preflight 返回 actual、required、typed blocker、remediation、evidence link、fit window、trial/fold estimate、
catalog/source completeness、retention runway 和 input hashes。未实现的 trial/path/fill/gap producer 不得以
空数组伪装成功。九类 Evidence object 均提供 hash/typed-schema 重验后的服务端分页 row API；原始下载只
对 versioned Object-Lock object 返回短期签名 URL，不返回无界大 JSON。

Workbench 固定为 Profile & Target、Data Readiness、Method & Candidates、Review & Enqueue 四步；Policy
Detail 是全页面 Overview/Readiness、Validation、Execution Evidence、Lineage & Audit；Report Detail 展示
守恒漏斗、typed reason filter 和逐市场 lineage。所有 blocker 来自服务端 DTO；页面覆盖 keyboard、focus、
`aria-live`、窄屏和 i18n。

## 9. Phase Exit

只有以下条件同时满足，11.7.2 才可从 `Blocked` 变为可执行：

1. Source Slice、latency profile、retention runway、trial ledger、Weather fitter 和 row-level Validate 的真实
   producer 全部上线，且 source slice 可从 WORM 独立恢复重放；
2. ClickHouse 月分区迁移完成 count/hash/min/max/session/gap 对账和 atomic exchange，旧表验收后删除；
3. batch replay 不存在 per-token N+1；training/reconciliation 不读取当前 fee cache重算历史费用；完整路径、
   cash-budget 和 fee golden/property tests 通过；
4. report transactional outbox/reconciliation 与全市场 funnel 守恒在真实 shadow 数据通过；
5. Rust、architecture、dead-semantics、UI quality gates 和受保护 E2E 全绿；
6. 连续 24 小时 ReportOnly shadow 的 conservation/PIT/fee/replay/evidence 指标全部通过，并生成交给
   11.11 的 `$25`、单 open intent canary handoff evidence；本 phase 不提交真实订单。

在上述条件完成前，credential/source/durability typed blockers、`Blocked` 状态和 ReportOnly 是正确生产
行为；仓库不存在可被误认为已实现的独立 fit kill-switch 配置。
