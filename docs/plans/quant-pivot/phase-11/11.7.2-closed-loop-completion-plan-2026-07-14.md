# Phase 11.7.2 生产级闭环收尾方案

> 状态：**实施中；Weather fitter / 独立 Validate / Evidence sealing 代码已闭环，目标环境与 24h shadow 尚未验收**  
> 冻结日期：2026-07-14  
> 最后核对：2026-07-15  
> 权威性：本文是 11.7.2 的收尾契约与实施台账；与旧 11.7.2 草案冲突时以本文为准。完成前不得宣称存在可发布或可激活的生产策略。

## 1. 结论与唯一可信链路

本阶段不是补齐脚手架，而是建立以下唯一可信业务闭环：

```text
完整市场目录
→ PIT Source Slice v2
→ L2 / CLOB market info / fee / weather 回放
→ 固定画像下的拟合与反过拟合验证
→ Evidence Bundle v2 + WORM
→ Validate / Publish 治理
→ report facts 可靠投递
→ ReportOnly shadow
```

真实订单、`PreparedVenueOrder exact-submit`、fill/exit/settlement 与 `SemiAuto` 首次激活由 11.11 的
bounded `$25` canary 验收，不属于本 phase 的运行交付。

当前运行结论仍是 `Blocked`，但本轮要求的研究代码链已经接通：Fit 与 Validate 共用同一纯函数
candidate fill/barrier/cohort replay kernel 和 Weather orchestration；真实盘口时间轴驱动 entry、FOK/FAK、
passive queue、barrier、scale-out、trailing、signal invalidation、time exit 与 resolution；固定 `N=8,k=3`
产出 56 folds/21 complete paths，并计算 uniqueness ESS、DSR、8-block PBO、market-cluster bootstrap utility
和真实 2× latency replay。Fit 只有在全部门禁通过后才写 typed Parquet evidence、append-only trial ledger，
逐对象 read-back 后 manifest-last sealing 并创建 Draft；独立 Validate 重新读取 Dataset/Source Slice/签名
latency evidence，重新推理和重放，逐 key 比较 sealed/recomputed row hash，再以 CAS 完成治理迁移。

`TradePolicyArtifact` 已升至 v5，精确冻结 `model_version_id`、签名 `latency_evidence_id` 和 `fit_job_id`；
Evidence Bundle v2 绑定对象 byte hash、semantic row-chain hash、trial-ledger hash 与 WORM durability。仓库完成
不代表生产证据已经存在：目标环境物理迁移、WORM 恢复/崩溃注入、真实数据 fit/Validate/Publish 以及连续
24 小时 `ReportOnly` shadow 尚未验收，故不得宣称已有 `Published` policy 或可激活策略。

2026-07-14 二次全链路审计发现的 per-token replay、report ClickHouse-first/best-effort mirror、Dataset
current-fee 回看和 reconciliation expected-fee 覆盖 actual-fee 已在本轮删除。现在的剩余 blocker 是
structural-volatility OOS baseline producer、目标环境物理迁移、WORM 恢复演练、全故障点崩溃注入、真实
数据门禁结果和 24 小时 shadow。UI、synthetic fixture 或单元级守恒测试不能替代这些真实研究与运行证据。

## 2. 冻结契约

### 2.1 版本与零兼容

- Runtime Config：v14。
- Dataset Artifact：v5。
- Model Artifact：v5。
- Trade Policy Artifact：v4。
- Evidence Bundle：v2。
- Phase 11.9 如需破坏式变更，从 Runtime v14 升至 v15，不复用 v14 wire identity。
- 不提供旧 parser、compat reader、双写、conversion shim 或 re-export。
- 旧持久化对象只允许审计读取；禁止进入 Dataset build、fit、Validate、Publish、report、activation 或 order admission。
- Dataset、Model、Policy、Report、Recommendation、OrderIntent、PreparedVenueOrder 均携带不可变 `ResearchProfileRef { id, version, content_hash }`。
- `TradePolicyCohortKey` 包含 `profile_ref`；金额档位唯一名称为 `cash_budget_tier`。
- 质量门禁使用 `eligible_market_coverage`，不再使用含糊的 `universe_coverage`。
- publication quality gate 的唯一权威是 immutable profile；Runtime v14 只保留 candidate resource ceiling 与
  production latency evidence window。CPCV/PBO/utility/latency stress 是版本化方法常量并进入
  methodology hash，不存在 runtime/profile 两套阈值再取 strictest 的重复治理。

### 2.2 不可变 Research Profile

不建立可变 Research Program CRUD。`profile_ref + evaluation_track + canonical candidates` 计算 `research_program_hash`，写入 Dataset、job、trial ledger、Policy 和 Evidence。

每个 `ResearchProfileArtifact` 冻结：

- information regime、market selector、decision trigger、去重规则；
- 唯一 target horizon、最大持有期、exit heartbeat；
- 固定 fit span、最大 feature lookback、purge/embargo；
- 必需 PIT source 与完整性门槛；
- 允许的 cash-budget tiers、激活资格与质量门槛；
- content hash、publisher、published time、governance reason。

Runtime v14 只注册：

| Profile | 固定契约 | 激活资格 |
|---|---|---|
| `pooled_1h_control@1` | 1h horizon；研究/回归基线 | `ResearchOnly` |
| `weather_forecast_24h@1` | 90 个自然日 fit；精确 24h horizon；每小时决策；最新完整 GEFS cycle；每 market/hour 一个样本；`$25` 最大总现金支出 | `SemiAutoCandidate` |

截止或 resolution 距决策不足 24 小时的 Weather 样本以 `insufficient_horizon` 排除，不缩短 horizon。Sports、deadline narrative、scheduled release 和 crypto expansion 在 PIT source、resolution、成本和 horizon 契约齐全前不得注册空画像。

## 3. 数据、PIT 与存储

### 3.1 Raw facts 生命周期

ClickHouse 是通用 raw facts 的唯一查询面：

- L2 events/checkpoints/sessions、trade tape 使用月分区；
- hot window 固定 14 天；配置 cold volume 时使用 ClickHouse 原生 `TTL MOVE`；
- `required_days(profile) = fit_span + ceil(max_feature_lookback) + ceil(target_horizon) + ceil(purge_embargo)`；
- `retention_days = max(180, 2 × max(required_days(profile)))`；当前 Weather profile 为 `2 × 100 = 200` 天；
- `TTL DELETE` 默认关闭。只有 Source Slice 已 WORM 封存、逐对象 hash 通过、恢复演练通过、容量预算与读取基准通过，并绑定 canonical signed retention-plan hash，才允许启用；
- ClickHouse backup、raw retention、WORM evidence 是三个不同责任边界。

已删除应用层 Parquet archive worker、archive manifest/drop command/audit、partition-drop scheduler、archive repository/config/test。不得重新引入第二套 raw 查询系统。该选择依据 ClickHouse 原生存储策略与 TTL 的官方实践：[storage best practices](https://clickhouse.com/blog/10-best-practice-tips)、[hot/cold TTL](https://clickhouse.com/resources/engineering/observability-cost-optimization-playbook)。

### 3.2 报告容量

`reports.hard_candidate_ceiling` 是部署压测上限，不是 selection cap：

```text
ceil_to_1000(max(100000, 2 × recent_30d_catalog_visible_p99))
```

由 `cargo run -p quant-pivot-xtask -- report-capacity-ceiling --catalog-visible-p99 <N>` 生成。超过时返回 typed `ResourceCapacityExceeded { actual, ceiling }` 并使整份报告失败，禁止截断后继续。

### 3.3 Source Slice v2

fit 与 Validate 只可读取不可变 `SourceSliceManifestV2`，不得回读动态源。Manifest 必须：

- 绑定 profile、program、Runtime v14、Dataset v5、fit window 与 PIT cutoff；
- 绑定真实 `catalog_sync_batch` 完整基线 batch、终止 batch、有序 batch-chain hash、
  `committed_through`、对象数量与 catalog snapshot hash；删除虚构的 complete sequence；
- 引用 catalog market/event、CLOB market info、L2 event/checkpoint/session/gap、trade tape、weather fact、calibration、resolution、decision、feature、label；
- 每对象记录 URI、object version、BLAKE3、schema hash、row count、min/max `event_time` 与
  `available_at`；
- 保存 first-failure invalid session ledger；
- availability cutoff 不得晚于 materialization 或请求 PIT cutoff；
- 覆盖固定 fit window 以及完整 target horizon；
- 对象 URI 唯一、canonical sort；消费时逐对象流式 BLAKE3 校验。

WORM 只保存被 Dataset/Policy Evidence 实际引用的 source slice；不作为第二个通用 raw archive。

### 3.4 CLOB market info 与 fee 真相

`ClobMarketInfoVersion` 是 append-only、双时态唯一真相，保存 condition/token、tick size、minimum order size、negative risk、taker delay、完整 `fd={r,e,to}`、builder fee schedule、`effective_at`、`available_at` 和 payload hash。

- 周期 worker 只发一次 HTTP：保留原始 payload，并用固定 SDK response type 对同一字节二次反序列化，
  避免双请求和跨时刻 TOCTOU；
- 缺少 PIT version 的 fill/sample 直接 unavailable；
- 官方响应不提供历史 effective time；首个采集之前的样本直接 unavailable，`effective_at=available_at`
  只表达首次可知时刻，不推断历史；
- `fd`、builder maker/taker schedule 都是必填事实；任一缺失、raw/SDK mismatch 或解析失败均拒绝整条
  observation，禁止默认为零；
- Gamma fee canonical fields、category fee config、category fallback、`FeeSource::CategoryDefault` 和重复公式已删除；
- fee 按实际 market 与 match time 计算，支持 exponent 0/1/2，按 5 位小数规则取整；
- 规则依据 [V2 migration](https://docs.polymarket.com/v2-migration)、[fees](https://docs.polymarket.com/trading/fees)、[CLOB market info](https://docs.polymarket.com/api-reference/markets/get-clob-market-info)。

## 4. 执行与重放

### 4.1 单一 cash-budget engine

`$25` 的定义是 BUY 最大总现金支出，而不是 fee-exclusive gross notional。

共享执行引擎输入：cash budget 或 SELL shares、side、fill requirement、PIT full-depth book、PIT fee schedule、builder schedule、latency profile。输出：

- `gross_order_amount`；
- `expected_fee`；
- signed `total_cash_delta`；
- fills、unfilled cash/shares、VWAP、worst price；
- book/info/profile/fee/latency hashes。

强制不变量：

- BUY：`gross + fee <= cash_budget`；
- SELL：输入 shares，fee 从 proceeds 扣除；
- FOK 不完整时返回完整 unfilled budget/shares，不暴露局部 fill；FAK 才允许 partial；
- final admission 原子冻结 `PreparedVenueOrder`；dispatcher 只能 exact-submit，不得重算金额、价格或 fee；
- Allocation、report sizing、simulator、composer、admission、dispatcher、exit、reconciliation 和 attribution
  必须收敛到同一执行语义；事后链路优先消费 venue actual fee，否则消费 prepared order 冻结 schedule，
  禁止回看进程内“当前费率”。

官方订单单位与 FOK/FAK 语义见 [Create order](https://docs.polymarket.com/trading/orders/create)。

### 4.2 PIT L2 replay

生产 reader 的最终验收契约：

- 按 token page/window/cutoff 批量查询，查询类型与次数不随 token 数线性增长；
- session 必须从 snapshot 开始，sequence 是唯一排序真相；
- gap/reset/tick inconsistency/numeric decode failure 后立即 invalid，直到新 snapshot；
- entry、exit、stop/barrier、同事件歧义、scale-out、trailing、invalidation、vertical、resolution 全部 deterministic；
- FOK/FAK 使用实际深度；passive fill 只接受已对账 opposite-side trade tape；cancel 不消耗 queue；session reset 使 queue unavailable；
- 数值解析返回 typed error，禁止 `unwrap_or(Decimal::ZERO)` 等 fail-open 降级。

## 5. Weather 24h 与统计验证

### 5.1 Weather 数据契约

- 只支持已经落地的 airport daily-high `WeatherSubject`：ICAO、时区、本地日期、单位、整数区间、resolution rule、station binding 必须完全匹配；
- GEFS 必须为完整 31-member cycle；NCEP GEFS v12 每日四个 cycle、31 members、最长 16 天：[NCEP GEFS](https://www.emc.ncep.noaa.gov/emc/pages/numerical_forecast_systems/gefs.php)；
- AWC METAR/SPECI/COR 用于实时观测与修正；高频/回填优先官方 cache，并遵守限额：[AviationWeather API](https://aviationweather.gov/data/api/)；
- GHCNh 只用于历史 QC、bias 与 calibration，不冒充 live availability 或 settlement：[GHCNh](https://www.ncei.noaa.gov/products/global-historical-climatology-network-hourly)；
- financial label 以 Polymarket 最终 token resolution 为准；provider fact 是 subject/feature evidence；mapping/provider/resolution 冲突即作废并阻断激活；
- SemiAuto source gate：至少 500 station-days、20 stations、30 dates；总体 Wilson 95% 下界 `>= 0.95`；目标站至少 20 天且下界 `>= 0.90`；availability `>= 99%`。

### 5.2 CPCV、DSR、PBO

- 复用通用统计原语，不复制实现；
- CPCV 固定 `N=8,k=3`：56 splits、21 paths；强制 purge、embargo、market isolation、uniqueness、ESS、common support；
- trial ledger append-only，包含 attempted/failed/cancelled/successful；
- experiment family 由请求前置声明的 profile、track、candidates 冻结；
- Weather publication：DSR `>= 0.95`、PBO `<= 0.50`、每 served cohort ESS `>= 100`、utility one-sided 95% lower bound `> 0`；
- `policy_net_positive` 必须来自共享执行引擎的完整成本结果；
- structural-volatility 只作 Polymarket OOS baseline candidate，禁止移植 Kalshi 系数：[paper](https://arxiv.org/abs/2607.08199)；
- 11.7.2 不以 program-wide Romano–Wolf 为单 profile 发布门槛；Phase 11.9 只有在同一治理决策跨 profile 选 winner/分配资金时才引入。

方法依据：[Deflated Sharpe Ratio](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2460551)、[Probability of Backtest Overfitting](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2326253)、[Romano–Wolf stepdown](https://statistics.stanford.edu/technical-reports/stepwise-multiple-testing-formalized-data-snooping)。

## 6. Report、API 与 UI

### 6.1 守恒漏斗

保留 `MarketSelectionId` 与 included-member snapshot。`ReportMarketFunnelRow` 是每份报告的全市场、append-only 决策真相：

```text
catalog_visible → business_eligible → executable_data_eligible
→ feature_ready → model_scored → model_gate_passed
→ sizing_eligible → portfolio_funded → published
```

每个 catalog-visible market 恰好一行，保存唯一 terminal stage、typed primary reason、secondary diagnostics、profile/model/selection/runtime lineage 与 row hash。所有阶段满足 `input = output + excluded`，页面 summary 从行事实派生。资源 ceiling 是 report failure，不是 terminal market exclusion。

### 6.2 Typed API

已冻结接口：

```text
GET  /research/trade-policy-profiles
GET  /research/trade-policy-profiles/{id}/{version}
POST /research/trade-policy-fits/preflight
POST /research/trade-policy-fits
GET  /research/trade-policy-fits/{job_id}
GET  /research/trade-policy-fits/{job_id}/trials
GET  /research/trade-policies/{id}
GET  /research/trade-policies/{id}/cohorts
GET  /research/trade-policies/{id}/source-slice
GET  /research/trade-policies/{id}/evidence/{kind}/download
GET  /quant/reports/{id}/funnel
GET  /quant/reports/{id}/funnel/markets
```

仍需在 fitter/evidence producer 完成后启用的 row APIs：

```text
GET /research/trade-policies/{id}/cpcv-paths
GET /research/trade-policies/{id}/fills
GET /research/trade-policies/{id}/gaps
```

禁止以空数组伪装未实现。完成前页面通过 typed blocker 与 Evidence object availability 表达 `Blocked`。

Preflight 只接受 `profile_ref`、PIT cutoff、typed candidates、`ResearchOnly | SemiAutoCandidate`；Dataset、Source Slice、Runtime、program hash、manifest URI/hash 全部由服务端推导、物化和复用。
horizon、fit span、cadence、cash tier 和 quality gate 均由 profile 推导，运行资源限制来自 Runtime v14。
返回 typed blocker：稳定 kind、actual、required、remediation、evidence link；并返回 input hashes、fit
window、candidate/fold 规模、catalog/source completeness、required retention 与 measured runway。
production latency/retention producer 已落地；服务端仅接受 scope、有效期、payload hash、签名和
WORM 校验均通过的真实 evidence。证据缺失或过期时返回有依据的 blocker，不再以硬编码
`false/None` 冒充已测量结论。

Evidence download 只在 versioned + Object-Lock S3 上签发 5 分钟、绑定 object version 的 URL；Local ArtifactStore 拒绝伪造签名 URL。
