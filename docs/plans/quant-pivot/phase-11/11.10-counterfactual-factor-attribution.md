## 1. 目标与闭环定位

回答"**这笔 recommendation 的盈亏,归因到哪些因子/模型决策**",并回填 live 归因中被延后的
MAE / missed-return。它把 05.7 的"realized PnL 归因到 recommendation"深化为"realized PnL 归因到
factor 贡献 + 反事实(如果某因子不同会怎样)",为 11.9 的再训练与 11.1/11.2 的因子取舍提供**因果级**证据。

设计立场(有文献支撑):

- **SHAP / Shapley values** 是把预测输出公平分配到各特征贡献的博弈论方法,满足 efficiency/symmetry/
  additivity(<https://shap.readthedocs.io/en/stable/>、
  <https://christophm.github.io/interpretable-ml-book/shapley.html>)。
- 但"Shapley 不是反事实":标准 SHAP 解释的是"相对平均的贡献",不等于"移除该特征会怎样";要做
  actionable 反事实需用 **CF-SHAP**(用反事实集作 background)
  (<https://facctconference.org/static/pdfs_2022/facct22-3533168.pdf>)。
- 权重线性模型(11.4 主路径)的因子贡献本就是 `weight·normalized·confidence`(可解释闭式);GBDT/非线性
  候选(11.4 shadow)才需要 SHAP。

闭环定位:11.9(归因反馈)消费本子phase的因子贡献做 factor 取舍与再训练;11.5 的 MAE 依赖本子phase
的 book replay。

## 3. 契约与算法设计

### 3.1 统一归因引擎

```rust
/// Attributes realized outcome to factor contributions. Weighted models use the
/// closed-form linear decomposition; non-linear (GBDT) models use SHAP; optional
/// CF-SHAP produces counterfactual ("had factor X differed") contributions.
pub trait FactorAttributionEngine {
    fn attribute(&self, rec: &RealizedRecommendation, model: &ModelArtifact)
        -> QuantResult<FactorAttribution>;
}

pub struct FactorAttribution {
    pub per_factor: Vec<FactorContribution>,   // 贡献值 + 方向 + 置信
    pub method: AttributionMethod,             // LinearClosedForm | Shap | CfShap
    pub baseline: Decimal,                     // SHAP base value / 平均
    pub reconciles_to_score: bool,             // efficiency 校验:Σ贡献 + baseline == score
}
```

- **Weighted 模型(主路径)**:闭式分解 `contribution_i = weight_i · normalized_i · confidence_i`,
  天然 recommendation-level,无需 SHAP。
- **GBDT/非线性(shadow→可晋升)**:TreeSHAP(树模型精确 Shapley);满足可解释后可解除"仅 shadow"限制。
- **CF-SHAP(可选)**:用反事实集作 background,回答"若该因子取反事实值,分数/决策会怎样",支持
  "为什么这笔亏了 + 哪个因子该改"的 actionable 归因。

### 3.2 realized 因子归因(与 PnL 挂钩)

- 把 §3.1 的**分数贡献**与 05.7 的 **realized PnL** 关联:按分数贡献占比 + realized 结果,产出
  "每因子对本笔 realized PnL 的贡献"(注意:分数贡献 ≠ PnL 归因,需明确这是"决策贡献 × 实现结果"的
  组合,文档中写清语义,避免误读)。
- 聚合到 factor-level realized IC / 贡献,喂 11.9 factor 取舍与 11.1 共线/正交决策。

### 3.3 MAE / missed-return 回填(#20)

- **MAE**:对每笔已成交 recommendation,用历史 book replay(11.5/11.6 的 PIT book)计算持有期内最大
  不利偏移,回填 `max_adverse_excursion_bps`(不再 `None`)。
- **missed_return**:反事实"若未提前退出/若按不同 barrier"的收益,与实际对比,量化退出策略优劣
  (回流 11.7 barrier 参数调优)。

## 6. 生产不变量与失败语义

- **efficiency 校验**:SHAP/线性分解必须满足 `Σ贡献 + baseline == 模型分数`(数值容差内),否则拒绝
  该归因(防错误解释)。
- **语义精准**:明确区分"决策贡献"(SHAP on score)与"realized PnL 归因"(贡献 × 实现结果),文档与
  UI 都不得混淆(避免"Shapley 当反事实"误读,见 Interpretable ML Book 警告)。
- **MAE 用 PIT book**:回填 MAE 只用历史 PIT book replay,禁止 live BookStore(与回测基线一致)。
- **可解释门禁联动**:GBDT 模型只有产出通过 efficiency 校验的 SHAP,才可解除 11.4 的"仅 shadow"限制。

## 7. 第三方 crate 引入

- **TreeSHAP**:优先纯 Rust 实现(树模型 Shapley 有确定性算法);若引入 crate 需 feature-gate 且做
  MSRV/native 检查。不引入 Python `shap`。
- 复用 `ndarray`/`statrs`。
