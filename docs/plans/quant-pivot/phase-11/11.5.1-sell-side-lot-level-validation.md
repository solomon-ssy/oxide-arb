## 0. 前置设计与落地实现的三处纠正（权威结论，覆盖原设计草案）

深度代码调研（落地前对磁盘 HEAD 的逐条验证）发现原设计草案的三处设想与既有代码惯例不一致，落地时予以
纠正，本文档不再采用原草案的对应提法：

1. **不新增 `GateId::SellCpcvRequired`/`SellDeflatedSharpe`/`SellPbo`**（原 §3.5 提法）。既有代码里
   `GateId::SampleCount`/`LabelCoverage` 已经是"买卖共用同一个 `GateId`，按 branch 各自代入不同阈值
   源"的模式（[`gates/model_quality.rs`](../../../crates/quant-pivot-research/src/gates/model_quality.rs)
   `evaluate_coverage_gates`/`evaluate_sell_gates`）。落地复用既有
   `CpcvRequired`/`RankIc`/`DeflatedSharpe`/`Pbo`/`MinTrackRecordLength` 五个变体。Remediation 仅为
   Sell 特有的基线比较新增 `GateId::SellBaselineUplift`（wire name `sell_baseline_uplift`），不复制
   CPCV alpha gate 枚举。前端 `needsCpcvRunCta`/`needsBindCta` 仍按家族无关的 alpha gate 字符串工作；
   `cpcvGateOutcomes` 对 Sell 额外展示 `max_drawdown`/`tail_loss_budget`/`sell_baseline_uplift`。
   抽屉与列表按 `model_family` 隐藏 Sell 的单路径 Backtest 按钮。
2. **不新增 `research.validation.sell_gates.*`/`sell_trials.*` 命名空间**（原 §3.4/§5 提法）。Sell
   阈值的真实治理归宿是既有 `quality_gate.sell.*`（[`SellQualityGateConfig`](../../../crates/quant-pivot-models/src/runtime_config/sections/config.rs)），
   与 `research.validation.*` 是两个不同的既有配置段；落地在 `quality_gate.sell.*` 下新增
   `rank_ic_min`/`dsr_significance`/`max_pbo` 三个字段（替换被删除的 `min_exit_alpha_rank_ic`），
   trial grid 直接复用 `research.validation.trials.*`（见第 3 点），**不新建任何配置命名空间**。
3. **不新增 `TrialGridSpec::Sell` 变体**（原 §3.4 提法）。`SellScorerTrainer::train_sell_scorer`
   消费的 `TrainSellScorerRequest.objective: TrainingObjectiveSpec` 与 Buy 的
   `TrainModelRequest.objective` 是**同一个类型**（`fit_simplex_weights` 买卖共用，见
   [`model/trainer.rs`](../../../crates/quant-pivot-research/src/model/trainer.rs)），
   `TrialGridSpec::WeightedFactor(WeightedFactorTrialGrid)` 天然适用，落地**零改动复用**。

### 0.1 `validation::` 算法层的一次真实泛化（原设计"零改动复用"的表述不成立）

原设计草案称 `validation::` 全部零改动复用——**不成立**。落地前 `FoldModelSource::train_fold` 返回具体
的 `Box<dyn QuantModelRuntime>`，`ReplayEngine::evaluate` 参数也锁定 `&dyn QuantModelRuntime`；而
Sell 侧运行时是完全独立的 `SellScorerRuntime` trait（非 `QuantModelRuntime` 的变体或子集）。且原
`GroupEvaluation.rank_ic: Option<Decimal>` 是"一个 group 内部按 Spearman 算一个标量"，对 Sell
"一个 group = 一个 lot"的原子单元**结构性失效**（单点无法算 Spearman，会永久退化为 0，杀死整个
rank_ic 硬门禁）。落地做了一次小而真实的破坏式泛化：

```rust
pub enum FoldRuntime {
    Buy(Box<dyn QuantModelRuntime>),
    Sell(Box<dyn SellScorerRuntime>),
}
impl FoldRuntime {
    pub fn as_buy(&self) -> QuantResult<&dyn QuantModelRuntime>;
    pub fn as_sell(&self) -> QuantResult<&dyn SellScorerRuntime>; // 类型不符 fail-closed 报错，不 panic
}
pub struct RankObservation { pub score: Decimal, pub realized: Decimal }
pub struct GroupEvaluation {
    pub group_index: usize,
    pub return_value: Decimal,
    pub rank_observations: Vec<RankObservation>, // 取代 rank_ic: Option<Decimal>
}
```

`build_path`（[`validation/cpcv.rs`](../../../crates/quant-pivot-research/src/validation/cpcv.rs)）不再
对每个 group 的 `Option<Decimal>` 取均值，而是把路径内**所有** group 的 `rank_observations` 池化成两条
并行序列，调用既有 `stats::spearman` 算**一次**路径级相关性——对 Buy（一个 group=一个 tick 的多候选者）
与 Sell（一个 group=一个 lot 的单观测）都成立，且统计上比"逐 group Spearman 再平均"更稳健（小样本 group
的 Spearman 方差大）。**这是本次改动里唯一影响已上线 Buy 侧数值语义的一处**（`rank_ic` 的计算口径变了，
不是数值 bug）；`purge`/φ-path 重构/trial-grid 编排/DSR/PBO **零改动**——`DefaultCombinatorialPurgedBacktester::run`
内部只是把 `model.as_ref()` 换成 `&model`（`FoldRuntime` 是具体枚举，不再需要 trait object 的
`.as_ref()`）。

### 0.2 一个关键正向发现（避免重复设计）

`HoldVsExitProceedsLabeler`（[`training/labeler.rs`](../../../crates/quant-pivot-research/src/training/labeler.rs)）
已经把"此刻退出 vs 持有到终局"的净收益差（`hold_vs_exit_alpha_bps`）冻结进每个 `TrainingExample.labels`，
且 `matured_at = lot.closed_at`。**lot 级回放不需要重新计算任何"此刻退出净收益/持有到终局净收益"**——
[`LotReplayBacktester`](../../../crates/quant-pivot-research/src/backtest/lot_replay.rs) 直接读取该决策点
已冻结的标签值即为"真实兑现结果"，与 Buy 侧回放读取预先算好的 `SampleOutcome.realized_return_bps` 是同一
模式。这比原设计草案设想的"新增 `ExitDecisionReplayContext` 携带 `exit_now_net_proceeds_usd`/
`hold_terminal_net_proceeds_usd`"简单得多，零重复计算。

### 0.3 消除的一处线上/线下重复逻辑

线上 `OpportunisticSellSignalEvaluator`（[`service/opportunistic_sell.rs`](../../../crates/quant-pivot-core/src/service/opportunistic_sell.rs)）
原内联的开仓退出判定谓词（`confidence >= min_confidence && p_exit_better >= min_p_exit_better &&
exit_alpha_bps >= min_alpha`）已提炼为
[`quant_pivot_research::model::sell_scorer::{SellSignalPolicy, sell_signal_fires, sell_signal_target}`](../../../crates/quant-pivot-research/src/model/sell_scorer/mod.rs)，
线上评估器与 `LotReplayBacktester` 的离线回放**逐字复用同一函数**，避免线上/线下判定规则漂移（11.6
训练-服务一致性基线的延伸）。

## 1. 目标与闭环定位

Sell/Hold-vs-Exit 打分模型（`ModelFamily::HoldVsExitWeighted`）落地前的"验证"仅仅是训练器内部的滚动
折验证（`ValidationReport`，与 Buy 共用 `fit_simplex_weights`），从未有任何组合回放级的、样本外的、
防过拟合方法论覆盖；质量门禁 `evaluate_sell_gates` 里 `RankIc` 仍是 soft、读单路径 `input.backtest`——
与 Buy 侧 11.5 落地前的状态完全一样，是同一个方法论问题在另一个模型家族上的镜像。

落地把 11.5 已验证有效的方法论（label-horizon purge/embargo → CPCV φ 路径分布 → trial-grid CSCV →
DSR/PBO 硬门禁 → 发布前重扫）原样套用到 Sell 家族，解决三个 Sell 特有的问题（§3.1–3.3），其余全部
复用（§0）：

1. Sell 家族的"原子分裂单元" = 一个持仓 lot（`lot_context.position_id`）。
2. Sell 家族的组合回放引擎 `LotReplayBacktester`。
3. Sell 家族接入 `FoldModelSource`（`SellFoldSource`），`rank_ic` 从软阈值单路径升级为硬门禁多路径。

闭环定位：11.5（买方方法论落地，证明算法正确）→ **11.5.1（方法论套用到卖方）**；与 11.7（标注/入场/
退出结构）是姊妹关系而非依赖关系——11.7 精化 `matured_at` 的取值来源，但不改变本文档的算法契约。

## 3. 契约与算法设计（已落地）

### 3.1 Lot 级原子分裂单元

Buy 的原子单元是"同 `as_of` 截面组"；Sell 家族的原子单元是**一个持仓 lot**——同一 lot 内的多个
hold-vs-exit 决策点（`TrainingExample.lot_context.position_id` 相同）高度相关，如果 purge/CPCV 把同一
lot 的早期决策点分进训练折、晚期决策点分进测试折，就是同 lot 内的信息泄漏。

```rust
// crates/quant-pivot-core/src/service/cpcv_backtest.rs
fn build_lot_timeline_groups(
    examples: &[TrainingExample],
    label: &LabelSelector,
) -> QuantResult<(Vec<TimelineGroup>, Vec<LotDecisionSequence>)>;
```

按 `lot_context.position_id` 分组；组内取最早 `as_of` 作为组的 `as_of`，取该 lot 携带选定标签的行的
`matured_at` 最大值（`HoldVsExitProceedsLabeler` 已对同一 lot 的每一行统一写成 `closed_at`，取 max
仅做防御性兜底）作为 `label_horizon_end`。产出的 `Vec<TimelineGroup>` 直接喂给既有 `DefaultPurgedSplitter`
——**零改动复用**。同时产出的 `Vec<LotDecisionSequence>`（index 与 `groups` 对齐）是**唯一**的每 lot
决策序列物化副本，被 `SellFoldTemplate`（训练）与 `SellReplayTemplate`（回放）共享，不重复物化。

验收测试：`lot_timeline_groups_keep_one_lots_decisions_in_one_group`、
`lot_timeline_groups_are_sorted_ascending_by_as_of`（[`cpcv_backtest.rs` 测试模块](../../../crates/quant-pivot-core/src/service/cpcv_backtest.rs)）。

### 3.2 `LotReplayBacktester`（新增，`quant-pivot-research::backtest::lot_replay`）

```rust
pub trait LotBacktester: Send + Sync {
    fn run(&self, inputs: LotBacktestInputs<'_>) -> QuantResult<LotBacktestRunResult>;
}
pub struct LotBacktestInputs<'a> {
    pub model: &'a dyn SellScorerRuntime,
    pub policy: SellSignalPolicy,
    pub label: LabelSelector,
    pub lots: &'a [LotDecisionSequence],
}
pub struct LotDecisionSequence { pub position_id: PositionId, pub decisions: Vec<TrainingExample> }
pub struct LotOutcome {
    pub position_id: PositionId,
    pub as_of: DateTime<Utc>,                 // 首个决策时刻（lot-native 序列锚点）
    pub return_value: Decimal,               // 路径同构切片上的 Σ (sold/hist_remaining)×(α_bps/1e4)
    pub cumulative_exit_pct: Decimal,        // 相对回放 denominator 的累计退出比例 ∈ [0, 1]
    pub rank_pairs: Vec<(Decimal, Decimal)>,  // (预测 exit_alpha_bps, 冻结标签值)
    pub path_diverged: bool,                 // 部分退出后与历史 remaining 分叉 → 停止
}
```

与 `crates/quant-pivot-research/src/backtest/runner.rs::PortfolioReplayBacktester` 平级、不依赖
`validation::*`。核心循环**同步、无 I/O**，并与生产 `opportunistic_delta` 对齐：

1. **Denominator** = 首决策 `lot_context.remaining_shares`（回放窗口起点的在管份额）。
2. 命中时卖出 `max(0, target×denominator − already_sold)`，按
   `(sold / historical_remaining) × (frozen hold_vs_exit_alpha_bps / 1e4)` 计提——仅在模拟
   remaining 仍等于历史 remaining 时成立（标签按「退出当时全部 historical remaining」标定）。
3. **路径分叉 fail-closed**：任一部分退出使 `simulated_remaining ≠ historical_remaining` 后，
   后续 PIT 行的 `position_state`/标签描述的是未减仓世界——继续评分即 train-serve skew。引擎
   **停止**；残仓按持有到终局计（增量 alpha = 0）。100% 退出干净终止，不分叉。
4. `rank_pairs` 只覆盖路径同构阶段走过的决策点；从未命中则 `return_value = 0`。

验收测试：`lot_replay_full_exit_stops_subsequent_decisions`、
`lot_replay_partial_exit_accrues_slice_then_stops_on_divergence`、
`lot_replay_backtester_holds_to_terminal_when_never_exits`、
`null_baseline_exit_at_first_takes_first_label` / `null_baseline_always_hold_is_zero_alpha`
（[`backtest/lot_replay.rs`](../../../crates/quant-pivot-research/src/backtest/lot_replay.rs)）。

### 3.3.1 Activity-only lot-native series + null baseline

- `calendarize_lot_returns`：**仅活动观测**——同 `period_secs` 桶内 lot 收益求和；**空桶省略，
  绝不填 0**（零填充会压低波动、抬高 Sharpe，污染 DSR/PBO）。
- 前置门禁：`active_observation_count >= pbo.block_count`（有效活动桶数，不是 raw lot 数，也不是
  零填充后的墙钟跨度）。
- Null baselines：`AlwaysHold`（0）与 `ExitAtFirstDecision`（首决策冻结标签全平）。
- `baseline_uplift = median(path mean activity return) − mean(exit-at-first activity return)`，写入
  `SharpeDistribution.baseline_uplift`（可选字段，免 DB migration）；同时写入
  `median_max_drawdown` / `median_tail_loss` 供 Sell 风险硬门禁读取。

Trial grid：`TrialGridSpec::WeightedFactor` 原样复用（§0 已论证类型同源）。Sell 种子权重
（`sell_seed_weights`，新增小函数——不是重复设计：`weighted_seed_weights` 读的是 Buy 治理化
`factors.factor_weights` 配置，Sell 没有这个治理段且需要额外纳入 position-state 伪因子）：均匀权重，
覆盖 `factor_values` 全部出现的因子名 + 3 个 position-state 伪因子。

`CpcvBacktestConfig` 新增 `sell_policy: SellSignalPolicy` 字段，在 core 层的
[`app/ports/cpcv_backtest.rs::cpcv_config_from_runtime`](../../../crates/quant-pivot-core/src/app/ports/cpcv_backtest.rs)
从 `execution.exit_monitor.opportunistic_sell` 冻结——CPCV 复用生产阈值，不是发明一套平行配置。

### 3.4 Quality Gate 接线

```rust

```

从原 `evaluate_cpcv_alpha_gates` 抽出，Buy/Sell 两分支共用，逐字复用
`CpcvRequired`/`RankIc`/`DeflatedSharpe`/`Pbo`/`MinTrackRecordLength` 门禁逻辑（§0 点 1）。Buy 分支
`evaluate_cpcv_alpha_gates` 变薄，从 `input.validation_thresholds` 取三元组 + `input.backtest` 的窗口
转发；Sell 分支 `evaluate_sell_gates` 保留 `SampleCount`/`LabelCoverage`/`SellL2BookFidelity`/
`SellFallbackRatio` 不变，删除旧的 soft `RankIc` 块，新增调用共享 helper，并从
`BacktestPathSetInfo.window_start/window_end` 传入窗口，使 Sell `MinTrackRecordLength` 可按 path-set
窗口评估。

Remediation 同时把 Sell path-set 风险门禁补齐：CPCV 后先把 lot-level path returns 按
`LotOutcome.as_of` calendarize 成等间隔序列，再重算每条 path 的 `group_returns`/`sharpe`/
`max_drawdown`/`tail_loss`。`SharpeDistribution` 通过 optional serde 字段持久化
`median_max_drawdown`、`median_tail_loss`、`baseline_uplift`，无需 DB migration。Sell publish/auto 在
path set 存在时硬门禁：

- `median_max_drawdown <= quality_gate.max_drawdown`。
- `median_tail_loss * 10_000 >= research.validation.gates.min_tail_loss_bps`（path tail loss 是 fractional return，门禁配置是 bps）。
- `baseline_uplift > 0`，其中 `baseline_uplift = median(model path mean calendar return) - mean(exit-at-first baseline calendar return)`；AlwaysHold baseline 仍计算为零 alpha 参照。

`SellQualityGateThresholds` 新增 `rank_ic_min`/`dsr_significance`/`max_pbo`，删除 `min_exit_alpha_rank_ic`。

### 3.5 Governance 接线

`model_governance.rs::evaluate_gate` 里 `bound_path_set` 的调用不再排除 `is_exit`——`bound_path_set`
本身早已是完全 family-agnostic 的实现（只读 `version.publish_path_set_id`），`bind_publish_path_set`/
`POST .../bind-publish-path-set` 端点同样 family-agnostic，**均未改动**——这条闭环对 Sell 天然生效，
只是之前被 `!is_exit` 挡住了读取。

## 6. 生产不变量与失败语义

- **Lot 内不可跨折**：同一 `position_id` 的全部决策点必须整体分进同一折，CPCV 分区/purge 的粒度是
  lot，不是决策点——违反即视为泄漏，`build_lot_timeline_groups` 的分组是唯一防线。
- **Residual-shares + path-divergence stop**：命中时按生产 `opportunistic_delta` 语义卖增量；
  部分退出导致模拟 remaining ≠ 历史 remaining 后**停止评分**（残仓持有到终局，增量 alpha=0），
  禁止用未减仓历史 PIT 行继续计提。
- **Sell Sharpe/DSR/PBO 必须 activity-only**：lot return 不是等间隔墙钟序列；CPCV 后按活动桶
  折叠（同桶求和、**空桶省略**），再重算 path Sharpe/DSR；rank IC 仍保持 path 内池化。
  **活动观测数 < 2 硬失败**；前置门禁要求 `active_observation_count >= pbo.block_count`。
  禁止静默 `sharpe_ratio → 0`，禁止空桶填 0 膨胀 Sharpe。
- **Sell path-set 风险/基线门禁 fail-closed**：缺少 `median_max_drawdown`/`median_tail_loss`/
  `baseline_uplift` 的 Sell path set 不得 publish；baseline uplift 必须严格大于 0；
  `sharpe_distribution` JSON 解码失败 → 显式 Err（禁止静默丢诊断字段）。
- **DSR α 单一权威**：`research.validation.gates.dsr_significance` 同时驱动 CPCV 计算与
  Sell/Buy publish 门禁；无 `quality_gate.sell.dsr_significance`。
- **线上/离线退出判定规则单一实现来源**（`SellSignalPolicy::try_from_runtime` +
  `sell_signal_fires`/`sell_signal_target`）：任何阈值调整只需改一处，不会漂移（§0.3）。
- **rank IC 池化相关性对 Buy/Sell 统一**：不存在"因为原子单元换了就单独发明一套统计口径"的分叉
  （§0.1）。
- 沿用 11.5 的全部不变量：回测禁用 live BookStore、purge 必须 label-horizon-aware、发布前重扫泄漏、
  rank_ic/DSR/PBO 硬门禁未过不得进 candidate→publish（Sell 与 Buy 同等要求，§3.5）、多路径优先单点
  数字、**不自动 bind**（须显式 `bind-publish-path-set`）。
