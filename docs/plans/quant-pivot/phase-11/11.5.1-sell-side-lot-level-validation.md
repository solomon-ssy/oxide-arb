## 1. 目标与闭环定位

Sell/Hold-vs-Exit 打分模型（`ModelFamily::HoldVsExitWeighted`，[`crates/quant-pivot-research/src/model/sell_scorer/trainer.rs`](../../../crates/quant-pivot-research/src/model/sell_scorer/trainer.rs)）今天的"验证"仅仅是训练器内部的滚动折验证（`ValidationReport`，与买方共用 `fit_simplex_weights`），**从未有任何组合回放级的、样本外的、防过拟合方法论覆盖**。质量门禁 [`gates/model_quality.rs`](../../../crates/quant-pivot-research/src/gates/model_quality.rs) 的 `evaluate_sell_gates` 里 `RankIc` 仍是 soft、阈值 `min_exit_alpha_rank_ic`（默认 0.05）——与买方 11.5 落地前的状态完全一样,是同一个方法论问题在另一个模型家族上的镜像。

目标:把 11.5 主方案证明有效的方法论(label-horizon purge/embargo → CPCV φ 路径分布 → trial-grid CSCV → DSR/PBO 硬门禁 → 发布前重扫)**原样套用**到 Sell 家族,不重新发明算法,只解决三个 Sell 特有的问题:

1. Sell 家族的"原子分裂单元"是什么(§3.1)。
2. Sell 家族没有组合回放引擎(§3.2 `LotReplayBacktester`)。
3. Sell 家族怎么接入 `FoldModelSource`(§3.3)、怎么建自己的 trial grid(§3.4)。

闭环定位:11.5(买方方法论落地,证明算法正确)→ **11.5.1(方法论套用到卖方)**;与 11.7(标注/入场/退出结构)是姊妹关系而非依赖关系——11.7 精化 `matured_at` 的取值来源,但不改变本文档的算法契约。

## 3. 契约与算法设计

### 3.1 Lot 级原子分裂单元

买方的原子单元是"同 `as_of` 截面组"(11.4 已确立,11.5 复用);Sell 家族的原子单元是**一个持仓 lot**——因为同一 lot 内的多个 hold-vs-exit 决策点(`TrainingExample.lot_context.position_id` 相同)高度相关(同一底层仓位、重叠的 forward horizon),如果 purge/CPCV 把同一 lot 的早期决策点分进训练折、晚期决策点分进测试折,就是同 lot 内的信息泄漏——这与"同一 `as_of` 截面的行分到不同折"是完全相同性质的错误,只是分组键不同。

```rust
/// Build one lot's `TimelineGroup` for the Sell family: `as_of` is the lot's
/// first decision instant, `label_horizon_end` is the lot's terminal close
/// (mirrors `HoldVsExitProceedsLabeler::matured_at` from 11.5 §3.1 — refined by
/// 11.7's triple-barrier `first_touch` when it lands, interface unchanged).
pub fn lot_timeline_groups(examples: &[TrainingExample]) -> QuantResult<Vec<TimelineGroup>>;
```

按 `lot_context.position_id` 分组;组内取最早 `as_of` 作为组的 `as_of`,取 `lot_context` 对应 lot 的
`closed_at`(经 `matured_at` 已在 11.5 里落到每行的 `TrainingLabel`)作为 `label_horizon_end`。产出的
`Vec<TimelineGroup>` 直接喂给 11.5 已落地的 `PurgedSplitter`/CPCV 分区算法——**零改动复用**。

### 3.2 `LotReplayBacktester`(新组合回放引擎)

买方 `PortfolioReplayBacktester` 的模拟结构是"每个 `as_of` 独立分配、互不影响";Sell 家族的模拟结构
本质不同——**同一 lot 内的决策点是顺序相关的,一旦模型在某个决策点判定"exit",这个 lot 的模拟路径就
终止**(不能再对同一 lot 的后续决策点打分,那些决策点在真实交易里根本不会发生)。

```rust
#[async_trait]
pub trait LotBacktester: Send + Sync {
    /// Replay one hold-vs-exit scorer over lot-grouped decision points. Within
    /// each lot, decision points are walked in `as_of` order; the first
    /// decision the scorer marks `Exit` terminates that lot's simulated path
    /// (later decision points in the same lot are never scored — they would
    /// not occur in reality once the position is closed). A lot that never
    /// triggers `Exit` is held to its natural terminal outcome.
    async fn run(&self, inputs: LotBacktestInputs<'_>) -> QuantResult<LotBacktestRunResult>;
}

pub struct LotBacktestInputs<'a> {
    pub model: &'a dyn QuantModelRuntime,   // WeightedSellScorerRuntime 打分
    pub lots: Vec<LotDecisionSequence>,     // 按 lot 分组、组内按 as_of 升序的决策点序列
}

pub struct LotDecisionSequence {
    pub position_id: PositionId,
    pub decisions: Vec<LotDecisionPoint>,   // 该 lot 的全部候选决策点,已按 as_of 升序
}

pub struct LotDecisionPoint {
    pub as_of: DateTime<Utc>,
    pub model_input: ModelRuntimeInput,     // 该决策点的打分输入
    pub exit_proceeds_if_exit_now: Usd,     // 若此刻退出的模拟成交净收益(ExitFillSimulator)
    pub hold_terminal_proceeds: Usd,        // 若持有到终局的净收益(hold_terminal_proceeds oracle)
}
```

每个 lot 的已实现结果 = 模型在该 lot 序列上**第一个** `SellScore` 判定退出的决策点的
`exit_proceeds_if_exit_now`,若全程未判定退出则取最后一个决策点的 `hold_terminal_proceeds`。
把所有 lot 的已实现结果按其决策/终局时刻映射回时间轴,即得到一条可计算 Sharpe/rank_ic/max_drawdown/
tail_loss 的组合级序列——**复用 [`backtest/metrics.rs`](../../../crates/quant-pivot-research/src/backtest/metrics.rs) 的全部现有指标函数,不重新发明**。产出形状复用现有 `BacktestReport`(字段语义不变,只是"一个样本"的定义从"一次买入建仓"换成"一个 lot 的终局或退出结果")。

## 6. 生产不变量与失败语义

- **Lot 内不可跨折**:同一 `position_id` 的全部决策点必须整体分进同一折(训练或测试),CPCV 分区/purge
  的粒度是 lot,不是决策点——这是本文档最核心的不变量,违反即视为泄漏。
- **首次退出终止模拟**:`LotBacktester` 必须在模型判定退出的第一个决策点停止模拟该 lot 的后续决策点
  (不得继续对已"卖出"的仓位打分),否则回放结果系统性乐观。
- 沿用 11.5 的全部不变量:回测禁用 live BookStore、purge 必须 label-horizon-aware、发布前重扫泄漏、
  rank_ic/DSR/PBO 硬门禁、多路径优先单点数字。
