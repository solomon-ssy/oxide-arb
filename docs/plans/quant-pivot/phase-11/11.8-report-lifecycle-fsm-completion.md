## 1. 目标与闭环定位

Phase 11.8 把报告平面从“进程内定时器触发一次构建，成功后直接出现 Published 行”重构为五层、
可持久观察且可并发证明正确的业务闭环：

1. **ReportRun**：一次计划或人工构建的持久运行账本，拥有排队、租约、失败和重试语义。
2. **RecommendationReport**：完整、不可变的决策制品；只有全量 required artifacts 已原子提交后才存在。
3. **ReportFactDelivery**：把不可变 PG 制品投递并校验到 ClickHouse 的 outbox 子状态机。
4. **Recommendation**：报告中的单条入场建议，拥有独立 entry-authority 与 attribution 生命周期。
5. **Execution**：intent/condition/capital/order 的真实资金状态；报告取代只关闭新入场，绝不抹除已提交订单。

### 1.1 业务成功标准

- **FSM-001**：构建运行与完整报告制品彻底拆分；报告表不持久化 `Building`/`Failed`。
- **FSM-002**：`profile_id + report_kind` 定义唯一 report scope；同 scope 至多一个 `Published`。
- **PUB-001**：报告先 `Prepared`，ClickHouse 两表事实校验后才原子 `Published`。
- **PUB-002**：新报告发布与旧报告 supersession、recommendation/intent/condition/capital 级联同事务线性化。
- **SCH-001**：schedule occurrence、run、gap、lease 全部在 PG 可恢复；多副本不会重复构建。
- **SCH-002**：永不以历史 `scheduled_for` 伪造决策；missed occurrences 只 coalesce latest 并记录 gap。
- **ATT-001**：被 supersede 但未提交的建议是 censored observation，不得污染训练负标签。
- **ATT-002**：合法 censor 必须独立计数且不得进入 `planned_samples` 覆盖率分母，不能伪装成证据缺失。
- **API-001/UI-001**：刷新、重连、进程重启后，操作员仍可从 durable API/UI 看到运行、发布和取代真相。
- **DEL-001**：旧 scheduler、ephemeral build truth、empty suppression 和重复 trigger authority 删除干净。
- **PUB-006**：ClickHouse recommendation 行只冻结决策快照，不复制 PG live lifecycle；非空报告和
  `SupersededUnfilled` attribution 必须通过真实空库 schema 插入契约。

### 1.2 In scope

- PG report-run ledger、schedule state、schedule gap、租约、heartbeat、queue/backpressure。
- `Prepared → Published` 原子发布、current scope、lineage、supersession/obsolete/revoke/expire。
- recommendation、pre-submission intent、entry condition、reserved capital 的原子级联。
- superseded attribution censor 及训练数据排除。
- report/run/schedule API、durable WS、operation-log timeline、scope-safe diff。
- Reports、Runs & Schedule Health、run detail、lineage、timeline、diff、Dashboard durable projection。
- metrics、alerts、health projection、空库首次激活和完整质量门禁。

### 1.3 Out of scope

- **历史 tick backfill/replay**：历史研究回放属于 research/backtest，不得伪装成在线报告。
- **旧库升级与旧 wire 兼容**：项目尚未正式生产，继续使用空库 schema/catalog 重建；无旧 parser、双读、alias、re-export。
- **跨 profile 资金分配**：Phase 11.9 owner；本期只定义每个 `profile_id + report_kind` 的 current authority。
- **自动再训练与 winner/challenger**：Phase 11.9 owner；本期只交付 `SupersededUnfilled` censored input。
- **反事实因子归因**：Phase 11.10 owner；本期 diff 只比较已冻结报告制品，不计算因果贡献。
- **取消 Running build**：本期由 lease loss、failure、abandon、retry、revoke/obsolete 完成恢复闭环，不暴露 cancel。

## 3. 新领域类型 / 表 / API 契约

### 3.1 ReportRun FSM（FSM-003）

```text
Queued ──claim──> Running ──prepare commit──> Succeeded
  │                  ├──build error────────> Failed
  │                  └──lease lost─────────> Abandoned
  └──coalesce/reconfigure/ttl──────────────> Skipped
```

| 状态 | 是否持有 lease | 是否允许生成报告 | 允许后继 | 业务含义 |
|---|---:|---:|---|---|
| `Queued` | 否 | 否 | Running/Skipped | 已接受且 durable，等待全局 build slot |
| `Running` | 是 | 是 | Succeeded/Failed/Abandoned | 实际 `decision_at` 已冻结 |
| `Succeeded` | 否 | 已完成 | 无 | 完整 PG report 已 Prepared；不等于 Published |
| `Failed` | 否 | 否 | 新 retry run | 构建在 report commit 前失败 |
| `Skipped` | 否 | 否 | 新 retry run（仅 ad-hoc） | occurrence 被 coalesce、重配置或队列过期 |
| `Abandoned` | 否 | 否 | 新 retry run（仅 ad-hoc） | lease 过期；原 run 永不恢复 |

`retry` 永远创建新 `report_run_id`，记录 `retry_of_run_id`，使用新的实际决策时间；不得复活终态 run。

### 3.2 RecommendationReport FSM（FSM-004）

```text
Prepared ──facts verified/newest──> Published ──newer publish──> Superseded
    │                                  ├──operator/parity─────> Revoked
    ├──newer/equal current─────────> Obsolete
    └──operator containment────────> Revoked

Published ──all recommendations age out──> Expired
```

| 状态 | 曾是 current | 允许新 intent | 允许 publication retry | 终态原因 |
|---|---:|---:|---:|---|
| `Prepared` | 否 | 否 | delivery=Failed 时允许 | 完整制品等待事实验证 |
| `Published` | 是/当前 | 是 | 否 | 同 scope 唯一 current authority |
| `Superseded` | 是 | 否 | 否 | 被更新 Published 报告取代 |
| `Obsolete` | 否 | 否 | 否 | 发布竞争时已经存在不旧于它的 current |
| `Revoked` | 可能 | 否 | 否 | operator/parity containment |
| `Expired` | 是 | 否 | 否 | recommendation validity 全部结束 |

- **FSM-005**：空报告状态仍为 `Published`；`published_recommendation_count=0` 时 `summary.empty_reason` 必填。
- **FSM-006**：撤销/过期 current 不重新激活 predecessor；current 可以暂时不存在。
- **FSM-007**：`Superseded` 与 `Obsolete` 不可互换；前者曾产生 entry authority，后者从未产生。

### 3.3 FactDelivery FSM（FSM-008）

现有 `Pending/Delivering/Retrying/Failed/Verified` 增加 `Cancelled`：

- `Failed` 表示自动重试耗尽，但 report 仍为 `Prepared`，操作员可 governed publication retry。
- `Cancelled` 用于 report 被 Revoked/Obsolete 或由更新 report 清理；worker 的 lease CAS 随后必须失败。
- `Verified` 与 report publication 在同一 PG 事务完成，不能先 Verified 再独立 Published。

**FSM-010（settlement claim-loss）**：`fail_fact_delivery` 与 `verify_and_publish_report` 不得用通用
`StateConflict` 表示一个已存在 delivery 的 lease/CAS 丢失，而必须返回 typed
`FactDeliverySettlement::{Applied,ClaimLost}`。`ClaimLost` 包含当前 durable delivery 状态；worker 对
`Cancelled`、lease expiry 或 owner replacement 记录低基数 metric/log 后 noop 并继续轮询。delivery 行缺失、
数据库 I/O、schema/invariant corruption 仍是 `Err`；worker 对单次 `process_one` 错误记录 metric、退避并继续，
不得永久退出唯一 runtime task。

### 3.4 Recommendation / execution / attribution（FSM-009、EXE-001、ATT-001）

`RecommendationStatus` 增加 `Prepared/Superseded/Obsolete`：

- `Prepared → Published | Obsolete | Revoked`。
- `Published/IntentCreated → Superseded | Revoked | Expired`。
- Superseded recommendation 若已有 Submitted/filled ledger，仍可最终 `Attributed`。
- Obsolete recommendation 不进入 intent、attribution 或训练。

新增：

```text
ApprovalInvalidation::ReportSuperseded
RecommendationOutcome::SupersededUnfilled
RecommendationAttributionOutcome::SupersededUnfilled
```

`SupersededUnfilled` 只适用于没有已提交/成交订单、因 report supersession 被关闭的建议；它是
**censored observation**，dataset/calibration 构建必须排除且记录排除计数，禁止编码为 0 或负标签。
`DatasetCoverage.live_attribution_censored_superseded_unfilled` 是该 censor 的唯一计数；它不得增加
`live_attribution_dropped_missing_evidence`，也不得进入 `planned_samples`，否则 feature-build coverage 与
11.9 drift/governance 会把合法业务 censor 误判为数据质量故障。每次构建必须满足
`live_attribution_candidates = live_attribution_materialized + live_attribution_dropped_missing_evidence +
live_attribution_censored_superseded_unfilled`；溢出或不平衡一律 fail closed。

### 3.5 PostgreSQL 表（SCH-003）

#### `quant_report_run`

| 字段 | 类型/约束 | 语义 |
|---|---|---|
| `report_run_id` | UUIDv7 PK | run identity |
| `trigger_kind` | PG enum | scheduled / ad_hoc |
| `trigger_key` | TEXT UNIQUE | 唯一幂等 authority |
| `schedule_id` / `request_id` | nullable TEXT + CHECK | 与 trigger kind 一致 |
| `retry_of_run_id` | nullable self FK RESTRICT | retry lineage |
| `scheduled_for` | nullable timestamptz | schedule occurrence；非 decision time |
| `requested_at` | timestamptz | 入队时间 |
| `status` | PG enum | ReportRunStatus |
| `started_at/decision_at/heartbeat_at/lease_expires_at/finished_at` | nullable timestamptz | lease/run clocks |
| `lease_owner` | nullable UUID | worker identity |
| `decision_policy_snapshot_id` | nullable FK | Running claim 时冻结 |
| `top_n/knowledge_lag_secs` | nullable integer/bigint | Queued ad-hoc 保存可选 request override；scheduled Queued 为空；Running claim 原位冻结为精确有效参数，终态保留该证据 |
| `output_report_id` | nullable UNIQUE FK RESTRICT | Succeeded 必有；其他状态必须无 |
| `terminal_reason` | nullable PG enum | typed skip/fail/abandon reason |
| `error_code/error_summary` | nullable TEXT | sanitized，分别 ≤128/4096 chars |

Indexes / constraints：

- 唯一 `trigger_key`。
- partial unique constant index：`WHERE status='running'`，全系统只允许一个 Running build。
- partial unique `(schedule_id) WHERE status='queued' AND trigger_kind='scheduled'`。
- claim index：`(status, requested_at, report_run_id)`。
- lease recovery index：`(status, lease_expires_at)`。

#### `quant_report_schedule_state`

`schedule_id` PK、`decision_policy_snapshot_id` FK、`spec_hash`、`next_scheduled_for`、
`last_materialized_for`、`enabled`、`created_at/updated_at`。它是 runtime config 的 durable derived state，
不是第二份业务配置；worker 始终通过 version FK 加载精确 schedule spec。

#### `quant_report_schedule_gap`

append-only：`gap_id` UUIDv7 PK、`schedule_id`、config version FK、`reason`、
`first_scheduled_for/last_scheduled_for`、`missed_count > 0`、`detected_at`、sanitized detail。
一个 reconcile pass 对连续缺口写一行，禁止为长时间停机逐 tick 写无限行。

Retention：run/gap/schedule state 均保留在 PG；本期不加自动删除。数据量达到真实容量证据后由运维 retention
phase 决定，禁止无证据提前丢审计账本。

### 3.6 Report schema（PUB-003）

- 新增 `profile_id TEXT NOT NULL`，CHECK `profile_id = profile_ref->>'id'`。
- 新增 `successor_report_id` self FK、`superseded_at`、`obsoleted_at`。
- `(profile_id, report_kind) WHERE status='published'` partial unique index 是 current invariant 的最终数据库护栏。
- 删除 `trigger_kind/trigger_key/trigger_time/knowledge_lag_secs`；通过 `quant_report_run.output_report_id` 一对一回查。
- `published_at` 仅在 `Prepared → Published` 设置；prepare 时必须为 NULL。
- `status_reason` 只保存 lifecycle reason，不再重复 empty reason。

### 3.7 ClickHouse decision fact（PUB-006、DEL-016）

- report fact bundle 破坏式升级为 `ReportFactBundleV2` / `format_version=2`；不解析 v1，不保留 alias/re-export。
- `quant_recommendation_event` 破坏式重命名为 `quant_report_recommendation_fact`，row 类型为
  `QuantReportRecommendationFactRow`。它表达 prepare 时已经冻结的 rank/score/trade-plan/validity 决策快照，
  **不含 recommendation/report/delivery lifecycle status**。
- PG `quant_recommendation.status` 与 `quant_recommendation_report.status` 是 live lifecycle 唯一权威；
  ClickHouse 不接受“Prepared 镜像”，也不在 publish/supersede 时追加伪状态更新。
- `quant_recommendation_attribution_event.outcome` 是终局分析事实，Enum8 必须包含
  `'superseded_unfilled'=6` 并与 Rust `ChRecommendationAttributionOutcome` 闭集一致。
- 空库 DDL 后必须真实插入一条 recommendation decision fact 与一条 `SupersededUnfilled` attribution；
  只对 Rust enum 或 SQL 文本做各自单测不足以证明跨语言契约。
- ClickHouse migration 1 是 WORM baseline，不篡改其 checksum；新增 migration 2
  `report_lifecycle_v2`，显式标记 `OfflineRequired`。它只有在旧 recommendation/attribution 两表均为空时，
  才 DROP 旧表并创建新闭集；非空即 fail closed。无数据搬运、旧表 view、双写或兼容读取。
- 项目未生产运行，首次激活从空库执行 deploy-only `clickhouse-schema apply-offline`，随后 runtime 仅允许
  online-safe auto-apply/read-only verify。

### 3.8 Diff（API-003）

- base/compare 必须具有相同 `profile_id + report_kind`，否则 `ReportError::IncomparableReports` → 400。
- 默认 baseline 是 direct predecessor；UI 不列出跨 scope candidate。
- `RecommendationDeltaView` 改为：identity、change kind、`base/compare: RecommendationDiffSnapshot?`、
  `changed_fields`。
- snapshot 冻结 rank、composite/risk-adjusted score、confidence、expected/downside bps、sizing、validity、
  execution eligibility、typed trade plan 与相关 canonical hashes。
- `changed_fields` 固定为 rank/score/confidence/return/sizing/entry/exit/eligibility/factor。

### 3.9 WebSocket（WS-001）

- 新频道 `quant.report_run`：`queued/running/succeeded/failed/skipped/abandoned`。
- `quant.report` 只发有 durable backing 的 aggregate event：
  `prepared/published/superseded/obsolete/revoked/expired/delivery_retrying/delivery_failed`。
- WS 是 revision hint；客户端收到后重新读取 REST。sync/reconnect 不试图重放内存事件。
- 删除 ephemeral `started/failed/empty` 和 nullable report id 契约。

### 3.10 UI（UI-002）

复用现有 Vben/Ant Design Vue、Page、表格、tag options、route guard、governed modal 和
feature-integrity run drawer，不引入新视觉语言：

- Reports workspace 顶部 health strip：从 health projection 展示每个 scope 的 current、最近有效期、active run、last publication、
  24h gaps/failures、next fire。
- 一级 tabs：`Reports`、`Runs & Schedule Health`。
- ad-hoc 成功后立刻打开 route-backed run drawer；刷新/深链可恢复。
- run drawer 展示 scheduled vs actual、lateness、queue latency、lease、frozen config、terminal reason、
  sanitized error、retry lineage、output report。
- report detail lifecycle banner：Prepared 不可执行；Published=current；Superseded/Obsolete 链接 successor 和 diff；

### 4.1 Runtime v16（DEL-015）

## 6. 生产不变量与失败语义

### 6.1 原子 publication（PUB-004）

事实 worker 完成 CH 写入/读取校验后，PG 单事务按固定顺序：

1. 只读预检 delivery/candidate identity，仅用于解析 scope，不获取任何行锁。
2. 获取由 `profile_id + report_kind` 稳定派生的 transaction advisory lock；这是该事务的第一把锁。
3. lock delivery，重新验证 `Delivering + claim_owner + lease`。
4. lock candidate report，重新验证 scope 与 `Prepared`；再 lock current Published 和同 scope 更旧 Prepared。
5. 若 current `decision_at >= candidate.decision_at`：candidate/recommendations → Obsolete，delivery → Cancelled。
6. 否则 candidate/recommendations → Published，设置 `published_at`。
7. current → Superseded，记录 successor；旧 Prepared → Obsolete，取消其 delivery。
8. 级联旧 recommendation、pre-submission intent、condition、capital。
9. delivery → Verified；写 publish/supersede/obsolete operation logs。
10. commit；其后才发 WS/alerts/notifications。

advisory lock 负责同 scope 串行化，partial unique index 是不可绕过的最终防线。即使应用锁代码回归，DB 仍拒绝双 current。预检结果不具有权威性；所有可变状态必须在 scope 锁后持行锁重新读取并校验，从而与 submission 使用完全一致的锁序。

### 6.2 Execution race（EXE-002）

publication/supersession 与 submission 共享 lock order：scope advisory lock → report → recommendation → intent →
condition/capital。submission write-ahead transaction 必须在同一锁域内重新验证 parent report/recommendation。

- supersession 先赢：pre-submission intent → Invalidated，capital release，submission CAS 拒绝。
- submission 先赢：Submitted order 保留，supersession 只关闭后续新入场；exit/reconciliation/settlement 继续。
- 禁止对 Submitted/PartiallyFilled/Filled order 做“回滚式 supersession”。

### 6.3 Run lease / crash（SCH-005）

- claim、heartbeat、prepare commit 都以 `(run_id,status=Running,lease_owner,lease_expires_at)` CAS。
- heartbeat 失败必须取消本地 build future；即使取消延迟，prepare CAS 仍拒绝提交。
- expired Running → Abandoned；scheduled 不自动 retry，等待下一 cadence；ad-hoc 由 operator retry。
- report 与 run `Succeeded + output_report_id` 在同一事务提交，禁止“有报告但 run 仍 Running”。

### 6.4 Schedule reconcile（SCH-006）

- schedule state 从 active RuntimeConfig version 派生；spec hash 未变时只推进 cursor。
- 新增/修改 schedule 的 `next_scheduled_for` 严格晚于 activation time；不得补旧 spec occurrence。
- coordinator 发现多个 due occurrence 时，只 materialize latest；早期区间写一条 `CoordinatorLag` gap。
- 已有 queued schedule run 时，新 occurrence 将旧 run `Skipped(CoalescedByNewerOccurrence)` 并替换。
- config 修改/禁用将旧 queued run `Skipped(ScheduleReconfigured)`。
- global queue 按 `requested_at, report_run_id` FIFO；queued schedule 的不断替换会刷新时间，不会饿死更早任务。
- `decision_at` 使用 claim 的 DB `statement_timestamp()`；`scheduled_for` 只用于审计和 lateness。

### 6.5 Empty / failure / recovery（PUB-005、OBS-001）

- 完整业务评估为零 recommendations：Prepared → Published，supersede 旧 current。
- build failure：run Failed，不创建半成品 report，不影响旧 current。
- fact delivery retry/failed：report 保持 Prepared，不影响旧 current。
- publication retry 复用相同 immutable bundle；若期间已有更新 current，最终转 Obsolete。
- revoke current 不恢复 predecessor；UI/health 显示“无 current”。
- alert/metric 失败不回滚 committed business transaction；durable state 可供 retry/reconcile。

## 7. 第三方 crate 与外部设计依据

- 删除 `tokio-cron-scheduler`；不新增 scheduler crate。
- 保留直接依赖 `croner` 解析 cron/interval next occurrence。
- 复用 SeaORM/PG transaction、`FOR UPDATE SKIP LOCKED`、partial unique index 和 advisory lock。

调度结论依据：

- [Kubernetes CronJob](https://kubernetes.io/docs/concepts/workloads/controllers/cron-jobs/)：overlap policy、missed schedule、
  scheduled timestamp 与 job idempotency 必须显式定义。
- [Temporal Schedule](https://docs.temporal.io/schedule)：schedule identity 与 execution 分离，overlap/catch-up/backfill 是不同策略；
  time-sensitive workflow 默认不应隐式回补。
- [Tokio MissedTickBehavior](https://docs.rs/tokio/latest/tokio/time/enum.MissedTickBehavior.html)：Burst/Delay/Skip 会改变时钟语义，
  不能依赖未声明的 timer 默认行为。
- [PostgreSQL partial indexes](https://www.postgresql.org/docs/current/indexes-partial.html)：对 Published/Running 子集建立唯一约束。
- [PostgreSQL advisory locks](https://www.postgresql.org/docs/current/explicit-locking.html#ADVISORY-LOCKS)：对应用定义 scope 做事务串行化。
- [ClickHouse Enum](https://clickhouse.com/docs/sql-reference/data-types/enum)：Enum 列只能保存 DDL 中列出的闭集值，
  未知名称或底层整数都会抛异常；因此 Rust repr 与空库 DDL 必须通过真实 insert 一体校验，但 live lifecycle
  本身不应被复制进 immutable decision fact。

## 9. Blocker / Phase Exit

以下任一点存在，Phase 11.8 不得标记完成：

- 报告仍持久化 Building/Failed 或 empty suppression 仍可启用。
- report 在 fact Verified 前可创建 intent，或 Published 与 delivery Verified 不原子。
- 同 scope 可出现两个 Published，或 supersession 与 intent/capital 不同事务。
- Submitted order 会被 supersession 错误撤销，或 supersession race 可产生新 submission。
- scheduler 仍依赖进程内 job truth、全局 waiting mutex、静默 missed tick 或历史 decision time。
- run lease 丢失后仍可 commit report。
- `SupersededUnfilled` 被当作负样本/零值进入训练。
- recommendation decision fact 携带 live lifecycle，或空库不能插入非空 report / superseded censor。
- delivery `ClaimLost`/单次 process error 使唯一 fact worker 永久退出。
- 合法 superseded censor 进入 missing-evidence 桶或 `planned_samples` 分母。
- WS/页面刷新后无法从 durable API 恢复运行与 lifecycle 真相。
- 旧 enum/config/API/WS/dependency/re-export 任一残留。
- 文档验收矩阵没有实际实现与测试证据。
