# 11.8 — Report Lifecycle FSM Completion

> 关闭审计点:**#17(无 `superseded` 报告状态、无持久化 `building`、错过的 tick 不补跑)**。

## 1. 目标与闭环定位

补全报告生命周期状态机的语义精准性:让"报告被后继取代"、"报告构建中"成为**持久化的一等状态**,并给
错过的调度 tick 一个**明确策略**(补跑或显式记录 gap),而不是静默丢弃。它是 report 平面
`draft/building/published/expired` FSM 与 scheduler 的重构。

## 2. 删除 / 合并 / 重构清单

| 对象 | 现状 | 处置 |
|---|---|---|
| 报告 `superseded` 状态缺失(设计提及,`enums/quant.rs` 无) | 死语义/缺失(#17/#23) | **实现**:新增 `Superseded` 状态 + 新报告发布时自动作废同 scope 旧报告(§3.1)。 |
| `building` 仅 ephemeral WS,PG 直接落 `Published`/`PublishedEmpty`(`composer.rs`) | 无持久化中间态 | **重构**:先持久化 `Building` 行,再 transition 到终态,run 崩溃可见(§3.2)。 |
| 错过 tick 被 overlap guard 直接丢(`infra/schedule/overlap.rs`) | 静默 gap | **重构**:引入 missed-tick 策略(§3.3):补跑最近一次 / 记录 `ScheduleGap` fact + 告警。 |
| 报告 diff 只比 rank + suggested_usd(`report_diff.rs`) | 语义不全 | **扩展**:diff 覆盖 entry/exit plan 与分数变化(§3.4),供 superseded 展示"改了什么"。 |

## 3. 契约与算法设计

### 3.1 `Superseded` 状态与自动作废(#17)

```rust
pub enum RecommendationReportStatus {
    Building,          // 新:持久化中间态
    Published,
    PublishedEmpty,
    Superseded,        // 新:被同 scope 后继报告取代
    Failed,
    Revoked,
    Expired,
}
```

- 新报告 `Published` 成功后,同一 scope(schedule_id / market universe)的前一 `Published` 报告在
  同一事务内转 `Superseded`,并记录 `superseded_by_report_id`。
- 语义:同一时刻同 scope 至多一个 active(`Published`)报告,消除"两个报告有效期重叠"的歧义。
- `Superseded` 报告只读留档(审计),UI 标注"已被 <report_id> 取代 + diff"。

### 3.2 持久化 `Building`(#17)

- lifecycle 开始 run 时,先在事务内写 `Building` 行(带 trigger key)。
- 成功 → transition `Building → Published/PublishedEmpty`;失败 → `Building → Failed`(带失败原因)。
- 好处:run 崩溃/超时后,PG 有可见的 `Building`/`Failed` 记录(不再只有 WS ephemeral),便于运维排障与
  幂等恢复(重启后可判定"上次卡在 Building")。
- 幂等:`find_by_trigger_key` 若发现残留 `Building`(超 TTL)→ 标 `Failed` 后允许新 run。

### 3.3 Missed-tick 策略(#17)

```rust
pub enum MissedTickPolicy {
    /// 丢弃(现状),但显式记录 ScheduleGap fact + metric(不再静默)。
    RecordGapOnly,
    /// 补跑一次最近错过的 tick(catch-up),以 backfill trigger key 标记。
    BackfillLatest,
}
```

- overlap guard 命中(上一个还在跑)或进程重启导致错过 → 按 `MissedTickPolicy` 处理。
- 无论哪种,都写 `quant_schedule_gap_event`(CH)+ `quant_report_schedule_missed_total`(metric)+ 告警,
  运维可见。默认 `RecordGapOnly`(报告有时效性,补跑旧 tick 常无意义);高价值 schedule 可选 `BackfillLatest`。

### 3.4 diff 扩展(#17 支撑 superseded 展示)

`compute_report_diff` 扩展:除 rank / suggested_usd,增加 entry_plan / exit_plan(TP/SL/trigger)/
composite_score / eligibility 的 delta,让 `Superseded` 关系能展示"新报告相对旧报告改了什么"。

## 6. 生产不变量与失败语义

- **单 active 报告**:同 scope 同时至多一个 `Published`;发布新报告原子作废旧报告为 `Superseded`。
- **Building 可恢复**:残留 `Building` 超 TTL → `Failed`,不阻塞后续 run。
- **无静默 gap**:错过 tick 必写 fact + metric + 告警。
- **状态转移合法**:`Building→{Published,PublishedEmpty,Failed}`;`Published→{Superseded,Revoked,Expired}`;
  仓库层强校验(与 order_intent FSM 校验同风格)。
