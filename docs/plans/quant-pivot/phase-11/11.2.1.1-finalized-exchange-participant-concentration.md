# 11.2.1.1 Finalized Exchange Participant Concentration

> **Canonical contract**：Polygon 官方登记的 CTF / NegRisk Exchange V1+V2 是 execution participant 事实的唯一来源。MarketWs `LastTrade` 只属于 L2 ledger，不能替代 maker/taker 或成交语法。

## 数据与正确性

- HyperSync 提取官方四个 exchange contract；Combo 明确排除。
- 日志按 `(contract_address, tx_hash)` 聚合并按 `log_index` 排序。V1 允许 standalone `fillOrder/fillOrders`，V2 只允许完整 match group；leftover 或歧义交易进入 typed quarantine。
- extractor 用完整 header chain 验证连续性；独立 attestor 读取边界、confirmation anchor 与日志涉及的稀疏 headers。两侧均校验各自 provider 的 `log.block_hash == header.hash`。
- ClickHouse execution / participant facts 只通过 active acceptance revision 可见。训练绑定不可变 `FitSeal`，报告绑定 `decision_at` 对应的 `ServingHeadSeal`；发布前重新验证 revision 与 active quarantine。

## 特征合同

- `struct.participant_concentration` 由 bilateral participant facts 计算 Gini、HHI 与 CR1。
- 缺 concentration 证据是全局 `Penalize`，不删除已有真实成交且满足最少参与者门槛的市场；必需 execution history 不足仍 `RejectMarket`。
- maker/taker 专属指标只在 projection grammar 完整且 participant role 可证明时发布，禁止用 top-of-book、mid 或 MarketWs side 猜测。

## 运维与门禁

- `GET /api/system/exchange-history/quarantines` 是隔离证据唯一运维读面；不存在 skip/bypass。
- active quarantine、seal invalidation 或未建模正持仓阻断报告发布并告警。
- 自动化覆盖 V1/V2 grammar、provider/header/parent-chain mismatch、rewind revision、replacement seal、三参与者 penalized row 与历史不足拒绝。
