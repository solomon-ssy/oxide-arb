# 11.3 — Probabilistic Calibration and Scenario Uncertainty

<!-- quant-pivot-deployment-contract:v1 -->
> **Clean-break contract**：文件名保留 phase 编号定位，但 Kelly sizing 已彻底删除。本文只治理
> Route-specific probability calibration、uncertainty evidence 与联合 scenario distribution contract。

## 1. 目标

把每个 Route 的 raw model output 转换为经过 held-out/PIT 证明的 calibrated payout distribution 与
confidence set，供 `ExecutableEconomicTier` 和 `PortfolioScenarioArtifact` 使用。不同 Route 的 raw score
不能直接比较。

## 2. CalibrationArtifact

每个 artifact 必须冻结：

- exact Buy Route、model version、serving contract 与 feature/research profile；
- calibration method 与 fitted parameters；
- disjoint train/calibration/evaluation windows、knowledge lag、purge/embargo；
- sample/cohort definition 与 category/group coverage；
- 对 winner-take-all conditional probability 的 multiclass/proper score、reliability bins 与 calibration error；
- `SplitPayout` 的独立事件频率、样本量和区间，禁止把 0.5 强制转换成 win/loss 或直接丢弃其不确定性；
- probability interval/uncertainty estimator；
- artifact schema/content hash 与 promotion evidence。

Platt、isotonic 或后续方法必须由 sample-size/quality policy 显式选择；没有 heuristic/default probability
fallback。calibration 不可用或与 Champion 不兼容时 represented Route readiness 失败。

## 3. Proper scoring 与 multicalibration

- 使用 strictly proper Brier/log scoring 评估概率，而不是准确率或 raw rank metric。
- reliability evidence 必须同时覆盖 Route 总体和有足够样本的 material subgroup。
- subgroup calibration gap 超过 promotion threshold 时 artifact 不可成为 Champion binding。
- 所有 threshold、window 和 cohort 来自 immutable Research Method/Profile，不进入 Runtime sizing config。

## 4. Scenario uncertainty contract

CalibrationArtifact 输出：

- per-candidate `P(win | winner_take_all)`、`P(split)` 与派生的完整 `P(loss/split/win)`；
- expected payout `P(win) + 0.5·P(split)`，它和 profit probability 是两个不同量；
- conservative lower/upper interval；
- residual/cohort identity；
- 可供 joint bootstrap 的 PIT residual evidence；
- compatibility digest。

`PortfolioScenarioArtifact` 使用这些 evidence 构建允许的 scenario distribution set，并显式加入 structural/
stress scenarios。runtime 不得从 point estimate 合成 independence、Pearson 或 category proxy。

## 5. Report consumption

- candidate admission 使用 profit-probability lower bound 和 maximum interval width。
- scenario cashflow 使用完整 calibrated distribution/confidence set。
- global optimizer 最大化 worst-distribution expected net USD 并施加 CVaR/scenario-loss hard constraints。
- calibration score/confidence 本身不进入 portfolio objective，也不缩放独立仓位。
- Recommendation 展示 probability/economic evidence，不展示 Kelly fraction。

## 6. Promotion 与 fail-closed

promotion 必须原子验证 Champion、CalibrationArtifact、Trade Policy、Research Profile 和 scenario binding。
任一 digest/schema/Route/time-window 不一致时拒绝 activation。报告运行中不自动换 calibrator，不允许
uncalibrated bootstrap artifact 进入 production report 或获得 `OperatorApproval` / `PolicyAutomatic` execution authority ceiling。

## 7. 验收

- calibration train/evaluation leakage guard、purge/embargo 与 PIT replay。
- multiclass/proper score、reliability bins、split-rate interval 和 subgroup calibration gate。
- 0/0.5/1 三态场景能够改变 expected payout、profit probability、VaR/CVaR，且 split 不被二元化。
- model/calibrator/Route/profile compatibility mismatch fail closed。
- missing calibration 使整份 represented-route report 失败。
- probability interval monotonicity 与 deterministic artifact hash。
- scenario artifact 只能消费 promoted calibration evidence。
- raw score/order 相同但 calibration 不同的候选按最终 USD economics 正确比较。
