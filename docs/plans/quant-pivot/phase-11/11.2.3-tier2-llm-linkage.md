## 1. 目标与闭环定位（含 trigger conditions）

**目标**：在 Tier 0（series slug 直读）与 Tier 1（`CryptoSubjectParser` 模板解析）均 `Ok(None)` 或
产出候选但被 grounding gate `Rejected` 的长尾 crypto 市场上，以**离线-only** LLM 结构化抽取提高 linkage
覆盖率，同时保持与 11.2.2 相同的 fail-closed 与 bitemporal 可回放语义。

**Trigger conditions**（全部满足才调用 Tier 2；任一不满足则跳过，市场保持 `Unresolved`）：

| # | 条件 | 语义 |
|---|---|---|
| T1 | `market.category = Crypto` | 非 crypto 垂直不走本 Tier 2 实现（Sports/… 见 §10 加性扩展） |
| T2 | Tier 0 **and** Tier 1 均已尝试 | `LayeredResolver` 顺序不变；Tier 2 是第三层，不得短路确定性层 |
| T3 | Tier 0/1 结果为 `Ok(None)` **或** grounding `Rejected` | `Rejected` 不 fall-through 到下一 tier（11.2.2 不变量）；Tier 2 仅在**批量离线 re-resolve** 任务中作为**独立 pass** 触发，输入为「确定性层 unresolved 集合」 |
| T4 | `domain.linkage.tier2.enabled = true` | runtime-config 显式开关；默认 **false** |
| T5 | 市场 `metadata_version` 自上次 Tier 2 pass 以来有变更 **或** ruleset/resolver_version bump | 避免对冻结记录重复烧 token |
| T6 | 当日 Tier 2 token/cost budget 未耗尽 | 见 §7 |
| T7 | 市场不在 Tier 2 blocklist（人工标记「永不 LLM」） | 运维 override 优先 |

**闭环定位**：`LinkageResolverService` 的离线 re-resolve 管线在 Tier 0/1 batch 之后，对 `Unresolved`
集合可选跑 `Tier2LlmExtractor`；产出仍经 `DefaultSubjectValidator` → append-only ledger。在线
`LinkageStore::valid_at` 只读冻结记录，**零 LLM 调用**。

**Schema-enforced extraction**（verbatim 契约）：

```rust
/// Wire shape the LLM must emit. Deserialized then validated; any extra field = reject.
#[derive(Debug, Clone, Deserialize, JsonSchema)]
#[serde(deny_unknown_fields)]
pub struct LlmExtractedCryptoSubjectWire {
    pub asset: String,
    pub quote: String,
    pub comparator: String,
    pub strike: Option<String>,
    pub reference_at: Option<DateTime<Utc>>,
    pub observation_at: DateTime<Utc>,
    pub resolution_oracle: String,
    /// Field → { source_field, start, end, text } — must match source metadata literally.
    pub grounding_spans: Vec<LlmGroundingSpanWire>,
    pub confidence: f64,
}

/// Provider-agnostic offline LLM call. Returns raw JSON bytes only; parsing/validation
/// is research-side (schema-enforced + SubjectValidator).
pub trait LlmLinkageProvider: Send + Sync {
    fn provider_id(&self) -> &'static str;
    async fn extract_crypto_subject(
        &self,
        metadata: &LinkageSourceMetadata,
        schema: &serde_json::Value,
    ) -> QuantResult<Vec<u8>>;
}

/// Tier 2 implementation — OFFLINE ONLY.
pub struct Tier2LlmExtractor {
    provider: Arc<dyn LlmLinkageProvider>,
    min_confidence: Probability,
}

impl SubjectExtractor for Tier2LlmExtractor {
    fn tier(&self) -> ResolverTier { ResolverTier::Tier2Llm }
    fn extract(&self, metadata: &LinkageSourceMetadata)
        -> QuantResult<Option<ExtractedCandidate>> { /* schema parse → map to MarketSubject → candidate */ }
}
```

**Processing pipeline**（单市场）：

1. Build prompt from frozen `LinkageSourceMetadata`（slug, question, description, series_slug, end_date）。
2. Call `LlmLinkageProvider` with JSON Schema constraint（provider-native structured output 或 tool schema）。
3. `serde_json` deserialize → `LlmExtractedCryptoSubjectWire`（fail → `Err`, 不 fabricate）。
4. Map to `ExtractedCandidate` + `GroundingProof`。
5. **`DefaultSubjectValidator::validate`** — 与 Tier 0/1 **同一 gate**（§6）。
6. 若 `Accepted` 且 `auto_accept_on_gate_pass` → freeze ledger；否则 → review queue（§6）。

## 6. 生产不变量与失败语义（SubjectValidator reuse + deterministic fallback + human review）

### 6.1 SubjectValidator grounding gate reuse

- **无 LLM 专用 validator**；复用 [`DefaultSubjectValidator`](../../../crates/quant-pivot-research/src/linkage/extractor.rs)。
- 每个 load-bearing 字段（`asset`, `strike` when present, `resolution_oracle`）必须有 literal span。
- `instrument_key` 必须与 frozen ruleset 一致（`rule_for_alias`）。
- LLM 自报 `confidence` **不能**绕过 gate；gate 失败 → `Rejected`，记录 `rejection_reason`。

### 6.2 Deterministic fallback

优先级（不可打乱）：

1. **Tier 0** slug 直读（最高 precision）
2. **Tier 1** 模板解析
3. **Tier 2** LLM（仅离线 batch，且 trigger §1 满足）
4. **`Unresolved`** — fail-closed，`DomainMissing`，通用模型继续
5. **人工 override** — `LinkageStore::set_override`（审计留痕，`ResolverTier::Override`）

Tier 2 **不得**覆盖已有 `Resolved` 确定性记录（content_hash 不变则 idempotent no-op）。Tier 2 候选被
gate 拒绝后**不**自动 retry 同一 provider（避免幻觉放大）；仅 metadata/ruleset 变更或人工触发 re-run。

### 6.3 Human review queue

当 `domain.linkage.tier2.auto_accept_on_gate_pass = false`（默认）且 Tier 2 候选 `Accepted`：

- 写入 `quant_market_linkage_review`，状态 `PendingApproval`，**不**立即 append ledger。
- Admin UI：展示源 metadata、LLM JSON、grounding spans 高亮、provider/model、estimated cost。
- `Approve` → append `MarketLinkage`（`resolver_tier = Tier2Llm`）+ close review。
- `Reject` → close review，市场保持 `Unresolved`。
- `Override` → 运维手工编辑 subject → 仍过 `SubjectValidator` → `ResolverTier::Override`。

SLA：无自动 SLA 降级；队列积压只告警，不静默采纳。

## 9. Blocker（触发即判定失败）

- Tier 2 在在线/PIT/report 热路径被调用（含 `FeatureBuilder`、`PointInTimeSnapshotSource`、`FactorEngine` 间接调用）。
- LLM 输出未经 serde + schema 约束直写 ledger。
- Tier 2 绕过 `DefaultSubjectValidator` 或降低 grounding 要求。
- `auto_accept_on_gate_pass` 或任何 flag 允许 ungrounded 字段冻结。
- Tier 2 覆盖 Tier 0/1 已 `Resolved` 且 content_hash 不变的记录。
- cost budget 失效导致 silent unlimited LLM spend。
- review queue 绕过（gate accept 直写 ledger 而 config 要求 review）。

## 10. 延后 / 缺口（extension to other verticals + 11.2.2 交接项）

| 能力 | 处置 / 归属 |
|---|---|
| **Chainlink Data Streams** 作 settlement oracle 特征/ basis | 11.2.2 §11 → 独立 ingest + `ResolutionOracle::ChainlinkDataStreams` PIT；**非** Tier 2 职责 |
| **RTDS**（Polymarket real-time data stream）作 auxiliary 证据 | 11.2.2 §11 → 可选 `EvidenceSourceKind` 扩展；Tier 2 prompt 可读 RTDS 快照作 context，**不**替代 grounding |
| Sports/Politics/Weather/Geopolitics Tier 2 | **加性扩展**：新 `LlmExtracted*SubjectWire` + vertical-specific schema + 同一 `SubjectValidator` 模式；post-11.2.3 |
| 多 provider ensemble / 投票 | 不做；单 provider + gate + human review 足够 |
| Fine-tuned 专用 linkage 模型 | 延后；先用 general structured-output API |
| Cross-event linkage（非 neg-risk） | 独立子 phase |
| Embedding 模糊匹配 tier | **明确不做**；与 precision≫recall 立场冲突 |

**回指**：Tier 2 落地后更新 11.2.2 §11 Tier 2 行状态为「已移交 11.2.3」；长尾 unresolved 率应可观测
（linkage governance dashboard metric）。
