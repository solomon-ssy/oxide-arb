## 1. 目标与闭环定位

把"单路径回测 + 时间戳扫描 + soft rank_ic"升级为**financial-ML 标准的防过拟合验证方法论**:
purged/embargoed CV、Combinatorial Purged CV 多路径、Deflated/Probabilistic Sharpe、PBO、最小
track record length,并把 `rank_ic` 升为硬门禁、发布前重扫泄漏。它是离线闭环 `Backtest →
QualityGate → Publish` 的验证层重构,决定"回测数字能不能被信任"。

设计立场(权威来源,López de Prado *Advances in Financial Machine Learning* Ch.7/11/12):

- 普通 k-fold/单路径回测在标签有重叠 horizon + 序列相关时**系统性高估**表现。必须 **purge**(移除标签
  horizon 与测试集重叠的训练样本)+ **embargo**(测试段之后再屏蔽一段)。见 methodology
  <https://github.com/eslazarev/purged-cross-validation/blob/main/docs/methodology.md>、Wikipedia
  <https://en.wikipedia.org/wiki/Purged_cross-validation>。
- **CPCV** 生成 **φ(N,k)=C(N-1,k-1)** 条完整回测路径的分布(不是 C(N,k) 条组合折),可做稳健统计推断
  (<https://ml4trading.io/docs/diagnostic/methods/cpcv/>)。
- **Deflated Sharpe Ratio / PBO / Min Track Record Length** 纠正多重检验/选择偏差
  (Bailey & López de Prado 2014/2012)。

## 3. 契约与算法设计

### 3.1 Purged + Embargoed 切分

```rust
/// Leakage-aware time-series splitter. Purges training rows whose LABEL horizon
/// overlaps the test window, and embargoes rows immediately after each test fold.
pub trait PurgedSplitter {
    fn split(&self, samples: &[SampleTimeline]) -> Vec<TrainTestFold>;
}

pub struct SampleTimeline {
    pub as_of: DateTime<Utc>,
    pub label_horizon_end: DateTime<Utc>,   // 标签成熟时刻(triple-barrier vertical barrier / horizon)
}

pub struct PurgeConfig {
    pub embargo_pct: Decimal,               // 例如 0.02(测试段后 2%)
    pub purge_by_label_horizon: bool,       // true:按 label_horizon_end 重叠 purge
}
```

关键:**purge 必须知道每个样本的 label horizon**(不是只看 feature observed_at)——这正是 #7 现状
缺的。11.7 的三重障碍标注提供 `label_horizon_end`(vertical barrier 或首个障碍触达时刻)。

### 3.2 Combinatorial Purged CV(多路径)

```rust
/// C(N,k) combinatorial purged CV: partitions the timeline into N groups, tests on
/// all k-subsets, reconstructs multiple out-of-sample backtest paths.
pub trait CombinatorialPurgedBacktester {
    async fn run(&self, req: CpcvRequest) -> QuantResult<BacktestPathSet>;
}

pub struct BacktestPathSet {
    pub path_set_id: BacktestPathSetId,
    pub paths: Vec<BacktestPath>,           // 每条一个 OOS 路径的指标
    pub sharpe_distribution: SharpeDistribution,
    pub deflated_sharpe: Decimal,           // §4
    pub pbo: Decimal,                       // Probability of Backtest Overfitting
    pub min_track_record_length: Duration,
}
```

CPCV 复用 11.4 的模型 + 11.1 的因子 + 历史 PIT(禁止 live BookStore,与既有基线一致)。N/k 可配。

**路径数(勿与组合数混淆):**

| 量 | 公式 | 例 `N=8,k=2` |
|---|---|---|
| 组合/折数 | `C(N,k)` | **28** |
| 完整 φ 路径 | `φ(N,k)=C(N-1,k-1)` | **7** |

实现以 φ-path 重构为准(见 `validation/cpcv.rs`);UI/文档不得把 28 写成“路径数”。

### 3.3 发布前重扫泄漏(#9)

`ModelGovernance::publish/promote` 增加步骤:解码候选 dataset 的 Parquet,对**真实样本**重跑
`scan_future_leakage`(含 label-horizon purge 检查),产出**真实 `LeakageFindings`** 喂 gate;

## 4. Quality gate 重构(#7 hard gate + DSR/PBO)

| Gate | 旧 | 新 |
|---|---|---|
| `rank_ic` | soft,阈值 0 | **hard**,要求 IC > 阈值 **且** DSR 显著(p<0.05) |
| `deflated_sharpe` | 无 | **新增 hard**:DSR 校正多重检验后仍 > 0 显著 |
| `pbo` | 无 | **新增 hard**:PBO ≤ `max_pbo`(默认 0.5,越低越好) |
| `min_track_record_length` | 无 | **新增 soft/信息**:数据是否够长以信任结果 |
| `no_pit_leakage` | build 期 | **hard + 发布重扫**(§3.3) |
| `turnover` / `tail_loss` | 未 gate | **新增**:与 11.4 目标一致的 gate(超预算硬失败 for auto) |

DSR 计算:用 CPCV 的 Sharpe 分布 + 试验次数(超参搜索次数)按 Bailey-López de Prado 公式校正
(Deflated Sharpe = 观测 Sharpe 相对"选择偏差下的期望最大 Sharpe"的显著性)。

## 6. 生产不变量与失败语义

- **回测禁用 live BookStore**(沿用基线);CPCV 只用历史 PIT。
- **purge 必须 label-horizon-aware**:仅 feature-timestamp purge 视为不合规。
- **发布必重扫**:publish/promote 未产真实 leakage findings → 硬失败。
- **rank_ic/DSR/PBO 硬门禁**:未过不得进 candidate→publish。
- **多路径优先单路径**:report 展示 Sharpe 分布(min/median/max),不展示单点数字。
- 确定性:同 dataset + 同 CPCV config + 同 seed → 同 `path_set_id` 关联指标可复现。
