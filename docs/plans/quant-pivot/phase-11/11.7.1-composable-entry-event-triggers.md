# 11.7.1 — 可组合入场事件触发器

> 状态：设计冻结、未实施。11.7.1 落地前，生产代码不得保留 `DataEvent` enum、config、空 trait、
> 脚本 hook 或兼容 JSON。

## 1. 目标与边界

在 11.7 的 `Immediate | PriceCondition` 之上，引入版本化、可回放、无任意脚本执行能力的 typed
condition AST。AST 只描述确定性条件，不携带网络调用、SQL、模板表达式或动态代码。

```rust
enum EntryConditionV1 {
    Price(PriceCondition),
    Clock(ClockCondition),
    Factor(FactorCondition),
    MarketEvent(MarketEventCondition),
    All { children: NonEmpty<EntryConditionV1> },
    Any { children: NonEmpty<EntryConditionV1> },
}
```

`All/Any` 只允许有限深度、有限节点数和稳定 child order；禁止 `Not`，避免把数据缺失误解释为条件
成立。每个 leaf 必须三态求值：`Satisfied / Unsatisfied / Unavailable(reason)`。

## 2. 叶节点

- `Price`：token、comparison、threshold、confirmation、max gap、book max age。
- `Clock`：absolute instant 或相对 resolution/start deadline；时区一律 UTC。
- `Factor`：ModelVersion/FactorDefinition 版本、comparison、threshold、freshness、PIT feature vector ref。
- `MarketEvent`：版本化 event type、subject identity、source、effective_at/observed_at、finality policy。

所有外部 event 必须保存 point-in-time provenance。late/corrected event 只触发新 evaluation，不重写历史。

## 3. 确定性求值

- `All`：任一 Unsatisfied 即短路；否则任一 Unavailable→Unavailable；全部 Satisfied 才成立。
- `Any`：任一 Satisfied 即短路；否则任一 Unavailable→Unavailable；全部 Unsatisfied 才不成立。
- audit 保存每次语义跃迁的 leaf snapshot、短路 child、reason、source refs 与 evaluator version。
- confirmation 必须连续成立；任一 leaf stale、Unavailable、观察 gap 超限即重置。
- restart 时任何 in-memory continuity 归零；durable state 恢复到 Waiting 后重新确认。

## 4. Admission 与恢复

Ready 不是提交许可。提交 claim 前用最新 PIT inputs 重新执行完整 AST，并重新检查 11.7 admission、
report/model/policy lifecycle、账户与风控。AST/hash/evaluator version 不一致即拒绝。

worker 保存 condition artifact ID/hash、state、last transition、confirmation start 和 last observed refs；
不保存逐 tick trace 到 PostgreSQL。高频 evaluation trace 进入有 retention 的事实存储，语义跃迁进入 WORM audit。

## 5. UI

提供非脚本条件构建器：类型选择→字段→comparison→freshness/confirmation→All/Any 分组；实时显示
自然语言摘要、PIT 数据来源、当前求值树、短路原因和 unavailable blocker。禁止自由文本表达式。

## 6. 测试与上线门禁

- canonical serialization/hash、深度/节点限制、稳定 child order；
- 三态 All/Any 真值表与短路 reason；
- event late arrival/correction、freshness、continuous confirmation、restart reset；
- replay 与 live evaluator parity；
- Ready re-admission/TOCTOU；
- UI builder round-trip、不可构造非法 AST、审计 timeline；
- ReportOnly shadow 至少一个完整观察窗口后，才允许 SemiAuto 条件触发。
