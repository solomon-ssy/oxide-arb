# 11.2.1.1 — Trade-Tape Participant Concentration（实现契约）

> **状态**：On-chain `OrderFilled` 闭环已落地。Polygon CTF/NegRisk Exchange V1+V2 为唯一 trade-tape 真源；
> maker-side participant concentration 写入 ClickHouse → PIT feature window →
> `struct.participant_concentration` neutral structural factor → Structural Alpha API/UI。
>
> **语义边界**：`struct.book_churn_intensity` 保留为 book-derived churn regime 信号；它不是 maker
> concentration。真实 trade-tape 信号命名为 `struct.participant_concentration`。maker/taker 专属指标只有在数据源覆盖可证明时发布。
>
> **外部依据**：近期研究显示 Polymarket off-chain CLOB 不能公开重建地址级 quote lifecycle；方向性微结构应优先依赖
> on-chain `OrderFilled`。本期只做 fill-side participant concentration，不发布未验证的 whale-fade 方向信号。
> 参考：[Fill-Side Non-Retail Trading](https://arxiv.org/abs/2605.11640)、
> [Polymarket-v1 Database](https://arxiv.org/abs/2606.04217)。

## 1. 本期闭环

1. **数据面**：`quant-pivot-api/exchange` 解码 V1/V2 `OrderFilled`；每条 log 主行 `participant_role=Maker`（可选 Secondary `Taker`）。
2. **存储面**：ClickHouse `quant_trade_tape`（`source=on_chain` only）与 Postgres `quant_trade_tape_block_cursor`。
3. **摄入面**：`TradeTapeWorker` 按 block chunk 扫描四合约，`eth_getLogs` → normalize → CH batch → 推进 block cursor。
4. **PIT/feature**：`TradeTapePitParams` + `FeatureWindowProvider` 统一 online/offline 窗口 `[from, to)`；`RuntimeConfig::pit_knowledge_lag_secs()` 取自 enabled schedule 的唯一 `knowledge_lag_secs`。
5. **特征/因子**：`struct.*` trade-tape 特征与 `struct.participant_concentration`（Maker-primary Gini/HHI/CR1 composite）。
6. **观测面**：Structural Alpha API/UI 展示 on-chain source health、PIT 边界、lag、coverage、missing reason、top participants。

## 2. 数据模型

### 2.1 Normalized print

`TradeTapePrint` 字段：

- `market_id`、`token_id`、`event_time`
- `participant_address`、`participant_role`
- `side`、`price`、`size_shares`、`notional_usd`
- `tx_hash`、`trade_id`、`source`、`coverage_flags`

`participant_role` 取值：

- `maker` / `taker`：on-chain `OrderFilled` 证明的 leg 角色
- `unknown`：保留给 enrichment

`source` 仅 `on_chain`。

### 2.2 ClickHouse fact

`quant_trade_tape`：

- `ReplacingMergeTree(ingestion_time)`
- `PARTITION BY toYYYYMM(event_date)`
- `ORDER BY (market_id, token_id, participant_role, event_time, trade_id, participant_address)`
- `participant_role Enum8('Maker'=1,'Taker'=2,'Unknown'=3)`
- `source Enum8('OnChain'=1)`

### 2.3 Block cursor

Postgres `quant_trade_tape_block_cursor`：

- 主键：`(source, contract_address)`
- checkpoint：`last_finalized_block`、`last_log_index`
- health：`head_lag_blocks`、`status`

cursor 只在 ClickHouse 写成功后推进。

## 3. Feature / Factor Contract

Estimand：market-level concentration = notional-weighted Gini/HHI/CR1 over **unique `OrderFilled.maker` wallets**（on-chain primary rows）。

`struct.participant_concentration`：

- `FactorDirection::Neutral`
- raw composite 默认 `0.50*gini + 0.30*cr1_share + 0.20*hhi`

schema bump：

- `RUNTIME_CONFIG_SCHEMA_VERSION = 4`
- `feature_schema_version = 4`

---

## 4. API / UI Contract

- `GET /quant/structural/trade-tape/coverage`
- `GET /quant/structural/participant-concentration`
- `GET /quant/structural/participant-concentration/{market_id}`

DTO numerics unscored 时为 `null`（UI 显示 `—`）；响应含 `pit_as_of` / `pit_cutoff`。

## 5. Deploy config

```toml
[market_data.trade_tape_on_chain]
enabled = true
poll_secs = 30
confirmations = 12
max_blocks_per_tick = 2000
max_blocks_per_request = 2000
batch_size = 1000
```

PIT delay 来自 runtime-config `reports.schedules[].knowledge_lag_secs`（所有 enabled schedule 必须相同）。
