# 11.7 — Labeling, Entry & Exit Closed-Loop

> 关闭审计点:**#14(TP/SL 由模型启发式曲线推导,不用经验 MFE/MAE)**、
> **#15(退出结构最小化:partial_exit_nodes/trailing_stop/signal_invalidation_rules 恒空)**、
> **#16(入场触发只有 LimitPrice/Immediate;无 confirmation_window)**、
> **#18(FOK 来源是配置 `allow_market_orders`,非 recommendation 流动性要求;neg-risk flag)**。

## 1. 目标与闭环定位

用**三重障碍(triple-barrier)标注**统一"训练标签 ↔ live 退出结构",让 composer 真正生成基于经验
MFE/MAE 与波动率的 TP/SL、分批退出、移动止损、失效规则,并让入场触发与订单类型语义精准。它闭合
"买什么/何时买/买多少/何时卖/卖多少"的产物表达力。

设计立场(有文献支撑):

- **三重障碍法**(López de Prado)用"上障碍(止盈)/下障碍(止损)/垂直障碍(最大持有)"标注,barrier
  用近期波动率的倍数设定,比固定 horizon 标签更贴近真实交易机制
  (<https://paperswithbacktest.com/course/triple-barrier-method>;mlfinlab
  <https://random-docs.readthedocs.io/en/latest/implementations/tb_meta_labeling.html>)。
- 同一 barrier 结构**既是训练标签,也是 live 退出规则**——这正是把 11.7 的标注与 05.6 执行退出对齐的关键。
- Polymarket 订单类型:GTC/GTD 是限价挂单,FOK/FAK 是市价(price 字段=滑点保护);多结果市场必须
  `negRisk:true`,否则路由错交易所导致结算失败(<https://docs.polymarket.com/trading/orders/create>、
  <https://polymarkets.co.il/en/bots/polymarket-negrisk-execution/>)。

闭环定位:11.3(校准的收益/下行分布)→ **11.7(barrier 标注 + 退出/入场结构)**→ 11.8(报告生命周期)。
标注同时回流 11.4(meta-labeling label)与 11.5(purge 的 `label_horizon_end`)。

## 3. 契约与算法设计

### 3.1 三重障碍标注(训练侧,统一标签)

```rust
/// Triple-barrier labeling: profit-take (upper), stop-loss (lower), max-hold (vertical).
/// Barriers are volatility-scaled. Also emits meta-labels (was the signal profitable)
/// for 11.4 meta-labeling, and label_horizon_end for 11.5 purge.
pub struct TripleBarrierLabeler {
    pub pt_sigma_mult: Decimal,   // 上障碍 = entry * (1 + k_up * vol)
    pub sl_sigma_mult: Decimal,   // 下障碍 = entry * (1 - k_dn * vol)
    pub max_hold: Duration,       // 垂直障碍
}

pub struct BarrierLabel {
    pub first_touch: BarrierTouch,          // Upper | Lower | Vertical
    pub realized_return_bps: Decimal,
    pub mfe_bps: Decimal,                   // 最大有利偏移
    pub mae_bps: Decimal,                   // 最大不利偏移
    pub label_horizon_end: DateTime<Utc>,   // 首个障碍触达时刻 → 11.5 purge
    pub meta_label: bool,                   // 主信号是否盈利 → 11.4
}
```

barrier 用近窗 realized vol 缩放(与 ATR/Chandelier 思想一致);vol 估计来自 11.1 `realized_vol`。

### 3.2 经验 MFE/MAE 驱动 TP/SL(#14)

composer 的 `exit_plan()` 重构:

```text
TP_price = entry * (1 + tp_from_calibrated_mfe)      # tp 取校准分位的 MFE(11.3 分布 + barrier 统计)
SL_price = entry * (1 - sl_from_calibrated_mae)      # sl 取校准分位的 MAE
max_hold = barrier vertical(按 category / horizon)
```

- TP/SL 不再来自"model heuristic 曲线 + 固定 reward multiple",而是**经验 MFE/MAE 分位 + 波动率**;
  `hold_to_resolution` 市场仍可去掉 TP、保留 SL(既有语义保留)。
- 一致性:同一 barrier 定义既产训练标签(§3.1)也产 live 退出(此处),消除"训练与执行两套阈值"。

### 3.3 富退出结构(#15,消除死语义)

composer 生成:

- `partial_exit_nodes`:按 MFE 分位分批止盈(如触及 MFE 50%/75% 各减仓 x%),幂等累计 scale-out
  与 05.6/06.1 已落地的执行侧对齐。
- `trailing_stop`:vol-scaled 移动止损(Chandelier 式:峰值 − k·ATR),仅当 barrier 允许。
- `signal_invalidation_rules`:thesis 失效条件(分数退化阈值 / 关键因子翻转),交给 06.0
  `ExitSignalReinferer` 消费(执行侧已落地)。

### 3.4 富入场触发(#16,消除死语义)

`EntryPlan` 真正 emit(按 recommendation 语义选择):

| 触发 | 何时用 |
|---|---|
| `LimitPrice` | 默认被动挂单 |
| `Immediate` | 高紧迫 + 允许市价 |
| `Pullback` | 等回调到目标价再入(mean-reversion 类) |
| `Breakout` | 突破确认后入(momentum 类) |
| `TimeWindow` | 仅在指定时窗内有效 |
| `DataEvent` | 等待数据/事件确认(如 resolution proximity) |

新增字段 `confirmation_window_secs`:触发后需持续满足条件 N 秒才下单(抗假突破)。

### 3.5 订单类型由 recommendation 决定(#18)+ neg-risk 硬化

```rust
/// Order type is derived from the recommendation's liquidity requirement and entry
/// plan urgency — NOT a global `allow_market_orders` flag. neg_risk always sourced
/// from the registry (Gamma), never guessed.
pub fn derive_order_spec(rec: &Recommendation, market: &MarketRegistryView) -> VenueOrderSpec {
    let order_type = match (rec.entry_plan.trigger_kind, rec.liquidity_requirement) {
        (Immediate, AllOrNothing) => OrderType::Fok,     // 全成或撤
        (Immediate, PartialOk)    => OrderType::Fak,      // 成可成、撤余
        (LimitPrice, _)           => OrderType::Gtd { expiration: rec.entry_plan.valid_until },
        _                          => OrderType::Gtc,
    };
    VenueOrderSpec { order_type, neg_risk: market.neg_risk, price_is_slippage_cap: order_type.is_market() }
}
```

- FOK/FAK 的 `price` 字段语义 = 滑点上限(Polymarket 市价语义);限价单 price = 挂单价。
- `neg_risk` 强制来自 registry;binary→false、multi→true;错配即拒绝(避免结算失败)。
- 引入 `liquidity_requirement`(recommendation 级:AllOrNothing / PartialOk),取代全局 flag。

## 6. 生产不变量与失败语义

- **标注=退出同定义**:训练 barrier 与 live 退出 barrier 用同一 `TripleBarrierLabeler` 参数源
  (config),禁止两套阈值(与 11.6 一致性精神一致)。
- **无死语义**:partial/trailing/invalidation/entry-trigger 全部有生产 emit 点(否则 11.0 CI red)。
- **neg-risk 正确**:订单必带 registry `neg_risk`;错配拒绝下单(fail-closed,防结算失败)。
- **订单类型语义精准**:FOK/FAK price=滑点上限;限价 price=挂单价;由 recommendation 决定不由全局 flag。
- PIT:barrier 前视路径只用成熟事实(与 11.5 purge/maturity 一致)。
