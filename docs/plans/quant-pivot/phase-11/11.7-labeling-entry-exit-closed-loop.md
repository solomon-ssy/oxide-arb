## 1. 唯一业务闭环

```text
可执行 L2 轨迹
  → TradePolicyArtifact（content-addressed、治理）
  → policy path simulation / policy_net_return_bps / policy_net_positive
  → 独立 PolicyEvaluationArtifact 绑定 policy ID/hash
  → Recommendation 冻结 entry/exit policy 与 cohort provenance
  → SemiAuto 审批即 Arm / AutoExecution policy approval 即 Arm
  → Recommendation-owned durable condition worker
  → Qualified 时原子 claim + 重新 admission
  → 真实成交、ScaleOut/FullExit
  → final Attribution
```

任何环节缺失 policy、hash 不一致、cohort coverage 不足、L2/费用证据不足、tick 不一致或
时间窗口不合法，都只能产 `ReportOnly` 可读结果或不可执行 recommendation，不得回退到启发式
TP/SL、configured budget、mid-price P&L 或 live runtime 策略阈值。

## 2. 固定决策

1. 交易策略参数唯一来源是 `TradePolicyArtifact` 及其不可变 `ResearchProfileArtifact`。runtime config
   v15 仅保存 worker cadence、
   staleness、资源和风险安全上限，不覆盖 entry/barrier/scale-out/trailing/invalidation。
2. `SemiAuto` approval 是未来自动提交的授权动作。成功后 intent 自动 Arm；删除
   `POST /quant/intents/{id}/submit`、Submit 权限和 UI CTA。真实提交 claim 前始终允许 Cancel。
3. `EntryPlan.condition` 只允许 `Immediate` 或 content-addressed `EntryConditionArtifactV1`；
   `Price/Clock/Factor/MarketEvent/All/Any` AST、Recommendation-owned instance、Crypto/Weather
   source binding 由 [11.7.1](11.7.1-composable-entry-event-triggers.md) 承接。
4. policy-derived 标签由一次完整路径模拟原子生成；`return_to_horizon`、raw MFE/MAE、
   liquidity-exit 和 settlement 标签继续保留，且不得被 policy barrier censor。
5. Polymarket 映射固定为：aggressive all-or-nothing→FOK；aggressive partial-ok→FAK；
   passive→post-only GTD。FOK/FAK BUY amount 是 USD，SELL 是 shares；market order price 是
   worst-price cap。GTD wire expiration=`effective_expiry + 60s`，且 effective lifetime 至少 120s。
   Rust SDK 自动获取 tick size 与 NegRisk；领域订单不保存手工 `neg_risk`。
6. Prediction-market barrier 不直接套 ATR/GBM。cohort 至少按 profile、category、horizon、entry-price、
   `cash_budget_tier`、liquidity、volatility regime 分层，并显式处理 `[0,1]` 边界与 resolution deadline。

官方订单语义依据：[Create Order](https://docs.polymarket.com/trading/orders/create)、
[Orders Overview](https://docs.polymarket.com/trading/orders/overview)。结构化波动依据：
[Volatility in Prediction Markets: A Structural Approach](https://arxiv.org/abs/2607.08199)。

## 3. TradePolicyArtifact

### 3.1 生命周期与不可变边界

```text
Draft → Validated → Published → Retired
```

- payload canonical hash 决定 `TradePolicyArtifactId`；数据库同时校验 ID、hash、payload。
- 状态变更与 `TradePolicyGovernanceAudit` 在同一 PostgreSQL transaction 内提交；audit 是 WORM。
- 只有 `Published && publication_blockers().is_empty()` 可被 dataset、model 和 composer 消费；
  Validate/Publish 都从 immutable payload 与 frozen quality gate 重新推导，不信任自报状态。
- `Retired` 禁止生成新 recommendation；已成交 position 继续消费 intent 冻结的 exit policy。
- 不修改已发布 payload，不提供旧版本 loader、alias、compatibility re-export、JSONB 双读或迁移 shim。

### 3.2 payload v6

必须固化：

- source dataset ID/hash、runtime config ID、fit window、PIT cutoff、embargo；
- profile/category/horizon/entry-price/cash-budget/liquidity/volatility cohort key；
- selected entry condition template/order、candidate-set hash、完整 trial ledger、upper/lower/vertical barrier、
  最多三档累计 scale-out、trailing、thesis invalidation；
- candidate/executable sample count、coverage、缺失原因、父 cohort shrink provenance；
- fee model hash、fill simulator version 和 L2 fidelity；
- frozen `TradePolicyQualityGate`：cohort/effective sample、executable/full-L2 coverage、CPCV path、
  DSR、PBO、ambiguous-touch、depth-failure 和 utility lower-bound 阈值；
- PIT cutoff evidence、trial ledger hash、CPCV path count、DSR、PBO、ambiguity/depth failure 等
  验证证据。未知证据使用 `None`，不得使用零值、假 hash、`passed: bool` 或自由文本 publication decision。

### 3.3 拟合与发布门禁

- entry basis：在最大总现金预算内求解 `gross + fee <= cash_budget`，逐档 walk ask ladder；
- exit basis：目标 shares 逐档 walk bid ladder 的 VWAP，减 venue fee。
- 不存在 top-of-book/microstructure execution fallback；缺完整 L2 直接 unavailable。
- 同 cohort 候选策略在 fit fold 内选择；validation/calibration/evaluation 数据不得反向参与选择。
- sparse cohort 只允许确定性的 parent shrink；可信效用下界 `<= 0` 或 coverage 不足即不可执行。
- 当前实现若无法形成真实 CPCV/DSR/PBO 或完整 L2 证据，只能保存 Draft，publish fail closed。
- `Validate` 与 `Publish` 每次都调用 immutable payload 的 `publication_blockers()`；blocker 是稳定 enum，
  至少区分 format/fit contract、PIT cutoff、full-L2 entry/exit/coverage、fee、trial ledger、CPCV、DSR、
  PBO、ambiguity/depth failure、cohort samples/coverage/utility 和 parent provenance。
- 当前生产 fitter 在 full-L2、PIT fee、latency profile 任一不完整时拒绝 enqueue，且不创建空 Draft；
  只有 11.7.2 的真实 full-L2 fitter 与 row-level evidence bundle 可以解除这些 blocker。

## 4. 标签与时间隔离

新增：

- `policy_net_return_bps`；
- `policy_net_positive = 1` 当冻结策略完整净可执行路径收益 `> 0`，否则 `0`；
- `policy_entry_fill_ratio` / `policy_exit_fill_ratio`。当前没有 AFML
  primary/secondary model，禁止用误导性的 `meta_label` 名称或预埋接口。

`matured_at` 是首个可证明 barrier touch 或 vertical deadline。同一采样桶同时穿越上下障碍且
无法确定先后时，返回 `AmbiguousBarrierTouch`，不得猜顺序。vertical 使用 executable best-bid
close；entry 使用 executable ask basis。raw MFE/MAE 仍扫描完整 horizon。

`TradePolicyFitContract.pit_cutoff` 必填，且 `fit_window_start < fit_window_end <= pit_cutoff`。fitter
读取边界只接受 `matured_at <= pit_cutoff` 的标签，以及 `observed_at <= pit_cutoff` 的市场、fee、
resolution 与 metadata 证据；artifact 固化过滤后的样本数/hash 和被 cutoff 排除的数量。dataset 可以
物理包含 cutoff 后的数据，但不得被 fitter 消费。fit preflight 返回 cutoff 合法性、cutoff 前成熟标签数
和 typed blockers。

时间顺序是硬门禁：

```text
policy fit → embargo → model training → embargo → calibration → final evaluation
```

model training 起点必须满足 `training_start >= pit_cutoff + policy_embargo`，不得以
`fit_window_end + embargo` 代替。decision 落在 fit window、但 label 在 cutoff 后才成熟的 observation
必须被排除。

`ModelTrainingContract` 使用封闭 `ModelTrainingTarget`，不存在 executable policy-derived Buy target：
`OutcomePayout`、research-only `ForwardReturn` 与 sell-side `HoldVsExitAlpha` 是全部合法任务。可选
`evaluation_trade_policy_artifact_id` 只冻结独立 OOS executable evaluation 与 Route readiness binding，绝不生成、
筛选或改写监督标签。Buy Dataset 必须覆盖完整 pre-decision score population 的 canonical payout truth；
`policy_net_return_bps` 等 policy label 只能进入独立 Trade/Execution Policy research evidence。

项目尚未生产运行，因此当前 Dataset、Model、Policy 与 Evidence schema 直接以 fresh-boot 唯一结构落地；不读取、
迁移、归档或保留任何旧 artifact format、兼容 parser 或双写路径。

## 5. Recommendation 契约

recommendation 只持久化一个非空 `trade_plan JSONB`；旧 `entry_plan/sizing_plan/exit_plan/risk_envelope`
四列和 API 字段已删除：

```rust
enum RecommendationTradePlan {
    Unavailable { blockers: Vec<TradePlanBlocker> },
    Frozen {
        policy: TradePolicyCohortProvenance,
        entry: EntryPlan,
        sizing: SizingPlan,
        exit: ExitPlan,
        risk_envelope: RiskEnvelope,
    },
}
```

`Frozen.policy` 是唯一 artifact/cohort provenance；`EntryPlan/ExitPlan` 不再自带可选 policy。缺少模型
policy binding、artifact 不存在/未发布/format/hash 不一致、cohort/tier/coverage/depth/tick 不匹配、
价格越界或 return model 未校准时，只能生成带 `TradePlanBlocker` 的 `Unavailable`。禁止零金额、
Immediate/passive、TP/SL 或 sizing fallback；`OrderIntent` 只能从 `Frozen` 创建，并在服务端重新验证
Published 状态、hash、cohort 和实时 L2 admission。

`ReportSummary`、report diff 与 ClickHouse recommendation fact 只聚合 Frozen sizing；
`suggested_usd` 对 Unavailable 是 `NULL`，`trade_plan_available=false`。没有 calibrated return model
时记录 `RejectionReason::ReturnModelUncalibrated`；空报告使用
`EmptyReportReason::ReturnModelUncalibrated`。ReportOnly 可以展示真实 Frozen 计划或 Unavailable 原因，
但 Unavailable 永远不能创建 intent。

```rust
enum EntryConditionPlan {
    Immediate,
    Conditional {
        artifact_id: EntryConditionArtifactId,
        content_hash: ContentHash,
    },
}

enum EntryOrderPolicy {
    Passive { limit_price: Price, post_only: bool },
    Aggressive { worst_price: Price, fill_requirement: FillRequirement },
}
```

删除 `LimitPrice/Pullback/Breakout/TimeWindow/DataEvent` 混合 enum。breakout/pullback 是 comparison
方向；时间是有效窗口；订单策略与触发条件正交。

`ExitPlan/ExitPolicySpec` 冻结：

- `ScaleOutTarget { target_id, trigger_price, target_cumulative_exit_pct, min_price, validity }`；
- `TrailingStopPolicy`；
- `ThesisInvalidationPolicy { min_score_retention, min_expected_return_bps,
  require_execution_eligibility }`；
- policy ID/hash 与 cohort provenance。

删除 `PartialExitNode`、`SignalInvalidationRule`、重复 `ExitTriggerKind`。退出归因统一使用
`ExitReason`。composer 必须从 ModelVersion header 解析 Published artifact，并以当前 L2 fill
simulation、cash budget、liquidity、price/tick cohort 选择结果生成计划；失败时 recommendation 不可执行。

## 6. Arm、触发与 admission

`EntryConditionState`：`NotRequired / Waiting / Unavailable / Confirming / Qualified / Consumed /
Expired / Invalidated`。状态属于 Recommendation，不属于 intent。

- `SemiAuto Approved` 与 `AutoExecution ApprovedByPolicy` 自动进入 dispatcher。
- 条件连续成立满 confirmation window 才 Qualified；leaf stale、gap、correction、recross 或条件失效
  立即 Waiting/Unavailable。
- 只持久化状态跃迁，不逐 tick 写 PostgreSQL。
- restart 时 `Confirming → Waiting`，不得补猜停机期间的连续成立。
- Qualified 原子 claim 后重新验证价格、L2 depth、policy/hash、report 状态、runtime mode、账户、资本、风控、
  tick/NegRisk metadata；任一变化都 fail closed，关闭 TOCTOU。
- FOK/FAK 一次提交后不自动 retry；ambiguous response 进入 reconciliation，而不是重复下单。

到期是一个真实原子事务：`PendingApproval/Approved/ApprovedByPolicy`（包括 Waiting、Unavailable、
Confirming 与 Qualified-but-not-claimed）同时转成 intent `Expired`、condition `Expired`，释放
capital reservation，并写一条 WORM operation audit。真实 submission claim
已获胜后由 submission/reconciliation FSM 接管，expiry 不得回收。expiry、Cancel 与 Qualified claim 使用
row lock/条件更新竞争唯一终态；重复扫描不重复释放资本或重复写 audit。

## 7. 订单与 ScaleOut 真相

`OrderAmount` 是 tagged union：aggressive BUY 冻结 `Usd`，resting/SELL 冻结 `Shares`。资本锁定、
venue request、fill reconciliation 和 attribution 必须消费同一 amount 真相。

approval wire 只有 `reason + override_amount: Option<OrderAmount> + override_price: Option<Price>`：

- override tag 必须与 frozen amount 相同，只能缩小且必须大于零；
- BUY 价格只能下降、SELL 价格只能上升；USD price-only override 不改变冻结 spend，Shares 则用最终
  `shares × price` 重算 allocation；
- approval、最终 entry spec 与 capital reservation 在同一事务内提交；并发审批只能一个获胜；
- UI 按 amount tag 只显示一个单位输入，并要求操作员勾选“审批后自动监听并在条件满足时提交”。

所有资金变更订单 FOK/FAK/GTD/GTC 都是一次 build、sign、`POST /order`；不存在 order retry config、
setter 或按 order type 的 retry。`Prepare/Sign` 错误证明未发送；进入传输阶段的 timeout、连接中断或
无法证明结果的 5xx 是 `Post/Ambiguous`，明确 4xx 是 `Rejected`。Ambiguous 只通过 venue
order/fill/account reconciliation 收敛，绝不再次 POST。读取 API 和幂等 cancel 使用各自独立策略。
日志与 audit 只记录无敏感信息的 fingerprint、intent、submission stage 和 reconciliation 状态。

GTD 保存 effective expiry 与 wire expiry 两个真相；有效期至少剩余 120 秒，wire 额外加官方 60 秒。
窗口不足即 fail closed。SDK 自动处理 NegRisk/tick metadata；冻结 registry 与 venue metadata 不一致
即拒绝，领域请求不保存手工 `neg_risk`。

`ScaleOutState` 合并 deterministic 与 opportunistic 状态：

- denominator 是固定 entry-filled shares；
- 保存 cumulative exited shares、settled target IDs、pending target；
- 每次 order delta=`target cumulative shares - cumulative exited shares`；
- partial fill/restart/reconciliation 后仍单调、幂等，不再对 remaining shares 重复乘比例。

## 8. API 与 UI

Trade Policy API：list/detail、fit preflight、async fit run、validate/publish/retire；所有治理写要求
actor、reason、quality gate 与 WORM audit。Research 提供 policy 列表/详情，Model detail 展示 policy
binding、window/cohort/coverage/cost/barrier/CPCV/DSR/PBO/hash/status/references。

policy detail 返回服务端推导的 authoritative publication blockers 与 allowed actions；
`GET /research/trade-policies/{id}/audits` 按 `(created_at DESC, audit_id DESC)` 稳定分页返回 actor、reason、
from/to state、artifact ID/hash、时间与 audit ID。UI 用 Descriptions 展示 artifact、Timeline 展示真实
governance audit，cohort 不冒充时间线。

Recommendation detail 首屏回答“买什么、何时触发、下多少、最差成交价、如何退出”。Intent detail
展示 Waiting/Unavailable/Confirming/Qualified/Consumed、canonical tree、node evidence、连续确认、
有效期和 blocker，并明确
“审批后将自动提交”；不显示 Submit CTA。Open position/intent 展示 peak mark、effective trailing
stop、下一 target、累计退出、最新 reinference 与下次检查。

exit monitor 在受治理 cadence 保存 nullable `latest_reinference_json`，而非逐 tick 写库。monitor 与 API
projection 共用纯领域函数计算 effective trailing stop、下一累计 scale-out target、delta shares 与累计
退出比例；UI 不自行重算。intent detail 返回强类型 `exit_monitor_observation`，position detail 返回
`position + exit_monitor_observation`，list 仍保持轻量。

触及的详情页只使用项目 VXE adapter、Descriptions、Timeline 等设计系统。测试专用 Actix binary
复用真实 production routes、独立 PostgreSQL seed、BookStore driver、真实登录与 RBAC；状态控制 endpoint
只注册在测试 binary。Playwright 已覆盖 policy blocker/audit、Unavailable/Frozen、approval-as-arm、
Waiting→Confirming→Qualified、stale reset、Cancel-before-claim、model binding、position exit monitor，以及
桌面与窄屏当前 golden 比较。改造前历史截图在本次工作树中不存在，因此不能伪造旧 UI 的 before
evidence；该 provenance 缺口在状态表单独记录。
