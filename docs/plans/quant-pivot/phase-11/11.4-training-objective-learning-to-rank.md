## 1. 目标与闭环定位

把训练目标从"rank IC + L2 的坐标搜索"升级为**与业务目标对齐的 learning-to-rank + 风险惩罚**目标函数,
让"训练时优化的东西"= "上线要赚的东西"。它是离线闭环 `TrainingDataset → Trainer → Backtest →
QualityGate` 的 Trainer 层重构,并为 11.3 校准提供分数、为 11.5 验证提供候选。

设计立场(有文献支撑):

- 横截面策略的成败取决于**排序质量**;用回归/分类点损失 then-rank 是次优的,LTR(pairwise/listwise)
  显著提升排序与 Sharpe(Poh et al. 2020,cross-sectional momentum 上 Sharpe ~3×
  <https://arxiv.org/pdf/2012.07149v1>)。
- 若目标就是 Rank IC,应**直接优化 Rank IC 的 LTR 目标**,而非用 NDCG 代理或 rank-then-sort;
  LambdaRankIC 给出 ΔRankIC 的闭式 lambda 梯度(<https://arxiv.org/html/2605.00501>)。
- 目标函数应内置**下行(tail/CVaR)与换手惩罚**,而不是训练后才在回测里度量。
- 引入**meta-labeling**:主模型定方向/排序,二级模型定"是否下注 + 置信/仓位",提升精度与风险控制
  (López de Prado;<https://paperswithbacktest.com/course/meta-labeling>)。

闭环定位:11.1/11.6(因子 + 一致性)→ **11.4(目标)**→ 11.5(验证)→ 11.3(校准)。

## 3. 契约与算法设计

### 3.1 目标函数(与业务对齐)

```text
minimize  L(w) = L_rank(w)                      # 排序损失(LTR)
                 + λ_tail · TailPenalty(w)       # 下行:组合级 CVaR / max drawdown proxy
                 + λ_turnover · Turnover(w)       # 换手:与上期权重/持仓差异
                 + λ_l2 · ‖w‖²                    # 复杂度
```

- `L_rank`:三选一(config 驱动):
  - `pairwise`(RankNet 逻辑损失,LambdaMART 基础);
  - `lambda_rank_ic`(直接优化 Rank IC 的 lambda 梯度,LambdaRankIC 论文);
  - `listwise`(如 ListNet/近似 NDCG)。
- `TailPenalty`:用组合模拟的 CVaR_α(与 11.5 回测同定义,同代码路径)。
- `Turnover`:相邻 report tick 的分配 L1 距离(把交易成本内生化)。

### 3.2 目标契约

```rust
/// A composable training objective aligned with production economics.
pub struct TrainingObjective {
    pub rank_loss: RankLossKind,          // Pairwise | LambdaRankIc | Listwise
    pub lambda_tail: Decimal,             // CVaR / drawdown penalty weight
    pub cvar_alpha: Decimal,              // e.g. 0.95
    pub lambda_turnover: Decimal,
    pub lambda_l2: Decimal,
}

/// Trainers optimize the SAME objective; weighted (argmin/coordinate) and
/// classical GBDT (LambdaMART-style) are two implementations behind one trait.
pub trait ModelTrainer {
    fn model_family(&self) -> ModelFamily;      // WeightedFactor | GbdtRanker | ...
    async fn train(&self, req: TrainModelRequest) -> QuantResult<TrainedModelArtifact>;
}
```

### 3.3 模型族

- **WeightedFactorTrainer(主路径,可解释)**:线性因子权重,用 `argmin`(`optimize`)最小化 §3.1 目标;
  坐标搜索作 deterministic fallback。输出仍可直接给出 recommendation-level 因子贡献。
- **GbdtRankerTrainer(shadow 候选,非线性)**:LambdaMART 风格(pairwise + metric-aware 梯度)。
  用 `smartcore`(`ml-classical`)tree ensemble;若 smartcore 的 LTR 支持不足,则自研 lambda 梯度 +
  tree ensemble(参考 XGBoost LTR 语义:按 report tick 分 query group,qid=as_of)。**必须能出
  feature importance / SHAP(11.10)**,否则只能 shadow。

### 3.4 Meta-labeling(仓位/取舍二级模型)

- **主模型**:§3.3 产出方向 + 排序分。
- **二级 meta-model**:用**三重障碍标注**(11.7)的 meta-label(主信号是否盈利,0/1)训练一个
  gatekeeper,输出 `take_probability ∈ [0,1]`;它经 11.3 校准后**作为 Kelly 的 confidence/参与概率**。
- 好处:方向与"是否下注/多大"解耦,提升精度与风险控制(López de Prado meta-labeling)。

## 6. 生产不变量与失败语义

- **训练=回测同定义**:`TailPenalty`/`Turnover` 用与 `backtest/metrics.rs` **同一实现**(11.6 一致性),
  禁止两份公式。
- **可解释门禁**:任何进入 auto/semi 的模型必须能出 recommendation-level 贡献(11.10);GbdtRanker
  无法解释则只能 shadow(与 08 §15.5 一致)。
- **确定性**:同 dataset + 同 objective + 同 seed → 同 artifact hash(deterministic)。
- **f64 边界**:优化器/GBDT 用 f64,权重/分数量化回 Decimal 再进业务。
- **query group 正确**:LTR 按 report tick(as_of)分组,禁止跨 as_of 混排(否则泄漏未来截面)。

## 7. 第三方 crate 引入

- `argmin` + `argmin-math`(`optimize`,11.0 起必链接)。
- `smartcore`(`ml-classical`)tree ensemble 作 GBDT 候选;LTR lambda 梯度若 smartcore 不支持则自研
  薄层(纯 Rust)。
- 不引入 `ort`/`burn`/`candle`(仍延后)。

## 8. 验收测试

- `objective_includes_tail_and_turnover_penalties`(#6 核心:断言目标函数含这两项且改变最优解)。
- `lambda_rank_ic_gradient_matches_delta_rank_ic`(闭式梯度单测)。
- `ltr_beats_regression_then_rank_on_synthetic_cross_section`(排序质量对比)。
- `meta_labeler_gate_improves_precision`。
- `training_and_backtest_use_same_tail_penalty_impl`(11.6 联合)。
- `weighted_trainer_deterministic_hash`。
- `gbdt_ranker_without_explanation_cannot_auto_execute`。

## 9. Blocker

- 目标函数仍不含下行/换手惩罚。
- `optimize` 未必链接(11.0 未硬化)。
- LTR 跨 as_of 混排(泄漏)。
