## 2. Canonical truth 与 outcome

### 2.1 ResolutionObservationInbox

- PostgreSQL `quant_resolution_observation_inbox` 是 source observation 的 WORM inbox。
- 同一事务写入完整 source page、raw hash/URI、provider revision、cursor advance 和 projection
  outbox；ClickHouse 只保存 canonical projection，不是第二 truth。
- 未知 market 进入 typed `PendingMapping` / `Quarantined`，保留 observation 并持续重试；linkage 完成
  后 exactly-once 投影。禁止跳过 observation 后推进 cursor。
- revision、crash point、ClickHouse outage 和 mapping replay 必须保持 observation 零丢失、
  canonical fact 零重复。

### 2.2 ExecutionAttemptOutcome 与 RecommendationExecutionRollup

- `ExecutionAttemptOutcome` 以 `order_intent_id` 为唯一身份，封存该 intent 的 immutable terminal
  order/position/economics graph。
- `RecommendationExecutionRollup` 只有在 recommendation 不能再创建新 intent，且全部
  intent/order/position terminal 后才能封存。
- rollup 按确定顺序绑定全部 attempt hash 与聚合经济指标；feedback execution cohort 只消费最终
  rollup，不消费“首个成功 attempt”。
- reconciliation due/retry/lease 均在 PostgreSQL。单实例进程重启、永久 deferred 首项和 ClickHouse
  暂时失败不能饿死后续任务；`FOR UPDATE SKIP LOCKED` 用于数据库队列安全，不代表部署多副本。

### 2.3 TruthFreeze

每个 cycle 在进入 coverage 前必须封存 resolution inbox、attempt projector 和 recommendation rollup
三类 watermark。任何影响 cohort 的 quarantine、unresolved mapping、projection lag 或 rollup lag
都产生 typed blocker；未知值不能显示或参与计算为 0。

## 3. Auto-Retraining 与统计治理

唯一 DAG：

```text
Trigger → TruthFreeze → Coverage → Attribution → Drift → RecipePlan → DatasetSeal
        → Training → Calibration → CPCV → Validation → Comparison → ShadowBind → Shadow → Decision
```

- scheduler state 由 PostgreSQL clock 和
  `next_due_at / pending_cutoff / last_cycle_id / cooldown_until / lease / settlement /
  attempt / retry_at / pause_revision` 决定。pending identity 在成功 settlement 前保持不变；AWS
  单实例只运行一个 resident scheduler。
- scheduler 固定使用 `Conditional`。Scheduled 与人工 Conditional 在相同
  `profile + cadence_cutoff` 下收敛到同一 cycle；触发来源写 append-only provenance。
- `ForcedRetraining` 只能从已终止的 Conditional `NoAction` cycle 派生显式 child attempt；它只绕过
  “阈值未触发训练”，不能绕过 truth、coverage、cooldown、dataset、CPCV、validation、shadow
  slot 或 promotion CAS。pause 只暂停计划评估。
- Attribution 产出本周期诊断证据；RecipePlan 只能读取 `available_at <= cutoff`、同
  profile/route/model-family 且 `origin_cycle_id != current_cycle_id` 的历史证据。Recipe template
  是受审批、版本化、不可变 catalog；缺少可用 challenger 返回 typed readiness blocker。
- `policy.max_challengers` 必填，首版所有 profile 固定为 1。planner 按 trigger match、历史 OOS
  uplift 下界、catalog priority、recipe ID 稳定排序；champion 仅作 control baseline，不重复训练。
- `Validation` 只调用唯一 `ModelQualityGate`。完整 trial universe 进入 CPCV、DSR、PBO 和
  multiple-testing accounting；未通过者不得进入 Comparison、Shadow 或 CandidateReady。
- quality report 覆盖 No-PIT、coverage、rank IC、DSR、PBO、turnover/tail loss、calibration、
  feature parity 与 explainability。
- scheduler 和 manual trigger 都不会签发 permit 或改变 serving route。

## 4. Attribution 的不可混淆语义

| Artifact | 解释对象 | 禁止宣称 |
|---|---|---|
| `PredictionExplanationArtifact` | 模型分数；weighted 使用精确闭式分解，logistic 使用冻结标准化输入与系数贡献 | 现实因果效应、PnL 因果贡献 |
| `DecisionInterventionReplayArtifact` | 在真实有向计算图 `feature → transform → model output → calibration/composite → rank → TopN → decision` 上执行 feature-specific、domain-admissible、in-support intervention | causal effect、OOD/不可执行 side flip 的有效反事实 |
| `ResolutionOutcomeAssociationArtifact` | explanation 与 canonical resolution truth 的带不确定性条件关联 | 未满足识别假设时的 causal attribution |
| `ExecutionOutcomeAssociationArtifact` | recommendation、attempt、partial fill、fee 与排序 terminal-rollup set 的可审计关联 | 空 rollup set 或缺失 execution truth 下的有效关联 |
| `ExecutionTrajectoryArtifact` | size-specific executable L2 depth、剩余 shares、fee schedule、滑点与 PIT path | canonical execution truth |
| `PolicyCounterfactualOutcome` | `LatestExecutableAtOrBeforeHorizon` / `FirstBarrier` 等已批准 alternative policy 的同口径净收益 | 缺 baseline/depth/fee 时以 0 代替或宣称 realized return |

所有 artifact 都是 content-addressed、immutable、PIT-bound。cycle N 的 recipe planner 只能消费
`available_at <= cutoff` 且来自先前 cycle/training cohort 的 artifact；N 的 evaluation/shadow
产物最早供 N+1 使用。

weighted 与 payout `LogisticRegression` research/shadow materializer 接通；后者在没有 calibrated payout
distribution 时不得 active serving。所有 forward-return regression、GBDT、RF/ExtraTrees 与 TreeSHAP
路径均已删除。core 只从已验证的 production model-input events 按冻结列序重建输入，并重新校验
run/version/family、input contract、transform、training-input hashes 与 feature support。缺少任一
preimage、completion、列、support 或 identity commitment 都 fail closed。Attribution/replay 只能
经必填 page size、并发、working-set bytes 与 deadline 的 `ComputeExecutor` 执行。

## 6. 唯一 serving authority

- 删除全局 `active_model_version_id`、`category_model_pointers`、
  `shadow_model_version_id` 与可变 publication lifecycle；每条 Buy route 只拥有
  `champion + optional shadow`，binding 封存 source cycle、bound time、config revision 与 generation。
- `ModelCandidateManifest` 一次绑定 model bytes、dataset、feature/input transform、calibration、
  CPCV path set、explanation validation 和 `PromotionGateArtifact`；封存后不可 rebind。
- `PromotionGateArtifact` 绑定 TruthFreeze、Attribution、RecipePlan、Validation、Comparison、
  ShadowBind、Shadow、
  feature parity、policy/profile hashes 与最终 aggregate hash。
- bootstrap、feedback promotion 与 config rollback 都由唯一 route owner 管理；旧模型
  publish/bind mutation 和 runner best-effort Shadow mutation 已删除。

闭环 API：

```text
POST /research/model-route-activation-permits
POST /research/model-route-activation-permits/{permit_id}/revoke
POST /research/model-route-activations
GET  /research/model-route-activations/{activation_id}
POST /research/model-route-shadow-bindings/{binding_id}/reject
POST /research/resolution-projections/{observation_id}/remediations
```

permit request 只接收 `feedback_cycle_id`、`ttl_secs`、`idempotency_key`、`reason_code`、`note`。
TTL 默认 30 分钟，范围 5–60 分钟，按 PostgreSQL clock。candidate、route、serving identity、base revision 与
gate hash 全由服务端推导。

activation request 只携带 permit、cycle、expected revisions、idempotency、reason code 和 note。
事务重新校验 stale/expired/revoked permit、aggregate hash、route/runtime revision，以及 execution/
capital authority 不变量；成功 receipt 包含 before/after generation、activation/audit/outbox IDs、
transaction hash、server timestamp 和 actor lineage。允许同一 actor 完成两步，但两步分别审计。
`publication:authorize` 与 `publication:activate` 是不同权限和高风险确认；同一 principal 可以同时
拥有两者。

`ShadowBind` 是 coordinator 内部阶段：按 champion/policy/candidate/route generation 原子 CAS
写 config、receipt、audit 与 outbox，并等待 runtime convergence。观察窗口从 `bound_at` 开始；
每 route 最多一个 shadow，不同 route 可并行但受总模型内存预算约束。CandidateReady 持槽直至
activate/reject/cancel/受控 rollback；promotion 只交换目标 route，rollback target 恢复旧 champion
且 shadow 为空。

已删除且不得恢复：

```text
POST /research/models/{id}/publish
POST /research/models/{id}/bind-calibration
POST /research/models/{id}/bind-publish-path-set
```

rollback 继续复用 config revision rollback，不新增第二套 rollback API。

## 8. 单实例生产运维边界

1. systemd/ECS service desired count 固定为 1；不实现 leader election 或多副本 scheduler。
2. PostgreSQL lease 仍必须存在，用于进程崩溃、systemd restart、stale work recovery 和同进程任务
   CAS，不能退回 process-local cursor。
3. source inbox/outbox、feedback scheduler、research jobs、permit 和 route transaction 都在数据库
   commit 后才对运行时可见。
4. runtime apply 失败时 durable route 仍是 authority；同一实例重启后从 committed generation 收敛。
5. source inbox age、quarantine、projector lag、rollup lag、scheduler overdue、stage latency、
   attribution efficiency failure、quality-gate reason、permit expiry、promotion conflict 与 WS
   recovery 必须有 metrics/alerts。

## 9. Closure 与 Activation 分离

`Implementation Closure` 只证明软件合同和 fresh production-like stacks。它不证明当前真实数据、
credentials、资金或模型足以激活某条 route。

单 route 的 `Operational Activation` 还要求：

1. authenticated current source/outcome reads；
2. profile/family mature-label 门槛；
3. 当前数据重新生成的 TruthFreeze、AttributionManifest、Validation、Comparison、Shadow 与 gate；
4. 至少一个完整 `retraining_cooldown` 的真实 non-executing shadow；
5. operator 先签 permit，再执行 activation；
6. activation 后验证 receipt、route generation 与现有 config rollback。

证据不足的 Weather family 保持 typed `InsufficientEvidence`。
