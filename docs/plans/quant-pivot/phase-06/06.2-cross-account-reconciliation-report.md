# 06.2 — Cross-Account Reconciliation Report

> 父：[`README.md`](README.md) · 前置：[`../phase-05/05.5-reconciliation.md`](../phase-05/05.5-reconciliation.md) §11
> · 账户平面：[`../09-account-capital-position-reconciliation.md`](../09-account-capital-position-reconciliation.md)

## 1. 目标与闭环定位

05.5 已实现**逐订单**对账（`Submitted`/`Ambiguous`/`Open` 订单 → venue truth 校正）。
本子phase扩展为**跨账户、周期性** reconciliation report：聚合 PG ledger + venue 快照，产出
operator 可读的差异报告与可选 auto-resolve 建议（不替代 05.5 逐单 fail-closed 引擎）。

**不在本子phase：** 替换 05.5 单订单证据链；改变 per-lot position 语义。

## 2. 删除 / 合并 / 重构清单

- 无删除（净新增 report 生成器 + 可选 HTTP 只读 API）。

## 3. 新领域类型 / 表 / ClickHouse fact

### 3.1 Postgres

```sql
-- 周期对账报告头
CREATE TABLE quant_reconciliation_report (
    id UUID PRIMARY KEY,
    period_start TIMESTAMPTZ NOT NULL,
    period_end TIMESTAMPTZ NOT NULL,
    funder_address TEXT NOT NULL,
    status qp_reconciliation_report_status NOT NULL, -- pending/completed/failed
    summary_json JSONB NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 行级差异（token / capital / order 聚合）
CREATE TABLE quant_reconciliation_report_line (
    id UUID PRIMARY KEY,
    report_id UUID NOT NULL REFERENCES quant_reconciliation_report(id),
    category qp_recon_report_category NOT NULL, -- token_balance/capital/reserved/open_orders
    token_id TEXT,
    ledger_value JSONB NOT NULL,
    venue_value JSONB NOT NULL,
    delta_usd NUMERIC,
    severity qp_recon_severity NOT NULL, -- info/warn/critical
    suggested_action TEXT
);
```

### 3.2 ClickHouse（可选，05.7 镜像）

- `quant_reconciliation_report_event` — report 完成镜像。

## 4. 必建模块与 trait

```text
crates/quant-pivot-core/src/reconciliation/
├── report.rs              # ReconciliationReportBuilder
└── report_worker.rs       # TaskId::ReconciliationReport（PeriodicTask，默认 daily UTC）
```

```rust
pub struct ReconciliationReportInput {
    pub funder: Address,
    pub period: (DateTime<Utc>, DateTime<Utc>),
    pub ledger: LedgerSnapshot,       // Σ open lots by token, capital FSM sums
    pub venue: VenueAccountSnapshot,  // Data API + CLOB collateral
}

pub trait ReconciliationReportBuilder: Send + Sync {
    async fn build(&self, input: ReconciliationReportInput) -> QuantResult<ReconciliationReport>;
}
```

**聚合规则：**

- `token_balance`：venue ERC-1155 余额 vs `Σ open lot.shares` by token（05.6 R3 per-lot 聚合视图）。
- `capital`：`sum(reserved+spent+...)` vs venue USDC collateral（09 § 口径）。
- `open_orders`：venue open orders vs PG `Submitted`/`PartiallyFilled` 计数。

差异 `severity=critical` → 告警 + 建议 enqueue 05.5 逐单对账（不自动改 ledger）。

## 5. deploy-config / runtime-config

```toml
[execution.reconciliation.report]
enabled = true
cron = "0 6 * * *"          # UTC daily
lookback_hours = 24
auto_enqueue_recon = false  # true：critical 行自动 insert quant_reconciliation 逐单任务
```

## 6. 生产不变量与失败语义

- Report **只读**；任何 ledger 校正仍走 05.5 `ReconciliationService::resolve` / 自动校正路径。
- venue 不可用 → report `failed`，不臆测 venue 值。
- per-lot 粒度差异在 report line 附 `lot_ids[]` 供 operator drill-down。

## 7. 第三方 crate 引入

- 无新增（复用 05.5 venue client + PG repos）。

## 8. 验收测试

- `daily_report_matches_aggregated_token_balance`。
- `capital_delta_detects_reserved_drift`。
- `critical_delta_does_not_auto_modify_ledger_without_flag`。
- `report_period_idempotent`（同 period 重跑覆盖或 skip）。

## 9. Blocker

- 若 report 直接写 position/capital 绕过 05.5 事务守卫，失败。
- 若聚合不用 R3 per-lot `aggregate_by_token`，失败。
