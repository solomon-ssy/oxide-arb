# 06.6 — Counterfactual Factor Attribution

> 父：[`README.md`](README.md) · [`../phase-05/05.7-attribution-api-governance-closeout.md`](../phase-05/05.7-attribution-api-governance-closeout.md)
>
> 闭环定位：在 05.7 final attribution 的基础上，解释 outcome 之后“哪些 factor 真的贡献了收益、
> 损失或错失收益”，并产出可训练、可审计、可回放的 counterfactual attribution。

## 1. 目标与闭环定位

- 基于 frozen recommendation evidence、feature vector、factor breakdown 和事后事实，构建
  counterfactual factor attribution。
- 精细化 `missed_return_bps`，支持未入场/取消/失败路径的机会成本估计。
- 输出 factor-level realized / counterfactual contribution，进入训练和模型治理报告。
- 不改变 05.7 WORM final attribution；counterfactual attribution 是派生分析产物。

## 2. 删除 / 合并 / 重构清单

- 不覆盖 `quant_recommendation_attribution` 原终态行。
- 不在 report composer 热路径做事后 book replay。
- 不用当前 live feature 重算替代 frozen feature。
- 不把 factor contribution 写成不可解释 blob；必须有 factor name/version/source refs。

## 3. 数据契约

### 3.1 05.7 label 承接（WORM attribution → counterfactual 派生）

05.7 写入 `quant_recommendation_attribution` 的 live-training label 与 06.6 的分工：

| 05.7 label | 05.7 as-built | 06.6 交付 |
|---|---|---|
| `max_favorable_excursion_bps` | filled：`peak_mark_price` vs entry（粗粒度，写入 WORM 行） | 可选 book replay 精化；**不 update** WORM 行 |
| `max_adverse_excursion_bps` | filled：**`None`**（exit monitor 无 trough） | **trough 跟踪或 post-outcome book replay window** 计算 MAE；写入 counterfactual 派生产物（仍不 update WORM 行） |
| `missed_return_bps` | unfilled：`expected_return_bps` 代理 | counterfactual path 精化（§1 目标） |

06.6 **不在第一版实现 runtime trough 跟踪**（高频 peak/trough 增强归 Phase 8+）；MAE 通过 **离线 book replay** 计算，而非改 exit monitor hot path。

新增派生结果：

- `counterfactual_attribution_id`
- `recommendation_id`
- `attribution_id`
- `factor_name`
- `factor_definition_version`
- `observed_value`
- `counterfactual_value`
- `realized_contribution_bps`
- `missed_contribution_bps`
- `confidence`
- `source_refs`
- `analysis_hash`

## 4. 输入来源

- 05.7 final attribution。
- recommendation frozen `evidence_refs`。
- frozen feature vector payload/source refs。
- recommendation `factor_breakdown`。
- ClickHouse / PG historical book facts for post-outcome replay。
- execution/reconciliation/position ledger。

## 5. 必建模块

```text
crates/quant-pivot-research/src/attribution/
├── counterfactual.rs
├── missed_return.rs
└── factor_contribution.rs

crates/quant-pivot-core/src/service/
└── counterfactual_attribution.rs
```

## 6. 分析流程

```text
FinalAttribution
 -> load frozen recommendation evidence
 -> load frozen feature vector
 -> load post-outcome book/settlement window
 -> reconstruct executable counterfactual path
 -> estimate missed/realized factor contribution
 -> write derived counterfactual attribution
```

analysis hash 必须覆盖 input ids、feature hash、factor definition versions、time window、algorithm version。

## 7. 生产不变量与失败语义

- counterfactual 输出是派生分析，不改变 execution truth。
- input evidence 不完整时 drop 并计入 coverage，不猜默认值。
- replay window 缺事实时输出 unavailable reason，不产假 precision。
- 同 input + algorithm version 必须 deterministic。
- 任何 money/price/share 仍用 Decimal/newtype，只有统计边界可转 `f64`。

## 8. 验收测试

- 完整 evidence 可生成 deterministic analysis hash。
- 缺 frozen feature vector 时 drop 并计 coverage。
- 缺 book replay facts 时标记 unavailable。
- 未入场 recommendation 生成 missed contribution。
- 已平仓 recommendation 生成 realized contribution。
- factor definition version 改变会改变 analysis hash。
- counterfactual 结果不更新 05.7 WORM attribution 行。

## 9. Blocker

- 用 live feature 重算替代 frozen evidence，失败。
- 覆盖原 attribution 终态行，失败。
- 缺事实仍生成数值 contribution，失败。
- analysis hash 不覆盖算法版本，失败。

## 10. 延后 / 非目标

- 因果推断实验和 deep learning attribution 不在 06.6 第一版。
- **Runtime trough 跟踪**（filled MAE 的在线维护）不在 06.6；06.6 用 book replay 离线算 MAE（见 §3.1）。
- UI 可视化可以后续 Phase 7 做；06.6 只要求 API/JSON/report artifact 可消费。
- 自动策略参数更新由 06.5/后续治理决定。
