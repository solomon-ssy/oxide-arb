# 06.3 — ONNX Runtime Integration

> 父：[`README.md`](README.md) · [`../08-third-party-crates-and-ml-stack.md`](../08-third-party-crates-and-ml-stack.md) §7/§17
>
> 闭环定位：把外部训练并导出的 ONNX 模型接入线上推理面，但不让 ONNX runtime 成为
> report-only / weighted scorer 的启动硬依赖。

## 1. 目标与闭环定位

- 引入 `OnnxInferenceEngine` trait 和 `OrtOnnxInferenceEngine` impl。
- ONNX model 只能通过 model registry 发布后的 artifact 加载。
- 推理输入必须来自冻结 `FeatureVector`，输出进入统一 `ModelPredictionBatch`。
- session 初始化、warmup、schema 校验、runtime version 校验全部 fail closed。
- `ort` 通过 cargo feature gate 引入，默认不开。

## 2. 删除 / 合并 / 重构清单

- 删除任何直接在 report composer / execution admission 中加载 ONNX 的实现倾向。
- 不允许业务代码依赖 `ort` concrete type；只能依赖 `OnnxInferenceEngine` trait。
- 不新增 Python runtime 或 PyO3 主路径。
- 不把 ONNX artifact 当作 classical/weighted artifact 的兼容 alias。

## 3. 领域类型与 artifact contract

新增或收敛：

- `OnnxArtifactRef`
- `OnnxRuntimePolicy`
- `OnnxInferenceInput`
- `LoadedOnnxModel`
- `ModelPredictionBatch`

artifact 必须包含：

- `model.onnx`
- `input_schema.json`
- `output_schema.json`
- `preprocessing.json`
- `postprocessing.json`
- `training_report.json`
- `sha256sum`

## 4. 配置与 feature gate

- Cargo feature：`ml-onnx = ["dep:ort"]`，默认关闭。
- deploy/runtime config 只允许选择已发布 `model_version_id`，不允许传任意本地路径。
- execution provider 默认 CPU；CUDA/TensorRT 等 native provider 必须独立 feature gate。
- Phase 开工前必须拍板 MSRV：若采用最新 `ort 2.x rc`，workspace MSRV 需同步升级；若不升级，
  必须记录旧版本 API/维护/安全权衡。

## 5. 必建模块

```text
crates/quant-pivot-core/src/model_runtime/
├── onnx.rs          # OnnxInferenceEngine trait + runtime policy
├── ort_engine.rs    # feature-gated ort implementation
└── schema.rs        # input/output schema validation
```

## 6. 加载与推理流程

```text
ModelVersionInfo
 -> artifact hash verification
 -> feature/output schema verification
 -> ort session build
 -> warmup
 -> FeatureVector payload to tensor
 -> session.run
 -> postprocess
 -> ModelPredictionBatch
```

所有错误必须带 model version、artifact hash、schema hash、runtime policy，不记录 secret 或账户数据。

## 7. 生产不变量与失败语义

- ONNX session load 失败不得影响 weighted scorer/report-only 启动。
- schema mismatch 必须 fail closed，不做字段名模糊匹配。
- corrupted artifact 必须 fail closed。
- 推理超时必须返回 typed error，并由调用方降级到已治理的 fallback。
- 同一 artifact + 同一 feature vector 必须产确定性结果。

## 8. 验收测试

- artifact hash mismatch 拒绝加载。
- input schema mismatch 拒绝推理。
- output schema mismatch 拒绝发布或加载。
- corrupted ONNX file 拒绝加载。
- CPU session warmup 成功后可推理 fixture batch。
- feature gate 关闭时 workspace 不链接 `ort`。
- report-only 启动不需要 ONNX runtime。

## 9. Blocker

- `ort` concrete type 泄漏到业务层，失败。
- 无 MSRV 决策即引入最新 `ort`，失败。
- ONNX artifact 可绕过 model registry 直接加载，失败。
- 推理失败被吞掉并产默认 prediction，失败。

## 10. 延后 / 非目标

- GPU/TensorRT provider 不是 06.3 默认目标。
- 深度学习训练不在 06.3；训练仍在外部或后续 Phase 8+。
- ONNX 输出如何进入自动发布由 06.4/06.5 治理。
