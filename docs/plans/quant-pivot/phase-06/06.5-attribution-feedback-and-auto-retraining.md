# 06.5 — Attribution Feedback & Auto Retraining

> 父：[`README.md`](README.md) · [`../phase-05/05.7-attribution-api-governance-closeout.md`](../phase-05/05.7-attribution-api-governance-closeout.md)
>
> 闭环定位：把 05.7 的 final attribution 从“可被 dataset builder 消费”提升为“受治理的反馈、
> 再训练、候选模型创建和发布前评估编排”。

## 1. 目标与闭环定位

- 建立 attribution feedback scheduler。
- 按 sample source coverage 自动触发 dataset build。
- 在阈值满足时触发 retraining candidate，不自动 publish。
- 加强 CH/outbox 覆盖率：execution/capital/position/attribution mirror 的生产覆盖和重放。
- 训练结果进入 06.4 classical publish path 或 weighted scorer candidate path。

## 2. 删除 / 合并 / 重构清单

- 不新建第二套 training pipeline；继续复用 `TrainingDatasetService`。
- 不允许 worker 直接 publish model；publish 必须走 governance。
- 不把 CH 当 source of truth；PG attribution / recommendation / execution ledger 是唯一真相。
- 不重新计算 live attribution sample 的 PIT 特征。

## 3. 数据契约

新增 feedback run 元数据：

- `feedback_run_id`
- `window_start` / `window_end`
- `sample_sources`
- `dataset_id`
- `coverage_report`
- `training_run_id`
- `candidate_model_version_id`
- `decision`（skipped / dataset_built / trained_candidate / failed）

CH/outbox 覆盖：

- `quant_execution_event`
- `quant_capital_allocation_event`
- `quant_position_event`
- `quant_recommendation_attribution_event`

## 4. 配置

```toml
[research.feedback]
enabled = false
sweep_secs = 3600
min_live_attribution_samples = 100
min_label_coverage_bps = 7000
max_dataset_age_secs = 86400
auto_train_candidate = false
```

默认关闭；开启后也只创建候选模型，不自动发布。

## 5. 必建模块

```text
crates/quant-pivot-core/src/app/
└── attribution_feedback_worker.rs

crates/quant-pivot-core/src/service/
└── attribution_feedback.rs

crates/quant-pivot-repository/src/postgres/quant/
└── feedback_run.rs
```

## 6. 编排流程

```text
final attribution rows
 -> coverage threshold
 -> BuildTrainingDatasetRequest(sample_sources=[historical_pit, live_attribution])
 -> dataset hash
 -> training candidate
 -> quality gate report
 -> model candidate in registry
 -> human/governed publish path
```

每一步必须幂等：同 window + sample sources + config hash 不重复创建等价 dataset/run。

## 7. 生产不变量与失败语义

- 自动反馈不得自动 publish。
- coverage 未达标只记录 skipped，不训练。
- CH mirror 落后不得污染 PG truth；outbox 重放可以补齐 CH。
- dataset hash 必须覆盖 sample source。
- feedback run 失败必须可重试且不重复产生等价候选。

## 8. 验收测试

- attribution 样本不足时 skip 并记录 coverage。
- 默认 sample sources 同时包含 historical/live attribution。
- `[historical_pit]` 不消费 attribution。
- live attribution 缺 frozen evidence drop 并计入 coverage。
- 同 window 重跑不重复创建 dataset。
- 训练 candidate 不会自动 publish。
- CH writer 失败只计数/告警，不回滚 PG。

## 9. Blocker

- feedback worker 可绕过 governance publish，失败。
- 以 CH 作为 attribution 真相，失败。
- feedback run 非幂等，失败。
- live sample 重新计算 PIT 特征，失败。

## 10. 延后 / 非目标

- 多臂 bandit / online learning 不在 06.5。
- 深度反事实 factor attribution 不在 06.5，见 06.6。
- 跨账户周期 reconciliation report 仍由 06.2 承接。
